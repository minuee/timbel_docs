# 출처(sources) 데이터 약속 — 제목·본문 하이라이트 보장 조건

> 상담 화면 "출처 문서 원본보기 + 근거 위치 하이라이트(형광펜)" 기능이 정상 동작하기 위해
> 백엔드(데이터 제공자)가 sources[] 각 청크에 보장해줘야 하는 데이터 형식 정리.

## 동작 원리 (왜 이 데이터가 필요한가)
프론트 강조는 "청크의 content 텍스트를 원본 문서에서 그대로 찾아 그 범위를 칠하고, heading_path로 제목 위치를 짚는" 방식이다.
따라서 content가 원문에 실제 존재하는 텍스트여야 하고, heading_path가 그 content의 진짜 섹션 제목이어야 한다.

---

## ✅ 필수 — 이게 있어야 강조가 됨

[1] document_id
- 약속: 원본 문서 식별자
- 안 지키면: 원본보기 자체가 안 열림

[2] content
- 약속: 원문에 그대로 있는 텍스트 (요약·재작성 금지, 표는 마크다운 형태 OK)
- 안 지키면: 원문에서 못 찾아 → 본문 강조 실패

[3] source_location.heading_path
- 약속: content가 실제 속한 섹션 제목 경로. 마지막 값이 그 섹션 제목과 일치
- 안 지키면: 제목이 엉뚱한 곳에 찍히거나 강조 위치가 틀림

## 🟡 권장 — 있으면 정확도·기능 향상

[1] section_title
- 효과: 있으면 리스트 제목으로 우선 사용 (heading_path보다 깔끔)

[2] page_number
- 효과: PDF 문서일 때 해당 페이지로 점프

[3] start_char_offset / end_char_offset
- 효과: 정밀 위치 (현재는 heading + 텍스트 매칭이라 미사용이나, 향후 정확도 향상용)

## ⚠️ 원문에 없는 "요약/합성 청크"를 줘야 한다면
- 예: 문서 전체 개요를 LLM이 새로 작성한 청크 (원문에 그대로 존재하지 않음)
- 위 content 원문 조건을 못 지키므로 → is_synthetic: true 같은 플래그로 구분해서 전달
- 그러면 프론트가 그 청크만 "요약 출처 · 원문 위치 강조 미지원"으로 안내 처리 (강조는 못 하지만 깨져 보이지 않게)

---

## 한 줄 요약
content = 원문 그대로 + heading_path = 그 content의 진짜 섹션 제목.
이 두 개만 맞으면 제목·본문 강조 모두 정상 작동. 원문에 없는 요약문이면 is_synthetic 플래그로 표시.

## 부록 — 실제 사례 비교 (rag_distill_no3 응답 기준)

▶ ref 1 (강조 실패)
- content: 원문에 없는 요약/재작성 문장 ("…자본소득을 추구하는 2등급…")
- source_location.file_url: null
- start/end_char_offset: null
- page_number: null
- heading_path: ["15. 집합투자기구 공시 정보 안내"] (content 내용과 불일치)
- 결과: 제목만 강조, 본문 강조 불가

▶ ref 2~5 (강조 정상)
- content: 원문 그대로의 섹션 텍스트
- source_location.file_url: /repos/…/docs/…
- start/end_char_offset: 4151 / 5034 등
- page_number: 1
- heading_path: content와 일치
- 결과: 제목 + 본문 범위 강조 정상

참고: ref 1은 score(0.731)는 가장 높지만 AI 답변이 인용하지 않았고(`[2][3][4]`만 인용), 위치정보가 전부 null인 합성 청크였다.
