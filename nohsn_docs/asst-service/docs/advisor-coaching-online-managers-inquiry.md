# [백엔드 문의] 코칭요청 — "접속 중인 관리자" 목록 제공 요청

> 작성일: 2026-06-29
> 목적: 상담사가 코칭요청 시 고르는 "관리자 선택" 드롭다운을 **현재 접속 중인 관리자**로 거르고 싶음. 현재 프론트엔 관리자 접속상태 데이터가 전혀 없어 백엔드 지원이 필요함.

---

## 1. 현재 동작 (프론트 기준 사실)

- 상담사 코칭요청 모달의 "관리자 선택" 드롭다운 출처:
  `CoachingRequest.vue` → `userListStore.admins` → `getAdminsOfAgent()` → **`GET {PROXY_USER}/get_managers`**
- `/get_managers` 응답(`managers[]`)은 **조직/권한 기준 배정 관리자 명단**일 뿐, **접속(온라인) 여부 필드가 없음.**
- 그래서 **로그인 안 한 관리자도 그대로 셀렉트에 노출**되고, 상담사가 그 관리자에게 요청을 보낼 수 있음.
- 오프라인 관리자에게 보낸 요청도 `POST /coaching-requests`로 DB에 저장되고, 그 관리자가 나중에 **관리자 페이지 진입 시(refreshCoachings)** 조회로 받아봄. (실시간 소켓 토스트만 못 받음)

### 참고: 상담사(agent)는 presence 인프라가 이미 있음 (관리자만 없음)
| 항목 | 상담사(agent) | 관리자(manager) |
|---|---|---|
| presence 룸 | `agent-status` | ❌ 없음 |
| 실시간 이벤트 | `agent-status-update` | ❌ 없음 |
| Redis 스냅샷 | `getAgentStatusFromRedis` (`dev:global:call:status:active`) | ❌ 없음 |
| 상태 store | `agentStatus.ts` | ❌ 없음 |

→ 상담사 상태(통화중/대기/이석/휴식/미접속)는 실시간 추적되는데, **관리자 presence는 인프라 자체가 없음.**

---

## 2. 요청사항 (택1 또는 조합)

### (A) 권장 · 가벼운 방식 — 조회형
- `GET /get_managers` 응답의 각 manager에 **접속상태 필드 추가**.
  - 예: `is_online: boolean` (+ 가능하면 `last_seen_at: ISO8601`)
- 프론트는 셀렉트 열 때 1회 조회로 필터/정렬만 하면 됨.
- 코칭요청은 빈도가 낮아 **실시간까지는 불필요** → 가성비 최선으로 판단.

### (B) 실시간 방식 — 구독형 (필요 시)
- 상담사처럼 `manager-status` 룸 + `manager-status-update` 이벤트 + Redis presence.
- 구현비 큼. (A)로 부족할 때만.

---

## 3. 백엔드에 확인할 질문

1. **관리자 presence를 백엔드가 알 수 있나?**
   - 관리자 로그인/소켓 연결 시 Redis 등에 접속상태를 기록하고 있는지?
   - 없다면 신규로 추적 가능한지? (코칭 룸 `coaching_{managerId}` join 여부로 대용 가능한지 포함)
2. **"접속"의 판단 기준**을 무엇으로 정의할지?
   - 소켓 연결 여부 / 코칭 룸 join 여부 / 로그인 세션 유효 — 어느 것?
3. **제공 방식**: `/get_managers`에 `is_online` 필드 추가(A)가 가능한지? 아니면 별도 엔드포인트/구독 채널이 나은지?
4. **갱신 주기/정확도**: 조회형(A)일 때 상태 신선도는 어느 정도 보장되는지? (스테일 허용 범위)

---

## 4. UX/정책 결정 (내부 합의 필요 — 백엔드 무관)

- 오프라인 관리자를 **셀렉트에서 완전히 숨길지** vs **회색+(오프라인) 표시만 하고 선택은 허용**할지.
  - 권장: **숨기지 말고 오프라인 표시만.** 현재 "오프라인 관리자에게 보낸 요청도 나중에 받는" 메시지함 동작이 실무상 유용하므로 유지.
- 표시한다면 정렬: 온라인 우선 노출.

---

## 5. 결정되면 프론트 작업량 (참고)

- 백엔드가 상태만 내려주면 변경 사소함:
  - `CoachingRequest.vue`의 `coachingRequestAdvisorOptions` computed에 `is_online` 기준 **필터/정렬 + (오프라인) 라벨** 추가 (≈한 곳).
- 즉 **관건은 100% 백엔드 presence 데이터 유무.**
