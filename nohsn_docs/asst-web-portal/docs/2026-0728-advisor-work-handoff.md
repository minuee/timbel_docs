## 3. 코칭 상세 UI 분리 🟡

## 4. 알림 = 순수 알림 원칙 🟡

### 무슨 일이 있었나

관리자가 코칭요청 알림을 받고 **알림 팝오버**에서 답변하려 했으나 입력폼이 없었다.
조사 결과 답변 기능은 **실시간 모니터링 페이지의 코칭 모달 안에만** 있었다.

| 화면 | 코칭요청 확인 | 답변 |
|---|---|---|
| 알림 팝오버 | ✅ | ❌ |
| 코칭 관리 페이지 | 목록·읽음만 | ❌ (상세 자체가 없음) |
| 실시간 모니터링 > 코칭 모달 | ✅ | ✅ **원래 있었음** |

즉 **기능 부재가 아니라 동선 단절**이었다. 알림을 받고 자연스럽게 가는 두 경로(알림·코칭 관리)에 답변이 없어서, 답변하려면 "알림 확인 → 모니터링 이동 → pill 열고 → 카드 찾아 → 클릭" 5단계를 돌아야 했다.

### 결정

알림 팝오버에 답변폼을 넣었다가 **철회**하고, 나아가 **관리자의 확인(읽음) 처리까지 막았다.**

> **알림은 "무엇이 왔는지" 알려주는 것까지만 책임진다.**
> 처리 기능이 알림에 들어오면 알림함이 두 번째 작업화면이 되고, 원래 담당 화면과 스펙이 갈라져 유지보수가 배로 든다.

- 관리자 코칭 상세에는 **안내 문구만** 노출 (`"답변과 확인은 코칭 메뉴에서 처리할 수 있습니다."`)
- 확인 버튼을 막은 건 안전장치이기도 하다 — **답변도 안 한 채 "확인"만 누르면 미확인 목록에서 사라져 요청이 유실**된다
- 상담사는 그대로 둔다. 받은 코칭은 "확인"이 곧 완결이라 알림에서 끝나도 되는 성격

### 이식 시 확인
- [ ] 알림/벨 UI 에 도메인 처리 기능(답변·전송·상태변경)이 들어가 있지 않은가
- [ ] 그 도메인의 "제대로 된 작업 화면"이 존재하고, **알림에서 거기로 갈 수 있는가**
- [ ] 미확인 목록에서 항목을 지우는 액션(읽음)이 **본 작업 없이** 눌릴 수 있는가 → 유실 위험

## 5. 다크모드 — EP 컴포넌트 배경 토큰 불일치 🟢

**증상**: 다크모드에서 `<ElDivider>` 라벨("상담이 종료되었습니다") 배경만 주변보다 어두운 사각형으로 떴다.

**원인**: element-plus 기본 CSS 가 `.el-divider__text` 배경을 `--el-bg-color` 로 박아둔다.

| 토큰 | 다크 값 | 의미 |
|---|---|---|
| `--el-bg-color` | `#141414` | **페이지** 배경 |
| `--color-white` | `#1d1e1f` | **카드/패널** 표면 |

카드 위에 올라간 EP 요소가 페이지 배경색을 쓰니 어긋난다.
라이트 모드에선 둘 다 흰색이라 **아무도 몰랐다** → 다크에서만 드러나는 유형.

**조치** (해당 컴포넌트 스코프에만, 전역 미변경):
```scss
:deep(.el-divider__text) {
  background-color: var(--color-white); // 하드코딩 대신 표면 토큰 → 라이트/다크 자동
}
```

> **일반화**: 카드/패널 위에 얹히는 **모든 EP 컴포넌트**가 같은 함정을 갖는다.
> 다크에서 "배경만 겉도는" 증상을 보면 `--el-bg-color`(페이지) vs `--color-white`(표면) 조합을 먼저 의심할 것.
> 관련: `darkmode-hardcoded-color-guide.md`

## 6. 코칭 검색 / 기간 필터 미연결 🟢

**증상**: 관리자 코칭 모달 상단 검색에 상담사명을 넣고 엔터·조회를 눌러도 무반응.

**원인 (2중)**:
1. **조회·초기화 버튼에 `@click` 이 아예 없었다** — `<button type="button">조회</button>` 껍데기
2. 입력값(`consultantName`)도 기간(`searchStartDate/EndDate`)도 **부모에서 아무 데도 쓰이지 않았다**

즉 API 문제도 필터 버그도 아닌 **처음부터 미연결**. (원본 화면도 동일하니 이식 대상 레포에도 있을 가능성이 높다)

**조치**:
- 필터에 `search` / `reset` emit 추가 → 조회 클릭 · **입력창 엔터** · 초기화 연결
- 목록 API 가 이름·기간 파라미터를 받지 않아(모르는 쿼리는 400) **클라이언트 필터**
- 이름은 카드 표기가 `"From. 홍길동"` 형태라 **접두사 제거 후 부분일치**(대소문자 무시)
- **탭 개수도 필터 결과 기준**으로 교체 — 검색 중 개수만 전체로 남으면 어긋나 보인다

### ⚠️ 함정 2가지 (이식 시 그대로 밟게 됨)

**(1) 기간을 즉시 적용하면 안 된다**
기본값이 "오늘"이라 즉시 적용하면 **모달을 여는 순간 과거 코칭이 전부 사라진다.**
→ `applied*` 를 **빈 값(미적용)으로 시작**하고, **조회를 눌렀을 때만** 범위를 건다.
세그먼트(오늘/이번주) 클릭은 날짜 입력값만 바꾼다.

**(2) 날짜 비교에 표시용 문자열을 쓰면 안 된다 + 타임존**
카드의 날짜는 `toLocaleDateString("ko-KR")` 결과(`"2026. 7. 28."`)라 크기 비교가 불가능하다.
→ 원본 ISO(`created_at`)를 항목에 심어 비교한다.

그리고 **`iso.slice(0, 10)` 으로 자르면 안 된다.** UTC 로 오면 자정 근처에서 하루가 밀린다.

```
2026-07-28T16:10:00Z   (KST 로는 07-29 01:10)
  slice(0,10)                                          → 2026-07-28  ❌
  toLocaleDateString("sv-SE", {timeZone:"Asia/Seoul"}) → 2026-07-29  ✅
```

`sv-SE` 로캘이 곧 `YYYY-MM-DD` 포맷이라 이걸로 한국시간 날짜를 뽑는다(표시부의 `timeZone: "Asia/Seoul"` 과 기준 일치).
→ **밤늦게 온 코칭이 "오늘" 조회에서 빠지는 사고를 막는다.**

시각 정보가 없는 항목은 기간으로 거르지 않는다(원래 보이던 게 조회 후 사라지는 쪽이 더 혼란스럽다).
