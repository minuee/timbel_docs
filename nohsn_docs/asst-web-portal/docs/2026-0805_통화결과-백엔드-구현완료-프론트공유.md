# 통화 결과 — 백엔드 구현 완료 (프론트 공유)

작성: 2026-08-05 / 백엔드(asst-service) → 프론트(asst-web)
원 설계서: `docs/call-result-api-request.md`

> 설계서 내용대로 구현 완료. **스펙이 바뀐 곳은 §5 두 가지뿐**이고 나머지는 문서 그대로다.
> 테이블은 5F 운영 DB에 생성 완료.

---

## 1. 값 정의 (5종 + null)

| 코드값 | 라벨 | 채우는 주체 |
|---|---|---|
| `COMPLETE` | 완료 | 자동 + 수동 |
| `ABORTED` | 중도종료 | 자동 + 수동 |
| `TRANSFER` | 이관 | 수동만 |
| `CALLBACK` | 콜백 | 수동만 |
| `FAILED` | 실패 | 수동만 |
| `null` | (미지정) | 요약 미실행 / 배포 이전 콜 / 사람이 비운 콜 |

### 자동 판정 규칙

`/summary` 호출 시 대화록 턴의 **고객 발화(`role='customer'`) 유무만** 본다. LLM 미사용.

```
고객 발화 턴 수 == 0  →  ABORTED
그 외                 →  COMPLETE
```

`role` 이 없거나 빈 턴은 고객 발화로 세지 않는다.

**5F 실데이터 기준 예상 분포** (통화 79건):

| | 건수 |
|---|---|
| `COMPLETE` | 61 |
| `ABORTED` | 3 |
| 행 없음(`null`) | 15 — 대화록 턴 자체가 없어 요약이 실행되지 않는 콜 |

## 2. 목록 API — `GET /callstat/call-history`

응답 아이템에 **두 필드 추가**. 행이 없으면 둘 다 `null`.

```jsonc
{
  "id": "call_5f6effe6_...",
  "call_result": "ABORTED",        // COMPLETE|TRANSFER|CALLBACK|ABORTED|FAILED|null
  "call_result_source": "AUTO"     // AUTO|MANUAL|MANAGER|null
}
```

`call_result_source` 표기 구분:

| source | 의미 | 제안 표기 |
|---|---|---|
| `AUTO` | 서버 자동 판정 | 점선·연한색 |
| `MANUAL` | 상담사가 확인·수정 | 실선 |
| `MANAGER` | 관리자가 확인·수정 | 실선 |
| `null` | 미지정 | `-` |

### 필터 파라미터

| 파라미터 | 값 |
|---|---|
| `call_result` | `COMPLETE` / `TRANSFER` / `CALLBACK` / `ABORTED` / `FAILED` (생략 = 전체) |

- 값이 없는(미지정) 통화는 이 필터가 걸리면 **제외**된다 — `direction` 과 같은 규격이다.
- **"미지정만 보기" 필터는 넣지 않았다.** 필요하면 알려주면 `call_result=NONE` 같은 형태로 추가한다.

> 참고: `GET /callstat/agent-summary` 도 같은 조회 로직을 공유해서 두 필드가 함께 나간다.

## 3. 수동 수정 API (신규)

```
PATCH /aicc/asst-service/callstat/calls/{id}/result
```

### 요청

```jsonc
{
  "result_code": "CALLBACK",   // 필수. null 을 보내면 미지정으로 되돌린다
  "user_key": "user_5f6effe6", // 선택. 감사 추적용으로 기록만 한다
  "source": "MANUAL"           // 선택. 생략하면 MANUAL. 관리자 화면에서 고칠 땐 MANAGER
}
```

- `{id}` 는 `callstats_id`. **`call_id` 를 보내도 서버가 `callstats_id` 로 정규화**해 저장한다(한 콜이 두 행으로 갈리지 않게).
- 관리자 수정 기능을 붙일 때 **백엔드 수정 없이 `source: "MANAGER"` 만 보내면 된다.**

### 응답 (200)

저장된 행을 그대로 반환한다.

```jsonc
{
  "callstats_id": "call_5f6effe6_...",
  "call_id": "698592560905",
  "result_code": "CALLBACK",
  "source": "MANUAL",
  "updated_by": "user_5f6effe6",
  "created_at": "2026-08-05T02:11:00.000Z",
  "updated_at": "2026-08-05T02:11:00.000Z"
}
```

`404` — 해당 통화를 찾을 수 없음

### 권한

서버에서 강제하지 않고 `updated_by` 로 기록만 한다(설계서 §6 합의대로).
**"본인 콜만 수정"은 화면에서 처리**해야 한다. 관리자 화면은 표시·필터만.

## 4. ⭐ 사람이 고친 값은 재요약이 덮지 않는다

```
1. 통화 종료 → 요약     → AUTO: COMPLETE
2. 상담사 수정          → MANUAL: CALLBACK
3. 요약 버튼 다시 누름  → 서버가 스킵. 값은 CALLBACK 유지  ✅
```

- 잠금 판단은 `source` 만 본다. `AUTO` 일 때만 덮어쓴다.
- **`result_code: null` 로 비운 행도 잠긴다** — `source` 가 `MANUAL`/`MANAGER` 로 남기 때문에, 사람이 의도적으로 비운 값을 다음 요약이 되살리지 않는다.
- 백엔드 단일 SQL(`INSERT ... ON CONFLICT ... WHERE source = 'AUTO'`)로 처리해서, 자동 요약과 수동 수정이 동시에 일어나도 잠금이 뚫리지 않는다. **프론트에서 막을 필요 없다.**

실제 DB에서 위 시나리오 4단계를 실행해 검증 완료(3번에서 갱신 0건, 최종값 `CALLBACK/MANUAL` 유지).

## 5. 설계서와 달라진 것 (2가지)

### 5-1. `source` 에 `MANAGER` 추가

설계서는 `AUTO | MANUAL` 2종이었으나 관리자 수정을 나중에 구분하기 위해 `MANAGER` 를 추가했다.
프론트는 **배지 표기에서 `MANAGER` 도 `MANUAL` 과 같은 "사람이 확인한 값"으로 처리**하면 된다.

### 5-2. `PATCH` 바디에 `user_key` 를 프론트가 실어 보낸다

서버가 토큰으로 상담사를 역추적하면 최근에 걷어낸 `get_user` 의존이 되살아난다.
기존 memo API 와 같은 방식으로 **프론트가 `user_key` 를 바디에 넣어 보내는 것**으로 맞췄다.
없어도 저장은 되지만 `updated_by` 가 비어 감사 추적이 끊긴다.

---

## 6. 알아둘 것

- **기존 콜 소급 처리는 하지 않았다.** 배포 이전 콜은 해당 콜을 다시 요약하기 전까지 `null` 이다.
  (판정에 LLM 이 필요 없어 배치로 한 번에 채우는 것도 가능하다 — 필요하면 요청해달라)
- 대화록 턴이 아예 없는 콜은 `/summary` 가 404 로 끊겨 **행이 생기지 않는다**(위 79건 중 15건). 정상 동작이며 `-` 로 표기하면 된다.
- 통화 결과 저장은 LLM 호출보다 **먼저** 실행된다. CE(요약 LLM)가 실패해도 통화 결과는 남는다.

---

## 7. 프론트 작업 (설계서 §7 그대로)

- 카드 배지 — 5종 라벨·색상, `null` 은 `-`
- `call_result_source` 로 표기 구분 (`AUTO` = 점선·연한색 / `MANUAL`·`MANAGER` = 실선)
- 툴바 "전체 결과" 셀렉트 활성화 (양쪽 화면) — `call_result` 파라미터
- 콜 이력 상세 모달에 수정 UI + `PATCH` 연동 (`user_key` 함께 전송)
- 관리자 화면은 표시·필터만
