# 코칭 상세 화면 UI 원칙 — "턴 수가 다르면 템플릿을 나눈다"

> 대상: 코칭 / 코칭요청을 목록 → 상세로 보여주는 모든 화면
> 구현 기준: `asst-web-portal` `src/view/advisor-renual/chat/components/RenualRailCoaching.vue` (2026-07-28)
> 다른 레포에도 같은 도메인 화면이 있으면 이 문서의 **원칙 + 체크리스트**를 적용한다.

---

## 1. 문제

목록에서는 `From. / To.` 로 두 종류가 명확히 구분되는데, **상세로 들어가면 둘이 똑같이 보였다.**

코칭 도메인에는 성격이 다른 두 객체가 있다.

| 종류 | 실체 | 턴 수 |
|---|---|---|
| **요청한 코칭** (sent) | 상담사가 요청 → 관리자가 답변 | **2턴** |
| **받은 코칭** (received) | 관리자가 일방적으로 보냄 (요청과 무관) | **1턴** |

이 둘은 *방향만 다른 같은 것*이 아니라 **구성 자체가 다르다.** 그런데 하나의 상세 템플릿을 공유하고 있었다.

---

## 2. 원인 — 모델이 "2칸 고정"인데 템플릿이 종류를 안 봤다

```ts
interface CoachingThread {
  message: string;   // 내가 보낸 요청
  reply: string;     // 상대 응답
  kind: "sent" | "received";
  // ...
}
```

관리자가 먼저 보낸 코칭은 요청이 없으므로 `message: ""` 인 **반쪽 스레드**로 끼워 넣었는데,
템플릿이 `kind` 를 보지 않고 두 블록을 다 그렸다.

### 그래서 생긴 증상 3가지

1. **유령 블록** — 받은 코칭 상세 맨 위에 `나 → …` + `(내용 없음)` 이 그려진다. 사용자는 "내가 뭘 보냈다는 거지?" 가 된다.
2. **시각이 유령 블록에 붙음** — 시간 표기가 그 빈 블록 안에 있어서, 정작 본문에는 시간이 없다.
3. **발신자 이름이 틀림 (실버그)** — 응답 블록의 작성자 라벨이 `receiverName` 고정이었다.
   - sent 에선 receiver = 관리자 → 맞음
   - received 에선 **receiver = 나 자신** → **관리자가 보낸 코칭인데 발신자가 내 이름으로 표시됨**

> ⚠️ 이식 시 이 3번은 반드시 확인할 것. 같은 모델을 쓰면 같은 버그가 있을 가능성이 높다.

---

## 3. 원칙

> **목록에서 구분한 축은 상세에서도 유지한다.**
> 그리고 두 객체의 **턴 수가 다르면 상세 템플릿을 공유하지 않는다.**

공유 가능한 것은 *스타일 톤*이지 *구조*가 아니다. 데이터가 없는 자리를 빈 UI로 채우는 순간, 사용자에게는 "없는 사실"이 보인다.

---

## 4. 확정 UI 사양

### (A) 요청한 코칭 — 전폭 블록 2개를 위아래로

```
[긴급] To. 김관리

┌───────────────────────────┐
│ 나              07/28 14:20│   ← 배경: primary-10
│ 요청 내용                  │
└───────────────────────────┘
┌───────────────────────────┐
│ 김관리          07/28 14:35│   ← 배경: g5
│ 관리자 응답                │
└───────────────────────────┘

                    [ 확인완료 ]
```

- 상단 헤더에 `[긴급] To. 상대명` — 목록의 `To.` 표기와 같은 축
- 각 블록 상단: **발신자(좌) / 시각(우)** 한 줄
- 발신자 구분은 **배경색**으로 (내 것 / 상대 것)
- 응답 전이면 두 번째 블록 대신 `아직 답변이 없습니다.`

### (B) 받은 코칭 — 단일 상세 (대화 UI 없음)

```
[긴급] From. 김관리
07/28 14:20
┌────────────────────────┐
│ 코칭 본문                │
└────────────────────────┘
                [ 확인완료 ]
```

- **발신자는 `senderName`** (2절 3번 버그)
- 본문 영역에 `flex:1; min-height:0; overflow-y:auto` → 본문이 길어도 하단 확인 버튼이 밀리지 않는다
- 이 형태는 알림 팝오버 상세(`RenualNotifBell.vue`)와 **동일 형태로 맞춘다.** 같은 코칭이 화면마다 다르게 보이면 안 된다

---

## 5. ❌ 채택하지 않은 것 — 좌우 정렬 말풍선 (채팅형)

한 번 구현했다가 **되돌렸다.** 다른 레포에서 같은 제안이 나올 수 있으므로 이유를 남긴다.

```
                    ┌──────────┐
                    │ 내 요청   │   ← 우측 정렬
                    └──────────┘
┌──────────┐
│ 관리자 응답 │              ← 좌측 정렬
└──────────┘
```

| 반려 사유 | 설명 |
|---|---|
| **은유 불일치** | 실시간 대화가 아니라 **1턴씩 오가는 기록**이다. 채팅 UI는 "지금 주고받는 중"이라는 잘못된 기대를 준다 |
| **폭 낭비** | 좌우 정렬이 보이려면 말풍선 `max-width` 를 85% 이하로 줄여야 하는데, 좁은 사이드 레일에서 본문 폭이 그만큼 손해다 |
| **정보량 대비 과함** | 최대 2턴짜리 화면에 정렬·꼬리·색을 다 쓰는 건 과투자 |

> 방향 구분은 **배경색 + 발신자 라벨**로 충분하다.

## 6. 이식 체크리스트

다른 레포의 코칭 상세 화면을 볼 때 순서대로 확인.

- [ ] 상세 템플릿이 `kind`(sent/received)로 **분기하는가?** 안 하면 유령 블록이 있다
- [ ] 받은 코칭 상세에 **내가 보낸 적 없는 블록**이 그려지지 않는가
- [ ] 받은 코칭의 발신자 라벨이 **`senderName`** 인가 (`receiverName` 이면 내 이름이 뜬다)
- [ ] **각 메시지에 시각이 있는가** — 응답 쪽 시각이 누락된 경우가 많다 (모델에 `replyDate` 류 필드가 필요할 수 있음)
- [ ] 본문이 길 때 하단 **확인/액션 버튼이 밀려나지 않는가** (`flex:1; min-height:0; overflow-y:auto`)
- [ ] 같은 코칭을 **다른 화면(알림 팝오버 / 목록 페이지 / 사이드 레일)에서 봤을 때 형태가 같은가**
- [ ] 읽음처리 대상 id 가 맞는가 — **응답(코칭)의 id** 이지 요청의 id 가 아니다

---

## 7. 변경 범위 참고 (asst-web-portal 실측)

템플릿 + 스타일만. **데이터 계층은 무변경.**

| 구분 | 내용 |
|---|---|
| 템플릿 | 상세 뷰 `v-if="kind === 'sent'"` / `v-else` 로 2분기 |
| 스크립트 | 모델에 `replyDate` 1개 추가, 발신자 라벨 `senderName` 으로 수정 |
| 스타일 | 블록 카드 + `msg-head`(발신자/시각) + 단일 상세 블록 |
| **무변경** | 목록, 읽음처리, API 호출, 상태 판정 로직 |

---

## 8. 남은 개선 (미조치)

- **목록 페이지에 상세가 없다** — `advisor-renual/coaching/index.vue` 는 카드 클릭 시 읽음처리만 하고 상세를 열지 않는다. 사이드 레일에는 상세가 있는데 페이지에는 없어 비대칭.
- 블록 라벨(`나` / 상대명)을 아예 빼고 배경색만으로 갈지 여부는 열어둠.
