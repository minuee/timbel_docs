# 마크다운 구조 문서 결정적 세그멘테이션 + QnA/일반 블럭 모델 정합 (설계)

- 작성일: 2026-06-18
- 대상 repo: rag-parser-engine(KMS), aicm-service, aicm-web
- 관련 메모리: edit-screen-full-reindex-save, blockverifier-qna-overmerge, callbot-search-section-title

## 1. 배경 / 문제

마크다운으로 작성된 FAQ docx(예: 한국투자증권 고객 FAQ, 다이소 상품권_test)가 KMS에 등록될 때, gemma LLM 세그멘터가 원본의 명시적 마크다운 구조(`#`/`##`/`###`)를 **재해석하면서 비일관적으로 망가뜨린다.** 실측된 3가지 깨짐:

1. **한투-A**: 질문이 `paragraph` 블럭에 `### Q.` 마크다운째로 잔존, qna 아님.
2. **한투-B**: `qna` 블럭이지만 content에 `## 카테고리`/`### Q.` 마커가 누출, 질문이 qna_title·content에 중복.
3. **다이소**: 질문=`heading_3`, 답변=`heading_2`/`heading_3`, qna 블럭 0개(답변을 헤딩으로 오분류).

추가로 AICM 편집화면 저장 라운드트립(`_blocks_to_outline`/`_outline_to_blocks`)이 마커가 남은 블럭을 **헤딩+본문으로 더 쪼개** 질문/답변을 분리시킨다.

근본 원인: **원본에 이미 완벽히 명시된 마크다운 구조를 신뢰하지 않고 LLM이 재해석**하는 것. 이로 인해 "질문과 답변이 분리되어 질문만 검색되고 답변이 안 보이는" 문제가 재현된다.

## 2. 목표 / 비목표

**목표**
- 마크다운 구조 FAQ 문서를 **결정적(deterministic)으로** 분할해 일관된 qna 블럭을 생성한다.
- 검색에서 **질문으로 검색 시 답변이 매칭**되도록 보장(질문+답변 한 청크).
- 편집기는 공통이며 QnA·일반 문서 **둘 다 편집(수정/추가/삭제)** 가능.
- 일반 문서·비마크다운 문서는 **기존 동작을 그대로 유지**.

**비목표**
- gemma LLM 세그멘터 자체 품질 개선.
- 일반 문서 처리 방식 변경 — **비마크다운 문서뿐 아니라 마크다운이지만 FAQ가 아닌 일반 문서**도 기존 gemma 경로 그대로(정책 A).
- 검색 랭킹/리포뮬레이트 정책 변경.

## 3. 데이터 모델 (확정)

섹션 단위 `title_block_type`으로 두 종류를 구분한다.

| 항목 | QnA 섹션 (`title_block_type="qna"`) | 일반/헤딩 섹션 (`title_block_type="heading_N"`) |
|---|---|---|
| 목록 제목 | 질문 → 각 본문 블럭의 `metadata.qna_title` (별도 제목 블럭 없음) | 제목 → **독립 heading 블럭**(자체 청크) |
| 본문 | 답변 → `content` (**단락 1개 = 1청크**) | 단락 → **독립 paragraph 블럭 N개**(N청크) |
| content 내용 | **답변만** (`#`/`##`/`###` 마커·질문 텍스트 없음) | 단락 텍스트 |
| 임베딩 | `[질문] qna_title` + content 를 **한 벡터**로 | 헤딩 자체 청크 + 하위 단락에 `heading_path` 맥락 |
| 검색 역할 | 질문+답변 한 단위 | 제목=구조/맥락, 단락=콘텐츠 |

**불변식(invariant)**: 질문은 `qna_title` **단 한 곳**에만 존재한다. → content에 질문이 중복되지 않으므로 "목록 제목 ↔ content 속 제목" 어긋남이 **원천 불가능**.

**단락 정책(확정, 정책 가)**: QnA 섹션은 **답변 단락 1개**(content 1개, 줄바꿈·리스트는 그 안에서). 일반 섹션은 단락 N개. → QnA는 항상 1청크라 질문 중복 임베딩/답변 분할이 발생하지 않는다.

## 4. QnA vs 일반 구분 (확정)

문서 전체로 나뉘지 않는다(한 FAQ 문서도 `#`제목·`##`카테고리=헤딩 + `### Q.`질문=qna 가 혼재). **섹션 단위**로 결정한다.

| 생성 방식 | 결정 주체 | 규칙 |
|---|---|---|
| 문서 업로드 | KMS 세그멘터(§5.1) | 마크다운 레벨 + 질문 패턴 |
| 수동 편집 | 사용자(명시 선택) | "질문 추가(QnA)" vs "제목/목차 추가" (정책 가) |

## 5. 컴포넌트 설계

### 5.1 KMS 결정적 마크다운 세그멘터 (rag-parser-engine, 신규)

**적용 조건(라우팅) — 정책 (A): QnA만 결정적**
- **두 조건을 모두** 만족할 때만 결정적 분할 경로:
  1. 마크다운 구조(`#{1,6}\s` 헤딩 라인이 임계치 N개 이상), 그리고
  2. **질문 레벨이 감지됨**(가장 깊은 헤딩 레벨의 다수가 질문형 = FAQ, 아래 판정).
- 그 외는 **전부 기존 gemma `_segment_batch` 경로 유지**: 비마크다운 문서뿐 아니라 **마크다운이지만 FAQ가 아닌 일반 문서**(질문 레벨 미감지)도 포함 → **일반 문서 파싱 동작은 변경 없음**.
- enrich/embed 등 후속 단계는 두 경로 공통(변경 없음).

**FAQ 여부 판정 + 질문 레벨 (확정, 레벨 기반)**
- 문서의 **가장 깊은 헤딩 레벨 L**을 구한다(한투=`###`, 다이소=`###`).
- 레벨 L 헤딩의 **다수가 질문형**이면(질문형 = `?`로 끝 OR `Q.`/`질문:`/`문:`/`Question:` 접두 OR 한국어 의문 어미 `나요`/`까요`/`ㄴ가요`/`싶어요`/`하나요` 등) → **FAQ 문서**로 판정.
  - 레벨 L 헤딩 **전체**를 **질문(qna)**으로 처리(개별 헤딩의 `?` 유무와 무관 — 다이소 "…싶어요." 같은 평서형 질문도 레벨로 포착).
  - 레벨 < L 헤딩(`#`/`##` 등)은 구조 헤딩(제목/카테고리)으로.
- 다수가 질문형이 아니면 → FAQ 아님 → **결정적 경로를 타지 않고 기존 gemma 경로**로(정책 A, 일반 문서 동작 불변).
- `doc_type`(파일명 `faq` 등)은 보조 신호로만 사용(레벨+질문형 다수 판정이 1차).

**분할 규칙 — FAQ 마크다운 (레벨 L = 질문 레벨)**
- 레벨 < L 헤딩(존재 시):
  - `#` → 문서 제목 → `heading_1` 블럭.
  - `##` → 카테고리 → `heading_2` 블럭 + 하위 qna 블럭들의 `heading_path`/맥락으로 전파.
- **레벨 L 헤딩 → `qna` 블럭**:
  - `qna_title` = 헤딩 텍스트에서 마커(`#`/`Q.`/`질문:`/`문:`/`Question:`) 제거한 질문.
  - `content` = 다음 **레벨 L 이상(얕은)** 헤딩 또는 `---` 직전까지의 본문 = **답변**. 본문 안의 헤딩 라인·잔여 마커 제거. `[분류] …`·`---` 처리는 §7.
  - **질문 텍스트는 content에 넣지 않는다**(불변식).
- 다이소처럼 `#`/`##`가 없으면 **qna 블럭만** 생성된다(제목/카테고리 블럭 없음). 한투처럼 `#`/`##`가 있으면 heading_1/heading_2 + qna 블럭들.

> 정책 (A): FAQ가 아닌 일반 문서(마크다운이라도)는 **이 경로를 타지 않고** gemma 경로로 처리된다. 따라서 "일반 마크다운 결정적 매핑"은 본 스펙 범위가 아니다(추후 일반 문서 온보딩 시 별도 검토).

**근거 (원본 docx 로컬 검증 완료)**:
- 한투: `#`1(제목) / `##`22(카테고리) / `###`95(질문, 전부 `Q.`접두). 3단계.
- 다이소 상품권: `#`0 / `##`0 / `###`29(질문, `Q.`접두 0, `?`끝 18). 1단계.
- 다이소 매장문의: `###`14(`?`끝 13), 주문결제: `###`70(`?`끝 56).
- → 다이소는 `?` 없는 질문(예 "…연장하고 싶어요.")이 다수라 **패턴(`?`)만으론 놓침**. "가장 깊은 레벨 L 전체 = 질문" 규칙이 한투·다이소 모두를 일관·견고하게 처리(레벨 L 다수가 질문형이면 L 전체를 질문으로).

### 5.2 aicm-service 라운드트립 (chunk_endpoint.py)

세그멘터가 깨끗한 블럭(qna: qna_title+답변 content / heading: 헤딩+단락)을 주면 라운드트립은 대부분 현행 유지로 동작한다. 정합 보장 사항:
- `_blocks_to_outline`: `qna` 블럭(또는 `qna_title` 보유) → qna 섹션(title=qna_title, 답변 블럭 1개). `heading_*` 블럭 → heading 섹션. content에 마커가 없으므로 마크다운-경로 분해 휴리스틱에 의존하지 않는다(레거시 문서 대비용으로만 유지).
- `_outline_to_blocks`: qna 섹션 → 1 qna 블럭(`content`=답변, `metadata.qna_title`=제목), 제목 블럭 미생성. heading 섹션 → heading 블럭 + 단락 블럭들.
- **QnA 답변 단일 단락 보장**: qna 섹션에 단락이 2개 이상 들어오면(레거시/예외) `content`로 합쳐 1블럭으로 직렬화.
- content에 질문/마커 중복이 생기지 않도록 보장(불변식 검증 테스트).

> 비고: 2026-06-18 배포된 마크다운-경로 qna 임시수정(`_QNA_Q_RE`)은 본 설계에 포섭된다(레거시 Scenario A 문서 대비). 세그멘터가 정상화되면 신규 문서에선 트리거되지 않는다.

### 5.3 aicm-web 편집기 (documentDetail)

- **수동 섹션 추가 UI**: "질문 추가(QnA)" / "제목·목차 추가(일반)"로 분리 → 각각 `title_block_type="qna"` / `"heading_N"` 설정. (자동판별은 기본값 제안용으로만: 제목이 질문형이면 "질문" 기본 선택.)
- **QnA 섹션**: "단락 추가" 미노출. 제목(=질문) 1개 + 답변(content) 1개만 편집. 답변은 멀티라인/리스트 허용.
- **일반 섹션**: 단락 추가/수정/삭제 모두 제공(현행).
- 저장 게이트(2026-06-18 배포분): 블럭 미변경 시 `saveEditor` skip 유지.

## 6. 기존 문서 마이그레이션

- 이미 저장된 깨진 문서(한투 qna+마커, 다이소 heading_3/2)는 **재처리** 필요.
  - 방법 A: `POST /documents/{id}/retry?from_stage=blocking`(parse 캐시 재사용) → 새 세그멘터로 재생성.
  - 방법 B: 재업로드.
- 주의: KMS 직접 retry는 AICM과 status desync 가능(메모리 blockverifier-qna-overmerge) → 재처리 후 AICM에서 반려→재승인으로 active 동기화 확인.

## 7. 엣지/에러 처리

- **마크다운 구조 오탐**: 일반 문서에 우연히 `#`가 소수 등장 → 임계치 N + 헤딩 분포로 방지. 미달 시 gemma 경로.
- **질문 레벨 모호**: 패턴 보강(§5.1)으로 확정. 그래도 불명확하면 해당 헤딩을 일반 heading으로(분리), 데이터 손실 없음.
- **답변 없는 질문(헤딩만)**: `content` 빈 qna → 유지하되 임베딩 0 방지 가드 대상(메모리 embed-zero-vector). 정책: 빈 답변 qna는 경고 로그 + 보존(편집으로 답변 추가 가능).
- **`[분류] …` 라인**: 답변 메타성 정보 → content 선두에 보존(현행 표시와 일치). `---` 구분선: content에서 제거.
- **혼합 문서**: 섹션별 타입으로 자연 처리(같은 문서에 heading 섹션 + qna 섹션 공존).

## 8. 테스트

**단위(우선)**
- 세그멘터: 한투/다이소 샘플 텍스트 → 기대 블럭(heading_1 제목, heading_2 카테고리, qna 블럭들 with qna_title=질문·content=답변·마커없음).
- 라운드트립(aicm-service `test_outline_blocks_roundtrip`): qna 항등·멱등, content 마커/질문 중복 없음, 일반 문서 heading+단락 보존, QnA 단락 합치기.

**E2E(gemma 서버 필요)**
- 한투·다이소 재업로드 → block_type 분포(qna 다수, 답변 헤딩 오분류 0), content에 `##`/`###` 없음.
- 검색: 질문(원문/유사)으로 검색 → 답변 보유 청크 매칭.
- 편집: QnA 제목·답변 수정 후 저장 → 분리 없음, 미변경 저장 시 재인덱싱 없음. 일반 문서 단락 추가/삭제 정상.

## 10. 결정 사항 / 잔여

**해결·결정 완료**
1. ✅ **다이소 원본 마크다운 구조 확인**(2026-06-18): 다이소는 `###` 한 레벨만(상품권 29 / 매장문의 14 / 주문결제 70), `Q.`접두 없음, `?`도 일부만. 한투는 `#`/`##`/`###` 3단계. → 레벨 기반 확정.
2. ✅ **질문 레벨 자동 판정**: **가장 깊은 헤딩 레벨 L**을 질문 레벨로. 레벨 L 헤딩의 다수가 질문형(`?`/`Q.`/의문 어미)이면 FAQ로 판정하고 L **전체**를 질문(qna)으로. 개별 헤딩의 `?` 유무에 의존하지 않음(다이소 평서형 질문 포착).
3. ✅ **카테고리(`##`) 표현**: 독립 `heading_2` 블럭 + 하위 qna에 `heading_path` 전파(둘 다). 다이소는 `##`가 없어 무관, 한투에만 적용. (검색 기여도는 추후 측정해 조정 가능.)
4. ✅ **수동 편집 타입 자동제안**: 제목이 질문형(`?`끝 / `Q.`·`질문:`·`문:` 접두 / 의문 어미)이면 "질문(QnA)" 기본 선택 제안, 아니면 "제목". 사용자 오버라이드 우선.

**잔여(구현 중 결정)**
- 마크다운 구조 감지 임계치 N(헤딩 라인 최소 개수)·헤딩 분포 기준의 구체 수치 — 샘플 9종으로 튜닝.
- 의문 어미 사전(`나요`/`까요`/`ㄴ가요`/`싶어요`/`하나요`/`인가요` …)의 최종 목록 — FAQ 판정 다수결에만 쓰이므로 보수적으로.

## 11. 성공 기준

1. 한투·다이소 재업로드 시 모든 질문이 `qna` 블럭(질문=qna_title, 답변=content, 마커 없음)으로 생성된다.
2. 질문 텍스트로 검색하면 답변이 포함된 청크가 매칭된다(질문-only 청크 0).
3. 편집화면에서 수정 없이 저장해도 질문/답변이 분리되지 않고, 재인덱싱이 발생하지 않는다.
4. 일반(비FAQ) 문서는 기존과 동일하게 제목+단락 구조로 처리되고 단락 편집이 가능하다.
5. 라운드트립 단위테스트(항등·멱등·불변식)와 E2E 검색/편집 시나리오가 통과한다.
