### A-2. `build.bat` 이 WebRTC 를 강제함 (실제로는 불필요)

```bat
if not exist "%WEBRTC_LIB_DIR%\webrtc.lib" (
    echo ERROR: WebRTC library not found
    exit /b 1
)
```

그러나 CMake 옵션 기본값은 `OFF` 이고, 코드에는 NLMS AEC 폴백이 구현되어 있습니다.

`AudioHelper.cpp:669`
```cpp
#ifdef WEBRTC_APM_AVAILABLE
    aecBackend = std::make_unique<WebRtcAecBackend>(...);
#else
    aecBackend = std::make_unique<NlmsAecBackend>(...);   // 폴백 존재
#endif
```

**CMake 를 직접 호출하면 WebRTC 없이 빌드됩니다.**

**영향**: 불필요한 진입 장벽 (첫날 시간 낭비 요인)
**권장 조치**: `build.bat` 을 "WebRTC 있으면 사용, 없으면 NLMS 로 진행" 으로 수정

---

### A-3. `CMakeLists.txt` 가 쓰지도 않는 라이브러리를 인터넷에서 받음

```cmake
include(FetchContent)
FetchContent_Declare(json URL https://github.com/nlohmann/json/releases/download/v3.11.2/json.tar.xz)
FetchContent_MakeAvailable(json)
```

**`nlohmann/json` 은 코드 어디에서도 include 되지 않습니다.**
실제로는 벤더링된 `simple_json.hpp` (`using json = SimpleJson`) 를 씁니다.
같은 폴더의 960KB짜리 `json.hpp` 도 미사용입니다.

**영향**: 사내망/오프라인 환경에서 configure 단계 실패
**권장 조치**: FetchContent 블록 + `nlohmann_json::nlohmann_json` 링크 제거

---

### A-4. `form-data` 가 선언되지 않은 의존성

`src/main/main.js:3`
```js
const FormData = require("form-data");
```

`package.json` 의 dependencies:
```json
"axios", "better-sqlite3", "dotenv", "electron-log", "uuid"
```

**`form-data` 가 없습니다.** 현재는 `axios` 가 `form-data ^4.0.4` 를 전이 의존성으로
끌어오고 패키지 매니저가 루트로 호이스팅해주기 때문에 **우연히** 동작합니다.

**영향**: 패키지 매니저/호이스팅 정책이 바뀌면 즉시 `Cannot find module 'form-data'`
**권장 조치**: `npm install form-data` 로 명시적 선언

---

### A-5. `better-sqlite3` 네이티브 모듈 리빌드 미자동화

`better-sqlite3@12.4.1` + `electron@38` 조합입니다. 확인 결과:
- `package.json` 에 `postinstall` 스크립트 **없음**
- `electron-rebuild` 는 devDependencies 에만 존재하고 **호출하는 곳 없음**
- `.npmrc` **없음** (`runtime=electron` 설정 없음)

**영향**: `npm install` 후 실행 시 ABI 불일치 에러 가능
```
Error: The module '...better_sqlite3.node' was compiled against a different Node.js version
```
**대응**: `npx electron-rebuild -f -w better-sqlite3`
**권장 조치**: `"postinstall": "electron-rebuild"` 추가 검토

### A-10. `appId` 가 플레이스홀더인 채로 남아 있음

```json
"appId": "com.example.timblo-rec-app"
```

`com.example.*` 은 예제용 도메인입니다. Windows 에서는 설치 식별자/레지스트리 키에,
macOS 에서는 번들 ID(공증 대상)에 사용됩니다.

**영향**: 당장 동작은 하지만, 정식 배포 식별자로 부적절.
`afterSign.js` 의 notarize 호출에도 이 값이 하드코딩되어 있습니다.
**권장 조치**: 사내 도메인 기준으로 변경 (예: `io.timblo.recorder`)
> ⚠️ 변경 시 기존 설치본과 다른 앱으로 인식되므로 배포 전에 확정할 것

## B. 일반 품질 이슈

### B-1. ★ macOS 헬퍼 소스가 저장소에 없음

```
src/helpers/macos/AudioHelper -> /Users/jangjunho/dev/electron-recording-mac/src/helpers/macos/AudioHelper
```

**심볼릭 링크**입니다. 즉 **정식 배포 중인 macOS 플랫폼의 핵심 오디오 엔진 소스가
특정 개발자 PC 에만 존재**합니다.

Windows 작업에는 영향이 없지만, 프로젝트 전체로 보면 가장 심각한 리스크입니다.
(거꾸로 말하면, **Windows 는 소스가 전부 저장소에 있어서 상황이 훨씬 낫습니다.**)

**권장 조치**: 원 개발자로부터 Swift 소스 회수 후 저장소 편입

---

### B-2. `serverUpload` 가 Promise 를 반환하지 않음

`main.js:494` 의 `async function serverUpload(data)` 안에서
`main.js:632` 의 `axios.post(...)` 에 **`return` 이 없습니다.**

```js
async function serverUpload(data) {
  try {
    ...
    axios.post(url, form, {...})      // ← return 없음
      .then((res) => { ... return { success: true, ... }; })
      .catch((err) => { ... return { success: false, ... }; })
  } catch (error) { ... }
}
```

함수는 axios 완료 전에 `undefined` 로 반환됩니다.

**영향**:
- `ipcMain.handle('server-upload')` 가 업로드 완료를 await 할 수 없음
- **`retry-server-uploads` 의 `Promise.allSettled(tasks)` 가 실제 완료를 기다리지 않음**
- 따라서 "배치 완료 후 알림 큐 flush" 로직이 의도대로 동작하지 않을 수 있음

단건 업로드는 팝업/이벤트 기반으로 UI 를 갱신하므로 겉보기엔 동작합니다.

**권장 조치**: `return axios.post(...)` 또는 async/await 로 재작성
**우선순위**: 다건 재시도를 실제로 쓴다면 **높음**

---

### B-3. 토큰이 메모리에만 존재

`main.js` 의 `let token;` — 영속화되지 않습니다.
`endpoint` 도 딥링크 `host` 파라미터로만 설정되며 초기값은 빈 문자열(`let endpoint = ''`)입니다.

**영향**:
- 앱을 재시작할 때마다 재인증 필요
- 인증 전 상태에서 업로드하면 URL 이 `/api/contents/...` 로 깨짐

**권장 조치**: `safeStorage` 등으로 토큰/엔드포인트 영속화

### B-5. 재시도 업로드 동시성 무제한

`retry-server-uploads` 가 항목 수만큼 업로드를 한꺼번에 띄우고
`Promise.allSettled` 로 기다립니다. 제한이 없습니다.
(코드 주석에도 "무제한 병렬: 즉시 시작" 이라고 적혀 있습니다)

**권장 조치**: 동시성 3~5 제한
