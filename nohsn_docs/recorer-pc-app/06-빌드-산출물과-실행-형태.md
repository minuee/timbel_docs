# 06. 빌드 산출물과 실행 형태

> "이 소스를 빌드하면 실제로 어떤 앱이 나오는가?" 에 대한 답.
> Windows 11 의 Edge 와 비교하며 정리합니다.

---

## 한 줄 답

**네, 진짜 설치형 Windows 데스크톱 앱이 나옵니다.**

Edge 와의 비교는 생각보다 정확합니다 — **Electron 은 Chromium 엔진 그 자체**라,
Edge 와 같은 렌더링 엔진을 통째로 품고 있고 화면을 HTML/CSS 로 그리는 것도 동일합니다.

다만 **생김새와 배포 방식은 Edge 와 꽤 다릅니다.**

---

## 1. 빌드 산출물

```bat
npm run build
```

```
dist\
├── timbloRecApp Setup 1.0.0.exe     ← NSIS 설치 마법사 (배포용)
└── win-unpacked\                     ← 설치 없이 바로 실행 가능한 형태
    ├── timbloRecApp.exe              ← 실행 파일
    ├── resources\
    │   └── app.asar                  ← JS/HTML/CSS 번들
    └── helpers\
        └── windows\
            └── AudioHelper.exe       ← 네이티브 오디오 엔진
```

관련 설정 (`package.json`):

| 키 | 값 | 의미 |
|---|---|---|
| `productName` | `timbloRecApp` | 실행 파일명 · 설치본 이름 |
| `appId` | `com.example.timblo-rec-app` | ⚠️ `com.example` 그대로 — 배포 전 변경 권장 |
| `win.target` | `nsis` | NSIS 설치본 |
| `win.icon` | `electron-resources/logo.ico` | 앱 아이콘 |
| `nsis.oneClick` | `false` | 원클릭이 아닌 **설치 마법사** |
| `nsis.allowToChangeInstallationDirectory` | `true` | 설치 경로 변경 가능 |

### 설치 시 동작

- "다음 > 다음 > 설치" 형태의 일반적인 마법사
- 설치 경로 선택 가능
- 시작 메뉴 / 바탕화면 바로가기 생성 (electron-builder 기본 동작)
- `timbloRecApp://` 커스텀 프로토콜 등록 → 웹에서 딥링크로 앱 기동 가능

## 2. 실행했을 때의 모습 — Edge 와 다른 점

| 항목 | Edge | timbloRecApp |
|---|---|---|
| 창 크기 | 큰 브라우저 창 | **380 × 436** 작은 창 |
| 타이틀바 | 있음 | **없음** (`frame: false`) |
| 최소화 / 닫기 버튼 | Windows 기본 | **HTML 로 직접 그린 커스텀 버튼** |
| 작업표시줄 | 표시 | 표시 (`skipTaskbar: false`) |
| 트레이 아이콘 | 없음 | **있음** — 우클릭 시 `Open` / `Quit` |
| 항상 위 고정 | 없음 | **있음** (AOT 토글) |

`src/main/main.js:310`
```js
mainWindow = new BrowserWindow({
  width: 380,
  height: 436,
  frame: false,        // ← Windows 기본 타이틀바 없음
  movable: true,
  skipTaskbar: false,  // ← 작업표시줄에는 표시
  icon: ...logo_big.png
});
```

즉 브라우저 창이라기보다 **화면에 떠 있는 작은 유틸리티 위젯**에 가깝습니다.
항상 위 고정 기능이 있는 것도 "회의 중 화면 구석에 띄워두고 쓰는" 용도로 설계됐기 때문입니다.

### 창 구성 (총 4종)

| 창 | 특성 |
|---|---|
| main | 380×436, frameless. index(장치선택) ↔ recordingWindow 전환 |
| popup | alwaysOnTop. 업로드 진행률 / 확인 다이얼로그 |
| uploadList | frameless. 업로드 큐 목록 + 재시도 |
| summarize | alwaysOnTop. 언어/발화자 선택 |

창 크기는 `setWindowConstraints` IPC 로 렌더러가 화면 전환마다 동적으로 조정합니다.

## 3. 작업 관리자에서 보이는 모습

Edge 를 열면 프로세스가 여러 개 보이는 것과 **같은 이유로** 이 앱도 여러 개로 뜹니다.
(Chromium 의 멀티 프로세스 구조)

```
timbloRecApp.exe        메인 프로세스
timbloRecApp.exe        렌더러 (창마다 1개)
timbloRecApp.exe        GPU / 유틸리티
AudioHelper.exe         ← 이 앱 고유. 실제 녹음 담당
```

> 💡 **디버깅 팁**
> `AudioHelper.exe` 가 목록에 **없으면 헬퍼 기동 실패**입니다.
> 내일 문제가 생기면 작업 관리자가 1차 확인 수단이 됩니다.
> 그 다음은 `%APPDATA%\timbloRecApp\logs\` 의 `helper_start` 로그에서
> `helperPath` 와 `helperExists` 를 확인하세요.

## 4. 종료 동작

| 경로 | 동작 |
|---|---|
| 창 닫기 버튼 | 해당 창만 닫음 (`win.close()`) |
| 모든 창이 닫힘 | **Windows 에서는 앱 완전 종료** (`app.quit()`) |
| 트레이 → Quit | 앱 완전 종료 |
| 앱 종료 시 | `audioHelper.stopHelper()` 로 `AudioHelper.exe` 도 함께 정리 |

`main.js:1374`
```js
app.on("window-all-closed", () => {
  if (audioHelper) audioHelper.stopHelper();
  if (process.platform !== "darwin") app.quit();   // Windows: 완전 종료
});
```

macOS 와 달리 **Windows 는 창을 다 닫으면 앱이 끝납니다.** (플랫폼 관례대로)

## 5. Edge 와 결정적으로 다른 3가지 ★

### 5-1. 코드 서명이 없습니다

Edge 는 Microsoft 가 서명한 앱이라 그냥 설치되지만, 이 앱은
설치 시 SmartScreen 이 **"알 수 없는 게시자"** 경고를 띄웁니다.

- "추가 정보" → "실행" 으로 넘길 수는 있음
- 사내 배포라도 동일하게 발생
- → [04번 문서 A-6](04-알려진-이슈.md) 참조. **인증서 발급에 리드타임이 있으니 미리 신청**

### 5-2. 자동 업데이트가 없습니다

`package.json`
```json
"publish": null
```

업데이트 서버 연동이 아예 빠져 있습니다.
Edge 처럼 알아서 최신 버전이 되지 않고,
**새 버전은 매번 설치 파일을 다시 배포하고 사용자가 직접 설치**해야 합니다.

사내 배포 방식을 정할 때 고려할 사항입니다. 선택지:
- 수동 배포 (현재 상태) — 사내 공유 폴더 / 메신저로 설치본 전달
- `electron-updater` + 사내 정적 서버 도입
- 사내 소프트웨어 배포 시스템(SCCM/Intune 등) 활용

### 5-3. 설치 용량이 큽니다

Chromium 을 통째로 포함하는 구조라 수백 MB 규모가 됩니다.
기능 대비 크게 느껴질 수 있지만 Electron 앱의 일반적인 특성입니다.
