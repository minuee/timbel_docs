## 0. 이 앱은 어떤 형태인가

**Electron 데스크톱 앱**입니다. React Native 로 비유하면:

| | React Native | 이 프로젝트 (Electron) |
|---|---|---|
| UI | JSX → 네이티브 뷰 | HTML/CSS/JS → Chromium (`src/renderer/`) |
| 로직 | JS 스레드 | Node.js 메인 프로세스 (`src/main/main.js`) |
| 네이티브 모듈 | Java/Kotlin, Swift/ObjC | **AudioHelper** (Swift / C++) |
| 브릿지 | Native Modules | **JSON over stdin/stdout** |
| 결과물 | `.apk` / `.ipa` | **`.dmg` / `.exe`** |

**스토어를 거치지 않습니다.** 심사·대기 없이 `.dmg` 파일을 직접 배포합니다.
대신 macOS 는 **Apple 공증(notarization)** 을 통과해야 사용자 맥에서 경고 없이 열립니다.

마이크·시스템 오디오는 JS 로 불가능해서 Swift 로 별도 프로세스(AudioHelper)를 띄우고
JSON 을 주고받습니다. 이 헬퍼가 앱 번들 안에 동봉되어 함께 배포됩니다.

## 1. 배포 전 체크리스트 ★

배포본을 **한 명에게라도 배포하기 전에** 아래를 반드시 확인하세요.

### ✅ 1-1. `appId` 확정 (2026-08-19 완료: `net.timbel.timblo.recapp`)

**두 군데를 같이 바꿔야 합니다.** 한 곳만 바꾸면 공증이 ID 불일치로 실패합니다.

```
package.json:35        "appId": "net.timbel.timblo.recapp"
scripts/afterSign.js:33  appBundleId: 'net.timbel.timblo.recapp'   ← 하드코딩. 잊기 쉬움
```

> ⚠️ **배포 후에는 바꾸지 마세요.** macOS 의 TCC 권한(마이크·화면 기록)은 번들 ID 에
> 귀속됩니다. 배포 후 변경하면 사용자 맥에서 ① 권한이 초기화되어 다시 프롬프트가 뜨고
> ② 시스템 설정에 유령 항목이 남고 ③ 별개 앱으로 나란히 설치됩니다.
> `appId` 는 Windows NSIS 설치 ID 로도 쓰이는 **플랫폼 공통 값**입니다.

### ✅ 1-2. `NSScreenCaptureUsageDescription` 추가 (2026-08-19 완료)

시스템 오디오 캡처가 ScreenCaptureKit 기반이라 **화면 기록 권한 설명 문구가 필수**입니다.
누락 시 배포본에서 시스템 오디오가 동작하지 않습니다.

```json
"extendInfo": {
  "NSMicrophoneUsageDescription": "이 앱은 회의 녹음을 위해 마이크 접근 권한이 필요합니다.",
  "NSSystemAdministrationUsageDescription": "시스템 오디오 녹음을 위해 권한이 필요합니다.",
  "NSScreenCaptureUsageDescription": "회의의 시스템 오디오를 녹음하기 위해 화면 기록 권한이 필요합니다."
}
```

검증:
```bash
/usr/libexec/PlistBuddy -c "Print :NSScreenCaptureUsageDescription" \
  dist/mac-arm64/timbloRecApp.app/Contents/Info.plist
```

### ✅ 1-3. Swift 소스 노출 차단 (2026-08-19 완료)

`build.files` 는 `.cpp`/`.h` 만 제외하고 `.swift`/`.xcodeproj` 는 제외하지 않습니다.
`find` 로는 안 보이는데, **`app.asar` 안에 들어가 있기 때문**입니다.

2026-08-19 빌드에서 실제 확인된 내용:
```
/src/helpers/macos/AudioHelper/AudioHelper/AudioHelper.swift
/src/helpers/macos/AudioHelper/AudioHelper/AudioHelperController.swift
/src/helpers/macos/AudioHelper/AudioHelper/FileLogger.swift
/src/helpers/macos/AudioHelper/AudioHelper/JSONModels.swift
/src/helpers/macos/AudioHelper/AudioHelper/SegmentManager.swift
/src/helpers/macos/AudioHelper/AudioHelper.xcodeproj/...
  └─ xcuserdata/jangjunho.xcuserdatad/     ← 퇴사자 계정명까지 포함
```

`asar` 는 암호화가 아니라 **단순 아카이브라 누구나 풀 수 있습니다.**

조치 — `package.json` `build.files` 에 추가:
```json
"!src/helpers/macos/AudioHelper/**"
```

검증:
```bash
npx @electron/asar list dist/mac-arm64/timbloRecApp.app/Contents/Resources/app.asar \
  | grep -E "\.swift$|xcodeproj"        # 아무것도 안 나와야 정상
```

## 2. macOS 배포

### 2-1. 준비물

**① Apple Developer Program (연 $99)** — TIMBEL 팀 `7H4827QYPR`

현재 이 맥북에는 **배포용 인증서가 없습니다.** 확인 방법:
```bash
security find-identity -v -p codesigning
```
`Developer ID Application` 이 보여야 합니다.
(2026-08-19 기준 `Apple Development: lena47@naver.com` 만 존재 → 배포 불가)

| 인증서 종류 | 용도 |
|---|---|
| Apple Development | 개발 중 로컬 실행 |
| **Developer ID Application** | **스토어 밖 배포 ← 필요한 것** |
| Apple Distribution | App Store 배포 (이 앱은 해당 없음) |

**② 헬퍼를 Developer ID 로 서명**

```bash
open src/helpers/macos/AudioHelper/AudioHelper.xcodeproj
```

Xcode 에서:
1. 왼쪽 트리 최상단 파란 아이콘 `AudioHelper` 클릭
2. **TARGETS ▸ AudioHelper** 선택 (PROJECT 아님 — PROJECT 를 고르면 Signing 탭이 안 보임)
3. **Signing & Capabilities** 탭
4. Team → `TIMBEL`, Signing Certificate → **Developer ID Application**
5. Release 빌드 후 `src/helpers/macos/AudioHelper.app` 위치에 배치

> `.xcodeproj` 는 실제로는 디렉터리인데 Finder 가 파일처럼 보여줍니다. 그대로 더블클릭하면 됩니다.
> `.swift` 파일을 직접 열면 프로젝트 트리가 없어 Signing 탭 자체가 나타나지 않습니다.

> ⚠️ **`afterPack.js` 의 ad-hoc 재서명 로직은 통째로 주석 처리되어 있습니다**(`afterPack.js:64-133`).
> 서명 상태를 확인만 하고 재서명하지 않으므로, **헬퍼는 미리 제대로 서명해 두어야 합니다.**
> ad-hoc 서명 상태로 빌드하면 공증이 실패합니다.

**③ 공증 환경변수**

```bash
export APPLE_ID="..."
export APPLE_APP_SPECIFIC_PASSWORD="xxxx-xxxx-xxxx-xxxx"   # appleid.apple.com 에서 발급
export APPLE_TEAM_ID="7H4827QYPR"
```

앱 암호는 Apple ID 계정 암호가 아니라 **앱 전용 암호**입니다. appleid.apple.com ▸ 로그인 및 보안 ▸ 앱 암호에서 발급합니다.

### 2-2. 빌드

```bash
npm run build
```

파이프라인:
```
npm run build (electron-builder)
 ├─ extraFiles  → AudioHelper.app 을 Contents/helpers/macos/ 에 동봉
 ├─ afterPack   → 헬퍼 서명 확인 + lsregister 로 timbloRecApp:// 프로토콜 등록
 ├─ codesign    → Developer ID + hardened runtime + entitlements.mac.plist
 ├─ afterSign   → Apple 공증 (5~15분)
 └─ dist/*.dmg  ← 사용자에게 줄 파일
```

산출물:
```
dist/timbloRecApp-1.0.0-arm64.dmg        ← 배포 파일
dist/timbloRecApp-1.0.0-arm64-mac.zip
dist/mac-arm64/timbloRecApp.app          ← 검증용 앱 번들
```

### 2-3. 공증을 건너뛰면 어떻게 되나

`afterSign.js:19` 는 환경변수가 없으면 **경고만 내고 통과**시킵니다(빌드는 성공).
그렇게 만든 `.dmg` 는 사용자 맥에서:

- **"확인되지 않은 개발자"** 경고가 뜨고
- 우클릭 ▸ 열기로 강제 실행해야 하며
- Gatekeeper 설정에 따라 아예 차단될 수 있습니다

사내 테스트용은 무방하지만 **일반 배포에는 부적합**합니다.

### 2-4. 배포

`.dmg` 를 사내 공유 드라이브나 다운로드 링크로 전달하면 끝입니다.
`publish: null` 이라 **자동 업데이트가 없으므로** 새 버전은 매번 수동 배포입니다.

### 2-5. 사용자 쪽 첫 실행

TCC 권한은 **헬퍼가 아니라 헬퍼를 실행한 부모 프로세스(=앱)** 에 귀속됩니다.

1. 녹음 시작 시 **마이크 권한** 프롬프트 → 허용
2. **화면 기록 및 시스템 오디오 녹음** 권한 → 허용 후 **앱 재시작 필수**
3. 시스템 설정 ▸ 개인정보 보호 및 보안 ▸ 화면 기록에서 앱이 체크되어 있는지 확인

## 3. Windows 배포

```bash
npm run build          # win 타깃은 nsis
```

```json
"win": { "target": "nsis", "icon": "electron-resources/logo.ico" },
"nsis": { "oneClick": false, "allowToChangeInstallationDirectory": true }
```

- `AudioHelper.exe` 가 `extraFiles` 로 동봉됩니다
- `oneClick: false` 라 설치 경로를 사용자가 고를 수 있는 일반 설치 마법사가 나옵니다
- macOS 와 달리 공증 절차가 없지만, **코드 서명 인증서가 없으면 SmartScreen 경고**가 뜹니다
- `npm run build-helper` 로 헬퍼를 먼저 빌드해야 합니다 (`src/helpers/windows/build.bat`)

상세는 [02. Windows 빌드 가이드](02-Windows-빌드-가이드.md) 참조.

## 5. 우선순위 주의

**이 배포 작업은 macOS 대상이고, 담당 업무는 Windows 이관입니다.**
Windows 랩탑을 받으면 [02번 문서](02-Windows-빌드-가이드.md) 로 즉시 전환하세요.
macOS 검증의 가치는 "정상 동작 기준점 확보" 에 있지, 그 자체가 목표가 아닙니다.

1-2 / 1-3 은 빌드 시점에만 작용하므로 **endpoint 확정 후 macOS 배포본을 만들 때 함께 처리해도 됩니다.**
단 그 전까지 **`.dmg` 를 아무에게도 배포하지 않는다는 전제**입니다.
