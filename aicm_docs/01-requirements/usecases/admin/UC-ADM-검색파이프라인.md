# 관리자 유즈케이스 — 검색/파이프라인

> 검색 엔진 설정, AI 검색 데이터(임베딩) 변환 모니터링, AI 프롬프트 관리를 다룬다.

**비즈니스 목표**:
- **상담사 검색 품질 향상**: 동의어·제외어·가중치 튜닝을 통해 상담사가 원하는 문서를 더 빠르고 정확하게 찾을 수 있도록 한다.
- **AI 답변 정확도 유지**: 임베딩 파이프라인의 안정적 운영과 프롬프트 최적화를 통해 AI 답변의 신뢰도를 지속적으로 관리한다.
- **검색 반영 지연 최소화**: 임베딩 변환 모니터링과 알림을 통해 문서 게시 후 AI 검색 반영까지의 지연을 조기에 인지하고 대응한다.

---

## UC-ADM-07: 검색 설정 관리

**사용자**: 운영 관리자 (검색 설정 관리 권한 필요)

> 이 기능은 사용자들이 문서를 검색할 때 더 정확한 결과를 얻을 수 있도록 검색 엔진의 동작 방식을 조정하는 관리 기능입니다. 여기서 변경한 설정은 UC-SCH-01(키워드 검색), UC-SCH-02(AI 답변 검색)의 검색 결과에 반영됩니다.

**사전 조건**:
- 사용자가 운영 관리자이며 검색 설정 관리 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 관리자가 검색 설정 화면에 접근한다.
2. **일반 키워드 검색 설정**을 관리한다 ([FD-SCH](../../features/FD-SCH-검색.md) §6.1):
   - **동의어 사전**: 같은 의미의 다른 단어를 묶어준다. (예: "해지" 검색 시 "해약"도 함께 검색)
   - **제외어 목록**: 의미 없는 단어를 검색에서 제외한다. (예: "의", "에서", "그리고" 등)
   - **검색 가중치**: 특정 영역(제목, 본문, 태그 등)에 검색 중요도를 다르게 부여한다. (예: 제목에 나온 단어를 더 높은 순위로)
   - **사용자 사전**: 한국어 단어 분석기가 올바르게 인식하지 못하는 전문 용어를 등록한다. (예: "마이데이터"를 하나의 단어로 인식하도록)
3. **AI 답변 검색 설정**을 관리한다 (AI 답변 검색이 활성화된 환경에서, [FD-SCH](../../features/FD-SCH-검색.md) §6.2):
   - **간편 모드** (기본): 프리셋 선택 방식으로 설정한다. (예: "정밀도 우선" — 관련성 높은 소수 문서만 참조, "재현율 우선" — 넓은 범위의 문서를 참조, "균형" — 정밀도와 재현율의 균형)
   - **상세 모드** (검색 설정 상세 조정 권한 필요): 개별 파라미터를 직접 조정한다.
     - **문서 분할 방식**: AI가 문서를 검색할 때 어떤 크기로 나누어 처리할지 설정한다. (예: 짧게 분할하면 정확도가 높아지지만 맥락을 놓칠 수 있고, 길게 분할하면 맥락은 살지만 정밀도가 떨어질 수 있음)
     - **검색 정밀도**: 참고할 문서 조각 수, 관련성 기준값, 키워드와 의미 검색 비중 등을 설정한다. (예: 의미 검색 비중을 높이면 정확한 단어가 없어도 뜻이 비슷한 문서를 더 많이 찾아줌)
     - **결과 재정렬**: 1차 검색 후 AI가 결과를 다시 정밀하게 순위를 매기는 설정을 조정한다 (재정렬 기능이 활성화된 환경에서). (예: 재정렬을 활성화하면 검색 품질이 올라가지만 응답 시간이 약간 증가함)
     - **AI 지시문 설정**: AI가 답변을 생성할 때 따르는 지시문(프롬프트)과 사용할 AI 모델을 설정한다. 프롬프트 상세 관리는 UC-ADM-10 참조.
4. **테스트**: 설정을 변경한 후 같은 검색어로 변경 전후 결과를 나란히 비교해본다 (테스트 환경이 활성화된 환경에서, [FD-SCH](../../features/FD-SCH-검색.md) §6.3).
5. **운영 반영**: 검증이 완료되면 설정 유형에 따라 운영에 반영한다.
   - **즉시 반영 항목**: 검색 가중치, 검색 정밀도 파라미터, 결과 재정렬 설정 — 저장 즉시 다음 검색부터 적용된다.
   - **인덱스 재구성 필요 항목**: 동의어 사전, 제외어 목록, 사용자 사전 변경 — 저장 후 검색 인덱스 재구성이 비동기로 진행된다. 재구성 중에도 기존 인덱스로 검색이 가능하며, 완료 시 자동 전환된다. 시스템이 예상 소요 시간을 표시한다.
   - **AI 검색 설정 변경**: 문서 분할 방식, AI 모델 변경 등 — 기존 임베딩은 유지하되 새로 게시되는 문서부터 변경된 설정이 적용된다. 전체 문서에 적용하려면 UC-ADM-09에서 대량 재변환을 트리거한다.

**대안 흐름**:
- **설정 롤백**: 이전에 적용했던 설정으로 되돌릴 수 있다. 변경 이력에서 원하는 시점의 설정을 선택하여 복원한다.
- **검색 품질 지표 대시보드**: 관리자가 검색 운영 현황을 종합적으로 파악할 수 있는 대시보드를 제공한다.
  - **검색 성공률**: 검색 결과가 1건 이상 반환된 검색의 비율 (기간별 추이 포함)
  - **무결과율**: 검색 결과가 0건인 검색의 비율과 해당 검색어 목록 — 콘텐츠 부족 영역을 식별하는 데 활용한다
  - **AI 답변 만족도**: AI 답변 검색에 대한 사용자 피드백(긍정/부정) 비율과 추이 (AI 답변 검색이 활성화된 환경에서)
  - **검색 응답 시간**: 평균·최대 검색 응답 시간과 시간대별 분포
  - **인기 검색어 순위**: 최근 기간별 상위 검색어 목록과 검색 빈도 추이
  - **동의어 미등록 검색어**: 검색 결과가 저조한 검색어 중 동의어 사전에 미등록된 항목을 자동 추출하여 관리자에게 등록을 제안한다
  - 지표가 설정된 기준(예: 무결과율 20% 초과, AI 답변 만족도 60% 미만)을 벗어나면 관리자에게 알림이 발송된다
- **A/B 비교 테스트**: 서로 다른 설정 조합(A와 B)을 지정하여 동일 검색어에 대한 결과를 나란히 비교한다.
  1. 관리자가 테스트 대상 설정 항목(가중치, 동의어, AI 검색 파라미터 등)에 대해 A안과 B안을 구성한다.
  2. 실제 사용자 검색 로그 상위 N개 쿼리를 자동 실행하여 A/B 각각의 결과를 산출한다.
  3. 시스템이 결과 비교 보고서를 생성한다 — 쿼리별 결과 순위 변동, 평균 관련성 점수 차이, 무결과 쿼리 수 변화를 포함한다.
  4. 관리자가 보고서를 검토하여 더 나은 설정을 운영에 적용하거나, 추가 조정 후 재테스트한다.
- **사전 일괄 등록/내보내기**: 동의어 사전, 제외어 목록, 사용자 사전을 CSV 파일로 일괄 등록하거나 기존 데이터를 내보낼 수 있다.
  1. 관리자가 "일괄 등록" 버튼을 클릭하고 CSV 파일을 업로드한다.
  2. 시스템이 파일 형식을 검증하고 중복 항목을 감지하여 미리보기를 표시한다.
  3. 관리자가 중복 처리 방식(건너뛰기 / 덮어쓰기)을 선택한다.
  4. 시스템이 등록 결과 요약(성공 N건, 건너뛰기 N건, 오류 N건)을 표시한다.
  5. 등록 완료 후 인덱스 재구성이 필요하면 비동기로 시작된다.
- **검색 장애 시 수동 안내 모드**: 검색 엔진에 장애가 발생하여 정상 검색이 불가능한 경우, 관리자가 "검색 일시 중단 안내"를 활성화할 수 있다. 활성화되면 검색 화면에 "현재 검색 서비스 점검 중입니다. 게시판 목록에서 직접 탐색하시거나, 관리자에게 문의해 주세요"라는 안내가 표시된다. 장애 복구 후 관리자가 안내를 해제하면 정상 검색이 재개된다.
- **긴급 검색 제외 처리**: 보안 사고, 법적 조치, 민감 정보 유출 등의 긴급 상황에서 관리자가 특정 문서 또는 특정 게시판의 전체 문서를 검색 결과에서 즉시 제외할 수 있다.
  1. 관리자가 "긴급 검색 제외"를 선택하고 대상(개별 문서 / 특정 게시판)과 제외 사유를 입력한다.
  2. 시스템이 해당 문서를 키워드 검색과 AI 답변 검색 결과에서 모두 즉시 제외한다.
  3. 긴급 제외된 문서는 별도 목록에서 관리되며, 제외 사유와 제외 시각이 표시된다.
  4. 조치가 완료되면 관리자가 "검색 복원"을 실행하여 문서를 검색 결과에 다시 포함시킨다.
  5. 긴급 제외/복원 이력이 감사 로그에 기록된다.
- **정기 검색 품질 점검**: 시스템이 설정된 주기(예: 월 1회)마다 검색 품질 지표(검색 결과 없음 비율, 동의어 사전 미등록 검색어, AI 답변 실패율 추이)를 관리자에게 보고한다. 관리자가 보고를 검토하여 동의어 추가, 가중치 조정, 사용자 사전 갱신 등 개선 조치를 수행한다.
- **인수인계용 검색 설정 문서화**: 관리자 교체 시, 현재 검색 설정 전체(동의어 사전, 제외어, 가중치, AI 검색 파라미터)를 하나의 보고서로 내보낼 수 있다. 변경 이력과 현재 적용 중인 값이 함께 포함되어 인수인계 자료로 활용한다.
- **설정 변경 영향도 예측**: 검색 설정(가중치, 동의어 등)을 변경하기 전에, 최근 N일간의 실제 검색 쿼리 상위 목록에 대해 변경 전후 결과 차이를 자동 시뮬레이션하여 관리자에게 보여준다. 예상 영향이 큰 경우(결과 순위가 크게 변동하는 쿼리 비율이 높은 경우) 경고를 표시한다.

**예외 흐름**:
- **동의어/제외어 충돌 감지**: 동의어로 등록한 단어가 이미 제외어 목록에 있거나, 동의어 간 순환 참조(A→B, B→C, C→A)가 발생하면 시스템이 경고를 표시하고 등록을 차단한다. 관리자가 충돌을 해결한 후 재등록한다.
- **인덱스 재구성 실패**: 인덱스 재구성 중 오류가 발생하면 기존 인덱스를 유지하고 관리자에게 실패 알림을 발송한다. 관리자가 재구성을 다시 시도하거나, 설정을 롤백한다.
- **극단적 가중치 설정 방지**: 특정 영역의 가중치를 극단적으로 설정하면(예: 제목 100%, 나머지 0%) 시스템이 경고를 표시한다. 관리자가 확인 후 적용하거나 조정한다.

**사후 조건**:
- 감사 로그에 검색 설정 변경 기록이 남는다.
- 동의어/제외어/사용자 사전 변경 시 검색 인덱스 재구성이 비동기로 진행된다.
- 인덱스 재구성 완료 시 관리자에게 알림이 발송된다.
- 검색 품질 지표가 설정된 기준을 벗어나면 관리자에게 알림이 발송되며, 대시보드에서 상세 내역을 확인할 수 있다.
- A/B 비교 테스트 결과 보고서가 보관되어 설정 변경 근거 자료로 활용할 수 있다.
- 긴급 검색 제외/복원 실행 시 감사 로그에 기록되며, 제외 대상 문서 목록이 별도 관리된다.

**제약 사항**:
- AI 답변 검색 관련 설정은 AI 답변 검색이 활성화된 환경에서만 표시된다.
- 키워드와 의미 검색 비중 조정은 하이브리드 검색이 활성화된 경우에만 가능하다.
- 결과 재정렬 설정은 재정렬 기능이 활성화된 경우에만 조정 가능하다.
- 테스트 환경은 시스템 설정에 따라 제공되지 않을 수 있다.
- 검색 설정 편집 시 낙관적 동시성 제어를 적용한다 — 다른 관리자가 같은 설정을 먼저 변경한 경우, 저장 시 충돌 안내와 함께 최신 값을 확인하도록 한다.

## UC-ADM-09: AI 검색 데이터 변환 현황 모니터링

**사용자**: 운영 관리자 (AI 검색 데이터 변환 모니터링 권한 필요)

> **AI 검색 데이터 변환(임베딩)이란?** 문서를 AI가 이해할 수 있는 형태로 변환하는 과정입니다. 이 변환이 완료되어야 해당 문서가 AI 답변 검색에 반영됩니다. 변환이 지연되면 상담사가 최신 문서를 AI 검색으로 찾지 못하게 되어 상담 품질에 직접적으로 영향을 미칩니다.

**사전 조건**:
- 사용자가 운영 관리자이며 AI 검색 데이터 변환 모니터링 권한을 보유하고 있어야 한다.
- 모니터링 대시보드가 시스템에서 활성화되어 있어야 한다.

**기본 흐름**:
1. 관리자가 AI 검색 데이터 변환 현황 대시보드에 접근한다 ([FD-EMB](../../features/FD-EMB-임베딩파이프라인.md) §1.5).
2. 변환 대기열의 현재 상태(대기 중 / 처리 중 / 완료 / 실패 / 부분 완료)를 실시간으로 확인한다.
3. 특정 문서의 변환 상태를 개별적으로 조회할 수 있다 — 문서 제목이나 ID로 검색하여 해당 문서의 변환 진행 상태, 마지막 처리 시각, 실패 사유 등을 확인한다.
4. 실패한 항목의 실패 원인을 확인하고, 필요하면 수동으로 재시도를 실행한다.
5. 대량 변환(예: 공통 컨텐츠 수정으로 인한 다수 문서 재변환, AI 모델 변경으로 인한 전체 재변환 등) 시 진행률을 모니터링한다.
6. 평균 처리 시간, 대기열 밀림 정도, 처리 워커 수 등 성능 지표를 확인한다 ([FD-SCH](../../features/FD-SCH-검색.md) §6.4).

**대안 흐름**:
- **대량 재변환 트리거**: AI 모델이 변경되거나 문서 분할 방식이 변경된 경우, 전체 문서 또는 특정 게시판 문서의 재변환을 수동으로 시작할 수 있다.
  - 트리거 시 시스템이 예상 소요 시간과 현재 동시 처리 워커 수(UC-ADM-15에서 설정)를 표시한다.
  - 관리자가 확인 후 실행하면 비동기로 재변환이 진행된다.
- **AI 모델 교체 시 단계적 전환**: AI 검색용 모델을 교체할 때, 전체 문서를 한꺼번에 재변환하지 않고 단계적으로 전환하는 절차를 지원한다.
  1. 관리자가 새 모델을 등록하고, 시범 적용 게시판(소규모)을 지정한다.
  2. 시스템이 시범 게시판의 문서를 새 모델로 재변환한다. 기존 모델의 변환 데이터도 병행 보존된다.
  3. 관리자가 시범 게시판에서 검색 품질을 확인한다 — 동일 검색어에 대해 기존 모델과 새 모델의 결과를 비교할 수 있다.
  4. 시범 결과가 만족스러우면 관리자가 전환 범위를 확대(게시판 단위 또는 전체)한다.
  5. 전체 전환이 완료되면 기존 모델의 변환 데이터를 정리한다.
  6. 전환 중 문제가 발생하면 관리자가 기존 모델로 즉시 롤백할 수 있다 — 기존 변환 데이터가 보존되어 있으므로 롤백이 즉시 적용된다.
- **워커 수 확인**: 현재 동시 처리 워커 수와 재시도 횟수를 확인할 수 있다. 워커 수 임시 증감을 포함한 값 변경은 UC-ADM-15(시스템 운영 설정)에서 수행한다.
- **임계치 초과 알림**: 대기열 적체량이나 실패율이 설정된 임계치(UC-ADM-15에서 설정)를 초과하면 시스템이 관리자에게 알림을 자동 발송한다.
  - **대기열 밀림 알림**: 대기 중 건수 또는 평균 대기 시간이 임계치를 넘으면 운영 관리자에게 알림을 보낸다. (예: "변환 대기 문서가 500건을 초과했습니다")
  - **실패율 에스컬레이션**: 일정 기간 내 실패율이 임계치를 넘으면 상위 관리자 또는 시스템 관리자에게 에스컬레이션 알림을 보낸다. (예: "최근 1시간 변환 실패율이 10%를 초과했습니다")
  - 관리자는 대시보드에서 알림 이력과 현재 임계치 상태를 확인할 수 있다.
- **반복 실패 문서 자동 격리**: 최대 재시도 횟수를 초과하여 반복적으로 실패하는 문서는 자동으로 격리 목록(Dead Letter Queue)으로 이동한다.
  - 격리된 문서 목록을 별도 탭에서 확인할 수 있다. 실패 사유와 재시도 이력이 함께 표시된다.
  - 관리자가 격리 문서에 대해 수동 재시도, 원본 문서 확인, 변환 제외 처리 중 하나를 선택한다.
  - 격리 발생 시 관리자에게 알림이 발송된다.
- **장애 대체 운영 — 수동 우선순위 조정**: AI 서비스 부분 장애나 처리 지연이 발생한 경우, 관리자가 특정 게시판의 문서를 우선 처리하도록 대기열 우선순위를 수동으로 조정할 수 있다. 예: 상담 긴급 공지 게시판의 문서를 최우선으로 변환 처리한다.
- **정기 점검 시 변환 일시 중지**: 시스템 유지보수 모드가 활성화되면, 새로운 변환 작업 등록을 일시 중지하고 현재 처리 중인 작업만 완료한다. 유지보수 종료 후 대기 중이던 작업이 자동으로 재개된다.
- **용량 계획 기반 리소스 조정**: 관리자가 변환 대기열의 증가 추세를 확인하고, 시스템이 예상 적체 시점을 자동 산출하여 표시한다. 적체가 예상되면 관리자에게 사전 알림을 보내 시스템 운영 설정(ADM-15)에서 동시 처리 작업 수 증가를 검토하도록 안내한다.
- **정기 변환 상태 보고서**: 시스템이 설정된 주기(예: 주 1회)마다 변환 처리 현황(성공률, 평균 처리 시간, 격리 건수, 재시도 횟수 분포)을 보고서로 생성하여 관리자에게 전달한다. 운영 추이를 파악하고 개선 계획을 수립하는 데 활용한다.

**예외 흐름**:
- **대량 재변환 중 시스템 부하 초과**: 재변환 진행 중 시스템 부하가 임계치를 초과하면, 시스템이 자동으로 처리 속도를 조절(쓰로틀링)한다. 관리자에게 부하 초과 알림과 예상 지연 시간을 안내한다.
- **대량 재변환 중복 요청**: 대량 재변환이 진행 중인 상태에서 추가 재변환 요청이 들어오면, 시스템이 기존 작업 진행 상태를 안내하고 새 요청을 대기열에 추가할지 확인한다.
- **외부 AI 모델 서비스 장애**: AI 모델 서비스에 연결할 수 없는 경우 새로운 변환 작업을 일시 중지하고, 관리자에게 장애 알림을 발송한다. 서비스 복구 후 중단된 작업을 자동으로 재개한다.
- **재변환 대상 문서 수정/삭제**: 재변환이 진행 중인 문서가 수정되면 현재 변환을 완료한 후 수정된 내용으로 재변환을 다시 예약한다. 삭제된 문서는 변환 대기열에서 자동 제거된다.

**사후 조건**:
- 수동 재시도 실행 시 감사 로그에 기록된다.
- 대량 재변환 트리거 시 감사 로그에 기록된다.
- 격리 문서에 대한 관리자 조치 시 감사 로그에 기록된다.

**제약 사항**:
- 모니터링 대시보드가 비활성화된 환경에서는 접근할 수 없다.
- 최대 재시도 횟수를 초과한 항목은 격리 목록으로 자동 이동되며, 이후에는 수동 재시도만 가능하다.
- 임계치 값은 UC-ADM-15(시스템 운영 설정)에서 설정하며, 기본값이 제공된다.

## UC-ADM-10: AI 프롬프트 관리

**사용자**: AICM 관리자, 운영 관리자 (AI 설정 관리 권한 필요)

> **프롬프트(지시문)란?** AI에게 "이런 방식으로 응답해 줘"라고 알려주는 설정 텍스트이다. 예를 들어, "답변은 항상 존댓말로 하고, 출처를 명시해 줘"와 같은 지시를 설정할 수 있다.
>
> AI 기능(요약, 글쓰기 개선, RAG 답변 등)에 사용되는 프롬프트를 단일 관리화면에서 관리한다. 프롬프트의 저장, 버전 관리, 테스트, 롤백을 이 화면에서 완결적으로 처리한다 ([FD-AI](../../features/FD-AI-AI어시스턴트.md) §3).

**사전 조건**:
- 사용자가 관리자급 사용자(AICM 관리자 또는 운영 관리자)이며 AI 설정 관리 권한을 보유하고 있어야 한다.
- AI 관련 기능(요약, 글쓰기 개선 중 하나 이상)이 시스템에서 활성화되어 있어야 한다.

**기본 흐름**:
1. 관리자가 AI 프롬프트 설정 화면에 접근한다.
2. AI 기능(요약, 글쓰기 개선, RAG 답변 등)을 선택하면 해당 기능의 프롬프트 슬롯 목록이 표시된다 ([FD-AI](../../features/FD-AI-AI어시스턴트.md) §3.3).
3. 슬롯을 선택하면 현재 적용 중인 프롬프트가 표시된다.
4. 관리자는 권한 범위 내에서 프롬프트를 편집한다.
   - **AICM 관리자**: 전체 프롬프트 조회 및 편집 가능
   - **운영 관리자**: 운영 권한이 부여된 프롬프트만 조회 및 편집 가능
5. 샘플 텍스트로 테스트하여 결과를 확인한다. 여러 샘플에 대해 일괄 테스트하여 결과를 비교할 수 있다.
6. 만족스러우면 저장한다.
7. 저장 즉시 해당 테넌트의 모든 사용자에게 반영된다 — 이미 진행 중인 AI 요청에는 영향을 주지 않으며 저장 이후의 새 요청부터 적용된다.

**대안 흐름**:
- **프롬프트 버전 이력 조회/롤백**: 슬롯별 변경 이력(변경자, 시각, 변경 전/후 내용)에서 원하는 버전을 선택하여 프롬프트를 복원한다.
- **프롬프트 초기화**: 입력한 프롬프트를 비우면 기본 설정값으로 동작한다.
- **AI 사용 통계 조회**: 기능별 사용 빈도, 적용률, 사용자 피드백(긍정/부정 비율), 테넌트별 토큰 사용량/비용을 확인할 수 있다 ([FD-AI](../../features/FD-AI-AI어시스턴트.md) §4). 프롬프트 버전별 성과 비교(적용률, 피드백 점수)도 가능하다.
- **신규 슬롯 추가**: 새 AI 기능 도입 시 슬롯을 추가 등록한다.
- **AI 서비스 장애 시 대체 안내**: AI 서비스에 장애가 발생하여 AI 기능(요약, 글쓰기 개선, RAG 답변)을 사용할 수 없는 경우, 관리자가 사용자에게 표시할 대체 안내 메시지("현재 AI 기능 점검 중입니다. 키워드 검색을 이용해 주세요" 등)를 설정할 수 있다. 장애 복구 후 대체 안내가 자동으로 해제된다.
- **신규 서비스 프롬프트 일괄 세팅**: 새 AI 기능을 도입할 때, 관리자가 기존 프롬프트 구성을 참고하여 복수의 슬롯(시스템 지시문, 사용자 안내 등)을 한 번에 등록하고 일괄 테스트할 수 있다.
- **정기 프롬프트 효과성 검토**: 시스템이 설정된 주기(예: 월 1회)마다 프롬프트별 성과 지표(사용 빈도, 사용자 긍정/부정 피드백 비율, 평균 응답 시간)를 보고서로 생성한다. 관리자가 보고서를 검토하여 프롬프트 개선이 필요한 슬롯을 식별하고 조정한다.

**예외 흐름**:
- **프롬프트 길이 초과**: 프롬프트가 AI 모델의 컨텍스트 윈도우 한도를 초과하면 저장 시 경고를 표시하고, 관리자가 축소하거나 확인 후 저장한다. 한도 초과 프롬프트는 실행 시 잘림이 발생할 수 있음을 안내한다.
- **프롬프트 안전성 검사**: 프롬프트에 시스템 안전을 위협할 수 있는 패턴(프롬프트 인젝션 시도 등)이 감지되면 경고를 표시한다. 관리자가 내용을 확인하고 수정하거나 확인 후 저장한다.
- **AI 모델 연결 실패**: 테스트 실행 시 AI 모델 서비스에 연결할 수 없는 경우 "AI 서비스에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요" 안내를 표시한다. 프롬프트 편집과 저장은 테스트 없이도 가능하다.

**사후 조건**:
- 감사 로그에 `prompt.updated` 이벤트가 기록된다.
- 변경된 프롬프트는 저장 즉시 해당 테넌트의 모든 사용자에게 반영된다.
- 프롬프트 변경 이력(변경자, 시각, 변경 전/후 내용)이 보존된다.

**제약 사항**:
- 프롬프트 수정은 관리자급 사용자에게만 허용된다.
- AI 요약 관련 슬롯은 AI 요약 기능이 활성화된 경우에만 표시된다.
- AI 글쓰기 개선 관련 슬롯은 AI 글쓰기 개선 기능이 활성화된 경우에만 표시된다.
