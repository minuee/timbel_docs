# 관리자 유즈케이스 — 시스템 운영

> 감사 로그, 통계, 신고 처리, 접근 제한, 시스템 설정, 위젯 카탈로그 등 시스템 운영 전반을 다룬다.

**비즈니스 목표**:
- **규제 준수 리스크 해소**: 변경 불가능한 감사 로그를 통해 컴플라이언스 감사에 대응하고, 미준수 시 과태료·영업정지 위험을 사전에 방지한다.
- **운영 의사결정 지원**: 통계 대시보드를 통해 콘텐츠 전략 수립, 운영 병목 파악, 인력 배치 등 데이터 기반 의사결정을 지원한다.
- **서비스 품질 보호**: 신고 처리와 접근 제한을 통해 부적절한 콘텐츠로부터 서비스 품질을 보호하고, 민감 정보 유출을 방지한다.
- **운영 안정성 확보**: 시스템 설정의 변경 확인·감사 기록을 통해 잘못된 설정 변경으로 인한 서비스 장애 비용을 최소화한다.

**이 문서의 범위**: 운영 관리자가 수행하는 시스템 운영 기능만 다룬다. 인프라 관리(서버, 배포, 네트워크)는 시스템 관리자 담당이며 이 UC 범위에 포함되지 않는다. 시스템 헬스 모니터링(서비스 상태, 응답시간, 에러율 등)은 UC-ADM-18에서 별도로 다룬다.

## UC-ADM-08: 감사 로그 조회/내보내기

**사용자**: 운영 관리자 (감사 로그 조회 권한 필요)
**관련 FD**: FD-AUD | **관련 UC**: [UC-ADM-15](#uc-adm-15-시스템-운영-설정-관리) (감사 로그 활성 조회 기간 설정)

> **감사 로그란?** 시스템에서 일어나는 모든 주요 활동을 자동으로 기록한 이력입니다. "누가, 언제, 무엇을 했는지"를 추적할 수 있으며, 규정 준수 감사(컴플라이언스)에 대응하는 데 활용됩니다.

**사전 조건**:
- 사용자가 운영 관리자이며 감사 로그 조회 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 관리자가 감사 로그 조회 화면에 접근한다.
2. 조건(기간, 수행자, 행동 유형, 대상 문서 등)으로 필터링하고 검색하여 이력을 조회한다.
3. CSV(엑셀 호환) 또는 JSON(데이터 형식) 파일로 내보내기하여 외부 감사 검토에 대응한다.

**기록되는 감사 로그 종류**:
- **문서 변경 로그**: 문서 생성, 수정, 삭제, 상태 변경, 긴급 회수, 예약 배포 등
- **승인 이력**: 승인 요청, 승인, 반려, 철회, 긴급 발행 등
- **권한 변경 로그**: 역할 부여/변경/해제, 그룹 구성원 변경, 게시판 접근 권한 변경 등
- **관리자 활동 로그**: 게시판, 문서 양식, 승인 정책, 검색 설정, 시스템 설정 등의 변경 내역
- **인증 로그**: 로그인/로그아웃, 비정상 접근 시도 등
- **접근 제한 로그**: 운영 관리자가 접근 제한 문서를 열람한 기록

**대안 흐름**:
- **이상 패턴 알림**: 엄격 감사 모드가 활성화된 경우, 비정상 접근 패턴(예: 단시간 대량 문서 조회, 권한 변경 반복)이 감지되면 관리자에게 알림이 발송된다. 엄격 감사 모드란 감사 추적을 강화하기 위한 운영 모드로, [UC-ADM-15](#uc-adm-15-시스템-운영-설정-관리) 시스템 설정에서 활성화할 수 있다.
- **상세 검색**: 특정 문서의 전체 변경 이력을 시간순으로 추적하거나, 특정 사용자의 모든 활동을 조회할 수 있다.
- **아카이브 조회**: 활성 조회 기간이 지난 감사 로그는 아카이브 뷰에서 조회할 수 있다. 아카이브 데이터는 검색 속도가 느릴 수 있으나 내용은 동일하게 보존된다.
- **정기 감사 대응 패키지**: 외부 감사(예: 금융감독원 정기 검사)에 대응할 때, 관리자가 감사 기간·대상 범위를 지정하면 시스템이 해당 기간의 감사 로그, 권한 변경 이력, 접근 제한 열람 기록 등을 하나의 압축 파일로 묶어 내보낸다. 외부 감사인에게 전달할 수 있도록 민감 정보(개인 식별 정보 등)를 마스킹하는 옵션을 제공한다.
- **스토리지 사용량 안내**: 감사 로그 저장 공간이 시스템이 정한 기준치에 도달하면, 관리자에게 스토리지 사용량 경고 알림이 발송된다. 관리자는 활성 조회 기간을 조정하여 아카이브 이관 시점을 앞당기거나, 시스템 관리자에게 저장 공간 증설을 요청할 수 있다.
- **감사 로그 자동 보고서 생성**: 관리자가 보고 주기(주간/월간)와 포함할 로그 유형을 설정하면, 시스템이 해당 주기마다 감사 로그 요약 보고서를 자동 생성하여 지정된 수신자에게 전달한다.
  - 보고서에는 기간 내 주요 활동 요약(문서 변경 건수, 권한 변경 건수, 승인 처리 건수), 이상 패턴 감지 건수, 접근 제한 열람 건수가 포함된다.
  - 직전 주기 대비 변동이 큰 항목(예: 권한 변경 건수 급증)이 강조 표시된다.
  - 관리자가 보고서를 검토하여 추가 점검이 필요한 항목을 식별하고 조치한다.
  - 경영진 보고, 컴플라이언스 검토, 운영 현황 파악에 활용한다.
- **규제 감사 사전 대비 알림**: 관리자가 정기 감사 일정(예: 금융감독원 정기 검사)을 시스템에 등록하면, 감사 N일 전에 시스템이 자동으로 감사 대응 패키지 준비 상태를 점검한다. 필수 데이터(감사 기간 내 로그 보관 여부, 아카이브 무결성)를 검증하고, 이상이 있으면 관리자에게 사전 경고를 발송한다.
- **감사 로그 분석 도구**: 대규모 환경에서 감사 로그가 수백만 건에 달할 때, 관리자가 특정 패턴(비정상 접근 빈도, 권한 변경 집중 시기, 특정 사용자의 활동 추이)을 분석할 수 있는 도구를 제공한다. 분석 결과를 시각화(시간대별 분포, 사용자별 히트맵 등)하여 표시한다.

**예외 흐름**:
- **대량 내보내기 타임아웃**: 내보내기 대상이 시스템이 정한 건수를 초과하면 즉시 다운로드 대신 백그라운드 처리로 전환된다. 처리가 완료되면 관리자에게 알림이 발송되며, 다운로드 링크가 일정 기간 제공된다. 건수가 매우 많은 경우 파일이 자동으로 분할된다.
- **아카이브 데이터 조회 지연**: 아카이브에 보관된 대량의 과거 데이터를 조회할 때 응답이 느려지면, 시스템이 예상 소요 시간을 안내하고 조건(기간, 행동 유형 등)을 좁혀서 재검색하도록 권장한다. 조건을 좁혀도 응답이 지연되면 백그라운드 조회로 전환하여 결과를 알림으로 전달한다.

**사후 조건**:
- 내보내기 수행 시 "감사 로그 내보내기" 자체도 감사 로그에 기록된다.
- 정기 감사 대응 패키지를 내보낸 경우, 내보내기 범위(기간·대상)와 마스킹 적용 여부가 감사 로그에 함께 기록된다.
- 활성 조회 기간이 지난 데이터는 삭제되지 않고 아카이브로 자동 이관되어 보존된다.

**제약 사항**:
- 감사 로그는 시스템에서 영구 보존되며 삭제할 수 없다 — 추가만 가능하다.
- 감사 로그 활성 조회 기간은 시스템 설정([UC-ADM-15](#uc-adm-15-시스템-운영-설정-관리))에서 지정한다. 활성 조회 기간이 지난 데이터는 삭제되지 않고 아카이브로 이관되어 아카이브 뷰에서 조회할 수 있다. 관리자는 활성 조회 기간을 늘릴 수 있으나, 시스템이 정한 최소 기간 이하로 줄일 수는 없다.
- 감사 로그 조회 권한은 조회와 내보내기만 허용하며, 감사 로그 설정 변경은 시스템 운영 설정 권한이 필요하다.

## UC-ADM-11: 통계 대시보드 조회

**사용자**: 운영 관리자 (통계 조회 권한 필요)
**관련 FD**: FD-AGG | **관련 UC**: UC-ADM-18 (시스템 상태 확인)

**사전 조건**:
- 사용자가 운영 관리자이며 통계 조회 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 관리자가 통계 대시보드에 접근한다.
2. 조회 기간(일별/주별/월별)과 범위(전체/특정 게시판)를 선택한다.
3. 다음과 같은 집계 데이터를 확인한다:

   **콘텐츠 통계**:
   - **문서 현황**: 일별/주별 문서 등록 수, 활성 사용자 수
   - **인기 문서 순위**: 조회수, 좋아요, 댓글 수를 기준으로 한 인기 문서 목록
   - **트렌딩 문서**: 최근 급격히 조회가 늘어난 문서
   - **검색 트렌드**: 많이 검색된 키워드, 검색했지만 결과가 없었던 키워드 (콘텐츠 부족 파악에 활용)
   - **AI 답변 검색 현황**: AI 답변 생성 건수, 평균 답변 품질, 사용자 피드백 (AI 답변 검색이 활성화된 환경에서)
   - **게시판별 통계**: 게시판마다 문서 수, 활성 사용자 수, 게시판 구조별 집계

   **운영 KPI**:
   - **승인 처리 현황**: 승인 대기 평균 소요시간, 현재 승인 대기 건수, 승인/반려 비율
   - **검색 품질**: 검색 결과 없음 비율, AI 답변 실패율
   - **게시판별 문서 회전율**: 신규 등록 대비 만료/삭제 비율

> 시스템 상태(서비스 헬스, 응답시간, 에러율 등) 확인은 UC-ADM-18(시스템 헬스 모니터링)을 참조한다.

**대안 흐름**:
- **데이터 내보내기**: 통계 데이터를 CSV 파일로 내보내어 외부 분석 도구에서 활용할 수 있다.
- **기간 비교**: 두 기간의 통계를 나란히 비교하여 추이를 파악할 수 있다. (예: 이번 달 vs 지난 달)
- **이상값 자동 감지 및 상세 알림**: 통계 지표가 평소 범위를 크게 벗어나면 시스템이 관리자에게 상세 알림을 발송한다.
  - 감지 대상: 검색 결과 없음 비율 급등, 특정 게시판 조회수 급감/급등, 승인 대기 건수 폭증, 문서 등록량 급변, AI 답변 실패율 상승 등
  - 알림에는 이상 지표명, 현재 값, 평소 평균값, 변동 폭이 포함되며, 해당 지표 상세 화면으로 바로 이동하는 링크가 제공된다.
  - 관리자가 이상값 감지 임계치(예: 평소 대비 N배 이상 변동 시 알림)를 지표별로 조정할 수 있다.
  - 이상값이 감지되면 관련 기간의 감사 로그와 교차 확인하여 원인 파악에 참고할 수 있는 연관 이벤트(예: 설정 변경, 대규모 문서 이관)를 함께 표시한다.
- **정기 보고서 자동 생성**: 관리자가 보고 주기(주간/월간)와 포함할 지표를 설정하면, 시스템이 해당 주기마다 자동으로 보고서를 생성하여 지정된 수신자에게 전달한다. 경영진 보고, KPI 리뷰 등에 활용할 수 있다.
- **집계 데이터 수동 갱신**: 관리자가 최신 데이터를 즉시 확인해야 할 경우, 집계 데이터를 수동으로 갱신 요청할 수 있다. 갱신에는 시간이 소요될 수 있으며, 완료되면 알림으로 안내한다.
- **용량 계획 연계 지표**: 통계 대시보드에서 스토리지 사용량 추이, 동시접속자 추이, AI 사용량 추이를 확인하고, 시스템이 예상 소진 시점을 자동 산출하여 표시한다. 예상 소진 시점이 설정된 기간(예: 30일) 이내이면 관리자에게 사전 알림을 보낸다.
- **운영 인수인계용 KPI 현황 내보내기**: 관리자 교체 시, 현재 운영 중인 주요 KPI(승인 처리 현황, 검색 품질, 게시판별 활성도, 문서 회전율)의 최근 추이를 하나의 보고서로 내보낼 수 있다. 인수인계 자료로 활용하여 신임 관리자가 운영 현황을 빠르게 파악한다.
- **정기 운영 업무 체크리스트**: 관리자가 반복적으로 수행해야 하는 운영 점검 항목을 체크리스트로 관리한다.
  - **일간 점검**: 승인 대기 건수 확인, 신고 접수 현황 확인, AI 검색 데이터 변환 상태 확인, 검색 품질 이상 여부 확인
  - **주간 점검**: 통계 대시보드 KPI 추이 검토, 감사 로그 이상 패턴 확인, 미사용 게시판/양식/태그 점검
  - **월간 점검**: 권한 감사(미사용 권한, 과잉 권한), 스토리지 사용량 추이 확인, 승인 정책 효과성 검토, 통계 보고서 생성 및 배포
  - 시스템이 각 주기에 맞춰 체크리스트를 관리자에게 안내하며, 점검 완료 여부를 기록한다. 미완료 항목이 있으면 리마인더를 발송한다.
  - 체크리스트 항목은 관리자가 조직 상황에 맞게 추가·수정·비활성할 수 있다.
- **비상 연락 체계 및 에스컬레이션 정책 설정**: 관리자가 운영 비상 상황별 연락 체계를 시스템에 등록하고 관리한다.
  - 비상 상황 유형별(보안 사고, 서비스 장애, 데이터 오류, 규제 이슈) 연락 담당자와 연락 방법을 등록한다.
  - 에스컬레이션 단계(1차 담당자 → 2차 상위 관리자 → 3차 경영진)와 각 단계의 대기 시간을 설정한다.
  - 근무 시간대와 비근무 시간대(야간, 주말, 공휴일)별로 서로 다른 연락 체계를 설정할 수 있다.
  - 시스템이 정기적으로(예: 분기 1회) 비상 연락 체계 갱신 알림을 관리자에게 보내, 담당자 변경이나 연락처 변경을 반영하도록 한다.
  - 비상 연락 체계 등록/변경 이력이 감사 로그에 기록된다.

**예외 흐름**:
- **집계 지연**: 통계 데이터 갱신이 지연되는 경우, 대시보드에 "마지막 갱신 시각"을 표시하여 데이터의 최신성을 관리자가 판단할 수 있도록 한다. 갱신 지연이 시스템이 정한 시간을 초과하면 관리자에게 알림이 발송된다.
- **통계 데이터 불일치**: 동일 지표의 집계 결과가 서로 다른 화면에서 다르게 표시되는 경우(예: 문서 현황의 총 문서 수와 게시판별 합산 문서 수 불일치), 시스템이 불일치를 감지하여 관리자에게 안내하고 재집계를 권장한다.

**사후 조건**:
- 통계 데이터 내보내기 수행 시 감사 로그에 내보내기 기록(조회 기간, 범위)이 남는다.
- 정기 보고서 설정 변경 시 감사 로그에 설정 변경 기록이 남는다.
- 집계 데이터 수동 갱신 요청 시 감사 로그에 갱신 요청 기록이 남는다.
- 용량 계획 연계 지표의 예상 소진 알림이 발송되면 감사 로그에 알림 내역이 기록된다.
- 운영 인수인계용 KPI 보고서 내보내기 시 내보내기 범위와 수신자가 감사 로그에 기록된다.
- 감사 로그 자동 보고서 생성 시, 생성 이력과 수신자 목록이 감사 로그에 기록된다.
- 이상값 자동 감지 알림 발송 시, 감지된 지표와 이상 내용이 감사 로그에 기록된다.
- 정기 운영 체크리스트 완료/미완료 이력이 기록되어 운영 책임 추적에 활용할 수 있다.
- 비상 연락 체계 등록/변경 시 감사 로그에 기록되며, 정기 갱신 알림 이력도 보관된다.

**제약 사항**:
- 통계 데이터는 미리 계산된 집계 데이터를 기반으로 표시되므로 실시간이 아닐 수 있다 (예: 최대 1시간 전까지의 데이터가 표시됨).
- AI 답변 검색 현황은 AI 답변 검색이 활성화된 환경에서만 표시된다.
- 집계 데이터 수동 갱신은 시스템 부하를 고려하여 연속 갱신 간 최소 대기 시간이 적용된다.

## UC-ADM-12: 신고 처리

**사용자**: 운영 관리자 (게시판 관리 권한 필요)
**관련 FD**: FD-COM | **관련 UC**: [UC-COM-03](../user/UC-COM-커뮤니티.md#uc-com-03-문서-신고) (사용자 신고 접수)

**사전 조건**:
- 사용자가 운영 관리자이며 게시판 관리 권한을 보유하고 있어야 한다.
- 접수된 신고가 1건 이상 존재해야 한다.

**기본 흐름**:
1. 관리자가 신고 관리 화면에서 접수된 신고 목록을 조회한다. 각 신고에는 유형이 표시된다:

   | 신고 유형 | 설명 |
   |---------|------|
   | 스팸 | 광고성·홍보성 콘텐츠 |
   | 부적절 내용 | 욕설·비하·불쾌한 표현 등 |
   | 저작권 침해 | 타인의 저작물을 무단 사용 |
   | 오류 정보 | 잘못된 정보로 업무에 지장을 줄 수 있는 내용 |
   | 기타 | 위 유형에 해당하지 않는 신고 |

2. 신고 내용(신고 사유, 신고자, 신고 일시, 신고 유형)과 대상 문서 또는 댓글을 확인한다.
3. 신고 이력(같은 대상에 대한 이전 신고 건수, 같은 신고자의 신고 패턴)을 확인한다.
4. 관리자 재량으로 적절한 조치를 수행한다:
   - **삭제**: 대상 문서 또는 댓글을 삭제하고 신고를 "처리 완료"로 전환한다.
   - **신고 기각**: 문제가 없다고 판단하여 신고를 "기각"으로 전환한다.
   - **경고**: 대상 작성자에게 경고 알림을 발송하고 신고를 "처리 완료"로 전환한다.

**대안 흐름**:
- **자동 비공개 처리**: 같은 문서 또는 댓글에 대한 신고가 설정된 건수 이상 누적되면, 시스템이 자동으로 해당 콘텐츠를 비공개 처리하고 관리자에게 알린다.
- **일괄 처리**: 여러 신고 건을 선택하여 한 번에 처리(삭제/기각)할 수 있다. 같은 대상에 대한 복수의 신고를 묶어서 한 번에 조치할 수도 있다.
- **중복 신고 자동 병합**: 같은 대상에 대해 서로 다른 사용자가 접수한 신고가 여러 건이면, 시스템이 이를 하나의 묶음으로 그룹핑하여 관리자가 한 번에 검토할 수 있도록 한다. 각 신고의 사유와 유형은 개별적으로 확인 가능하되, 조치는 묶음 단위로 수행된다.
- **반복 신고자 관리**: 특정 사용자가 일정 기간 내에 기각된 신고를 반복적으로 접수하는 경우(예: 30일 내 기각 5건 이상), 시스템이 해당 사용자를 "주의 대상 신고자"로 표시하고 관리자에게 알린다. 관리자는 해당 사용자의 신고 이력을 검토하여 신고 기능 이용 제한 여부를 판단할 수 있다.
- **대량 신고 폭주 긴급 대응**: 단시간에 신고가 급증(예: 1시간 내 평소의 5배 이상)하면, 시스템이 관리자에게 긴급 알림을 발송하고 신고 현황 요약(신고 유형 분포, 대상 문서/게시판 집중도)을 제공한다. 관리자가 특정 게시판이나 문서에 신고가 집중된 경우, 해당 콘텐츠를 일괄 비공개 처리하고 사후 검토할 수 있다.
- **정기 신고 현황 보고**: 시스템이 설정된 주기(예: 월 1회)마다 신고 처리 현황(접수 건수, 처리율, 유형별 분포, 평균 처리 소요 시간)을 보고서로 생성하여 관리자에게 전달한다. 신고가 급증하는 게시판이나 콘텐츠 유형을 식별하여 사전 예방 조치에 활용한다.

**예외 흐름**:
- **신고 대상 이미 삭제**: 신고 대상 문서 또는 댓글이 이미 삭제된 경우, 시스템이 해당 신고를 "대상 삭제됨" 상태로 자동 전환하고 관리자에게 안내한다.
- **중복 신고 제한**: 동일 사용자가 같은 대상에 대해 이미 신고한 경우, 중복 신고는 접수되지 않는다.
- **신고 처리 중 대상 동시 삭제**: 관리자가 신고를 검토하는 동안 다른 관리자 또는 문서 작성자가 해당 문서를 삭제한 경우, 조치 버튼 클릭 시 "대상이 이미 삭제되었습니다"라는 안내와 함께 해당 신고를 "대상 삭제됨" 상태로 전환한다.

**사후 조건**:
- 감사 로그에 신고 처리(삭제/기각/경고) 기록이 남는다.
- 삭제 처리된 문서는 검색에서 제외된다.
- 신고 처리 결과는 신고자에게 알림으로 통보되지 않는다 (익명성 보호).
- 경고 조치 시 대상 작성자의 경고 이력이 누적되어 반복 위반 여부를 추적할 수 있다.
- 일괄 처리 시 각 건별 처리 결과가 개별적으로 감사 로그에 기록된다.

**제약 사항**:
- 신고는 게시판에 소속된 문서/댓글에 대해 접수되므로, 신고 처리에는 게시판 관리 권한이 필요하다.
- 피신고자(콘텐츠 작성자)의 항변/이의제기 절차는 포함하지 않는다 — 관리자 재량으로 처리한다.

## UC-ADM-13: 문서/블록 접근 제한 설정

**사용자**: 승인권자 (해당 게시판 승인 권한 보유자), 운영 관리자 (게시판 관리 권한 보유자)
**관련 FD**: FD-ACL | **관련 UC**: [UC-ADM-08](#uc-adm-08-감사-로그-조회내보내기) (접근 제한 열람 기록)

> **접근 제한이란?** 특정 문서나 문서의 일부 영역(블록)을 지정한 사람들만 볼 수 있도록 제한하는 기능입니다. 예를 들어, 민감한 고객 정보가 포함된 문서는 특정 팀원만 열람할 수 있도록 설정할 수 있습니다.

**사전 조건**:
- 문서 레벨 접근 제한 기능이 시스템에서 활성화되어 있어야 한다.
- 블록 단위 접근 제한은 블록 레벨 접근 제한 기능이 추가로 활성화되어 있어야 한다.
- 사용자가 해당 게시판의 승인 권한을 보유하거나, 운영 관리자이며 게시판 관리 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 사용자가 특정 문서 또는 문서 내 특정 블록의 "접근 제한" 설정에 진입한다.
2. 접근 제한을 활성화한다.
3. 접근을 허용할 대상과 허용할 행동을 지정한다:
   - **대상 유형**: 특정 사용자 또는 그룹
   - **허용 행동**: 열람 / 편집 / 승인
   - 그룹을 지정하면 해당 그룹의 활성 멤버 전원에게 지정된 행동이 허용된다.
4. 허용 목록에 포함되지 않은 사용자는 해당 문서나 블록에 접근할 수 없다.

**대안 흐름**:
- **접근 제한 해제**: 접근 제한을 비활성화하면 상위(게시판/문서) 권한이 그대로 상속된다.
- **운영 관리자 열람**: 운영 관리자는 접근이 제한된 문서도 열람할 수 있다 — 단, 이 접근은 감사 로그에 기록된다. 편집/승인은 허용 목록에 등록되어야 가능하다.
- **경고 표시**: 허용 목록에 등록된 사용자/그룹이 해당 게시판의 기본 접근 권한을 보유하지 않은 경우, 화면에서 경고를 표시한다 (게시판 기본 권한이 없으면 허용 목록에 있어도 접근 불가).
- **긴급 접근 제한**: 보안 사고(예: 민감 정보 유출 의심, 내부 감사 진행)가 발생한 경우, 운영 관리자가 여러 문서에 대해 한 번에 접근 제한을 설정할 수 있다. 긴급 접근 제한 시에는 사유를 필수로 입력하며, 설정 즉시 해당 문서들이 검색 결과에서 제외된다. 긴급 접근 제한 이력은 별도로 관리되어 사후 감사에 활용된다.
- **접근 제한 일괄 설정**: 같은 게시판 내 여러 문서에 동일한 접근 제한 조건을 한 번에 적용할 수 있다. 일괄 설정 시에도 건별 감사 로그가 기록된다.
- **규제 감사 대응 접근 제한 현황 보고**: 관리자가 접근 제한이 설정된 전체 문서 목록(문서명, 게시판, 제한 유형, 허용 대상, 설정일)을 보고서로 내보낼 수 있다. 외부 감사 시 민감 문서의 접근 통제 현황을 증빙하는 데 활용한다.
- **접근 제한 현황 대시보드**: 전체 시스템의 접근 제한 문서 수, 게시판별 제한 문서 분포, 최근 N일간 긴급 접근 제한 이력 등을 시각화하여 표시한다. 운영 관리자가 보안 현황을 한눈에 파악하고, 불필요한 접근 제한을 정리할 수 있다.

**예외 흐름**:
- **접근 제한 대상 간 권한 충돌**: 사용자가 직접 허용 목록에 등록되어 있으면서 동시에 소속 그룹이 다른 수준의 행동을 허용받는 경우(예: 사용자 개인은 열람만 허용, 소속 그룹은 편집까지 허용), 시스템이 충돌을 감지하여 관리자에게 경고를 표시한다. 이 경우 더 넓은 범위의 권한이 적용되며, 관리자가 의도에 맞게 조정할 수 있도록 안내한다.
- **허용 대상 삭제/비활성화**: 허용 목록에 등록된 사용자가 퇴사 처리되거나 그룹이 삭제된 경우, 시스템이 해당 항목을 "비활성 대상"으로 표시하고 관리자에게 허용 목록 갱신을 권장하는 알림을 발송한다. 비활성 대상은 접근이 자동으로 차단된다.

**사후 조건**:
- 감사 로그에 접근 제한 설정/해제/허용 목록 변경 기록이 남는다.
- 접근 제한이 설정된 문서는 허용되지 않은 사용자의 검색 결과에서 제외된다.
- 긴급 접근 제한이 설정된 경우, 해당 문서의 기존 열람 중인 세션에도 즉시 접근 차단이 반영된다.
- 접근 제한 설정 시 허용 목록에 포함된 대상의 수가 감사 로그에 함께 기록된다.

**제약 사항**:
- 접근 제한 기능이 비활성화된 환경에서는 모든 문서가 게시판 단위의 기본 권한만 따른다.
- 접근 제한은 게시판 기본 권한이 열어준 범위를 **축소**하는 것이다 — 게시판 기본 권한 없이 독립적으로 접근을 부여하지 않는다.
- 허용 목록에서 역할이 아닌 사용자/그룹을 사용하는 이유: 접근 제한은 "누구(실체)"를 지정하는 것이므로 개인과 조직 단위로 충분하며, 역할을 사용하면 간접 참조에 의한 의도치 않은 범위 확대 위험이 있다.

## UC-ADM-15: 시스템 운영 설정 관리

**사용자**: 운영 관리자 (시스템 운영 설정 권한 필요)
**관련 FD**: FD-SYS | **관련 UC**: [UC-ADM-08](#uc-adm-08-감사-로그-조회내보내기) (감사 로그 활성 조회 기간), [UC-ADM-11](#uc-adm-11-통계-대시보드-조회) (집계 가중치)

> **시스템 설정이란?** 서비스 전반의 운영 파라미터를 관리하는 기능입니다. 파일 업로드 제한, 알림 기준일수, 통계 가중치, 감사 로그 활성 조회 기간 등 운영 중에 조정이 필요한 값들을 관리자 화면에서 변경할 수 있습니다.

**사전 조건**:
- 사용자가 운영 관리자이며 시스템 운영 설정 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 관리자가 시스템 설정 화면에 접근한다.
2. 설정이 카테고리별로 그룹핑되어 표시된다. 관리자가 원하는 카테고리를 선택한다.
3. 다음과 같은 설정을 조정할 수 있다:

| 카테고리 | 설정 항목 | 설명 |
|---------|---------|------|
| 파일 | 파일 업로드 최대 크기 | 업로드 가능한 파일의 최대 크기 |
| 알림 | 임시 저장 방치 알림 기준 일수 | 임시 저장 문서 방치 시 알림을 보내는 기준 |
| 집계 | 인기 스코어 가중치 | 조회수/좋아요/댓글 수의 인기도 반영 비율 |
| 집계 | 트렌딩 증가율 기준값 | 트렌딩 문서 판정 기준이 되는 조회 증가율 |
| 집계 | 트렌딩 최소 조회수 | 트렌딩 대상이 되기 위한 최소 조회수 |
| 감사 | 감사 로그 활성 조회 기간 | 감사 로그를 활성 뷰에서 조회할 수 있는 기간. 기간 초과 데이터는 아카이브 뷰로 이관됨 (삭제되지 않음) |
| 내보내기 | 워터마크 텍스트 | 문서 내보내기 시 삽입되는 워터마크 문구 |
| AI 검색 | 동시 처리 작업 수 | AI 검색 데이터 변환을 동시에 처리하는 작업 수 |
| AI 검색 | 실패 최대 재시도 횟수 | 변환 실패 시 자동 재시도 최대 횟수 |

4. 값을 변경하면 **변경 확인 절차**를 거친다:
   - 시스템이 변경 내용(변경 전 값 → 변경 후 값)을 확인 화면에 표시한다.
   - 관리자가 변경 내용을 확인하고 최종 확인 버튼을 눌러야 적용된다.
5. 확인이 완료되면 변경된 설정이 적용된다.

**대안 흐름**:
- **변경 이력 조회**: 감사 로그에서 특정 설정 항목의 변경 이력(변경 전 값, 변경 후 값, 변경자, 변경 일시)을 확인할 수 있다.

**예외 흐름**:
- **설정 오류 영향 방지**: 서비스 전체에 큰 영향을 미칠 수 있는 설정(예: 파일 업로드 최대 크기를 0으로 설정, AI 검색 동시 처리 작업 수를 극단적으로 높게 설정)을 입력한 경우, 시스템이 "이 값은 서비스 운영에 심각한 영향을 줄 수 있습니다"라는 경고를 표시하고 관리자에게 재확인을 요구한다. 위험도가 매우 높은 설정은 이중 확인(한 번 더 확인 입력)을 거쳐야 적용된다.
- **유효 범위 초과 입력**: 설정값이 허용된 범위를 벗어난 경우(예: 음수, 상한 초과), 시스템이 허용 범위를 안내하고 저장을 차단한다. 감사 로그 활성 조회 기간처럼 하한선이 보호되는 설정은 최소값과 그 이유를 함께 안내한다.

**사후 조건**:
- 감사 로그에 설정 변경 기록(변경 전/후 값 포함)이 남는다.
- 변경 확인 절차를 거친 후 설정이 적용된다.
- 위험 설정 변경(이중 확인을 거친 경우) 시 감사 로그에 "위험 설정 변경"으로 별도 표기된다.

**제약 사항**:
- **감사 로그 활성 조회 기간의 하한선 보호**: 감사 로그 활성 조회 기간은 시스템이 정한 최소값 이하로 줄일 수 없다. 예를 들어 금융권 환경에서 최소값이 5년이면 이보다 짧게 설정할 수 없다. 늘리는 것은 자유롭게 가능하다. 활성 조회 기간이 지나더라도 감사 로그는 삭제되지 않으며 아카이브에서 조회 가능하다.
- 기능 존재 여부나 동작 모드에 해당하는 설정은 이 화면에서 변경할 수 없으며, 별도의 기능 활성화/비활성화 설정에 의해 제어된다.
- 시스템 운영 설정 권한은 위험도가 매우 높은 권한이다 — 잘못된 설정이 서비스 전체에 영향을 미칠 수 있으므로 최소 인원에게만 부여해야 한다.
- 인프라 관리(서버, 배포, 네트워크)는 시스템 관리자 담당이며 이 UC 범위에 포함되지 않는다.

## UC-ADM-17: 위젯 카탈로그 관리

**사용자**: 운영 관리자 (시스템 운영 설정 권한 필요)
**관련 FD**: FD-AGG | **관련 UC**: [UC-PER-05](../user/UC-PER-개인영역.md#uc-per-05-홈-대시보드-조회) (사용자 홈 대시보드)

> **위젯 카탈로그 관리란?** 홈 대시보드에서 제공할 위젯 종류와 노출 대상을 관리하는 기능입니다. 사용자의 개인 배치/표시 설정을 직접 수정하는 기능은 포함하지 않습니다.

**사전 조건**:
- 사용자가 운영 관리자이며 시스템 운영 설정 권한을 보유하고 있어야 한다.

**기본 흐름**:
1. 관리자가 위젯 카탈로그 관리 화면에 접근한다.
2. 시스템이 현재 제공 중인 위젯 목록(이름, 설명, 활성/비활성, 노출 대상 역할, 데이터 원천 유형, 기본 정렬 순서)을 표시한다.
3. 관리자가 위젯을 등록하거나 기존 위젯을 수정한다.
4. 관리자가 위젯별로 노출 대상 역할(일반 사용자/승인권자/관리자)과 기본 정렬 순서를 설정한다.
5. 관리자가 위젯의 활성/비활성 상태를 변경한다.
6. 시스템이 변경 사항을 저장하고 감사 로그에 기록한다.

**대안 흐름**:
- **비활성화 영향 안내**: 이미 개인 화면에 배치된 위젯을 비활성화하려고 하면, "해당 위젯은 사용자 화면에서 자동 숨김 처리됩니다" 안내와 함께 영향받는 사용자 수를 표시한다.
- **역할별 프리셋 조정**: 역할별 기본 위젯 구성을 함께 조정할 수 있다.
- **잘못된 구성 방지**: 모든 역할에서 비활성화되어 실제로 노출 대상이 없는 위젯 구성은 저장 전에 경고한다.
- **위젯 미리보기**: 위젯 등록 또는 수정 시, 실제 데이터를 기반으로 위젯이 사용자 화면에 어떻게 표시되는지 미리 확인할 수 있다. 역할별로 다른 화면이 노출되는 경우 각 역할의 미리보기를 전환하여 확인한다.
- **신규 서비스 오픈 위젯 세팅**: 새 서비스 출시 시, 서비스와 관련된 위젯(예: 해당 게시판 최신 문서, 서비스 관련 통계)을 한 번에 등록하고 대상 역할에 노출되도록 설정할 수 있다. 서비스 오픈 시점에 맞춰 위젯을 일괄 활성화한다.
- **정기 위젯 운영 점검**: 시스템이 설정된 주기(예: 분기 1회)마다 "사용률이 낮은 위젯(대다수 사용자가 숨김 처리한 위젯)", "데이터 원천 오류가 반복되는 위젯" 등을 관리자에게 보고한다. 관리자가 보고를 검토하여 위젯 정리 여부를 결정한다.

**예외 흐름**:
- **위젯 데이터 원천 오류**: 위젯이 참조하는 데이터 원천(예: 통계 집계, 인기 문서 목록)이 일시적으로 사용 불가능한 경우, 해당 위젯 영역에 "데이터를 불러올 수 없습니다. 잠시 후 다시 시도해주세요"라는 안내를 표시하고, 관리자에게 데이터 원천 오류 알림을 발송한다. 나머지 정상 위젯은 영향 없이 표시된다.
- **위젯 순환 참조 감지**: 위젯 구성 시 서로의 데이터를 참조하는 순환 관계(예: A 위젯이 B 위젯의 데이터를 참조하고, B가 다시 A를 참조)가 감지되면, 시스템이 "순환 참조가 발견되었습니다"라는 경고와 함께 저장을 차단하고 순환 경로를 안내한다.

**사후 조건**:
- 카탈로그 변경 결과가 즉시 홈 대시보드에 반영된다.
- 감사 로그에 카탈로그 변경 이력이 남는다.
- 비활성화된 위젯은 사용자의 개인 배치에서 자동으로 숨김 처리되며, 이후 해당 위젯이 다시 활성화되면 이전 배치 위치로 자동 복원된다.
- 위젯 등록/수정/삭제 시 변경 전후 상태(노출 대상, 정렬 순서 등)가 감사 로그에 기록된다.

**제약 사항**:
- 관리자는 위젯 카탈로그(제공 가능 위젯)만 관리하며, 특정 사용자의 개인 배치/표시 설정을 대리 변경할 수 없다.
- 개인 위젯 설정 변경은 사용자 본인이 [UC-PER-05](../user/UC-PER-개인영역.md#uc-per-05-홈-대시보드-조회)(홈 대시보드)에서 수행해야 한다.
