# Dozzle 오프라인 설치 가이드 (작성일: 2026-09-02)

인터넷이 차단된 사내 서버에 **Dozzle**(브라우저용 도커 컨테이너 로그 뷰어)을 단독 설치하기 위한 패키지와 절차.

- 대상: `npm install` / `docker pull` 이 불가능한 폐쇄망 서버
- 전제: 서버에 **docker + docker compose 가 이미 설치되어 있을 것** (그 외 의존성 없음)
- 백엔드 API(`asst-service-portal`) 소스와 **완전히 분리**된 독립 패키지

---

## 1. 왜 별도 패키지인가

기존 `docker-compose.monitor.yml` 은 이 저장소 안에서 돌던 구성이라 그대로 반출할 수 없다.

| 항목 | 기존 `docker-compose.monitor.yml` | 오프라인 패키지 |
|---|---|---|
| 이미지 획득 | `docker pull` (인터넷 필요) | 이미지 tar 동봉 → `docker load` |
| 이미지 태그 | `amir20/dozzle:latest` | **`v10.9.0` 고정** (재현성) |
| 네트워크 | `timbel_network` **external** 의존 | 의존 없음 (docker.sock 만 사용) |
| 백엔드 소스 | 같은 저장소에 존재 | **불필요** |
| 포트 설정 | compose 에 하드코딩 | `.env` 의 `DOZZLE_PORT` 한 곳 |

`timbel_network` 의존을 뺀 이유: Dozzle 은 도커 소켓만 읽으면 되고 다른 컨테이너와 통신하지 않는다.
외부 네트워크를 요구하면 그 네트워크가 없는 서버에서 `network timbel_network declared as external, but could not be found` 로 기동 자체가 실패한다.

---

## 2. 패키지 구성

배포물: **`dozzle-offline.tar.gz` (약 40MB)** — 이 파일 하나만 옮기면 된다.

```
dozzle-offline/
├── images/
│   ├── dozzle-v10.9.0-amd64.tar.gz   # x86_64 서버용 (21MB)
│   └── dozzle-v10.9.0-arm64.tar.gz   # ARM 서버용   (19MB)
├── monitor-data/users.yml            # 로그인 계정 (bcrypt)
├── docker-compose.yml
├── .env                              # DOZZLE_PORT=9999
├── install.sh                        # 이미지 load + 기동
├── uninstall.sh
└── README.md
```

> 이 패키지는 용량(40MB 바이너리) 때문에 `.gitignore` 처리되어 있다. 저장소에 커밋되지 않으므로
> **USB / 메신저 / scp 등으로 압축파일을 직접 전달**해야 한다.

### 이미지 획득 방식

작업 PC에 Docker 가 없어 `docker save` 를 쓸 수 없었으므로, Docker Hub 레지스트리 API 로
`amir20/dozzle:v10.9.0` 의 레이어를 직접 받아 `docker load` 형식 tar 로 조립했다.
각 레이어의 `diff_id` 를 원본 이미지 config 와 대조 검증했으므로 `docker save` 결과물과 내용이 동일하다.

amd64 / arm64 를 모두 담았고 `install.sh` 가 `uname -m` 으로 자동 판별하므로,
대상 서버 아키텍처를 미리 몰라도 된다.

## 3. 설치 절차

### 3-1. 반출 전 (작업 PC에서)

1. **포트 확인** — 대상 서버에서 쓸 포트를 `.env` 의 `DOZZLE_PORT` 에 맞춰 둔다. 현재 `9999` (→ 4절)
2. **계정 확인** — `monitor-data/users.yml` 의 기존 개발용 계정(ID `admin`)을 그대로 쓰기로 결정.
   교체가 필요해지면 5절 참고 (폐쇄망에서도 가능)
3. `dozzle-offline.tar.gz` 를 USB 등으로 복사

### 3-2. 서버에서

```bash
tar xzf dozzle-offline.tar.gz
cd dozzle-offline
./install.sh
```

`install.sh` 가 순서대로 수행하는 것:

| 단계 | 내용 | 실패 시 |
|---|---|---|
| 1 | `docker` / `docker compose` 존재·기동 확인 | 설치 안내 후 중단 |
| 2 | `uname -m` → amd64·arm64 판별, 해당 tar 만 `docker load` | 미지원 아키텍처면 중단 |
| 3 | `DOZZLE_PORT` 중복 점유 검사 (`ss`/`netstat`) | 포트 변경 안내 후 중단 |
| 4 | `docker compose up -d` | — |
| 5 | 3초 후 컨테이너 Running 여부 확인 | 컨테이너 로그 50줄 출력 후 중단 |

이미지가 이미 있으면 `load` 를 건너뛰므로 **재실행해도 안전**하다.

수동으로 하려면:

```bash
docker load -i images/dozzle-v10.9.0-amd64.tar.gz
docker compose up -d
```

### 3-3. 접속

```
http://<서버IP>:9999
```

**외부에서 접속할 때 쓰는 포트가 곧 `.env` 의 `DOZZLE_PORT` 값**이다 (현재 `9999`).
이 패키지는 호스트 포트와 컨테이너 리슨 포트를 같은 값으로 묶어두었으므로 그 한 줄만 보면 된다.

계정은 `monitor-data/users.yml` 에 정의된 값 (기본 ID `admin`).

## 4. 포트 변경

`.env` 한 줄만 고치고 재기동한다.

```bash
echo 'DOZZLE_PORT=8081' > .env
docker compose up -d --force-recreate
```

> **⚠️ Dozzle 은 `PORT` 환경변수를 읽지 않는다.** 리슨 주소는 `DOZZLE_ADDR`(기본 `:8080`)이다.
> 포트 매핑만 바꾸고 `DOZZLE_ADDR` 을 그대로 두면 컨테이너는 계속 8080 을 잡고 있어
> **매핑된 포트가 빈 포트가 되어 접속이 안 된다.** 이 패키지의 compose 는 `DOZZLE_PORT` 값을
> 포트 매핑과 `DOZZLE_ADDR` 양쪽에 동시에 주입하므로 `.env` 한 곳만 고치면 어긋날 일이 없다.

현재 기본값은 **9999** 로 잡아두었다.

> **참고:** 5F(124.194.32.36) 서버는 서비스앱 대역이 **62000~62999** 로 배정되어 있고,
> 기존 `docker-compose.monitor.yml` 은 그 대역의 62029 를 쓴다. 9999 는 대역 밖이므로
> **5F 에 올릴 경우** 포트 정책·방화벽에 걸릴 수 있다. 5F 라면 62029(또는 대역 내 다른 값)로,
> 대역 정책이 없는 다른 서버라면 9999 그대로 쓰면 된다. 어느 쪽이든 `.env` 한 줄만 고치면 된다.
> (참고: [2026-0729_5F-포트점유현황-및-회의포인트.md](./2026-0729_5F-포트점유현황-및-회의포인트.md))

또한 9999 는 여러 툴이 관례적으로 쓰는 흔한 포트라 충돌 가능성이 있다.
`install.sh` 가 기동 전에 점유 여부를 검사해 걸리면 중단하므로, 실패하면 다른 값으로 바꾸면 된다.

## 5. 계정 / 비밀번호

Dozzle v8+ 는 **bcrypt 만 지원**한다 (sha-256 폐기). 해시는 `dozzle generate` 로 만든다.

이미지를 `docker load` 한 뒤라면 **폐쇄망에서도 생성 가능**하다:

```bash
docker run --rm amir20/dozzle:v10.9.0 generate admin \
  --password '새비밀번호' --name admin --email you@example.com > monitor-data/users.yml
docker compose up -d --force-recreate
```

> **현 반출본:** 기존 개발용 계정(ID `admin`)을 그대로 사용한다. 비밀번호는 `users.yml` 주석에 평문으로 적혀 있으므로,
> 파일 자체가 곧 자격증명이다. **압축파일을 아무 데나 두거나 공용 채널로 돌리지 말 것.**
> 외부 노출이 우려되는 시점에는 위 명령으로 교체하면 된다 (교체 시 주석도 함께 정리).

## 6. 주의사항

| 항목 | 내용 |
|---|---|
| **조회 범위** | 해당 호스트에서 도는 **모든 컨테이너**의 로그가 보인다. 우리 앱만 보이는 게 아니다. |
| **범위 제한** | 특정 컨테이너만 노출하려면 `users.yml` 의 `filter` 사용 (예: `filter: "name=asst"`) |
| **권한** | 도커 소켓을 `:ro` 로 마운트 → 읽기 전용. 컨테이너 조작/삭제는 불가. |
| **소켓 노출 위험** | 그래도 도커 소켓 접근은 민감하다. **인증(`DOZZLE_AUTH_PROVIDER=simple`)을 끄지 말 것**, 그리고 해당 포트를 외부 인터넷에 직접 열지 말 것. |
| **방화벽** | 사내 방화벽에서 포트가 막혀 있으면 컨테이너가 정상이어도 접속이 안 된다. 개방 여부를 먼저 확인. |
| **docker 그룹** | `docker info` 실패 시 `sudo ./install.sh` 또는 `sudo usermod -aG docker $USER` 후 재로그인 |
| **앱 영향** | 기존 컨테이너/네트워크를 전혀 건드리지 않는다. `uninstall.sh` 도 dozzle 만 제거. |

## 7. 운영 명령

```bash
docker ps -f name=dozzle      # 상태 확인
docker logs -f dozzle         # dozzle 자체 로그
docker compose down           # 중지
./uninstall.sh                # 제거
./uninstall.sh --image        # 이미지까지 삭제
```

## 8. 트러블슈팅

| 증상 | 원인 / 조치 |
|---|---|
| `./install.sh: Permission denied` | Windows PC 를 경유해 옮기면 실행권한이 날아간다. `chmod +x install.sh uninstall.sh` 후 재실행 |
| 컨테이너는 Running 인데 접속 불가 | `DOZZLE_ADDR` 과 포트 매핑 불일치 (→ 4절). `docker exec dozzle netstat -ltn` 로 실제 리슨 포트 확인 |
| `port is already allocated` | 다른 서비스가 해당 포트 점유. `.env` 의 `DOZZLE_PORT` 변경 |
| `permission denied ... docker.sock` | 컨테이너가 소켓을 못 읽음. 호스트 `/var/run/docker.sock` 권한 확인 |
| 로그인 실패 | `users.yml` 해시가 bcrypt(`$2a$`/`$2b$` 시작)인지 확인. sha-256 해시는 v8+ 에서 동작 안 함 |
| 컨테이너 목록이 비어 있음 | 소켓 마운트 누락 또는 `users.yml` 의 `filter` 가 과도하게 좁음 |

## 9. 검증 상태

작업 PC에 Docker 가 없어 **실제 `docker load` + 기동 리허설은 미수행**. 아래까지 확인했다.

- ✅ 이미지 tar 레이어 4개 전부 `diff_id` 원본 일치 (amd64 / arm64)
- ✅ 각 레이어가 유효한 tar, `RepoTags` · entrypoint(`/dozzle`) · architecture 정상
- ✅ `install.sh` / `uninstall.sh` bash 문법 검사 통과
- ✅ `docker-compose.yml` · `users.yml` YAML 파싱 정상, external 네트워크 의존 없음
- ✅ 압축파일 내 실행권한(`0755`) 보존
- ⬜ **`docker load` → `up -d` → 브라우저 접속** — 도커 있는 환경에서 1회 리허설 권장
