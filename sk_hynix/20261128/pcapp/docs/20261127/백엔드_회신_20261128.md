## 1. 앱이 맞춘 것

|---|---|

| 7-2 갱신 실패 | 529·530·531 등 갱신 거절 → AM-Tray 인가토큰으로 다시 로그인을 한 번 시도합니다. 실패하면 사용자에게 재로그인 안내를 띄웁니다. |

## 2. 11-27 dev 서버 시험 결과 — 확인 부탁드립니다

### 2-1. ValidateToken 이 status 500 을 줍니다 (로그인 실패)

서버 로그 (2026-11-27, 요청 ID `264a22e0-ea1d-11f1-9d78-f16a7b3eed66`):

```
13:43:54.252  [IP Rate Limit] 통과: POST /auth/sso/amtray
13:43:58.314  [SSO_AMTRAY] ValidateToken 응답 => {"status":500,"result":"","hasUserId":false}
13:43:58.315  [SSO_AMTRAY] error => AM-Tray 인가토큰 검증 API 호출 실패
13:43:58.321  POST /auth/sso/amtray 200 84
```

- `ValidateToken 호출 실패 =>` 줄은 없습니다. 연결은 되었고, SSO 서버가 본문에 status 500 을 넣어 답한 것으로 보입니다. 응답까지 약 4초 걸렸습니다.
- 앱이 보낸 인가토큰은 AM-Tray DLL `GetSystemToken` 으로 방금 받은 값입니다(113자).

부탁드립니다:
1. **요청 키 이름 확인** — 지금 `{ systemID, authzToken }` 으로 보내고 있습니다. AM 측 Java 샘플(11-16)은 `systemId` 입니다. 대소문자가 다르면 SSO 서버가 시스템 ID 를 못 읽어 500 을 줄 수 있습니다. `systemId` 로 한 번 시험해 주실 수 있을까요?
2. **응답 본문 전체를 로그로** — 지금은 status·result·hasUserId 만 남습니다. 인가토큰 값을 뺀 본문 전체(`message` 등)가 있으면 원인을 바로 볼 수 있습니다.
3. 경로 대소문자 — `.env` 는 `.../tray/api/ValidateToken`, 샘플은 `.../tray/api/validateToken` 입니다. 1번으로 안 되면 함께 봐 주세요.

### 2-2. 요청이 모바일로 판정되었습니다 (이번에 앱에서 고침)

같은 요청의 `[initializeState]` 로그에 `"isMobile": true`, `"osType": "ANDROID"` 가 찍혔습니다. 당시 앱이 헤더 4개를 모두 보냈기 때문이며, 1장대로 고쳤습니다. 다음 시험 때 `isMobile` 이 false 로 나오는지 같이 봐 주세요.

## 4. 요청 — AI회의록 웹에서 PC 앱 호출 순서

웹의 [PC앱으로 녹음](또는 같은 역할 버튼)을 누르면 **먼저 앱을 호출하고, 앱이 열리지 않으면 설치 파일 주소로 보내 설치되게** 해 주세요.

```
[PC앱으로 녹음] 클릭
   │
   ├─ 1) 앱 호출: timbloRecApp://open
   │      └─ 2초 안에 페이지가 포커스를 잃음(브라우저 "SKHynixRecApp 열기" 확인창 또는 앱이 앞으로 나옴)
   │            → 설치된 것. 끝 (앱이 열리고, 로그인은 앱이 AM-Tray 로 알아서 함)
   │
   └─ 2) 2초 동안 반응 없음 → 설치 안 된 것으로 보고 설치 파일 주소 호출
          → 설치 파일 다운로드 → 사용자가 실행해 설치
          (안내창에 [다시 열기] 버튼도 함께 — 판단이 100% 정확하지 않음)
```

| 항목 | 값 |
|---|---|
| 앱 호출 주소 | `timbloRecApp://open` — 앱은 주소 뒤 내용을 보지 않고 **열기·앞으로 가져오기만** 합니다. 예전 `connect?code=…&host=…` 의 code 발급은 **이제 필요 없습니다**(로그인은 AM-Tray). |
| 설치 파일 주소 (dev) | `https://aimeetingdev.skhynix.com/downpcapp/SKHynixRecApp-Setup-latest.exe` |
| 설치 파일 주소 (운영) | `https://aimeeting.skhynix.com/downpcapp/SKHynixRecApp-Setup-latest.exe` |
| 설치 파일 이름 | 배포 때마다 같은 이름(`-latest.exe`)으로 덮어쓰므로 웹 링크는 바꾸지 않아도 됩니다. 버전이 붙은 파일(`SKHynixRecApp-Setup-0.0.17.exe`)은 앱 자동 업데이트용이라 웹 링크로 쓰지 않습니다. |
| 화면에 보이는 이름 | `SKHynixRecApp` (앱 주소 `timbloRecApp` 은 내부 이름) |

- 브라우저는 보안상 설치된 프로그램을 직접 조회할 수 없어서, 앱 주소를 열었을 때 페이지가 포커스를 잃는지(`blur` / `visibilitychange`)로 판단합니다.
- 예제 코드: 앱 저장소 `docs/과거참고용/web-integration/openPcApp.js` (10-31 작성). 그중 `buildPcAppUrl` 을 `() => 'timbloRecApp://open'` 으로 바꿔 쓰면 됩니다(code·host 인자 불필요).
- 설치 파일 주소는 정해진 값이 아니라 업데이트 서버 폴더(`/downpcapp`) 기준입니다. 실제 주소가 다르면 알려 주세요.
