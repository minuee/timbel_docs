# 하울링·단어 반복 원인 찾기 시험 (0.0.6)

작성 2026-11-06 · 대상: 회사 서버 담당자

## 무엇을 하나

병합 결과에 **울림(대강당 같은 잔향)** 과 **STT 단어 반복("안녕안녕")** 이 생긴다.
원본 파일에는 없다. 서버의 처리 중 무엇이 원인인지 **설정을 하나씩만 바꿔** 같은 파일로
병합해 보고 비교한다.

> ⚠️ **설정은 한 번에 하나만 바꾼다.** 여러 개를 같이 바꾸면 좋아져도 무엇 덕분인지 알 수 없다.
> 시험이 끝나면 `.env` 를 원래대로 되돌린다.

| 시험 | 바꾸는 것 | 무엇을 보나 |
|---|---|---|
| ① 기준 | 없음 (지금 그대로) | 비교 기준 |
| ② 음량 맞추기 끄기 | `.env` 에 `MERGE_LEVEL=off` | 울림이 줄면 → 합친 뒤 작은 소리를 키우는 처리가 원인 |
| ③ 드리프트 보정 끄기 | `.env` 에 `DRIFT_CORRECT=0` | 후반부 반복이 사라지면 → 폰 시계 보정이 원인 |
| ④ 오토믹서 세게 | `.env` 에 `AUTOMIX_FLOOR_DB=-60` | 울림이 사라지면 → 다른 폰에 담긴 같은 목소리가 겹친 게 원인 |
| ⑤ 오토믹서 끄기 | `.env` 는 그대로, 요청에 `automix=false` | 오토믹서가 오히려 나쁘게 만드는지 |

## ★ 권장: 자동 시험 스크립트 (`newDocs/howling_test.sh`)

위 설정들을 **섞은 12가지 조합**(음량 맞추기 2 × 드리프트 보정 2 × 오토믹서 3)을 한 번에 자동으로 돌린다.
아래 0~2절의 손 시험 대신 이것을 쓴다.

```bash
# 1) 회의마다 하위 폴더, 그 안에 그 회의의 "폰별 원본" flac (병합 결과 파일이 아님)
/data/howling_test/회의1/phone_A.flac, phone_B.flac ...
/data/howling_test/회의2/...

# 2) 실행 (비프음이면 값 없이. 안내 음성이면 SYNC_SOUND=voice, 영어면 SOUND_LANG=en 을 앞에)
chmod +x howling_test.sh
./howling_test.sh /data/howling_test
```

- `.env` 백업 → 조합마다 `.env` 수정·서버 재기동·회의 전부 병합·결과 저장 → 끝나면(중간 Ctrl+C 도) **원래 `.env` 로 복구**
- 시험 중에만 업로드 한도를 4GB 로 올린다 (기본 512MB 는 긴 회의 여러 폰이면 넘는다)
- 틀린 값(예: `SYNC_SOUND=beaf`)은 시작 전에 막는다. flac 이 1개뿐인 폴더는 건너뛴다
- 결과: `/data/howling_test/results_<날짜시각>/<회의>/` 에 flac 12개, 같은 이름의 `.log`·`.json`, `듣기표.md`. 전체 진행은 `run.log`
- ⚠️ 도는 동안 **서버가 8번 재기동**된다. 서비스가 안 쓰는 시간에 돌린다.
- 보낼 것: 회의마다 `듣기표.md` + `*.log` + `*.json`, 그리고 `run.log` (flac 은 반출 가능할 때만)

## 0. 준비 (한 번만)

### 0-1. 0.0.6 설치

`mobile-sync-server_0.0.6_amd64.tar`, `.tar.sha256`, `_patchkit.tar.gz` 를 받아
`deploy/SERVER_INSTALL.md` 5절 "새 버전 올리기" 대로 설치한다. `.env` 는 그대로 유지된다.

### 0-2. `.env` 백업

```bash
cd /data/timblo/mobile-sync-server
cp .env .env.before_howling_test
grep -E "^(MERGE_LEVEL|DRIFT_CORRECT|AUTOMIX_FLOOR_DB|MERGE_AUTOMIX|BEEP_MIN_TRACKS)=" .env
```

마지막 줄 결과를 기록해 둔다. (`BEEP_MIN_TRACKS` 는 1 이어야 한다.)

### 0-3. 시험 파일 준비

**울림이 심했던 회의 1건의 원본 flac 전부** (폰별 파일)를 한 폴더에 모은다.
예: `/data/howling_test/a.flac`, `b.flac`, `c.flac`

### 0-4. 시험 명령 등록

아래를 터미널에 그대로 붙여 넣는다. `FILES` 만 실제 파일로 고친다.
**앱이 쓴 값**(`syncSound`, `beepSource`)도 실제와 맞춘다.

```bash
cd /data/howling_test
API=http://127.0.0.1:9995
FILES="-F files=@a.flac -F files=@b.flac -F files=@c.flac"
COMMON="-F align=none -F syncSound=beep -F beepSource=all"

run_test() {   # 사용법: run_test <이름> [추가 -F 옵션...]
  name=$1; shift
  job=$(curl -s -X POST $API/v1/merge/upload $FILES $COMMON "$@" | grep -o 'mrg_[0-9a-f]*' | head -1)
  [ -z "$job" ] && { echo "요청 실패"; return 1; }
  echo "작업번호 $job — 끝날 때까지 기다리는 중..."
  until curl -s $API/v1/merge/$job | grep -q -E '"status": "(DONE|ERROR)"'; do sleep 5; done
  curl -s $API/v1/merge/$job > result_$name.json
  curl -s -o result_$name.flac $API/v1/merge/$job/download
  docker logs mobile-sync-server 2>&1 | grep "$job" | grep -E "merge_alignment|merge_drift" > log_$name.txt
  echo "완료: result_$name.flac / result_$name.json / log_$name.txt"
}
```

## 1. 시험 진행

### ① 기준

```bash
run_test 1_base
```

### ② 음량 맞추기 끄기

```bash
cd /data/timblo/mobile-sync-server
cp .env.before_howling_test .env
echo "MERGE_LEVEL=off" >> .env
docker compose --env-file .env up -d && sleep 10
cd /data/howling_test && run_test 2_level_off
```

### ③ 드리프트 보정 끄기

```bash
cd /data/timblo/mobile-sync-server
cp .env.before_howling_test .env
echo "DRIFT_CORRECT=0" >> .env
docker compose --env-file .env up -d && sleep 10
cd /data/howling_test && run_test 3_drift_off
```

### ④ 오토믹서 세게

```bash
cd /data/timblo/mobile-sync-server
cp .env.before_howling_test .env
echo "AUTOMIX_FLOOR_DB=-60" >> .env
docker compose --env-file .env up -d && sleep 10
cd /data/howling_test && run_test 4_floor_60
```

### ⑤ 오토믹서 끄기

```bash
cd /data/timblo/mobile-sync-server
cp .env.before_howling_test .env
docker compose --env-file .env up -d && sleep 10
cd /data/howling_test && run_test 5_automix_off -F automix=false
```

### 끝나면 원래대로

```bash
cd /data/timblo/mobile-sync-server
cp .env.before_howling_test .env
docker compose --env-file .env up -d
```

> `.env` 에 같은 이름이 두 줄 있으면 **아래 줄이 이긴다.** 그래서 `echo >>` 로 덧붙이기만 해도 된다.

### 로그에서 볼 값 (참고)

- `merge_alignment` 의 `offsets` — 폰별로 민 시간(ms). `fallbacks` 에 폰이 있으면 그 폰은 싱크음을 못 찾았다
- `merge_drift` 의 `ppm` — 폰별 시계 보정량. **수백 이상이면 비정상**(종료음을 잘못 찾음). 보통 수십 이하
