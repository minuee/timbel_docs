## ① (문의) exe 로 빌드하면 암호화되나? 탈취 시 노출 위험

**앱 코드는 암호화되지 않는다.** electron-builder 는 소스를 `app.asar` 한 파일로 묶을 뿐이라 `npx asar extract` 로 원래 JS 가 그대로 나온다.

| 무엇 | 상태 | 위험 |
|---|---|---|
| JS 소스, `app.config.json` | 평문 | 낮음 — 서버 주소뿐, 비밀번호·API 키 없음 |
| 로그인 토큰 | 메모리에만. 앱 끄면 사라짐 | 낮음 |
| 녹음 파일(.pcm) | AES-256 암호화 | **키가 AudioHelper.exe 안에 고정**(모바일 앱과 같은 키). exe 를 분석하면 키를 뽑을 수 있음 → 서버/모바일과 함께 정할 문제 |
| 로컬 DB `AppData\Roaming\timbloRecApp\app.db` | 평문 SQLite | 중간 — 녹음 이름·시각 |
| 로컬 로그 파일 | 평문 | 중간 — `{ token }` 은 로그 서버로 갈 때만 `***`, **로컬 파일엔 원문** |
| 테스트 로그인 | `MANUAL_LOGIN_ENABLED`, `EMPNO_LOGIN_ENABLED` 가 true | **운영 배포 전에 반드시 false** |

결정: 망분리 사내 전용이라 로컬 로그 토큰 가리기·테스트 로그인 끄기는 **하지 않기로 함**. asar 암호화·난독화도 하지 않음.

## ③ 업로드 리스트 X·삭제 버튼 반응 없음

맥에서 같은 화면을 띄워 실제로 눌러 봤을 때 **둘 다 정상**(X → 창 닫힘, 삭제 → "파일을 삭제할까요?" 팝업 요청)이었다. 그래서 Windows 에서만 생길 수 있는 원인 두 가지를 막았다.

| 의심 원인 | 조치 |
|---|---|
| 삭제 확인 팝업이 **항상 주 모니터** 가운데에 떠서, 듀얼 모니터면 다른 화면에 뜸 → 반응 없는 것처럼 보임 | 팝업을 연 창(업로드 리스트)이 있는 모니터 가운데에 띄움 |
| Windows 에서 제목 줄(드래그 영역) 안의 버튼 클릭이 창 이동으로 먹힘 | X 영역 전체를 드래그 제외 |

**그래도 안 되면** 로그 서버에서 확인 부탁:
- X 를 눌렀을 때 `upload_list_close_clicked` 가 있는지 → 없으면 클릭이 화면까지 안 온 것
- 삭제를 눌렀을 때 `upload_list_item_clicked`(itemAction: delete), 이어서 `popup_shown`(popupType: remove-job) 이 있는지

## ⑧ 로그 서버의 `Electron Security Warning (Insecure Content-Security-Policy)`

- 원인: 화면 HTML 에 보안 정책(CSP)이 없어서 Electron 이 콘솔에 남기는 경고. 렌더러 콘솔의 warn 이상은 로그 서버로 가서 쌓였다. 기능 영향 없음
- "정기적으로" 나오는 게 아니라 **창이 열리거나 화면이 바뀔 때마다** 한 번씩(로그인 → 마이크 테스트 → 녹음 화면, 업로드 팝업, 업로드 리스트, AI 요약 창…)
- 이 경고는 Electron 이 **설치본(패키징)이 아닐 때만** 띄운다(경고 문구 끝에 "This warning will not show up once the app is packaged"). 회사에서 `yarn start` 등 개발 실행으로 돌렸다면 그래서 나온 것
- 조치: 화면 7개에 CSP 한 줄씩 추가, `update.html` 안의 스크립트는 파일로 분리. 맥에서 7개 화면을 다 띄워 확인 — 경고 0건, 차단된 리소스 0건
  - 구글 폰트 주소는 허용해 두었다(망분리라 어차피 안 받아지고, 그래도 화면은 기본 글꼴로 나온다)

## ⑨ (문의) 시스템 소리 녹음 — 유튜브도 되나? 스피커에서 소리가 나야 하나?

**유튜브·동영상도 시스템 소리다.** 헬퍼는 WASAPI loopback 으로 "출력 장치로 보내지는 소리"를 그대로 받는다. Zoom·Webex·유튜브 구분이 없다.

**실제로 스피커에서 소리가 날 필요는 없다.** 마이크처럼 공기 중 소리를 듣는 게 아니라, 스피커로 **보내기 직전의 디지털 소리**를 복사한다. 그래서 **이어폰을 꽂고 들어도 녹음된다**(화상회의에서 원래 쓰는 방식).

다만 조건이 있다.

| 조건 | 설명 |
|---|---|
| **무언가 재생 중이어야 한다** | 아무것도 안 틀면 Windows 가 빈 소리만 주기 때문에 **막대가 안 움직이는 게 정상**이다. 이번 테스트에서 막대가 하나도 안 움직인 건 소리를 안 틀었기 때문일 가능성이 가장 크다 |
| 출력 장치가 맞아야 한다 | 마이크 테스트 화면의 출력 장치 = 실제로 소리가 나가는 장치(이어폰/헤드셋/모니터). 이어폰을 꽂으면 Windows 기본 장치가 바뀌는 경우가 많으니 "기본 출력 장치"가 무난 |
| 출력 장치가 있어야 한다 | 스피커·이어폰이 하나도 없는 PC 는 출력 장치가 없어서 잡을 소리도 없다 |
| 볼륨 | Windows 음소거·볼륨 0 이면 장치(드라이버)에 따라 녹음도 무음이 될 수 있다. 테스트 땐 음소거 풀고 작게 |

### 10-15 회사 테스트에서 무음 경고(7초·30초)·STT 실패가 난 이유 — 정상
- **"회의 소리만"(SystemOnly) 모드는 마이크를 0 으로 만든다.** 육성으로 말해도 녹음에 안 들어간다
- 그 상태에서 PC 에서 아무것도 재생하지 않았으니 녹음 전체가 완전한 무음
- 무음 감지는 최종 녹음(마이크+시스템 합친 결과)을 보므로 7초·30초 경고가 뜨고, 서버도 변환할 소리가 없어 STT 실패
- → 앱 오류가 아니라 테스트 조건 때문. 시스템 녹음이 되는지는 아직 판단 전

### 사무실에서 테스트하는 법
1. **이어폰은 없어도 된다.** 스피커를 작게 켜도 됨(Windows 음소거는 풀 것). 소리를 아예 못 내면 이어폰
2. 앱 마이크 테스트 화면: 모드 **"회의 소리만"**, 출력 장치 "기본 출력 장치"(또는 실제로 소리가 나는 장치)
   - 이 모드는 마이크를 안 쓰므로, 스피커 소리가 마이크로 다시 들어가도 녹음에 섞이지 않는다
3. 유튜브(말소리 나오는 영상)를 작은 볼륨으로 재생 → **시스템 사운드 막대가 움직이는지** 본다
4. 움직이면 녹음 → 업로드 → STT 결과에 영상 대사가 나오는지. 안 움직이면 아래 로그를 보내 줄 것
   - 로그 서버: `capture_mode_changed`, `render_device_changed`, `SYS_INIT_FAILED` 오류 여부
   - 헬퍼 로그의 `Current system device ID: ...` 줄

"내 목소리 + 회의 소리" 는 그다음에. 스피커로 틀면 그 소리가 마이크로도 들어가서 에코 제거(AEC)가 중복을 지워야 하므로, 이 모드에서 상대방 목소리가 깎이거나 두 번 녹음되지 않는지 따로 봐야 한다(실제 사용 모드).

**의심(추측, 서버 소스가 없어 미확정):** 서버가 `fileName` 에서 녹음 날짜를 꺼내는데 모바일 접두어(`A.Biz_m_rec_`) 기준이라, PC 접두어(`A.Biz_pcapp_rec_`)는 못 읽고 "생성일(업로드 시각)로 등록"으로 떨어졌을 수 있다.

### 확인 순서 (코드 수정 없음)
1. **모바일 앱으로 올린 회의록**을 웹에서 열어 같은 알럿이 뜨는지
   - 모바일도 뜸 → 웹 원래 동작. 우리 앱과 무관
   - 모바일은 안 뜸 → 2번
2. `src/config/app.config.json` 의 `"RECORDING_FILE_PREFIX"` 를 **`"A.Biz_m_rec_"`** 로 바꾸고 녹음 → 업로드 → 웹에서 열기
   - 알럿이 사라짐 → 원인은 접두어로 확정. 서버에서 PC 접두어도 인식하게 하거나, 우리가 맞춘다(결정 필요)
   - 그래도 뜸 → 접두어 문제 아님. 3번
   - ⚠️ 시험이 끝나면 원래 값 `"A.Biz_pcapp_rec_"` 로 되돌릴 것(접두어로 PC/모바일 구분이 필요할 수 있음)
3. 서버 담당자에게: "업로드한 회의록의 회의 날짜를 무엇으로 정하나? `fileName` 을 읽나? 형식/접두어 조건은?"

참고: `lang`(빈 값)·`attendeeNum`(0)도 모바일과 다르다. 날짜와는 무관해 보이나 2번 결과를 보고 맞출지 정한다.
