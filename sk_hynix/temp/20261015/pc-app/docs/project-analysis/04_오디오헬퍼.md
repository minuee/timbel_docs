# 04. 오디오 헬퍼 (네이티브 녹음 프로세스)

> 기준: 현재 소스 (2026-10-15 작업분, Windows 헬퍼 v0.4.2). 소스 위치는 `파일 · 함수` 로 표기.
> 실사용 대상은 **Windows**. macOS 는 "실행은 되는 수준"이라 마지막 절에 차이만 적었다.

---

## 1. 왜 따로 있나

Electron(Chromium) 만으로는 **PC 에서 나는 소리(시스템 오디오)** 를 안정적으로 녹음하기 어렵다. 에코 제거(AEC), 장치 변경 대응, 장시간 녹음도 마찬가지다.
그래서 OS 오디오 API 를 직접 쓰는 작은 프로그램(헬퍼)을 별도 프로세스로 띄우고, Electron 은 명령만 내린다.

| | Windows | macOS |
|---|---|---|
| 파일 | `src/helpers/windows/AudioHelper.exe` | `src/helpers/macos/AudioHelper.app` (arm64 전용) |
| 소스 | `AudioHelper.cpp`(약 3,800줄), `main.cpp`, `WavWriter.cpp`, `Logger.cpp`, `versioninfo.h` | `AudioHelperController.swift`, `SegmentManager.swift`, `JSONModels.swift`, `FileLogger.swift` |
| 마이크 | WASAPI 캡처 | AVCaptureSession |
| PC 소리 | WASAPI **loopback** (출력 장치를 골라서 녹음 가능) | ScreenCaptureKit (화면 전체의 소리, 장치 선택 불가) |
| 에코 제거 | WebRTC APM (MSVC `build.bat` 빌드에만 들어감) | 없음 |
| 암호화 | Windows CNG(BCrypt) AES-256-CBC | CryptoSwift AES-256-CBC |

## 2. 실행과 통신 (`src/main/audioHelperManager.js`)

### 실행
- 화면이 `startAudioHelper()` 를 부를 때 `spawn` 한다(앱 시작 시점이 아님). 이미 떠 있으면 다시 띄우지 않는다.
- **exe 경로** (`getHelperPath`): 아래 후보 중 처음으로 존재하는 것을 쓴다.
  1. `app.asar.unpacked/helpers/windows/AudioHelper.exe`
  2. `resources/helpers/windows/AudioHelper.exe`
  3. `<설치폴더>/helpers/windows/AudioHelper.exe` ← 설치본은 실제로 여기
  4. 개발 모드: `src/helpers/windows/AudioHelper.exe`
- **작업 폴더(cwd)**:
  - Windows: 녹음 저장 기준 폴더(`문서\SKHynixRecApp`, 안 되면 `C:\SKHynixRecApp`)
  - macOS: exe 가 있는 폴더
  - Windows 를 이렇게 정한 이유: 헬퍼가 저장 경로 명령을 놓치고 기본값 `recordings`(상대경로)로 저장해도 결국 같은 폴더에 저장되게 하려는 것이다(2026-10-15 수정).
- 종료할 때는 `kill()` 만 한다. `stop` 명령을 먼저 보내지 않는다.

### 통신 규약 (NDJSON)
- **Electron → 헬퍼**: stdin 에 JSON 한 줄 + `\n`. 모든 명령에 현재 `sessionId` 가 자동으로 붙는다.
- **헬퍼 → Electron**: stdout 에 JSON 한 줄씩. 형식은 `{ "ev": "...", ... }`.
  - UTF-8 디코더로 줄 단위로 끊어 파싱한다. JSON 이 아닌 줄은 debug 로그로만 남긴다.
- **stderr**: 오류 로그로 남기고, 렌더러에 `{ev:'helper_log', level:'error'}` 로 보낸다.
- **매니저가 직접 만드는 이벤트**: `helper_status` — stage 값은 `pre_spawn` / `spawned` / `closed` / `spawn_error`.
- 레벨·진행 이벤트는 양이 많아서 로그에는 0.1% 만 샘플링해서 남긴다.

## 3. 명령 목록

| cmd | 파라미터 | 동작 | 응답 이벤트 |
|---|---|---|---|
| `get_version` | — | 버전 정보 | `version_info` |
| `list_devices` | — | 마이크(+Windows 는 출력 장치) 목록 | `devices` |
| `set_output_dir` | `directory` | 녹음 저장 기준 폴더 | `output_dir_set` |
| `set_debug_files` | `enabled` | Windows: 원본 mic/sys/mix WAV 를 따로 저장. mac: 로그 레벨만 바뀜 | `debug_files_set` |
| `set_segment_config` | `encryption_enabled`, (Win) `segment_seconds` | 암호화 여부, 조각 길이 | `segment_config_set` |
| `start_test` | `mode`, `mic`, `render` | 마이크 테스트(레벨만, 저장 안 함) | `test_started` |
| `stop_test` | — | 테스트 정지 | `test_stopped` |
| `start` | `mode`, `mic`, `render`, `max_ms`, (mac) `segmenting.duration_ms`, `out.sr` | 녹음 시작 | `recording_started` |
| `pause` / `resume` / `stop` | — | 일시정지 / 재개 / 정지 | `paused` / `resumed` / `recording_stopped` (+마지막 `segment_ready`) |
| `set_mute` | `target`: mic·system·both, `value`: on·off | 음소거 | `mute_state` |
| `set_level_meter` | `enabled` | 레벨 이벤트 켜기/끄기 (기본 켜짐, 앱에서는 보내지 않음) | `level_meter_state` |

`mode` 값: `MicPlusSystem`(마이크+PC소리), `MicOnly`, `SystemOnly`.

## 4. 이벤트 목록

| ev | 주요 필드 | 의미 |
|---|---|---|
| `helper_info` | version, webrtc_aec, build_date | 실행 직후 1회 |
| `version_info` | version, webrtc_aec, build_date ... | `get_version` 응답. **webrtc_aec=true 여야 에코 제거 빌드** |
| `devices` | devices[{id, name, isDefault}], (Win) renderDevices | 장치 목록 |
| `level` | source(mic/system), rms | 100ms 마다 소스별 음량 |
| `progress` | seconds, samples | 녹음 진행 (파일 기준 시간) |
| `segment_ready` | index, path, samples, duration_ms, size_bytes, encrypted | **조각 파일 하나가 디스크에 저장됨** |
| `recording_stopped` | totalSamples | 정지 완료 |
| `silence` | state: early / sustained / off | 무음 감지. 녹음 중에만 |
| `disk_status` | status: ok / low / critical, free_bytes | 디스크 여유 |
| `audio_device_change` | change_type: added / removed | 장치 추가/제거 |
| `device_reconnected` | type: system | 기본 출력 장치가 바뀌어 PC 소리 캡처를 다시 연결함 |
| `mic_state` | state: available / unavailable | 마이크 상태 |
| `error` | code, message | 오류 (아래 표) |
| (Win) `waveform`, `audio_reinited` | | 화면에서 쓰지 않음 |

**화면이 반응하는 주요 오류 코드**

| code | 의미 | 화면 처리 |
|---|---|---|
| `MIC_DEVICE_LOST` | 선택한 마이크가 빠짐 | 녹음 중이면 오류 정지 (렌더러는 `SELECTED_MIC_REMOVED` 도 같이 처리하지만, 현재 헬퍼 소스는 이 코드를 보내지 않는다) |
| `MIC_DEVICE_CHANGED` | 장치 변경 | 마이크 테스트 화면: 목록 다시 받기 |
| `DISK_SPACE_CRITICAL` | 디스크 부족 임박 | 경고 팝업 |
| `DISK_SPACE_LOW_STOP` | 디스크 부족으로 정지 | 오류 정지 |
| `DISK_WRITE_OPEN_FAILED`, `SEGMENT_SAVE_FAILED`, `ENCRYPT_FAILED` | 파일 저장 실패 | (특별 처리 없음, 로그) |

## 5. Windows 녹음 처리 과정

```
[마이크 스레드] WASAPI 캡처 ─ float32 → 모노 → 16kHz 리샘플 ─▶ micFifo ─┐
[PC소리 스레드] WASAPI loopback ─ 같은 처리 ──────────────────▶ sysFifo ─┤
                                                                          ▼
[믹싱 스레드] 20ms 블록마다:  (MicPlusSystem 이면) WebRTC AEC (10ms 단위)
                → 음소거 → PC소리가 훨씬 크면 PC소리 ×0.7 (덕킹)
                → 게인 mic 1.0 / sys 0.7 → 클램프 → 16bit 정수
                → 메모리 조각 버퍼에 누적
                                                                          ▼
                3분(2,880,000 샘플)이 차면 → AES 암호화 → 파일 저장 → segment_ready
[감시 스레드] 최대 녹음 시간(max_ms), 디스크 여유 확인
```

| 항목 | 내용 |
|---|---|
| 출력 형식 | **16kHz / 모노 / 16bit PCM** 고정 |
| 조각 길이 | 180초(3분). 1초 미만 조각은 저장하지 않음 |
| 파일 경로 | `{outputDir}/{sessionId}/{sessionId}_{index}.pcm`. 같은 이름이 있으면 `(n)` 을 붙임 |
| 실제 위치 | `문서\SKHynixRecApp\recordings\{sessionId}\{sessionId}_1.pcm, _2.pcm …` |
| 암호화 | AES-256-CBC + PKCS7. **키·IV 가 소스에 고정**(모바일 앱 Dart 코드와 같은 값). 파일에는 헤더 없이 암호문만 들어감. 암호화를 끄면 `.raw`(평문) |
| 메모리 | 저장 전까지 최대 3분 분량을 메모리에 들고 있음 → **비정상 종료 시 최대 3분 유실** |
| SystemOnly | 그래도 마이크를 열어 시간 기준으로 쓴다(마이크 소리는 0으로 처리) |
| 일시정지 | 버퍼 비움. 재개 시 마이크가 없으면 `CANNOT_RESUME_NO_MIC` |
| 최대 시간 | 시계 기준과 샘플 수 기준 두 가지로 판정하고, 조각 경계에서 멈춘다 |
| 디스크 | 시작 전 50MB 미만이면 시작 거부. 녹음 중 1초마다 확인, critical 이면 정지 |
| 장치 변경 | 기본 출력 장치가 바뀌면 PC 소리 캡처를 다시 연결(AEC 초기화, 200ms 페이드인). 선택한 마이크가 빠지면 정지. **다른 마이크로 자동으로 바꾸지 않는다**(의도된 정책) |
| 무음 감지 | 20ms 블록 RMS < 0.02 가 이어지면 7·14·21·28초에 `early`, 30초에 `sustained`. 한 번 소리가 나면 `off` 를 보내고 그 녹음에서는 다시 감지하지 않음 |
| 레벨 미터 | 기본 켜짐. 녹음이 끝난 뒤에도 레벨용 캡처를 자동으로 다시 시작 |

### 빌드 종류와 AEC
| 빌드 | 방법 | AEC | 버전 표시 |
|---|---|---|---|
| MSVC (회사 PC) | `src/helpers/windows/build.bat` (`-DUSE_WEBRTC_AEC=ON`, `WebRTCLib/release/webrtc.lib` 필요) | 있음 | `v0.4.2 AEC` |
| mingw (Mac 에서 크로스 빌드) | `src/helpers/windows/build-mingw.sh` | **없음** | `v0.4.2` |

화면의 설정 → 버전 정보에서 `AEC` 가 붙었는지로 확인한다. 이어폰 없이 스피커로 회의하면 AEC 가 없을 때 상대방 소리가 두 번 녹음된다.

### 헬퍼 로그
- `exe 와 같은 폴더\AudioHelper.log`. 설치본은 `<설치폴더>\helpers\windows\AudioHelper.log` 다.
- 10MB 가 넘으면 `.1`~`.5` 로 회전한다.
- **경고 이상만 기록한다.** 디버그 매크로가 꺼져 있어서 INFO 로그는 남지 않는다.

## 6. macOS (실행 가능 수준)

Windows 와 다른 점만 적는다.

- 녹음 파일은 **`/tmp/recordings/{sessionId}/`** 에 저장된다. 재부팅하면 지워질 수 있다.
- **에코 제거가 없다.** 믹싱은 두 소스의 단순 평균이다.
- 화면 기록 권한(ScreenCaptureKit)과 마이크 권한이 필요하다.
- 명령을 비동기 Task 로 처리해서 **도착 순서가 보장되지 않는다.** 그래서 암호화 설정보다 녹음 시작이 먼저 실행되면 평문 `.raw` 로 저장될 수 있다.
- 암호화 기본값이 꺼짐이다(Windows 는 켜짐). 앱이 매번 켜라고 보내므로 평소에는 문제가 없다.
- 지정한 마이크가 없으면 기본 마이크로 바꾼다. Windows 는 이렇게 하지 않는다.
- 최대 녹음 시간 설정이 없어도 3시간(조각 60개)에서 멈춘다.
- 헬퍼 로그: `~/Library/Application Support/timbel.AudioHelper/Logs/AudioHelper.log` (JSON Lines)
- 바이너리가 arm64 전용이라 Intel 맥에서는 실행되지 않는다.
- `.gitignore` 대상이라 저장소에 커밋되지 않는다.

## 7. 앱과 헬퍼 사이에 맞지 않는 부분 (요약)

자세한 내용은 `08_확인필요.md`.

- 렌더러가 보내도 헬퍼가 쓰지 않는 값
  - `gains`, `out.blockMs`, `segmenting.max_cipher_bytes`, `align_to_block`
  - Windows 는 `segmenting` 전체를 쓰지 않는다. 조각 길이는 `set_segment_config.segment_seconds` 로만 바뀐다.
- Windows `start` 의 `mic` 값은 실제 녹음 장치를 정하지 않는다.
  - 녹음 장치는 마지막 `start_test` 로 고른 마이크가 쓰인다.
  - 마이크 테스트 화면에서 고른 마이크로 테스트를 돌린 뒤 녹음으로 넘어가므로, 평소에는 같은 장치가 된다.
- `recording_stopped.totalSamples` 는 샘플 수다. 렌더러는 이 값을 ms 와 비교한다(→ 최대 시간 판정 의심 버그).
- 회사 PC 에서 `output_dir_set.directory` 가 `undefined` 로 온 사례가 있다.
  - 현재 소스의 헬퍼는 `directory` 를 담아서 돌려준다.
  - 회사에서 쓰는 헬퍼 exe 가 옛 빌드일 가능성이 있다.
  - 지금은 앱 쪽에서 우회한다(cwd 지정, 빈 경로 채우기).
