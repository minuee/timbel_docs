## 2. 검토 내용 — TmTray(Windows SSO 에이전트)

- 고객사 SSO 방식 2가지: ① 아이디/비밀번호 ② **TmTray** (트레이 상주 에이전트, "윈도우 로그를 받는 구조")
- "윈도우 로그를 받는다" = **Windows에 로그인한 사용자(도메인 계정) 정보**를 에이전트가 받아 SSO에 쓴다는 뜻으로 추정. 앱은 TmTray에 물어 값을 받아 **입력 없이 자동 로그인**.
- **결론: 우리 앱(Electron)에서 연동 가능.** 매뉴얼에 나올 연동 방식은 보통 아래 중 하나이고, 모두 처리할 수 있다.

| 방식 | 매뉴얼 표현 예 | 난이도 |
|---|---|---|
| A. 로컬 포트 | `http://localhost:포트/...` | 쉬움 |
| B. 레지스트리·파일 | `HKCU\Software\...` | 쉬움 |
| C. 실행 파일 호출 | `xxx.exe /get ...` | 쉬움 |
| D. DLL/COM 함수 | `xxx.dll`, `GetToken()` | 어려움 (C++ 헬퍼 exe 추가로 처리) |

- 참고: 담당자가 그동안 C/C++/C# C/S 앱만 연동해 봤다고 함 → **D(DLL/COM) 방식일 가능성이 높음.** 매뉴얼에서 제공 형태가 C용 DLL+헤더(.h)인지, C#용 .NET DLL인지 꼭 확인.
- 매뉴얼은 사외 반출 불가 → 아래 항목의 **답만** 적어 오면 집에서 설계·구현한다.

## 회사에서 할 것

1. 담당자에게 2번(TmTray) 방식으로 하겠다고 알리고 **매뉴얼 요청**.
2. 매뉴얼이 안 오면 `docs/login-methods/tmtray-questions.md`(연동 방식 13가지 + 질문 목록)로 **역으로 질문**해서 답을 받는다.
3. 매뉴얼이 오면 아래 표의 답만 적어 온다.

## 회사에서 확인할 것 (매뉴얼 받으면)

| 무엇 | 적어 올 내용 |
|---|---|
| 1. 연동 방식 | A~D 중 무엇인지 + 주소/포트, 함수 이름·인자, 레지스트리 경로 등 |
| 2. 받는 값 | 토큰? 사번? 이름·부서? (항목 이름과 형식) |
| 3. 서버 검증 | 받은 토큰을 서버에서 검증하는 API가 있는지, 누가 호출하는지(앱/우리 서버/HMP) |
| 4. 유효시간 | 토큰 유효시간, 다시 받을 수 있는지 (녹음 중 만료 대응과 관련) |
| 5. 실패 시 | 에이전트가 없거나 꺼졌을 때 돌려주는 값·오류 |
| 6. Mac | Mac 지원 여부 (없으면 Mac은 사번/비번 로그인 유지) |
| 7. 앱 등록 | 앱 ID·인증서 등 사전 등록이 필요한지 |
| 8. DLL이면 | 32/64비트, 같이 배포해야 하는 파일 |

> 받는 값이 **사번만**이면 보안상 서버 쪽 추가 검증이 필요하다 ("사번만으로 토큰 발급" 보류 건과 연결).
