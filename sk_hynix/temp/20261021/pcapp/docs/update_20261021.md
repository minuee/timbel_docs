## ② 로그인 유지 — 옵션

### 켜고 끄기
`src/config/app.config.json` (개발 실행은 `.env` 가 우선)
```json
"SESSION_PERSIST_ENABLED": false
```
| 값 | 동작 |
|---|---|
| `false` (기본, 지금 값) | 지금과 같다 — 앱을 켤 때마다 로그인. 예전에 저장된 `session.dat` 가 있으면 지운다 |
| `true` | 로그인 화면에 "로그인 유지" 체크박스가 보이고, **체크하고 로그인했을 때만** 세션을 저장 → 다음에 켜면 로그인 없이 바로 마이크 테스트 화면 (③ 참고) |

### 어떻게 동작하나 (`true` 일 때)
- 저장: 로그인 성공·토큰 갱신·내 정보 조회 때마다 `AppData\Roaming\timbloRecApp\session.dat` 에 저장
  - 내용: accessToken, refreshToken, 서버 주소, 사용자 정보(이름·사번 등)
  - **Windows DPAPI 로 암호화** → 같은 Windows 계정에서만 풀린다. 파일을 다른 PC·다른 계정으로 복사해도 못 씀
  - 암호화를 못 쓰는 환경이면 저장하지 않는다(평문으로 남기지 않음)
- 대상: **SSO(MyAccess)·사번 로그인만** (refreshToken 이 있는 로그인). 테스트용 수동 로그인은 저장하지 않는다
- 앱을 켤 때:
  1. 저장된 세션이 있으면 바로 마이크 테스트 화면(제목 줄 이름도 바로 나옴)
  2. 뒤에서 내 정보·템플릿을 다시 받는다. 이때 accessToken 이 만료됐으면 **refreshToken 으로 조용히 갱신**
  3. 갱신이 **거절**되면(refreshToken 도 만료 등) 저장 파일을 지우고 **로그인 화면**으로
  4. 네트워크가 안 되면 세션은 그대로 둔다(녹음은 가능, 업로드할 때 다시 갱신 시도)
- 로그아웃하면 `session.dat` 삭제 → 다음 실행은 로그인 화면
- 녹음 화면에 있을 때 세션이 끊겨도 화면을 빼앗지 않는 건 예전과 같다
- 로그: `session_restored`(savedAt, accessTokenExpired), 실패 시 `session_persist_save_failed` / `session_persist_load_failed` / `session_persist_unavailable`. 토큰 값은 로그에 안 남김

### 서버 쪽 확인 필요
- **refreshToken 수명 = 로그인 유지 기간.** 서버 담당자에게 accessToken·refreshToken 각각 수명을 물어볼 것
- 보안 정책상 PC 에 (암호화해서라도) 토큰을 남겨도 되는지 → 안 되면 `false` 로 두면 끝

## ③ 로그인 화면 체크박스 — 사번 저장 / 로그인 유지

```
[ 사번      ]
[ 비밀번호  ]
☐ 사번 저장   ☐ 로그인 유지
[  로그인   ]
──── 또는 ────
[MyAccess 로그인]
```

| 체크박스 | 언제 보이나 | 체크하면 |
|---|---|---|
| 사번 저장 | 사번 로그인 폼이 보일 때 (`EMPNO_LOGIN_ENABLED`) | 사번 로그인 성공 시 사번을 저장 → 다음 로그인 화면에 채워 두고 비밀번호 칸에 커서. 체크를 풀고 로그인하면 지움. **비밀번호는 저장 안 함** |
| 로그인 유지 | `SESSION_PERSIST_ENABLED` 가 `true` 일 때만 (**지금은 false → 안 보임**) | 사번·MyAccess 로그인 모두 세션 저장(②). 체크를 풀고 로그인하면 `session.dat` 를 지움 |

- 처음엔 둘 다 꺼져 있고, 마지막으로 고른 값을 다음 로그인 화면에 그대로 보여 준다
- 사번 폼이 꺼져 있으면 "로그인 유지" 줄만 MyAccess 버튼 위에 나온다
- 저장 위치: `AppData\Roaming\timbloRecApp\login-prefs.json` — 체크 값과 사번만(평문). 토큰·비밀번호는 없음
- MyAccess 는 브라우저를 거쳐 딥링크로 돌아오므로, 체크박스를 바꾸는 순간 / 버튼을 누르는 순간 값을 미리 저장해 둔다
