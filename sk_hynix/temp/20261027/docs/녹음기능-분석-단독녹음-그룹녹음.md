# 녹음 기능 분석: 단독 녹음 vs 그룹 녹음 (SKT)

- 기준 소스: `fix/group_recording` 브랜치, 커밋 `adcae80` (2026-10-27 13:30, "fix:재전송팝업 오류 수정")
- 대상 서비스: **Hynix** (`SERVICE_TYPE=HYNIX`) ※ 1차 분석은 SKT 기준으로 작성됨. Hynix 차이는 10절 참고
- 목적: 고객사 프로젝트 관리자 대상 안내 문서를 만들기 위한 1차 기능 분석
- 표기: ✅ 코드로 확인됨 / ⚠️ 코드만으로는 단정할 수 없어 확인이 필요함

---

## 1. 진입 경로 (SKT)

SKT는 `MainContainerPage`를 사용합니다. Hynix 전용인 `MainContainerPageLight`는 쓰지 않습니다.

- 메인 하단 **[+] 버튼 → "회의록 만들기" 시트**에 3개 메뉴가 나옵니다 (`lib/widgets/common_bottomsheet.dart`).
  - **녹음** → 단독 녹음 화면 (`AppRoutes.recordingPage`)
  - **파일 업로드**
  - **그룹 녹음** → [그룹 생성] / [그룹 참여] 선택 시트 (`GroupEntry.showModeSheet`)
- 그룹 녹음 메뉴는 서비스 타입이나 개발자 옵션과 상관없이 항상 노출됩니다. ✅
- 홈 화면 위젯으로도 단독 녹음을 시작하고 종료할 수 있습니다. 그룹 녹음은 위젯에서 지원하지 않습니다. ✅

## 2. 한눈에 비교

| 항목 | 단독 녹음 | 그룹 녹음 |
|---|---|---|
| 개념 | 기기 1대로 녹음 | 여러 기기(최대 5대)가 동시에 녹음하고, 서버가 하나의 회의록으로 병합 |
| 시작 방법 | 녹음 화면에서 녹음 버튼 | 방장이 방을 만들고, 구성원이 4자리 코드로 참여한 뒤 방장이 [녹음 시작] |
| 일시정지/재개 | 본인이 직접 | **방장만** 가능하며 전원에게 함께 적용 |
| 종료 | 본인이 [완료] | **방장만** 가능하며 전원이 함께 종료 |
| 취소 | 본인 녹음 삭제 | 구성원: 본인만 빠짐 / **방장: 방 전체 취소, 전원의 녹음 폐기** |
| 종료 시 입력 항목 | 참석자 수, 인식 언어, 요약 템플릿, 제목 | 방장만 입력 (구성원은 입력 없음) |
| 싱크음 | 없음 | 시작/종료 시 기기에서 안내 음성과 비프음 재생 (기기 간 시간 정렬용) |
| 녹음 후 화면 | 메인으로 복귀, 업로드 진행 | "녹음 결과" 화면: 참가자별 업로드 현황과 회의록 생성 진행 상태 |
| 업로드 | 개별 업로드 큐 | 같은 업로드 큐에 방 ID를 붙여 각자 업로드한 뒤 서버에서 병합 |
| 암호화 | 개별 녹음용 키 | 그룹 전용 키 (서버 병합용) |
| 최대 시간 | 3시간 | ⚠️ 별도 제한 없음 (7절 참고) |

## 3. 단독 녹음 기능 상세

주요 파일: `lib/views/recording/recording_controller.dart`, `recording_page.dart`

### 3.1 화면 구성
- 제목 "새로운 녹음", 경과 시간(`00:00:00:00`), 실시간 파형
- 하단 버튼: **[취소] / [녹음·일시정지] / [완료]**. [완료]는 녹음을 시작한 뒤에만 보입니다.
- 안내 문구: "녹음 중 다른 앱 사용 시 녹음이 정상적으로 진행되지 않을 수 있습니다. 주의하세요."

### 3.2 기본 동작
| 기능 | 동작 |
|---|---|
| 시작 | 화면에 들어간 뒤 녹음 버튼을 눌러야 시작합니다. 자동으로 시작되지 않습니다. |
| 일시정지/재개 | 같은 버튼으로 전환하고, 일시정지 시 "녹음이 일시정지 되었습니다." 토스트를 띄웁니다. |
| 완료 | 녹음을 일시정지한 뒤 종료 팝업을 띄웁니다 (3.3). |
| 취소 | "녹음을 취소할까요? 취소하면 녹음 파일이 저장되지 않습니다."를 확인하면 녹음 폴더를 삭제합니다. |
| 뒤로가기 | 녹음 중에는 일시정지만 하고, 그 외에는 취소 팝업을 띄웁니다. |
| 화면 꺼짐 방지 | 녹음 중에는 화면이 꺼지지 않습니다. 일시정지하거나 종료하면 해제됩니다. |
| 백그라운드 녹음 | 백그라운드 서비스로 앱이 뒤로 가도 녹음을 유지합니다 (Android 알림 "AI회의록 / 녹음 중"). |

### 3.3 종료 팝업 ("녹음을 종료할까요?")
- **참석자 수**: 1~2명 / 3~6명 / 7~10명 / 11명 이상. 안내 문구는 "실제 발화자를 기준으로 입력하면 인식률이 향상됩니다."입니다.
- **인식 언어**: 한국어(기본) / 영어 / 일본어 / 중국어
- **요약 템플릿**: 서버 목록(`type=normal`)에서 고릅니다. 3초 안에 응답이 없으면 템플릿 없이 진행합니다.
- **회의록 제목** 입력
- 확인하면 녹음을 종료하고, 메타데이터를 저장한 뒤 업로드 큐에 등록합니다.

### 3.4 자동 보호 동작
| 상황 | 동작 |
|---|---|
| 최대 3시간 도달 | 자동으로 일시정지하고 종료 팝업을 띄웁니다. "최대 녹음 시간(3시간)에 도달하여…" |
| 저장공간 95% 초과 | 10초마다 확인하다가 넘으면 녹음을 중지하고 "디스크 용량이 95%를 초과하여 녹음이 중지되었습니다." 팝업을 띄웁니다. |
| 전화 수신 | 자동으로 일시정지하고, 통화가 끝나면 자동으로 재개합니다 (토스트/알림). 사용자가 직접 일시정지했다면 재개하지 않습니다. |
| 통화 중 시작/재개 시도 | "녹음할 수 없습니다" 팝업을 띄웁니다. |
| 유선 이어폰 연결/해제 | 자동으로 일시정지하고 토스트를 띄웁니다. |
| 블루투스 연결 변경 (iOS) | 녹음 스트림을 자동으로 다시 시작해 녹음을 이어갑니다. |

## 4. 그룹 녹음 기능 상세

주요 파일: `lib/views/group_recording/*`, `lib/services/group_recording/*`

### 4.1 전체 흐름
```
[방장] 그룹 생성 ─┐
                  ├─ 로비(대기실) ─ 방장 [녹음 시작] ─ 전원 동시 녹음 ─ 방장 [종료] ─ 결과 화면 ─ 회의록 생성
[구성원] 코드 입력 ┘
```
서버 방 상태: `active → recording → collecting(업로드 수집) → merging(병합) → transcribing(전사) → done | failed`. 방장이 나가면 `cancelled`가 됩니다.

### 4.2 방장 vs 구성원 기능 비교 ★

| 단계 | 방장 (진행자) | 구성원 (참여자) |
|---|---|---|
| 입장 | [그룹 생성]을 누르면 4자리 코드가 발급됩니다. | [그룹 참여]에서 4자리 코드(영문·숫자, 자동 대문자)를 입력합니다. |
| 로비 화면 제목 | "그룹 녹음 (진행자)" | "그룹 녹음 (참여자)" |
| 그룹 코드 | 크게 표시되고, 탭하면 복사됩니다. | 동일 |
| 참여 인원 | "참여자 N명"이 실시간으로 갱신됩니다. | 동일 |
| 녹음 시작 | **[녹음 시작] 버튼** ("모든 참여자가 준비되면 녹음을 시작하세요.") | 버튼 없음. "진행자가 녹음을 시작하면 자동으로 시작됩니다." |
| 음량 점검 (iOS) | 로비 진입 시와 시작 직전에 음량이 50% 미만이면 "기기 음량을 높여주세요"를 띄우고 **시작을 막습니다.** | 녹음 시작 전에 한 번 안내합니다 (차단하지 않음). |
| 음량 (Android) | 싱크음을 재생하는 동안 미디어 볼륨이 50% 미만이면 60%로 자동으로 올렸다가 되돌립니다. | 동일 |
| 녹음 중 화면 | 경과 시간, [그룹코드 XXXX], 파형 | 동일 |
| 일시정지/재개 | **가운데 버튼으로 전원 일시정지/재개** | 버튼 없음. 상태 표시만 하고 "진행자가 녹음을 일시정지/재개했습니다." 토스트를 띄웁니다. |
| 종료 | **[완료] 버튼 → 종료 팝업** (참석자 수, 언어, 템플릿, 제목). "모든 참여자의 녹음이 종료됩니다." | 버튼 없음. "진행자가 종료할 때까지 대기" |
| 취소/나가기 | "진행자가 나가면 그룹 녹음이 취소되고 **모든 참여자의 녹음이 저장되지 않습니다.**" | "세션에서 나가면 녹음이 저장되지 않습니다." (본인 녹음만 폐기되고, 다른 사람은 계속 녹음) |
| 방장 이탈 시 | (방 취소) | "방장이 그룹 녹음을 취소했습니다." 토스트와 함께 녹음을 폐기하고 홈으로 이동합니다. |
| 업로드 데이터 | 녹음 + 참석자 수, 언어, **템플릿, 제목** | 녹음 + 언어 (템플릿/제목 없음) |

### 4.3 참여 제한/오류 안내
| 상황 | 안내 문구 |
|---|---|
| 코드가 4자리가 아님 | 코드 4자리를 입력해주세요. |
| 없는 코드이거나 만료된 코드 | 존재하지 않거나 만료된 그룹 코드입니다. |
| 정원 초과 | 그룹 정원(최대 5명)이 가득 찼습니다. |
| 이미 녹음이 시작된 방 | 이미 녹음이 시작되어 참여할 수 없습니다. → **중간 참여는 불가합니다.** |

### 4.4 싱크음 (기기 간 시간 맞추기)
- 목적: 서버가 여러 기기의 녹음을 같은 시점으로 맞추는 기준음입니다.
- 현재 설정: **비프음 + 안내 음성**, **모든 기기에서 재생** (`beepSource=all`). 종류는 beep / voice / jingle 3가지를 지원합니다.
- 시작: 녹음을 시작하고 약 3초 뒤에 "음성녹음을 시작합니다"와 비프음을 재생합니다.
- 종료: 비프음과 "녹음을 종료합니다"를 재생하고, **약 5초 동안 녹음을 유지한 뒤** 종료합니다. 이때 "녹음을 종료하는 중입니다..." 로딩이 표시됩니다.
- 안내 음성은 서버가 잘라내므로 최종 회의록에는 남지 않습니다.
- 일시정지 상태에서 종료하면 종료 싱크음을 생략합니다.
- 안내 포인트: **기기 음량을 충분히 높여야 정렬이 정확합니다.** 무음/진동 모드에서의 동작은 ⚠️ 확인이 필요합니다.

### 4.5 녹음 결과 화면
- "녹음 완료" + [그룹코드]
- 진행 문구가 다음 순서로 바뀝니다.
  - "각자의 녹음이 업로드되면 자동으로 회의록이 만들어집니다."
  - "녹음을 병합해 회의록을 만들고 있습니다."
  - "녹음 병합을 마치고 회의록을 만들고 있습니다."
  - 완료: "회의록이 준비되었습니다." / 실패: "회의록 생성에 실패했습니다."
- **참가자 업로드 현황**: 참가자별로 업로드 완료 / 대기 중 / 실패를 표시합니다. 진행률(%)은 표시하지 않습니다.
- [확인]을 누르면 메인으로 돌아갑니다. 녹음이 끝난 뒤이므로 업로드와 병합은 계속 진행됩니다.

### 4.6 안정성 처리 (최근 커밋 반영)
| 상황 | 동작 |
|---|---|
| 실시간 신호(SSE)가 유실됨 | 5초마다 방 상태를 조회해 시작/일시정지/재개/종료를 따라잡습니다. |
| 시작 신호를 늦게 받음 | 경과 시간을 맞춰 녹음을 시작하고, 30초 안이면 싱크음도 재생합니다. |
| 오디오 포커스를 빼앗기는 등의 이유로 의도치 않게 일시정지됨 | 즉시 자동으로 재개합니다 (일시정지는 방장만 할 수 있으므로). |
| 녹음 시작 후 3초 동안 마이크 입력이 없음 | "녹음 시작에 실패했습니다." 토스트를 띄웁니다. |
| 수집 마감 이후에 늦게 도착한 업로드 | 서버가 거부하면 **해당 녹음을 삭제합니다** (`groupUploadRejectPolicy=delete`). |
| 싱크음 캐시 손상 | 크기를 검증하고 다시 생성합니다. |

## 5. 녹음 이후 공통: 업로드와 재전송

주요 파일: `lib/services/file_upload_services/upload_service.dart`, `recording_failure_page.dart`

| 기능 | 동작 |
|---|---|
| 업로드 큐 | 녹음을 종료하면 자동으로 큐에 등록하고 순서대로 업로드합니다. |
| 네트워크 끊김 | 업로드를 중단하고 "네트워크 대기" 상태로 둡니다. 재연결되면 자동으로 다시 시작합니다. |
| 앱이 백그라운드로 감 | 업로드를 유지합니다 (Android는 포그라운드 서비스 사용). |
| 업로드 정체 | 진행률이 일정 시간 갱신되지 않으면 정체로 판단하고 실패 처리합니다. 큰 파일이 느린 네트워크에서 잘못 끊기지 않도록 전체 시간이 아니라 진행 정체를 기준으로 합니다. |
| 업로드 실패 | "업로드에 실패한 파일은 재시도 또는 삭제해 주세요." → [재시도] / [삭제] |
| 녹음 실패 목록 | 전송하지 못한 녹음 폴더 목록에서 [재전송] / [삭제]를 할 수 있습니다. 재전송할 때 이전에 입력한 참석자 수, 언어, 템플릿, 제목을 복원합니다 (오늘 커밋에서 수정). |
| 그룹 녹음 재전송 | 방이 이미 병합 단계 이후라면 보내도 합쳐지지 않으므로 업로드하지 않습니다. 번역 문구로는 "통합 회의록이 이미 생성되어 그룹 녹음 파일을 업로드하지 않습니다."가 있습니다. |

## 6. 예외 상황별 비교 (고객 FAQ 후보)

| 상황 | 단독 녹음 | 그룹 녹음 |
|---|---|---|
| 전화가 옴 | 자동으로 일시정지했다가 통화 후 재개 | ⚠️ 그 기기만 일시정지했다가 재개. 그 구간이 병합 결과에 어떻게 반영되는지 확인 필요 |
| 유선 이어폰 연결/해제 | 자동 일시정지 | 자동으로 즉시 재개 (일시정지는 방장 권한) |
| 네트워크 끊김 (녹음 중) | 영향 없음 (로컬 녹음) | 녹음은 계속됩니다. 방장의 일시정지/종료 신호는 재연결 후 폴링으로 따라잡습니다. |
| 네트워크 끊김 (업로드 중) | 재연결되면 자동 재개 | 동일. 단, 수집 마감 이후에 도착하면 삭제됩니다. |
| 앱을 실수로 나감 | 백그라운드에서 녹음 유지 | ⚠️ 앱이 강제 종료된 뒤 다시 들어왔을 때의 복귀 경로 확인 필요 |
| 방장이 녹음 중에 나감 | - | 전원의 녹음이 폐기됩니다. |
| 저장공간 부족 | 95%에서 자동 중지 | ⚠️ 같은 녹음 엔진을 쓰므로 동작은 같을 것으로 보이나, 그룹 화면 처리는 확인 필요 |

## 7. ⚠️ 확인이 필요한 사항 (안내 문서 작성 전)

> **2026-10-27 확인 결과**
> 1. 그룹 녹음 정책은 **1시간 제한**입니다. 단, 앱 코드에는 1시간 제한 로직이 없고 단독 녹음과 같은 3시간 타이머(`RecordingController.maxSeconds`)만 있습니다. → 서버에서 강제하는지 확인하고, 필요하면 앱 반영 여부를 검토해야 합니다.
> 2. 회의록은 방장이 선택한 옵션으로 병합되어 **참여자 각자의 회의록**으로 생성됩니다.
> 3. 늦은 업로드 처리는 안내 대상에서 제외합니다.
> 4. 정원은 방장 포함 최대 5명입니다.
> 5. 음소거 버튼은 안내에서 제외합니다.
>
> 업로드 이후 흐름: `folderProcess` → `UploadService.addUploadItem`(큐 저장) → `handleUploadQueue`(한 번에 1건, 완료 후 `_uploadNextPending`으로 다음 건) → 홈 `UploadProgressWidget` 업로드 패널(진행률, 속도, 남은 시간) → 업로드가 끝나면 SSE 변환 상태(`UploadedListener.handleStatusEvent`)로 변환 패널 표시(PROGRESS: 음성 인식 0~70%, STT_DONE/LLM-RUNNING: 요약 80~90%, DONE: 패널 제거 및 목록 갱신). 그룹 녹음 항목(roomId 있음)은 RETRY일 때만 홈 패널에 표시됩니다.

1. **그룹 녹음 최대 시간**: 그룹 녹음도 단독 녹음 엔진(`RecordingController`)의 3시간 타이머를 공유합니다. 3시간에 도달하면 단독 녹음용 종료 팝업(`stopRecordingDialog`)이 뜰 수 있는 구조여서, 방장과 구성원 각각에서 실제 동작을 테스트해야 합니다.
2. **회의록 결과물 귀속**: 코드 주석에는 "회의록은 각자의 Content로 남는다"고 되어 있습니다. 구성원 목록에도 같은 회의록이 생성되는지, 방장만 받는지 서버 정책을 확인해야 합니다.
3. **템플릿과 제목**: 방장의 선택만 업로드됩니다. 구성원 쪽 회의록에도 같은 템플릿과 제목이 적용되는지 확인이 필요합니다.
4. **"지금 마감하고 회의록 만들기"**: 문구와 API(`finishRoom`)는 있지만 현재 화면에서 쓰지 않습니다. 업로드가 늦은 참가자를 기다리는 시간이나 자동 마감 기준을 서버에 확인해야 합니다.
5. **정원 5명**: 앱 문구 기준입니다. 서버의 실제 제한값을 확인해야 합니다.
6. **그룹 코드 만료 시간**: 로비에서 오래 대기할 때의 정책을 확인해야 합니다.
7. **단독 녹음 음소거 버튼**: 개발자 옵션(숨김 메뉴의 "그룹녹음" 토글, 기본 OFF)일 때만 노출되므로 **고객 안내에서는 제외합니다.**
8. **인식 언어**: 4개 언어(ko/en/ja/zh)가 SKT에서 모두 제공되는지 확인이 필요합니다.
