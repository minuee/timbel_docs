# master-api → recog 병합 호출 테스트 가이드 (포스트맨)

`newDocs/master-api` 소스와 앱 소스(`newDocs/mobileapp`)를 읽고 정리했다.

## 0. 결론 먼저 — master-api 에는 "병합만 부르는" 엔드포인트가 없다

master-api 가 우리 `/v1/merge` 를 부르는 곳은 **병합 워커 한 곳**뿐이다
(`src/services/engine/merge.service.js` → `POST {RECOG_API_URL}/v1/merge`).
워커는 아래 두 가지 중 하나로만 돈다.

| 트리거 | 엔드포인트 |
|---|---|
| 방 참가자 **전원 업로드 완료** (자동) | `POST /contents/upload/encryption/files` (`roomId` 포함) |
| 방장이 수동 마감 | `POST /rooms/:roomId/finish` |

그래서 포스트맨으로 테스트하려면 **방 만들기 → (참가) → 시작 → 종료 → 암호화 업로드** 를
앱이 하는 순서 그대로 따라 해야 한다. 이 순서를 컬렉션으로 만들어 두었다.

| 파일 | 내용 |
|---|---|
| `test_samples/master_api/master_api_group_test.postman_collection.json` | 포스트맨 컬렉션 (Import) |
| `test_samples/master_api/upload_A·B·C/encrypted_audio_0.pcm` | 안내음성 샘플(`guide_voice/`) 3개를 앱과 똑같이 암호화한 업로드 파일 |
| `test_samples/master_api/encrypt_for_upload.py` | 다른 음성 파일을 업로드용으로 암호화하는 스크립트 |

## 1. 안 됐을 가능성이 큰 원인 3가지

### ① 인증 헤더 — 포트로 직접 붙으면 `Authorization: Bearer` 가 안 먹는다

`src/handlers/authenticate.handler.js` 기준:

| 붙는 방법 | 필요한 헤더 |
|---|---|
| 게이트웨이 경유 (`https://<주소>/api/...`) | `Authorization: Bearer <토큰>` (앱·웹이 쓰는 방식) |
| master-api 포트 직접 (`http://<서버>:9012/...`) | **`x-timblo-token: <토큰>`** |

- master-api 자체는 `x-timblo-token` 만 읽는다. `Authorization` 은 `NODE_ENV=development` 일 때만 읽는다.
  운영 모드로 떠 있으면 Bearer 만 보냈을 때 **401**.
- 토큰은 **서명 검증 없이 풀어서 `pid` 만 꺼낸다.** 그 `pid` 로 DB 의 멤버를 찾으므로,
  실제 로그인한 계정의 토큰이어야 한다 (멤버가 없으면 500 류 오류).
- 컬렉션은 두 헤더를 **둘 다** 보내도록 해 두었다. 어느 방법으로 붙든 그대로 된다.
- 경로도 다르다: 게이트웨이는 `/api/rooms`, 직접은 `/rooms` (`/api` 없음). `masterUrl` 변수에서 맞춘다.
- `x-timblo-auth` 헤더는 **넣지 말 것.** 들어가면 외부 서버 연동 인증으로 빠져서 다른 검사를 탄다.

### ② 업로드 파일은 반드시 암호화된 PCM 이어야 한다

`/contents/upload/encryption/files` 는 flac·wav 를 받지 않는다. 서버가 하는 일:

1. 받은 청크를 이름 끝 번호(`_0.pcm`, `_1.pcm` …) 순으로 정렬, 0 ~ `totalNum-1` 이 다 있는지 확인
2. 청크마다 **AES-256-CBC(PKCS7)** 복호화 → 이어 붙임 (키·IV = consul `AES_KEY` / `AES_IV` 를 UTF-8 바이트로)
3. **16kHz / mono / s16le PCM** 으로 보고 FLAC 변환

그냥 flac 을 올리면 복호화에서 깨진다(`bad decrypt`). 그래서 `upload_A·B·C` 를 미리 만들어 두었다.

⚠️ **키 주의**: 앱은 그룹녹음일 때 **일반 녹음과 다른 키**(`groupAudioEncKey`)로 암호화한다
(`mobileapp/lib/constants/app_const.dart`). master-api 쪽은 `AES_KEY` 하나뿐이므로
**테스트 서버의 consul `AES_KEY` 가 앱의 그룹녹음 키와 같아야** 한다. 미리 만든 파일은 앱의 그룹녹음 키로 암호화했다.
업로드가 500 으로 깨지면 서버 키가 다른 것이다 → 서버 값으로 다시 만든다 (5절).

### ③ 같은 계정·같은 파일명 재업로드는 거부된다

- 한 방에서 같은 계정이 두 번 올리면 `E16508 이미 업로드를 완료한 참가자입니다`
- 같은 계정이 예전에 쓴 `fileName` 을 다시 쓰면 중복 녹음으로 거부
- 병합이 시작된 방에 올리면 `E16509 수집이 마감되어 업로드할 수 없습니다`

→ 컬렉션은 업로드할 때마다 `fileName` 을 현재 시각으로 새로 만든다. **테스트를 다시 할 때는 1-1 방 생성부터** 다시 한다.

## 2. 엔드포인트 정리 (전부 인증 필요, 응답 = `{ message, httpCode, data }`)

| # | 누가 | 메서드·경로 | 바디 | 응답 `data` |
|---|---|---|---|---|
| 1 | 방장 | `POST /rooms` | `{"beepSource":"leader","syncSound":"beep"}` (JSON) | `{ roomId, code }` |
| 2 | 참가자 | `POST /rooms/:code/join` | `{"deviceId":"아무값"}` (JSON) | `{ roomId, code, memberCount }` |
| 3 | 방장 | `POST /rooms/:roomId/start` | 없음 | `{ roomId, status: "recording" }` |
| 4 | 방장 | `POST /rooms/:roomId/stop` | 없음 | `{ roomId, status: "collecting" }` |
| 5 | 각자 | `POST /contents/upload/encryption/files` | multipart (아래 표) | `{ room: true, roomId, fileKey }` |
| 6 | 누구나 | `GET /rooms/:roomId` | — | 방 상태 + `participants[].uploadStatus` |
| 7 | 방장 | `POST /rooms/:roomId/finish` | 없음 | `{ roomId, status: "merge-queued" }` |

- `beepSource`: `leader` | `all` (기본 `leader`), `syncSound`: `beep` | `voice` | `jingle` (기본 `beep`).
  둘 다 **방 만들 때만** 받고, 병합 때 우리 서버로 그대로 넘어간다. 안내음성+비프 샘플은 `leader` / `beep`.
- 방장은 방을 만들면 자동으로 참가자가 된다 (join 불필요). 정원 5명.

### 업로드 multipart 필드

| key | 값 | 비고 |
|---|---|---|
| `files` | `encrypted_audio_0.pcm` (파일) | 청크가 여러 개면 `files` 를 여러 줄 |
| `deviceId` | 아무 문자열 | 필수 |
| `fileName` | `A.Biz_m_rec_20261027_101500_A` 처럼 매번 새 값 | 필수. 컬렉션이 자동 생성 |
| `totalNum` | 청크 개수 (샘플은 `1`) | 필수 |
| `roomId` | 1번에서 받은 값 | **이게 있어야 그룹녹음 경로** (없으면 개인 회의록이 생김) |
| `lang` | `ko` | 선택 |
| `attendeeNum` | `3` | 선택 |
| `title`, `templateId` | | 선택. **방장 업로드 값만** 반영 |

## 3. 포스트맨 사용 순서

1. Import → `master_api_group_test.postman_collection.json`
2. 컬렉션 **Variables** 탭
   - `masterUrl`: 게이트웨이면 `https://<주소>/api`, 직접이면 `http://<서버>:9012`
   - 토큰 3개(`tokenHost`, `tokenP2`, `tokenP3`): **계정 3개** 가 필요하다 (한 계정은 한 방에 파일 1개)
     - 게이트웨이면 `emailX`/`passX` 를 넣고 0-2~0-4 로그인 → 자동 저장
     - 아니면 브라우저 F12 → Network → 아무 요청의 `x-timblo-token`(또는 `Authorization: Bearer` 뒤) 값을 복사
3. **1-1 방 생성** → `roomId`, `code` 자동 저장
4. **1-2, 1-3 참가** (참가자 계정)
5. **2-1 시작 → 2-2 종료** (방장)
6. **3-1 ~ 3-3 업로드** — Body 탭의 `files` 에 `upload_A`(방장)·`upload_B`·`upload_C` 의 `encrypted_audio_0.pcm` 을 고른다
7. 세 번째 업로드가 끝나는 순간 master-api 가 우리 서버에 `/v1/merge` 를 보낸다.
   **3-4 방 상태** 로 `status` 가 `merging` → `transcribing` → `done` 으로 가는지 본다

**계정이 1개뿐이면**: 1-1 → 2-1 → 2-2 → 3-1 만 하면 된다. 방장 혼자라 업로드 1개로 "전원 완료"가 되어 바로 병합된다
(파일 1개 병합 — 우리 서버는 `BEEP_MIN_TRACKS=1` 이라 비프 찾고 앞뒤 자르기까지 한다).

### 스웨거를 브라우저로 못 볼 때

`0-1` 요청 (`GET {masterUrl}/api-docs/swagger-ui-init.js`, 인증 없음) 응답 안의 `"swaggerDoc"` 이 스웨거 정의 전체다.
운영 모드면 `ENABLE_API_DOCS=true` 일 때만 열려 있다 (아니면 401). 이 가이드의 표가 소스 기준이라 스웨거 없이도 된다.

## 4. 확인할 곳

**우리 서버 로그** — 요청이 왔는지

```bash
docker logs <recog 컨테이너> 2>&1 | grep merge_alignment
```

guide_voice 샘플 3개 기준 기대값 (로컬 실측): `mode=beep`, offsets `0 / 544 / 1296`, `trimmedMs≈6776`, `drift.endFound=3`.
`participantId` 는 `f1` 이 아니라 **master-api 멤버 id** 로 온다.

**master-api 로그** — `[roomMerge]` 줄에 단계가 찍힌다

```
stage=COLLECT_CHECK joined=3 uploaded=3 merged=3
stage=MERGE_REQUEST accepted jobId=mrg_... files=3 beepSource=leader syncSound=beep
stage=MERGE_POLL done jobId=... align=beep dur=...ms
```

멈춘 `stage=` 가 어디냐로 원인이 갈린다.

| 멈춘 단계 | 의미 |
|---|---|
| 업로드 응답이 500 | 암호화 키 불일치 (1절 ②) |
| `PRESIGN_INPUT` / `PRESIGN_OUTPUT` | MinIO 서명 주소 발급 실패 (master-api 쪽) |
| `MERGE_REQUEST` | `RECOG_API_URL` 이 틀렸거나 우리 서버에 못 닿음 |
| `MERGE_POLL` 에서 ERROR | 우리 서버 처리 실패 → 우리 로그의 `error.code` 확인 |
| `MERGE_VERIFY` | 우리가 결과를 PUT 했는데 MinIO 에 없음 |

## 5. 다른 음성 파일로 업로드 파일 만들기

ffmpeg 과 openssl 이 필요하다. 3분 넘는 파일은 청크가 여러 개로 나온다 (`totalNum` 에 그 수를 넣고 `files` 를 여러 줄로).

```bash
# 앱의 그룹녹음 키로 (mobileapp 소스에서 읽음)
python3 newDocs/test_samples/master_api/encrypt_for_upload.py 내파일.flac out_dir

# 서버 consul 값으로 (서버 키가 앱과 다를 때)
AES_KEY='<consul AES_KEY>' AES_IV='<consul AES_IV>' \
  python3 newDocs/test_samples/master_api/encrypt_for_upload.py 내파일.flac out_dir
```

키 값은 이 문서나 커밋되는 파일에 적지 않는다.
