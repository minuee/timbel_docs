# 비프 동기화 병합 테스트 샘플

같은 회의실에서 폰 3대가 **녹음 시작 시점이 조금씩 다르게** 녹음한 상황을 합성한 파일이다.
서버가 비프음으로 어긋난 시간을 찾아 맞추는지 `/v1/merge/upload` 로 확인한다.

## 1. 파일

| 파일 | 역할 | 녹음 시작 지연 | 파일 속 비프 위치 | 들어 있는 목소리 |
|---|---|---|---|---|
| `phone_A.flac` | 방장 (비프 재생) | 0.30초 | 2.70초 | 김 팀장 (여성) |
| `phone_B.flac` | 참가자 | 0.85초 | 2.15초 | 박 책임 (남성) |
| `phone_C.flac` | 참가자 | 1.60초 | 1.40초 | 이 선임 (남성 저음) |

- 16kHz / mono / FLAC, 각 2분 50초 전후 (말 속도 초당 약 5음절)
- 내용: 3명의 반도체 공정 회의 (HBM 수율, 하이브리드 본딩, 노광 장비 일정)
- 방장 폰이 녹음 시작 신호 3초 뒤 `sync_beep.wav` 를 1회 재생 (삐-삐-삐 3번)
- 각 파일에는 **그 사람의 발언만** 들어 있다. 방장 비프는 세 파일 모두에 들어 있다

파일 하나만 STT 하면 한 사람의 말만 띄엄띄엄 나온다. **세 파일을 머지해야 3명의 대화가
완성된다.** 정렬이 맞으면 질문 → 대답 순서가 자연스럽게 이어지고, 틀리면 대답이 질문보다
먼저 나오거나 말이 겹친다.

**파일을 그냥 겹치면** B는 0.55초, C는 1.3초 어긋나 목소리가 메아리처럼 들린다.
**정렬이 되면** 메아리 없이 각 사람의 말이 한 번씩만 또렷하게 들려야 한다.

## 2. Swagger 로 테스트

1. 브라우저에서 `http://<서버>:<포트>/docs` 접속 (Basic 인증)
2. **`POST /v1/merge/upload`** → `Try it out`
3. 입력
   - `files`: `Add string item` 을 눌러 3칸을 만든 뒤 **A → B → C 순서로** 파일 선택
   - `beepSource`: `leader`
   - `roomNo`: `TEST-BEEP-001` (아무 값이나 가능)
   - 나머지는 기본값
4. `Execute` → 응답의 `jobId` 복사
5. **`GET /v1/merge/{jobId}`** 에 `jobId` 를 넣고 실행. `status` 가 `DONE` 이 될 때까지 몇 초 간격으로 반복
6. **`GET /v1/merge/{jobId}/download`** 로 결과 파일을 받아 직접 들어본다

## 3. curl 로 테스트 (Swagger 대신)

```bash
SERVER=http://127.0.0.1:28080      # 실제 서버 주소로 변경

curl -s -X POST $SERVER/v1/merge/upload \
  -F roomNo=TEST-BEEP-001 -F beepSource=leader \
  -F files=@phone_A.flac -F files=@phone_B.flac -F files=@phone_C.flac
# → {"jobId": "mrg_xxxx", ...}

curl -s $SERVER/v1/merge/mrg_xxxx | python3 -m json.tool       # DONE 될 때까지 반복
curl -s -o merged.flac $SERVER/v1/merge/mrg_xxxx/download
```

## 4. 기대 결과 (로컬에서 실제로 돌린 값)

`participantId` 는 올린 순서대로 `f1`(A), `f2`(B), `f3`(C) 이다.

| 항목 | 기대값 | 실측값 |
|---|---|---|
| `alignment.mode` | `beep` | `beep` |
| `f1` (A) `offsetMs` | 0 | 0 |
| `f2` (B) `offsetMs` | 550 | 546 |
| `f3` (C) `offsetMs` | 1300 | 1296 |
| `alignment.trimmedMs` | 약 5000 | 5062 |
| `output.durationMs` | 약 166000 | 165680 |
| 결과 파일 앞부분 | 비프 없이 바로 회의 시작 | — |

`offsetMs` 는 수십 ms 이내로 맞으면 정상이다.

### 비교용: 비프 없는 버전 (`no_beep/`)

같은 회의, 같은 지연인데 **비프만 뺀** 파일이다. 같은 방법으로 `no_beep/` 의 A·B·C 를 올린다.

| 항목 | 기대값 | 실측값 |
|---|---|---|
| `alignment` | `{"mode": "none"}` | `{"mode": "none"}` |
| `output.durationMs` | 약 171000 (잘리지 않음) | 170742 |
| 결과 파일 | 대화 타이밍이 0.5~1.3초씩 어긋난다 (말이 겹치거나 순서가 바뀜) | — |

두 결과 파일을 번갈아 들어보면 "비프를 못 찾았을 때" 어떤 소리가 나는지 알 수 있다.
실제 회의 결과가 이 `no_beep` 결과처럼 들리면 비프 검출에 실패한 것이다.

## 6. 서버 로그로 확인

```bash
docker logs <recog 컨테이너> 2>&1 | grep merge_alignment
```

```
"mode": "beep", ... "offsets": {"f1": 0, "f2": 546, "f3": 1296}, "fallbacks": {}   ← 비프 있는 버전
"mode": "none", ... "offsets": {}                                                 ← no_beep 버전
```

## 7. 판정

| 결과 | 의미 |
|---|---|
| 비프 있는 샘플이 `mode=beep` + 위 표와 비슷한 `offsetMs` | **서버 정상.** 실제 회의 녹음에서 문제가 나면 원인은 앱 녹음 쪽이다 |
| 비프 있는 샘플이 `mode=none` | 서버 설정 문제. `.env.recog` 의 `BEEP_ENABLED`·`BEEP_FREQ_*` 값을 확인한다 |
| 비프 있는 샘플이 `mode=beep` 인데 `offsetMs` 가 크게 다름 | 서버 검출 문제. 응답 JSON 전체를 공유한다 |

샘플 테스트가 정상이면, 같은 방법으로 **실제 회의 녹음 파일**을 올려 `mode` 를 비교한다.
실제 파일에서만 `none` 이 나오면 비프가 녹음되지 않은 것이다 (앱 에코제거·소음제거 의심).

## 부록: 샘플 다시 만들기 (macOS 전용)

`gen_samples.py` 로 만들었다. macOS `say` 한국어 음성과 ffmpeg 가 필요하다.
지연값은 스크립트의 `PHONES`, 비프 재생 시점은 `BEEP_AT` 에서 바꾼다.

```bash
python3 newDocs/test_samples/gen_samples.py "$PWD" newDocs/test_samples /tmp/gen_work
python3 newDocs/test_samples/gen_samples.py "$PWD" newDocs/test_samples/no_beep /tmp/gen_work --no-beep
```

세 사람 모두 macOS 한국어 음성 `Yuna` 로 읽고, 남성 두 명은 ffmpeg `rubberband` 로 목소리
높이를 낮춰 만든다 (약 267Hz → 126Hz / 107Hz). macOS 의 남성 한국어 음성(Eddy·Rocko)은
외국인 발음처럼 들려서 쓰지 않는다. ffmpeg 에 `rubberband` 필터가 있어야 한다.
