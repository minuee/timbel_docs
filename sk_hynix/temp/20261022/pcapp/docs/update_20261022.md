## ① 약관 동의 확인

### 판단 기준 — 모바일과 같다
모바일(`intro_controller.dart termsAgreeCheck`)은 앱을 켤 때 `POST {HMP_BASE_URL}/api/auth/sso/hmp` (body `{ empno }`) 를 부르고
응답 `httpCode` 가 **404 또는 422 면 약관 미동의**로 본다. PC 도 같은 API·같은 기준을 쓴다.

| 로그인 방식 | 언제 확인 | 비고 |
|---|---|---|
| 사번 로그인 | 로그인 응답 그대로 | 이 API 로 로그인하므로 추가 호출 없음 |
| MyAccess(SSO) | 로그인 성공 → 내 정보(`user/me`)로 사번을 받은 뒤 **한 번 더 호출** | 응답에 토큰이 또 오지만 **버린다**(SSO 세션 그대로) |
| 로그인 유지 복원 | 앱 켤 때 복원 직후, SSO 와 같이 | |
| 테스트(수동) 로그인 | 로그인 성공 뒤 **한 번 더 호출** (SSO 와 같음) | 사번은 **입력한 사번**. 비워 두면 내 정보(`user/me`)의 사번, 둘 다 없으면 확인 못 하고 통과 |

### 결과별 동작
| 응답 | 동작 |
|---|---|
| 200 | 지금처럼 마이크 테스트 화면 |
| **404 / 422** | **로그아웃**(로그인 유지 파일도 삭제) → 로그인 화면 + 안내 팝업 |
| 그 밖의 코드, 네트워크 오류, 사번 없음 | **막지 않음**(통과). 서버 문제로 동의한 사람까지 못 쓰면 안 되므로. 로그만 남김 |

- 녹음 화면에 있을 때는(로그인 유지 복원 직후 바로 녹음 시작한 경우 등) 세션 만료처럼 **화면을 빼앗지 않는다.** 로그아웃만 되고, 홈으로 돌아오면 로그인 화면 + 팝업
- 끄려면 `TERMS_CHECK_ENABLED` 를 `false` (그러면 예전처럼 사번 로그인 거절은 빨간 글씨로 서버 메시지)

### 팝업
```
┌──────────────────────────────┐
│ 약관 안내 메시지                │
│ PC 접속하신 뒤 AI회의록 시스템    │
│ (https://aimeeting.skhynix.com/)│  ← 누르면 기본 브라우저로 열림
│ 에서 약관 동의후 이용가능합니다    │
│  [ 로그아웃 ]   [ 앱 종료 ]      │
└──────────────────────────────┘
```
- [로그아웃]: 이미 로그아웃된 상태라 팝업만 닫고 로그인 화면에 남는다 → 웹에서 동의 후 바로 다시 로그인
- [앱 종료]: 앱 종료
- 다국어(`MULTI_LANG_ENABLED`) 켜져 있으면 고른 언어로 (ko / en / ja / zh-CN). 링크 주소는 `TERMS_AGREE_URL`
- 타이틀 바(최소화·닫기)는 팝업이 가리지 않는다

### 로그
| 메시지 | 언제 |
|---|---|
| `terms_check_begin` (hasEmpno) | SSO·복원 뒤 확인 시작 |
| `terms_check_passed` | 동의함 |
| `terms_not_agreed` (method: `empno` / `after_login`, httpCode, message) | 미동의 |
| `logout` (reason: `terms_not_agreed`) | 미동의로 로그아웃 |
| `terms_check_error` (error, httpCode) | 판단 못 함 → 통과시킴 |
| `terms_page_opened` / `terms_page_open_failed` | 팝업 링크 클릭 |

### 집에서 확인한 것
가짜 HMP 서버로 18가지 확인(모두 통과): 200/404/422/500/연결 끊김 판단, 사번 로그인 422 → 팝업 코드, SSO 미동의 → 로그아웃·로그인 화면·팝업 신호 1회, SSO 동의 → 토큰 그대로 메인 화면, 네트워크 오류 → 통과, 녹음 화면은 안 바꿈, 테스트 로그인 미동의 → 로그아웃·팝업 / 동의 → 메인 화면, 링크 열기.
**화면(팝업 모양)은 집에서 못 봤다** → 아래 표에서 확인.

## ② 로그인 유지 — 테스트 로그인에도 적용

ver.5 에서는 refreshToken 이 있는 로그인(SSO·사번)만 저장했다. 회사에서는 아직 테스트 로그인만 쓸 수 있어서 테스트 로그인도 저장한다.

- `SESSION_PERSIST_ENABLED=true` + "로그인 유지" 체크 → 테스트 로그인 → 앱 종료 → 다시 실행 → **로그인 없이** 마이크 테스트 화면
  - "로그인 유지" 체크박스는 사번 폼 안(위쪽)에 있다. 체크한 뒤 아래 테스트 로그인으로 로그인하면 된다
- 테스트 로그인은 refreshToken 이 없어서 **accessToken 이 만료되면 갱신 못 한다**
  - 다음 실행 때 이미 만료돼 있으면 복원하지 않고 로그인 화면(로그 `session_restore_skipped`), `session.dat` 삭제
  - 쓰는 도중 만료되면 예전과 같다(업로드 401 → 로그인 화면)
  - 토큰 만료 시각을 모르는 형식(JWT 아님)이면 일단 복원하고, 쓰다가 401 이 나면 위와 같이 처리
- 복원 직후에도 약관 확인(①)을 한다 — 저장된 사번으로
- 로그 `session_restored` 에 `hasRefreshToken`(테스트 로그인이면 false) 추가
- 참고: 웹도 refreshToken 이 없다고 함 → 서버가 따로 갱신해 주는지는 나중에 확인(지금은 무시)

집에서 확인: 유효한 토큰 → 저장·복원됨 / 만료 토큰 → 복원 안 하고 파일 삭제 / JWT 아닌 토큰 → 복원됨
