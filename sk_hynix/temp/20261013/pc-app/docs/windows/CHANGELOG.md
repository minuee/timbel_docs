# 변경 기록 (CHANGELOG)

이 프로젝트의 모든 주요 변경사항이 이 파일에 기록됩니다.

## [0.4.2] - 2025-10-31
### Changed
- `mic_state` 이벤트 상태값 통일: macOS와 동일하게 `"available"`/`"unavailable"`만 사용 (`"disconnected"` 제거)
- Windows `SendMicStateEvent`를 macOS 로직과 동일하게 수정
- UI 코드 업데이트: `mic_state` 처리에서 `"disconnected"` 체크 제거, `"unavailable"`만 처리

## [0.4.1] - 2025-10-21
### Policy
- Microphone fallback forbidden: 선택 마이크가 없거나 비활성(비ACTIVE)일 때 테스트/레벨미터/녹음 모두 시작 금지
- Start/Reinit 경로에서 기본(디폴트) 마이크 폴백 제거, 선택/세션 마이크만 사용
### Changed
- HandleStart: 다른 마이크로의 자동 대체 제거, 선택/세션 마이크 ACTIVE 필수 검사
- HandleReinitAudio: `GetDefaultDevice(eCapture)` 제거, 요청/세션/선택 마이크 ID만 허용 + ACTIVE 필수
- StartLevelMeterCaptureIfNeeded / HandleSetLevelMeter: 선택 마이크 ACTIVE 아닐 시 캡쳐 시작 금지 및 `mic_state: "unavailable"` 전송
### Fixed
- 마이크 제거 후 다른 활성 마이크로 자동 전환되어 레벨이 표시되던 문제 차단
- 재연결 시 선택 마이크 ACTIVE 복귀 이전에는 시작/레벨미터 미동작 보장

## [0.4.1] - 2025-10-21

## [0.4.0] - 2025-10-20

### ✨ 변경/추가 기능
- **파일명 정책(회차별 접미사) 도입**
  - 저장 경로: `recordings/{sessionId}/`
  - 파일명: `{sessionId}{(take)}_{segmentIndex}.{ext}`
  - 첫 녹음: 괄호 생략 → `sessionId_0`, `sessionId_1`, …
  - 같은 `sessionId` 재녹음: `(1)`, `(2)` 증가 → `sessionId(1)_0`, `sessionId(2)_0`, …
  - 한 run의 모든 세그먼트에 동일 take 번호 적용(첫 저장 전에 1회 확정)

### 🛡️ 안정성/정책 강화
- **녹음 시작 사전 용량 체크**: 시작 직전 여유 공간이 50MB 미만이면 녹음 시작 거부
  - 에러: `DISK_SPACE_CRITICAL` (UI가 시작 버튼 상태를 즉시 복구)
- **set_segment_config 응답 확장**: `disk_status`, `free_bytes` 포함
- **set_output_dir 직후** 디스크 상태 이벤트(`disk_status`) 1회 전송

### 🧰 기타
- 버전 업데이트: 0.4.0

## [0.3.2] - 2025-10-15

### 🐛 버그 수정
- **세그먼트 인덱스 초기화 누락 수정**
  - `HandleStart` 함수에서 `SegmentManager::Reset()` 호출 추가
  - 녹음 시작 시 세그먼트 인덱스가 0부터 시작하도록 보장
  - 파일명이 `{sessionId}_0.{ext}`부터 시작하여 일관성 유지

- **음소거 상태 초기화 누락 수정**
  - `HandleStart` 함수에서 `muteMic`, `muteSystem` 초기화 추가
  - 녹음 시작 시 음소거 상태가 false로 초기화되어 이전 상태가 유지되지 않도록 보장

- **일시정지 중 시간 점프 문제 수정**
  - **원인**: 일시정지 중에도 레벨미터 때문에 FIFO에 샘플이 계속 쌓여서 resume/stop 시 시간이 앞으로 점프 (최대 3초)
  - **해결**: 
    - `ProcessMicrophoneData`와 `ProcessSystemData`에서 `isRecording && isPaused` 조건 시 FIFO 푸시 차단
    - 마이크/시스템 스레드의 SILENT 분기에서도 동일하게 적용
    - `HandlePause` 호출 시 FIFO 큐와 리샘플러 상태를 즉시 초기화
  - **효과**: 일시정지 경계가 정확히 유지되어 resume/stop 시 시간 연속성 보장
  - **영향 없음**: 테스트 모드와 레벨미터 기능은 정상 동작 유지

- **Pause→Stop 시 파일 길이 +5초 늘어나는 문제 수정**
  - **원인**: `HandleStopTest()`에서 플래그 순서 레이스 - `drainOnStop=true` 후 `isRecording=false`로 설정되어 드레인 중 FIFO에 쌓인 샘플이 파일에 추가 기록됨
  - **해결**: 
    - `isRecording=false`를 **가장 먼저** 설정하여 세그먼트 기록 즉시 차단
    - 메모리 장벽(`std::atomic_thread_fence`)으로 플래그 전환 순서 보장
    - 이후 `drainOnStop=true` 설정으로 남은 버퍼는 비우되 파일에는 기록하지 않음
  - **효과**: Pause(10초)→Stop 시 정확히 10초(±블록 경계)만 저장
  - **영향 없음**: 최대 녹음시간 도달 후 경계 정지 로직은 정상 동작 유지

### ✨ 추가된 기능
- **중복 세션 ID 파일명 처리**
- **set_segment_config 응답 확장**
  - 응답 이벤트에 현재 디스크 상태(`disk_status`)와 가용 바이트(`free_bytes`) 포함
  - 상태 기준: ok(≥500MB), low(≥50MB), critical(<50MB)

### 🛡️ 동작 정책 강화
- **녹음 시작 사전 용량 체크**
  - 시작 직전 여유 공간이 50MB 미만이면 녹음 시작을 거부
  - 에러 코드: `DISK_SPACE_CRITICAL`
  - UI는 시작 버튼 상태를 즉시 복구하고 경고 메시지 표시

  - 동일한 세션 ID로 여러 번 녹음 시 Windows 스타일로 `(1)`, `(2)` 등을 파일명에 자동 추가
  - 저장 경로: `recordings/{sessionId}/` (세션별 폴더, 동일 폴더 내 파일명 구분)
  - 중복 번호는 첫 세그먼트 저장 시 결정되어 해당 녹음의 모든 세그먼트에 일관되게 적용
  - 예: 
    - 첫 번째: `recordings/session-abc/session-abc_0.pcm`, `session-abc_1.pcm`, ...
    - 두 번째: `recordings/session-abc/session-abc(1)_0.pcm`, `session-abc(1)_1.pcm`, ...
    - 세 번째: `recordings/session-abc/session-abc(2)_0.pcm`, `session-abc(2)_1.pcm`, ...
  - 암호화/평문 파일 모두 체크하여 충돌 방지
  - `Reset()` 호출 시 중복 번호 초기화되어 다음 녹음에서 재확인

### 📝 기술적 개선
- 녹음 시작 시 상태 초기화 순서 명확화
- 무음 감지, 세그먼트 관리, 음소거 상태가 모두 초기화되어 일관된 녹음 시작 보장
- 일시정지 동작 개선으로 타이밍 정확도 향상
- 파일 저장 시 중복 체크로 데이터 손실 방지

## [0.3.1] - 2025-10-14

### 🔐 암호화 방식 변경
- **AES-GCM → AES-CBC로 변경**
  - Dart 코드와 호환성을 위해 AES-CBC 모드로 변경
  - 키/IV 처리 방식 변경: HEX 파싱 → UTF-8 문자열 직접 사용
  - 파일 구조 변경: `IV(12) + 데이터 + 태그(16)` → `데이터만`
  - 키/IV는 코드에 하드코딩 (`b7671acf046542c4848d6162ee9733cc` / `baf766f829f8489a`)

### 🛠️ 복호화 도구 업데이트
- **Python 복호화 스크립트 수정** (`tools/aes256_decrypt.py`)
  - AES-GCM → AES-CBC로 변경
  - Dart 코드와 동일한 키/IV 처리 방식 적용
  - C++ AudioHelper로 암호화한 파일 복호화 가능

### 📝 문서 업데이트
- CHANGELOG에 암호화 방식 변경 사항 기록
- DEVELOPMENT_STATUS 버전 정보 업데이트

- **무음 감지 이벤트 정리**
  - 30초 무음 시 `sustained` 이벤트만 전송

  - 녹음 중에만 무음 감지 및 디스크 상태 체크

- **문서 제외 패키징**: `package.json`의 `build.files`에 `!docs/**` 추가로 앱 패키지에서 문서 제외

- **진행 시간 표시**: 타이머 기반 → 헬퍼 progress 기반으로 전환하여 실제 녹음 시간과 동기화
- **녹음 시간 유지**: stop 후에도 마지막 녹음 시간을 UI에 유지하여 테스트 결과 확인 가능
- **새 녹음 시 초기화**: 새 녹음 시작 시에만 시간을 00:00:00으로 리셋

#### 기술적 개선
- **JSON 이벤트 수정**: `SimpleJson`에서 문자열 리터럴이 bool로 잘못 매칭되던 문제 해결
- **Progress 전송 주기**: 1초 → 200ms로 단축하여 실시간성 향상
- **블록 단위 동기화**: 각 믹스 블록마다 progress 이벤트 전송으로 지연 최소화
- **테스트/녹음 모드 분리**: `isTestMode`와 `isRecording` 플래그로 테스트 시 파일 저장 방지
- **세그먼트 시간 계산 수정**: `handleSegmentReady`에서 시간 중복 계산 방지

#### 버그 수정
- **max_ms 초과 시 세그먼트 폐기**: 설정된 시간 초과 시 마지막 미완성 세그먼트를 저장하지 않고 폐기
- **이벤트 중복 로그 억제**: "설정된 녹음 시간이 완료되었습니다" 메시지 중복 출력 방지
- **버전 정보 로딩**: 초기화 시 "로딩중" 상태에서 실제 버전 정보로 즉시 전환
- **테스트 모드 파일 저장 방지**: 테스트 단계에서 캡쳐된 데이터가 파일로 저장되지 않도록 수정
- **stop 후 시간 표시 오류**: 녹음 중지 후 UI 시간이 실제 시간의 2배로 표시되던 문제 해결

## [0.3.0] - 2025-10-14

### ✨ 추가된 기능
- **음소거 인터페이스(`set_mute`)**
  - 마이크/시스템 개별 또는 전체 음소거 지원 (`target`: "mic"|"system"|"both")
  - 음소거 중에도 캡쳐는 계속하되 저장 데이터는 0으로 처리
  - 응답 이벤트: `mute_state` (현재 음소거 상태 전송)

- **레벨미터 토글(`set_level_meter`)**
  - 레벨미터 on/off 전역 제어
  - on 시 테스트/녹음 여부와 무관하게 캡쳐 시작 및 레벨 이벤트 전송
  - 일시정지(pause) 중에도 레벨미터가 활성화되어 있으면 마이크/시스템 레벨 이벤트 계속 전송 (파일 저장 없음)
  - 테스트 종료/녹음 종료 후에도 토글이 on이면 캡쳐 자동 재시작
  - 응답 이벤트: `level_meter_state`

### 🔧 동작 정책 개선
- **무음 감지**
  - 30초 지속 시 `sustained` 이벤트 전송
  - 사운드 감지 시 `off` 이벤트 전송
  - 테스트 모드에서는 무음 감지/디스크 상태 체크 비활성화
  - 녹음 중(isRecording=true)에만 무음 감지 수행

- **진행(progress) 이벤트**
  - 녹음 중에만 전송 (테스트/pause/레벨미터 전용 캡쳐 시 미전송)
  - `mic_seconds`를 파일 진행(`seconds`)과 동기화하여 pause 구간 합산 방지
  - pause/resume 시 시간 점프 없이 멈춤 시점부터 재개

- **레벨 이벤트**
  - 음소거 상태 또는 레벨미터 비활성화 시 0 RMS 전송
  - pause 중에도 레벨미터 활성화 시 마이크/시스템 모두 계속 동작

- **파일명 형식**
  - 변경: `{sessionId}_{YYYYMMDD}_{HHMMSS}.{ext}` → `{sessionId}_{n}.{ext}`
  - 암호화 파일: `start` 명령의 `file_extension` 사용 (기본값: `.pcm`)
  - 암호화 안 된 파일: 항상 `.raw`
