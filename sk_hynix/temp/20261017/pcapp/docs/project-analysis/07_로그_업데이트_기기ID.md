## 1. 로그

### 1-1. 로컬 로그 파일 (`src/main/logger.js`)

| 항목 | 내용 |
|---|---|
| 위치 | Windows `%APPDATA%\timbloRecApp\logs\`, macOS `~/Library/Logs/timbloRecApp/` |
| 파일 | `combine-YYYYMMDD.log`(전체), `error-YYYYMMDD.log`(error 만). 10MB 를 넘으면 `.1`, `.2` … 로 나뉜다 |
| 보존 | 종류별 **최근 7개 파일**. 날짜 기준이 아니라 파일 개수 기준이라, 로그가 많은 날에는 7일보다 짧게 남는다 |
| 형식 | JSON Lines. `{ timestamp(로컬+오프셋), level, process(main/renderer), message(이벤트 이름), ...상세 }` |
| 쓰기 | 직렬 큐로 순서를 보장한다. 쓰기에 실패하면 `logs/pending/` 에 남겼다가 다음 시작 때 흡수한다 |
| 콘솔 | 모든 로그를 `console.log` 로도 찍는다(개발 모드 터미널에 보임) |

**로그를 남기는 방법**
- 메인: `logger.logInfo / logWarn / logError / logDebug('이벤트_이름', { 상세 })`
  - **첫 인자는 이벤트 이름이다.** 로그 서버에서 이 이름으로 검색한다.
  - 상세에 `message` 키가 있으면 이벤트 이름을 덮어쓰지 않도록 `detail` 로 옮긴다.
  - 상세에 문자열을 그대로 넘기면 `{ value: ... }` 로 감싼다. 토큰처럼 민감한 값은 반드시 `{ token }` 처럼 키를 붙여서 넘긴다. 키 이름으로 가리기 때문이다.
- 사용자 동작: `logger.logUserAction('login_attempt', {...})` → `category: "user_action"`
  - 렌더러 버튼 클릭은 `developerAPI.logAction()` 으로 남긴다.
- 렌더러: `developerAPI.sendInfo/sendWarn/sendError/sendDebug` 로 남긴다.
  - 렌더러의 `console.*` 출력도 메인이 `console-message` 로 모아서 `channel: "console"` 로 기록한다.
- 헬퍼: stderr 출력은 `helper_error` 로 남긴다.
  - 헬퍼 이벤트는 debug 레벨이고, 레벨·진행 이벤트는 0.1% 만 샘플링한다.
  - 헬퍼 자체 로그 파일은 따로 있다(`04_오디오헬퍼.md`).

### 1-2. 로그 서버 전송 (`src/main/services/logShipper.js`)

```
logger.logWrite (파일 기록) → remoteSink → logShipper.enqueue → 메모리 큐 → 3초마다 최대 100건씩 POST
```

| 규칙 | 내용 |
|---|---|
| 대상 | `LOG_SERVER_MIN_LEVEL`(기본 info) 이상. 렌더러 console 로그는 warn 이상만 보낸다 |
| 주소 | `LOG_SERVER_URL` = `https://aimeeting.mobile.skhynix.com/m/api/pcapp/log`, body `{ logs: [...] }` |
| 인증 | apiService 로 보낸다 → Bearer 토큰과 `timblo-App-*` 헤더가 붙는다. **로그인 전에는 보내지 않고 쌓아 둔다** (게이트웨이가 토큰 없는 요청을 막음) |
| 401 | 토큰 갱신이나 세션 종료를 하지 않는다(`skipRefresh`). 로그 때문에 로그아웃되면 안 되기 때문이다 |
| 공통 필드 | 모든 로그에 `empno`(사번), `deviceId`(`pc-…`), `appOs` 를 붙인다 |
| 가리기 | 키 이름에 token/password/authorization/secret/cookie 가 들어가면 `***` 로 바꾼다. `Bearer xxx` 문자열은 마스킹한다. 긴 문자열은 2000자에서 자른다 |
| 실패 | 3초 → 6초 → … 최대 60초 간격으로 재시도한다. 큐가 2000건을 넘으면 오래된 것부터 버리고 `log_shipper_dropped` 로 알린다 |
| 종료 | 앱을 끌 때 최대 2초 동안 남은 로그를 한 번 더 보낸다 |
| 원칙 | 로그 서버가 죽어 있어도 앱은 그대로 동작한다. 이 모듈의 실패는 logger 에 남기지 않는다(무한 고리 방지) |

로그 서버 쪽 코드는 `docs/logserver/` 에 있다(앱 범위 밖).

## 2. 자동 업데이트 (`src/main/services/updateService.js`) — Windows 전용

```
앱 시작 → (Windows + 빌드본 + UPDATE_ENABLED + UPDATE_SERVER_URL 있음) 일 때만
  → {UPDATE_SERVER_URL}/latest.yml 로 버전 확인 (15초 타임아웃)
     ├─ 같거나 낮음 / 확인 실패 → 아무것도 안 함
     └─ 높음 → 화면이 로그인/마이크테스트면 업데이트 화면으로 전환 → 다운로드(진행률)
              → 조용히 설치(isSilent) → 앱 자동 재실행
              (녹음 화면이면 이번엔 건너뛰고 다음 실행 때 다시 확인)
```
- **강제 업데이트**다. 사용자에게 묻지 않는다.
- 확인은 앱을 켤 때 한 번만 한다. 그래서 녹음 중에 업데이트가 끼어들 일이 없다.
- 버전은 숫자 단위로 비교한다(`1.2.10 > 1.2.9`). 서버에 더 낮은 버전이 올라가 있어도 내려가지 않는다.
- 업데이트 서버는 파일만 올려 두는 폴더면 된다(electron-updater generic). 올릴 파일은 `latest.yml`, `timbloRecApp Setup <버전>.exe`, `.blockmap` 이다.
- electron-updater 는 npm 패키지가 아니라 `src/main/vendor/electron-updater.js` 번들을 쓴다(망분리 빌드용).
- 실패하면 전부 "업데이트 건너뜀"으로 처리한다. 업데이트 서버 장애 때문에 녹음을 못 하는 일이 없게 하기 위해서다.
- **현재 `UPDATE_SERVER_URL` 이 비어 있어 실제로는 동작하지 않는다.** 앱 버전도 `0.0.1` 이라 배포 전에 버전 정책이 필요하다.
- macOS 는 대상이 아니다.

## 3. 기기 ID (`src/main/services/deviceService.js`)

| 항목 | 내용 |
|---|---|
| 형식 | `pc-` + 32자리 hex. 같은 PC 면 항상 같은 값 |
| 만드는 법 | Windows `MachineGuid`(레지스트리) / macOS `IOPlatformUUID` 를 앱 고유 문자열과 섞어 SHA-256. 원래 하드웨어 값은 밖으로 나가지 않는다 |
| 예비 | OS 값을 못 읽으면 무작위 UUID 를 `userData/device-id` 에 저장해서 계속 쓴다 |
| 주의 | PC 를 같은 디스크 이미지로 복제했는데 sysprep 을 하지 않았다면 여러 대가 같은 값일 수 있다 |
| **쓰는 곳** | **로그 서버 전송의 `deviceId` 에만** 쓴다 |
| 쓰지 않는 곳 | **업로드의 `deviceId` 는 여전히 `'1'` 고정**(`authService.getDeviceId`). 서버가 기대하는 형식을 확인한 뒤 바꾸기로 한 상태 |

`timblo-Device` 헤더(`Windows_NT 10.0.xxxxx`)는 기기 ID 가 아니다. 모바일에서도 모델명을 보낸다.
