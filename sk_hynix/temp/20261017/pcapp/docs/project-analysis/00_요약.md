# 00. 프로젝트 요약 — SKHynixRecApp (timbloRecApp) PC 녹음 앱

> 기준: 2026-10-15 작업분(`docs/update_20261015.md`)까지 반영된 **현재 소스**.
> 이 문서는 남에게 프로젝트를 설명할 때 쓰는 요약본이다. 자세한 내용은 같은 폴더의 01~08 을 본다.
> 8월에 만든 옛 문서(`recording_architecture_*`, `electron_helper_interface.md` 등)는 현재 소스와 다른 곳이 있으니 그대로 믿지 말 것.

---

## 1. 무엇인가

**SK하이닉스 직원용 "AI 회의록 녹음기" PC 앱.**
Zoom·Webex 같은 온라인 회의나 대면 회의를 PC 에서 녹음한다. 마이크와 PC 에서 나는 소리를 함께 녹음해 서버로 올리면, 서버가 회의록(AI 요약)을 만든다.
회의록 서버는 모바일 앱과 같은 서버(`aimeeting.mobile.skhynix.com/m`)를 쓰고, 업로드 형식과 암호화 방식도 모바일과 같다.

- 실사용 대상: **Windows**. macOS 는 실행되는 수준으로만 유지한다.
- 내부 이름 `timbloRecApp`, 화면 이름 `SKHynixRecApp`, 녹음 이름 접두어 `A.Biz_pcapp_rec_`.

---

## 2. 기술 스택 한눈에

| 영역 | 기술 |
|---|---|
| 앱 | **Electron 38** + 순수 JavaScript (프레임워크·TypeScript·번들러 없음) |
| 화면 | HTML/CSS/JS 페이지 7개 |
| 녹음 엔진 | **별도 네이티브 프로세스**: Windows C++ (WASAPI + WebRTC 에코 제거), macOS Swift (ScreenCaptureKit) |
| 로컬 저장 | SQLite (`better-sqlite3`), 녹음 파일은 AES-256 암호화 조각 |
| 서버 통신 | axios, Bearer 토큰 |
| 배포 | electron-builder → Windows NSIS 설치 파일, 강제 자동 업데이트(electron-updater) |
| 제약 | **회사 PC 망분리**: `npm install` 불가 → 새 라이브러리는 `src/main/vendor/` 에 한 파일 번들로 넣는다 |

## 3. 구조

```
 [화면 (렌더러)]  로그인 · 마이크테스트 · 녹음 · 팝업 · 업로드옵션 · 업로드리스트
        │  preload.js 로 노출된 API 만 사용 (nodeIntegration off, contextIsolation on)
        ▼  IPC
 [메인 프로세스 main.js]  창 관리 · 업로드 · 딥링크 · DB · 인증/API/로그/업데이트 서비스
        │  stdin/stdout 한 줄 JSON
        ▼
 [오디오 헬퍼]  AudioHelper.exe — 마이크 + PC소리 캡처 → 에코 제거·믹싱 → 16kHz 모노
        │        → 3분마다 AES 암호화 조각 파일 저장
        ▼
 문서\SKHynixRecApp\recordings\{세션ID}\{세션ID}_1.pcm, _2.pcm …
        │  업로드(multipart, 폴더 안 파일 전부)
        ▼
 회의록 서버 → AI 요약
```

**핵심 원칙 4가지**
1. 오디오는 Electron 이 아니라 헬퍼가 직접 처리하고 직접 저장한다. Electron 은 명령과 이벤트만 주고받는다.
2. 토큰은 메인 프로세스 메모리에만 둔다. 디스크에도 렌더러에도 두지 않는다.
3. 서버 통신은 `apiService` 한 곳에서 한다. 서버 API 목록은 `apiEndpoints.js` 한 파일에 모여 있다.
4. **녹음은 끊기면 안 된다.** 세션 만료나 업데이트가 와도 녹음 화면은 건드리지 않는다.

## 4. 사용 흐름

```
앱 실행 → (남은 녹음 복구 안내) → (자동 업데이트)
 → 로그인: MyAccess(SSO, 브라우저→딥링크) / 사번 / 테스트
 → 마이크 테스트: 녹음 대상(마이크+PC소리 / 마이크 / PC소리), 마이크·출력장치 선택, 안내 동의
 → 녹음: 자동 시작. 일시정지·재개, 음소거, 항상 위, 최대 3시간
 → 종료 → "AI 요약 준비하기": 제목·언어·참석자 수·템플릿
 → 업로드(진행률 표시) → 성공하면 PC 의 녹음 파일 삭제 / 실패하면 업로드 리스트에 남아 재시도
```

## 5. 주요 정책 (꼭 알아야 할 규칙)

| 분야 | 정책 |
|---|---|
| 세션 | 메모리에만 보관한다. 앱을 다시 켜면 다시 로그인해야 한다. 만료가 다가오면 미리 갱신하고, 401 이 오면 1회 갱신 후 재시도한다 |
| 세션 만료 | 마이크 테스트 화면에 있을 때만 로그인 화면으로 보낸다. 녹음 화면은 그대로 둔다 |
| 녹음 저장 | `문서\SKHynixRecApp\recordings` 에 저장하고, 안 되면 `C:\SKHynixRecApp\recordings` 에 저장한다. 녹음 1건 = 폴더 1개, 3분 조각 파일 N개 |
| 녹음 이름 | `A.Biz_pcapp_rec_YYYYMMDD_HHmmss` (녹음 시작 시각, KST). 재업로드해도 같은 이름을 쓴다. 제목은 별도 필드다 |
| 암호화 | AES-256-CBC. 모바일과 같은 키를 쓴다(서버가 같은 방식으로 복호화) |
| 장치 | 녹음 중 선택한 마이크가 빠지면 녹음을 멈춘다. 다른 마이크로 자동으로 바꾸지 않는다. 기본 스피커가 바뀌면 PC 소리 캡처를 자동으로 다시 연결한다 |
| 디스크 | 50MB 미만이면 녹음을 시작하지 않는다. 녹음 중 부족하면 경고한 뒤 조각 경계에서 멈춘다 |
| 삭제 | 녹음 폴더 "아래" 경로만 지운다(잘못된 경로로 전체가 지워지는 것 방지) |
| 업로드 후 | 성공하면 PC 의 녹음 파일과 DB 기록을 지운다 |
| 복구 | 앱을 시작할 때 업로드 작업이 없는 녹음을 찾아 업로드 리스트에 올린다 |
| 부서장 알림 | 녹음을 시작할 때마다 서버에 안내 메일 발송을 요청한다(녹음 1건당 1회) |
| 로그 | 로컬 JSON 로그(종류별 7개 파일) + info 이상은 로그 서버로 보낸다. 사번·기기 ID 를 붙이고 토큰은 가린다. 로그인 전에는 보내지 않고 쌓아 둔다 |
| 업데이트 | Windows 전용 강제 업데이트. 앱을 켤 때 1회 확인하고, 녹음 화면에서는 하지 않는다. 실패하면 건너뛴다 |
| 설정 | `.env`(개발) → `src/config/app.config.json`(운영, 설치본에 포함) → 코드 기본값. 목록과 설명은 `.env.example` |

## 6. 알아둬야 할 것 · 위험 요소 Top 7

1. **최대 녹음 시간 판정 단위 오류 의심.**
   - 약 11분 15초를 넘는 녹음은 정상 종료해도 "최대 시간 도달"로 처리될 수 있다.
   - 위치: `recording.js` 의 `recording_stopped` 처리
2. **운영 전에 막아야 할 로그인.**
   - 사번 로그인이 비밀번호를 검증하지 않는다.
   - 테스트 로그인 폼이 켜져 있다.
   - 둘 다 `app.config.json` 에서 false 로 바꿔야 한다.
3. **에코 제거(AEC) 여부는 헬퍼 빌드에 달려 있다.**
   - 회사 PC 에서 `build.bat`(MSVC)로 빌드해야 들어간다.
   - 설정 → 버전 정보에 `AEC` 가 붙어 있는지 확인한다.
4. **헬퍼는 빌드할 때 컴파일되지 않는다.**
   - `src/helpers/windows/AudioHelper.exe` 파일을 그대로 설치본에 담는다.
   - 헬퍼 소스를 고쳤으면 exe 를 먼저 다시 빌드한다.
5. **비정상 종료 시 마지막 3분 이하 녹음은 사라진다.**
   - 그 전까지 저장된 조각은 다음 실행 때 복구 안내에 뜬다.
6. **서버와 정해야 할 임시값이 남아 있다.**
   - 업로드 `deviceId='1'`
   - `APP_OS=AOS`
   - 템플릿 응답 형식
   - `UPDATE_SERVER_URL`(비어 있음 = 업데이트 꺼짐)
   - 앱 버전 `0.0.1`
7. **로컬 DB 를 사용자 구분 없이 같이 쓴다.**
   - PC 를 여러 사람이 쓰면 업로드 리스트가 섞인다.
