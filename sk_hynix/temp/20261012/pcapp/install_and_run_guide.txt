# 회의 음성 녹음기 설치 및 실행 가이드

## 1단계: 개발 환경 설정

### Node.js 설치
1. https://nodejs.org/ 에서 LTS 버전 다운로드
2. 설치 후 확인:
```bash
node --version
npm --version
```

### Visual Studio 설치
1. Visual Studio Community 2022 다운로드
2. 워크로드: "C++를 사용한 데스크톱 개발" 선택
3. CMake 포함 설치

## 2단계: 프로젝트 설정

### 프로젝트 폴더 생성 및 초기화
```bash
mkdir meeting-recorder
cd meeting-recorder
npm init -y
```

### 필요한 패키지 설치
```bash
# Electron 및 개발 도구
npm install electron --save-dev
npm install electron-builder --save-dev

# 유틸리티
npm install uuid
```

## 3단계: Windows Helper 빌드

### CMake 빌드
```bash
cd src/helpers/windows
build.bat
```

빌드가 완료되면 `AudioHelper.exe` 파일이 생성됩니다.

## 4단계: Electron 앱 실행

### 개발 모드 실행 (권장)
```bash
# 프로젝트 루트에서 - 개발자 도구 포함
npm run dev
# 또는
electron . --dev
```

### 일반 실행
```bash
# 프로젝트 루트에서 - 개발자 도구 없음
npm start
# 또는
electron .
```

**주의**: 개발 중에는 반드시 `npm run dev`를 사용하세요. `npm start`는 개발자 도구가 없어 디버깅이 어렵습니다.

### 프로덕션 빌드
```bash
npm run build
```

## 5단계: 기능 테스트

### UI를 통한 테스트
1. **오디오 장치 확인**
   - 마이크와 시스템 오디오 장치가 감지되는지 확인

2. **녹음 테스트**
   - "테스트 시작" 버튼으로 오디오 캡처 테스트
   - 마이크와 시스템 오디오 레벨 확인

3. **실제 녹음**
   - "녹음 시작" 버튼으로 실제 녹음 진행
   - 일시정지/재개 기능 테스트
   - 주의: 시작 직전 디스크 여유 공간이 50MB 미만이면 녹음이 시작되지 않습니다. (에러 코드: DISK_SPACE_CRITICAL)

4. **장치 변경 테스트 (NEW!)**
   - 시스템 사운드 캡쳐 모드로 녹음 시작
   - 녹음 중에 Windows 사운드 설정에서 출력 장치 변경:
     * 스피커 → 이어폰
     * 이어폰 → 스피커
     * USB 헤드셋 → 내장 스피커
   - 캡쳐가 중단되지 않고 자동으로 새 장치에 재연결되는지 확인
   - UI에서 "device_reconnected" 이벤트 수신 확인

5. **마이크 장치 변경 테스트 (NEW!)**
   - USB 마이크를 기본 장치로 설정 후 녹음 시작
   - 녹음 중에 USB 마이크를 물리적으로 제거
   - 녹음이 즉시 중단되고 사용자에게 알림이 표시되는지 확인
   - 중단 시점까지의 데이터가 파일로 저장되는지 확인
   - UI에서 "MIC_DEVICE_LOST" 에러 이벤트 수신 확인

### AudioHelper 직접 테스트 (고급)

AudioHelper를 직접 실행하여 다양한 모드를 테스트할 수 있습니다.

#### 1. 마이크만 녹음 (MicOnly)
```powershell
cd src/helpers/windows
Set-Content cmds.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings"}',`
'{"cmd":"set_debug_files","enabled":"true"}',`
'{"cmd":"start","mode":"MicOnly","mic":"default","max_ms":"10000"}'
Get-Content .\cmds.json | .\AudioHelper.exe
```

#### 2. 시스템 사운드만 녹음 (SystemOnly)
```powershell
cd src/helpers/windows
Set-Content cmds.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings"}',`
'{"cmd":"set_debug_files","enabled":"true"}',`
'{"cmd":"start","mode":"SystemOnly","mic":"default","max_ms":"10000"}'
Get-Content .\cmds.json | .\AudioHelper.exe
```

#### 3. 마이크 + 시스템 믹싱 (MicPlusSystem)
```powershell
cd src/helpers/windows
Set-Content cmds.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings"}',`
'{"cmd":"set_debug_files","enabled":"true"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"10000"}'
Get-Content .\cmds.json | .\AudioHelper.exe
```

#### 4. 장시간 테스트 (10분)
```powershell
cd src/helpers/windows
Set-Content cmds.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings"}',`
'{"cmd":"set_debug_files","enabled":"true"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"600000"}'
Get-Content .\cmds.json | .\AudioHelper.exe
```

#### 5. 장치 변경 테스트 (NEW!)
```powershell
# 1단계: 시스템 사운드 캡쳐 모드로 녹음 시작
cd src/helpers/windows
Set-Content cmds.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings"}',`
'{"cmd":"set_debug_files","enabled":"true"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"120000"}'
Get-Content .\cmds.json | .\AudioHelper.exe

# 2단계: 녹음 중에 Windows 사운드 설정에서 출력 장치 변경
# 3단계: 로그에서 다음 메시지들 확인:
# - "Default render device changed to: [새 디바이스 ID]"
# - "System device change requested"
# - "Processing system device change"
# - "System device reconnected successfully"
```

#### 6. 마이크 장치 변경 테스트 (NEW!)
```powershell
# 1단계: 마이크+시스템 캡쳐 모드로 녹음 시작
cd src/helpers/windows
Set-Content test_mic_change.json -Value `
'{"cmd":"set_output_dir","directory":"test_recordings","sessionId":"test-session-123"}',`
'{"cmd":"set_segment_config","encryption_enabled":"true"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"600000","sessionId":"test-session-123"}'
Get-Content .\test_mic_change.json | .\AudioHelper.exe

# 2단계: 녹음 중에 USB 마이크를 물리적으로 제거
# 3단계: 로그에서 다음 메시지들 확인:
# - "Microphone device lost or disabled: [장치 ID]"
# - "Recording stopped due to microphone device change"
# - "Finalizing current segment on stop"
# 4단계: test_recordings/test-session-123/ 폴더에 세그먼트 파일 생성 확인
# - 파일명(현재): {sessionId}_{n}.pcm (암호화 안됨)
```

#### 7. AES256 암호화 테스트 (NEW!)
```powershell
# 암호화 활성화 테스트
cd src/helpers/windows
Set-Content test_aes256.json -Value `
'{"cmd":"set_output_dir","directory":"test_segments","sessionId":"aes-test-123"}',`
'{"cmd":"set_segment_config","encryption_enabled":"true"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"300000","sessionId":"aes-test-123"}'
Get-Content .\test_aes256.json | .\AudioHelper.exe

# 암호화 비활성화 테스트
Set-Content test_no_encrypt.json -Value `
'{"cmd":"set_output_dir","directory":"test_segments","sessionId":"raw-test-123"}',`
'{"cmd":"set_segment_config","encryption_enabled":"false"}',`
'{"cmd":"start","mode":"MicPlusSystem","mic":"default","max_ms":"300000","sessionId":"raw-test-123"}'
Get-Content .\test_no_encrypt.json | .\AudioHelper.exe

# 결과 확인:
# - recordings/{sessionId}/{sessionId}_{n}.pcm (Raw PCM)
```

#### 테스트 결과 확인
- `test_recordings` 폴더에 다음 파일들이 생성됩니다:
  - `YYYYMMDD_HHMMSS_mic-raw.wav` - 마이크 원시 데이터
  - `YYYYMMDD_HHMMSS_sys-raw.wav` - 시스템 오디오 원시 데이터  
  - `YYYYMMDD_HHMMSS_mix.wav` - 믹싱된 최종 데이터
- `test_recordings/{sessionId}/` 폴더에 세그먼트 파일들이 생성됩니다:
  - `{sessionId}_{n}.pcm` - Raw PCM 세그먼트 파일 (3분마다)
  - 예시: `abc123-def456-789/abc123-def456-789_0.pcm`
  - 예시: `abc123-def456-789_20250115_143325.raw` (Raw PCM)
- `test_segments/{sessionId}/` 폴더에 암호화 테스트 파일들이 생성됩니다:
  - `{sessionId}_{n}.pcm` - Raw PCM 데이터
- `AudioHelper.log` - 상세한 실행 로그

## 문제 해결

### 빌드 오류
- Visual Studio 2022가 설치되어 있는지 확인
- CMake가 PATH에 포함되어 있는지 확인
- Windows SDK가 설치되어 있는지 확인

### 오디오 장치 인식 안됨
- Windows 오디오 서비스가 실행 중인지 확인
- 마이크 권한이 허용되어 있는지 확인
- 관리자 권한으로 실행 시도

### 녹음 파일 생성 안됨
- 저장 경로에 쓰기 권한이 있는지 확인
- 디스크 공간이 충분한지 확인

### AudioHelper 테스트 오류
- **"초기화 중"에서 멈춤**: AudioHelper.exe 경로 확인
  ```powershell
  # 경로 확인
  Test-Path "src/helpers/windows/AudioHelper.exe"
  ```
- **JSON 파싱 오류**: cmds.json 파일 형식 확인
- **권한 오류**: 관리자 권한으로 PowerShell 실행
- **파일 생성 안됨**: test_recordings 폴더 쓰기 권한 확인

### 장치 변경 관련 문제 (NEW!)
- **장치 변경 감지 안됨**: 
  - Windows 오디오 서비스가 실행 중인지 확인
  - 관리자 권한으로 실행 시도
  - 다른 오디오 앱이 장치를 독점 사용 중인지 확인
- **재연결 실패**:
  - 새 장치가 활성 상태인지 확인
  - 장치 드라이버가 정상 설치되어 있는지 확인
  - 로그에서 구체적인 오류 메시지 확인
- **캡쳐 중단됨**:
  - 마이크 캡쳐는 계속 유지되어야 함
  - 시스템 오디오만 재연결 시도 중
  - 전체 녹음이 중단되면 다른 원인 확인 필요

### 마이크 장치 변경 관련 문제 (NEW!)
- **마이크 변경 감지 안됨**:
  - 마이크 장치가 실제로 제거되었는지 확인
  - Windows 사운드 설정에서 장치 상태 확인
  - 관리자 권한으로 실행 시도
- **데이터 저장 안됨**:
  - test_segments 폴더에 쓰기 권한이 있는지 확인
  - 세그먼트 설정이 올바르게 적용되었는지 확인
  - 로그에서 "Finalizing current segment" 메시지 확인
- **에러 이벤트 수신 안됨**:
  - UI에서 JSON 이벤트 파싱이 정상적으로 작동하는지 확인
  - 콘솔에서 "MIC_DEVICE_LOST" 에러 이벤트 확인

### 로그 확인 방법
- `AudioHelper.log` 파일에서 상세한 오류 메시지 확인
- 콘솔 출력에서 실시간 로그 모니터링

## 개발 팁

1. **디버깅**: `npm run dev`로 개발자 도구 열기 (F12)
2. **로그 확인**: 콘솔에서 헬퍼 프로세스 출력 확인
3. **성능 모니터링**: Task Manager에서 메모리 사용량 확인
4. **오디오 품질**: 16kHz/mono/PCM16 포맷으로 STT 최적화
5. **장치 초기화**: 개발자 도구에서 오디오 장치 초기화 상태 확인 가능
6. **장치 변경 디버깅 (NEW!)**: 
   - 로그에서 "device_reconnected" 이벤트 확인
   - 장치 변경 시 마이크 캡쳐는 계속 유지되는지 확인
   - 시스템 오디오 재연결 과정을 단계별로 모니터링
7. **마이크 장치 변경 디버깅 (NEW!)**:
   - 로그에서 "MIC_DEVICE_LOST" 에러 이벤트 확인
   - 마이크 제거 시 녹음이 즉시 중단되는지 확인
   - 중단 시점까지의 데이터가 세그먼트로 저장되는지 확인
8. **AES256 암호화 디버깅 (NEW!)**:
   - 로그에서 "Segment encryption enabled: true/false" 확인
   - 파일 확장자가 설정에 따라 .enc/.raw로 생성되는지 확인
   - 암호화된 파일 크기가 원본 + 28바이트인지 확인
   - 테스트 키가 올바르게 적용되었는지 확인

## 최신 업데이트 (2025-09-21)

### ✅ 새로 추가된 기능
- **AES256-GCM 암호화**: 실제 암호화 구현 (테스트 키 사용)
- **세그먼트 기반 저장**: 3분 단위 자동 분할 및 파일 저장
- **장치 자동 재연결**: 시스템 오디오 장치 변경 시 자동 감지 및 재연결

- **성능 최적화**: 마이크-마스터 아키텍처로 정확한 타이밍 보장

### 📊 현재 성능 지표

- **메모리 사용량**: 기본 ~50MB, 세그먼트 버퍼 ~11.5MB
- **CPU 사용률**: 유휴 2-3%, 활성 녹음 8-12%

### 🔄 개발 진행 상황
