## ① 녹음 시작 알림 메일에 토큰 붙이기

- `POST {MOBILE_SERVER_URL}/api/alert/recording?empno={사번}` 에 이제 `Authorization: Bearer {accessToken}` 이 붙는다
- 다른 API 와 같이 `apiService` 가 붙인다. 호출부는 바뀐 게 없다

### 참고 — 토큰이 붙는 API (확인 결과)
모든 서버 호출은 `apiService` 의 `client` 하나를 거치고, 요청 직전에 `Authorization`·`timblo-App-*` 헤더가 붙는다.
테스트용 수동 로그인(accessToken 직접 입력)도 같은 세션에 들어가므로 똑같이 붙는다.

| API | 토큰 |
|---|---|
| 업로드, 내 정보, 워크스페이스, 템플릿 목록, 로그 서버, **녹음 시작 알림 메일(오늘부터)** | 붙음 |
| 토큰 교환(SSO), 사번 로그인 | 안 붙음(로그인 전) |

- 수동 로그인은 refreshToken 이 없어서, 토큰이 만료되면 401 → 세션 끊김 → (마이크 테스트 화면일 때만) 로그인 화면
- 녹음 화면에 있을 때는 세션이 끊겨도 화면을 바꾸지 않는다(녹음 유지). 업로드가 실패하면 업로드 리스트에 남는다

## ② 로그 값이 한 글자씩 쪼개지던 문제

원인: `logger.logInfo(이벤트이름, 상세)` 의 **상세** 는 객체를 받도록 되어 있는데, 문자열을 넘기면
내부에서 펼치면서 `{ "0":"a", "1":"b", ... }` 가 되었다.
게다가 키가 숫자라서 로그 서버로 보낼 때 하는 토큰 가리기(키 이름에 `token` 이 있으면 `***`)도 빠져나갔다.

| 이렇게 쓰면 | 예전 | 지금 |
|---|---|---|
| `logInfo('x', 'abc')` | `{"0":"a","1":"b","2":"c"}` | `{"value":"abc"}` |
| `logInfo('x', 123)` / `logInfo('x', ['a','b'])` | 사라지거나 `{"0":...}` | `{"value":123}` / `{"value":["a","b"]}` |
| `logError('x', err)` (Error 객체) | `{}` (내용 사라짐) | `{"errorName","errorMessage","stack"}` |
| `logInfo('x', { token })` | 그대로 | 그대로 |

**권장 사용법** — 상세는 항상 객체로, 키 이름을 붙여서 쓴다.
```js
logger.logInfo('token_check', { token });          // 로컬 파일: 원문 / 로그 서버: "***"
logger.logInfo('upload_dir', { filePath: dir });
```
- ⚠️ `logInfo('token', 토큰문자열)` 처럼 쓰면 키가 `value` 라서 **로그 서버에도 원문이 간다**. 토큰은 꼭 `{ token }` 으로
- 렌더러의 `developerAPI.sendInfo(...)`, `developerAPI.logAction(...)` 도 같은 규칙이 적용된다

## ④ 업로드 실패 `filePath is not a directory` — 녹음 저장 위치 고정

### 원인
- 헬퍼가 `set_output_dir`(저장 경로)를 반영하지 못하고, `output_dir_set` 응답에 경로를 비워 보냈다(`undefined`)
- 그래서 헬퍼는 기본값 `recordings`(상대경로) = **헬퍼 작업 폴더** 기준으로 저장했다

- 앱은 `undefined/{uuid}` 를 업로드하려다 실패
- 헬퍼가 왜 경로를 반영 못 하는지는 회사 PC 에서만 재현 → 아래 수정은 **헬퍼가 어떻든 업로드되게** 만든 것

### 바뀐 동작
| | 예전 | 지금 |

## ⑦ 회사 헬퍼에 `AEC` 가 안 붙는 문제 — 확인 방법

`build.bat`(방법 B)은 WebRTC 라이브러리가 없으면 빌드를 **중단**한다. 그러니 B 로 만든 exe 가 제대로 들어갔다면 `AEC` 가 떠야 한다.
안 뜨면 지금 쓰는 exe 가 **A(집 Mac 에서 만든 것, WebRTC 없음)** 이거나, B 빌드 후 **복사가 실패**해 예전 exe 가 남은 것이다
(앱이 켜져 있으면 exe 가 사용 중이라 마지막 복사에서 `Failed to copy executable!`).

| # | 할 일 | 기대 결과 |
