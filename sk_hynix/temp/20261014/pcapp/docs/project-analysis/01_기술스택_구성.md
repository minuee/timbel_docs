# 01. 기술 스택 · 폴더 구성 · 설정

> 기준: 2026-10-15 작업분(`docs/update_20261015.md`)까지 반영된 **현재 소스**.
> 소스 위치는 `파일 · 함수` 로 적는다(줄번호는 코드가 바뀌면 어긋나므로 쓰지 않음).

---

## 1. 한 줄 정의

**Electron 데스크톱 앱 + OS별 네이티브 오디오 헬퍼(별도 프로세스)** 구조의 회의 녹음기.
마이크와 PC 소리(Zoom/Webex 등)를 함께 녹음해 암호화된 조각 파일로 저장하고, 서버에 올리면 서버가 AI 회의록을 만든다.
고객사는 SK하이닉스, 실사용 대상은 **Windows**. macOS 는 "실행은 되는 수준"으로만 유지한다.

---

## 2. 언어 · 런타임

| 영역 | 언어 / 기술 | 비고 |
|---|---|---|
| 앱 본체(메인 프로세스) | JavaScript (Node.js, CommonJS `require`) | TypeScript·번들러·프레임워크 없음 |
| 화면(렌더러) | 순수 HTML + CSS + JavaScript | React/Vue 등 없음. 페이지마다 `<script>` 하나 |
| Windows 오디오 헬퍼 | C++17, CMake, WASAPI, Windows CNG(BCrypt) | 선택적으로 WebRTC APM(에코 제거, AEC) 링크 |
| macOS 오디오 헬퍼 | Swift, Xcode 프로젝트, ScreenCaptureKit, AVFoundation, CryptoSwift | `AudioHelper.app` 번들 안의 CLI 프로그램 |
| 로컬 DB | SQLite (`better-sqlite3`, 동기 API) | `userData/app.db` |
| 빌드 · 설치본 | electron-builder → Windows NSIS 설치 파일 / macOS 앱 | |

### 주요 라이브러리 (`package.json`)

| 라이브러리 | 버전 | 쓰는 곳 |
|---|---|---|
| electron | ^38 (설치본 38.0.0) | 전체 |
| better-sqlite3 | ^12.4.1 | `src/main/db/*` |
| axios | ^1.12.2 | `src/main/services/apiService.js` (서버 통신 전부) |
| form-data | (axios 의존성으로 들어옴, package.json 에는 없음) | `main.js` 업로드 multipart 생성 |
| dotenv | ^17 | `main.js` 첫 줄. 개발용 `.env` 읽기 |
| uuid | ^9 | 녹음 sessionId |
| electron-log | ^5 | `audioHelperManager.js` 에서 불러오기만 하고 쓰지 않음. 실제 로그는 자체 `logger.js` |
| electron-updater | ^6.3.9 | **package.json 의 것은 쓰지 않음.** `src/main/vendor/electron-updater.js` (한 파일로 묶은 번들)를 사용 |

> **vendor 정책**: 회사 PC 는 망분리라 `npm install` 이 안 된다. 새 라이브러리는 의존성까지 JS 파일 하나로 묶어
> `src/main/vendor/` 에 넣는다(`src/main/vendor/README.md`). package.json 에 새 의존성을 추가하면 회사에서 빌드할 때 깨진다.

## 3. 폴더 구성 (앱 관련만)

```
recording-pc-app/
├─ package.json                 # 앱 이름 timbloRecApp, 버전 0.0.1, electron-builder 설정(build 항목)
├─ .env.example                 # 설정값 전체 목록 + 설명 (★ 설정의 "사전")
├─ build/entitlements.mac.plist # macOS 권한
├─ electron-resources/          # 앱 아이콘
├─ scripts/                     # afterPack/afterSign(macOS 서명 확인), 딥링크 프로토콜 등록 보조
└─ src/
   ├─ config/app.config.json    # ★ 운영 설정값 (설치본에 포함)
   ├─ main/                     # 메인 프로세스 (Node.js)
   │  ├─ main.js                # 진입점. 창 생성, IPC 대부분, 업로드, 딥링크, 앱 생명주기 (약 1,400줄)
   │  ├─ preload.js             # 렌더러에 노출할 API (contextBridge)
   │  ├─ audioHelperManager.js  # 헬퍼 프로세스 실행 · stdin/stdout JSON 중계
   │  ├─ recordingDir.js        # 녹음 저장 위치 결정, 삭제 가능 경로 검사
   │  ├─ config.js              # 설정 읽기 (.env → app.config.json → 기본값)
   │  ├─ logger.js              # 로컬 로그 파일(JSON Lines) + 로그 서버로 넘기는 출구
   │  ├─ db/                    # SQLite 테이블별 함수 (recordings, jobs, summaries, memos, tags)
   │  ├─ ipc/handleAuth.js      # 로그인 화면 ↔ 메인 화면 전환(loadHome), 인증 IPC
   │  ├─ ipc/handleWindow.js    # 전부 주석 (미사용)
   │  ├─ windows/               # 보조 창: popup(공용 팝업), summarize(업로드 옵션), uploadList
   │  ├─ services/              # 인증·API·사용자·템플릿·로그전송·업데이트·기기ID·복구
   │  └─ vendor/                # npm 없이 쓰는 번들 라이브러리 (electron-updater)
   ├─ renderer/                 # 화면
   │  ├─ index.html / index.js  # 마이크 테스트(홈)
   │  ├─ pages/                 # login, recordingWindow, popupWindow, summarizeWindow, uploadList, update
   │  ├─ scripts/               # 각 페이지 JS (recording.js 가 가장 큼, 약 1,800줄)
   │  ├─ styles/ , assets/icons/
   │  └─ testPage.html, styles.css   # 옛 테스트 페이지 (미사용)
   └─ helpers/
      ├─ windows/               # C++ 소스 + 빌드된 AudioHelper.exe (설치본에 그대로 들어감)
      └─ macos/                 # Xcode 프로젝트(AudioHelper/) + 빌드된 AudioHelper.app
```

`docs/` 아래 `logserver`, `build-offline`, `helper-build`, `dbeaver` 등은 앱 바깥(서버·빌드 도구)이라 이 분석에서는 다루지 않는다.

## 4. 설정 체계

### 4-1. 읽는 순서 (`src/main/config.js · get`)

```
1. 환경변수 / .env           ← 개발할 때만. .env 는 설치본에 들어가지 않는다
2. src/config/app.config.json ← 빌드할 때 설치본에 같이 들어감. 운영 값은 여기에
3. 코드에 적힌 기본값
```
- 빈 문자열은 "설정 안 함"으로 보고 다음 순서로 넘어간다.
- 값 이름과 설명은 **`.env.example` 에 전부 있다.** 새 설정을 추가하면 여기도 같이 적는 것이 규칙.
- 설정을 읽는 곳은 주로 `services/authConfig.js`(로그인), `services/apiEndpoints.js`(API), `services/logShipper.js`, `services/updateService.js`, `recordingDir.js`.

### 4-2. 현재 `app.config.json` 값 요약

| 키 | 현재 값 | 의미 |
|---|---|---|
| `APP_DISPLAY_NAME` | SKHynixRecApp | 트레이 이름, 녹음 저장 폴더 이름 |
| `RECORDING_FILE_PREFIX` | A.Biz_pcapp_rec_ | 녹음 이름 접두어 |
| `SSO_LOGIN_URL` | amdev.skhynix.com/sso/... | MyAccess 로그인 페이지 (쿼리 XX 는 회사에서 채움) |
| `HMP_BASE_URL` / `HMP_LOGIN_PATH` | aimeeting.mobile.skhynix.com/m + /api/auth/sso/hmp | 사번 로그인 |
| `EMPNO_LOGIN_ENABLED` | true | 사번 로그인 폼 표시 (⚠ 운영은 false 권장) |
| `MANUAL_LOGIN_ENABLED` | true | 테스트 로그인 폼 표시 (⚠ 운영은 반드시 false) |
| `REFRESH_PATH` / `REFRESH_METHOD` | /api/auth/refresh, put | 토큰 갱신 |
| `DEFAULT_API_BASE_URL` / `MOBILE_SERVER_URL` | aimeeting.mobile.skhynix.com/m | API 서버 |
| `ALERT_ON_RECORDING_START` | true | 녹음 시작 시 부서장 안내 메일 |
| `APP_OS` | AOS | 서버로 보내는 OS 헤더 (임시값, PC 인데 안드로이드로 보냄) |
| `LOG_SERVER_*` | 켜짐, …/m/api/pcapp/log, info | 로그 서버 전송 |
| `UPDATE_ENABLED` / `UPDATE_SERVER_URL` | true / 빈 값 | 자동 업데이트 (주소가 비어 있어 **현재는 꺼진 것과 같음**) |

`.env.example` 에는 `HOST_NAME` 이 "기존 값"으로 남아 있다. `main.js` 에서 읽기는 하지만 콘솔 출력에만 쓴다(실질 미사용).

## 5. 빌드 · 패키징 설정 (`package.json` 의 `build`)

| 항목 | 값 | 의미 |
|---|---|---|
| appId / productName | `net.timbel.timblo.recapp` / `timbloRecApp` | 데이터 폴더 이름(`%APPDATA%\timbloRecApp`)이 여기서 정해진다 |
| protocols | `timbloRecApp://` | SSO 로그인 후 앱으로 돌아오는 딥링크 |
| files | `src/**/*` (C++ 소스·mac 헬퍼 소스 제외) | 앱 코드 전체가 asar 로 들어감 |
| extraFiles | `AudioHelper.exe`, `AudioHelper.app` | 설치 폴더의 `helpers/windows/`, `helpers/macos/` 에 복사 |
| win.target | nsis (원클릭 아님, 설치 경로 변경 가능) | 바로가기·제거 이름은 `SKHynixRecApp` |
| npmRebuild | false | 네이티브 모듈(better-sqlite3) 재빌드 안 함 → node_modules 의 빌드본을 그대로 씀 |
| publish | `update-server.invalid` (가짜) | 실제 업데이트 주소는 런타임에 `UPDATE_SERVER_URL` 로 지정 |

**알아둘 점**
- **헬퍼는 빌드할 때 컴파일하지 않는다.** `src/helpers/windows/AudioHelper.exe` 에 이미 있는 파일을 그대로 담는다.
  그래서 헬퍼 소스를 고쳤으면 먼저 헬퍼를 빌드해서 exe 를 갈아 끼워야 한다(`build.bat` = MSVC + AEC, `build-mingw.sh` = Mac 에서 크로스 빌드, AEC 없음).
- 이름이 세 가지라 헷갈린다.
  - `timbloRecApp`: 내부 이름 — 데이터 폴더, 딥링크, 설치 파일명
  - `SKHynixRecApp`: 화면에 보이는 이름 — 바로가기, 트레이, 녹음 폴더
  - `A.Biz_pcapp_rec_`: 녹음 파일 이름 접두어
- `build.files` 가 `src/**/*` 라서 개발 중에 생긴 `src/helpers/windows/recordings`(테스트 녹음)나 테스트 json 까지 설치본에 들어갈 수 있다 → `08_확인필요.md`.
- 앱 버전이 `0.0.1` 이다. 자동 업데이트는 버전 비교로 동작하므로 배포 전에 올려야 한다.

## 6. 사용자 PC 에 생기는 파일 (Windows 기준)

| 무엇 | 위치 | 만드는 곳 |
|---|---|---|
| 로컬 DB | `%APPDATA%\timbloRecApp\app.db` (+ WAL 파일) | `db/db.js` |
| 앱 로그 | `%APPDATA%\timbloRecApp\logs\combine-YYYYMMDD.log`, `error-YYYYMMDD.log` | `logger.js` |
| 템플릿 캐시 | `%APPDATA%\timbloRecApp\templates.json` | `services/templateService.js` |
| 기기 ID 예비 파일 | `%APPDATA%\timbloRecApp\device-id` (OS 값을 못 읽을 때만) | `services/deviceService.js` |
| 녹음 파일 | `문서\SKHynixRecApp\recordings\{sessionId}\{sessionId}_N.pcm` (안 되면 `C:\SKHynixRecApp\...`) | 헬퍼 (경로는 `recordingDir.js`) |
| 헬퍼 로그 | `<설치폴더>\helpers\windows\AudioHelper.log` (경고 이상만 기록) | 헬퍼 `Logger.cpp` |

macOS: 데이터는 `~/Library/Application Support/timbloRecApp/`, 녹음은 `/tmp/recordings/`, 헬퍼 로그는 `~/Library/Application Support/timbel.AudioHelper/Logs/`.
