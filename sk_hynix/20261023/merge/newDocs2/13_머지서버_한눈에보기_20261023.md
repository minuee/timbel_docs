# 음성 병합(머지) 서버 한눈에 보기

> 2026-10-23 기준 (0.0.5). 오랜만에 다시 볼 때 이 문서부터 읽는다.

---

## 1. 한 줄 요약

**그룹녹음에서 참가자 폰마다 따로 녹음된 파일들을, 싱크음(비프) 기준으로 시작점을 맞춰 하나로 겹쳐 합치는 서버.**
이어붙이기가 아니라 겹치기다. 3명이 1시간 회의했으면 결과도 1시간이다.

---

## 2. 전체 흐름

```
 앱(폰 여러 대)                master-api                 머지 서버(우리)              저장소(MinIO)
 ─────────────                ──────────                 ──────────────              ─────────────
 녹음 + 싱크음 재생  ──업로드──▶  파일 저장  ─────────────────────────────────────────▶  참가자 파일
                               병합 요청 ──(파일 주소들)──▶  ① 파일 내려받기  ◀─────────  
                                                          ② 비프 찾고 맞추고 합치기
                               상태 조회(반복) ◀──────────  ③ 결과 올리기  ──────────────▶  결과 파일
                               STT 요청 ───▶ STT 엔진
```

- master-api 와 머지 서버는 **같은 도커 네트워크**에서 컨테이너 이름으로 직접 통신한다 (인증 없음).
- 머지 서버는 저장소 계정이 없다. master-api 가 주는 **서명된 주소(presigned URL)** 로만 내려받고 올린다.
- 테스트할 때는 Swagger(`http://서버IP:9995/docs`) 에서 파일을 직접 올려 병합할 수 있다.

---

## 3. 앱이 울리는 소리 (싱크음)

```
녹음 시작 → (약 3초) "음성녹음을 시작합니다" → 3연타 비프 ─── 회의 ─── 3연타 비프 → "녹음을 종료합니다" → (5초) → 녹음 종료
                                             ↑ 여기 끝에서 앞을 자름          ↑ 여기 시작부터 뒤를 자름
```

- **방장 폰만** 울린다 (`beepSource=leader`). 방 안의 모든 폰이 그 소리를 같이 녹음한다.
- 서버는 비프를 기준으로 자르므로 **안내 음성은 결과에 남지 않는다.**
- 음원: `newDocs/assets/sync_sounds/` (`1_beep3.wav`, `2_voice.wav`, `2_voice_end.wav`)

## 4. 병합 처리 순서 (서버 안에서)

| 순서 | 하는 일 | 대상 | 끄는 설정 |
|---|---|---|---|
| ① | 파일 내려받기, 형식 통일 (16kHz·1채널) | 파일마다 | — |
| ② | **시계 오차 보정** — 시작 비프~종료 비프 간격을 재서 폰마다 속도를 미세하게 맞춤 | 파일마다 | `DRIFT_CORRECT=0` |
| ③ | **시작 비프 찾기** — 파일마다 자기 비프 위치 (5절) | 파일마다 | — |
| ④ | **오토믹서 볼륨 계산** — 순간마다 말하는 사람 앞의 폰만 살리고 나머지를 줄임 (울림·반복 제거) | 파일마다 | `MERGE_AUTOMIX=0` |
| ⑤ | 비프 위치가 같아지도록 밀어서 **겹치기** | 병합 | — |
| ⑥ | **앞뒤 자르기** — 앞은 시작 비프 끝까지, 뒤는 종료 비프부터 | 병합된 파일 | — |
| ⑦ | **음량 맞추기** — 작게 녹음된 목소리를 구간별로 키움 | 병합된 파일 | `MERGE_LEVEL=off` |
| ⑧ | 결과 올리기 | — | — |

어느 단계(②④⑦)가 실패해도 **병합 자체는 계속된다** — 그 기능만 빠진다.

## 5. 비프 찾는 순서 (파일마다 따로)

```
① 정식 기준  : 두 음(3000·4200Hz) 모두, 1초 간격 3번  + 그 자리가 순음인지 확인
② 느슨한 기준: 한 음만 있어도, 첫 비프 + 한 번 더 (말소리와 구별되는 순음·250ms 유지일 때만)
③ 안내 음성  : "음성녹음을 시작합니다" 끝을 찾아 그 뒤 비프 위치를 계산
────────────────────────────────────────────
셋 다 실패한 파일만 → 시작 시각(API 가 보낸 경우) → 그것도 없으면 0초부터 그냥 겹치기
```

- **파일이 1개여도** 찾으면 자른다.
- 다른 파일 결과에 기대지 않는다.
- 응답의 `tracks[].foundBy` 로 어떻게 찾았는지 알 수 있다 (없음=①, `relaxed`=②, `voice`=③).

## 6. 응답에서 볼 것 (`GET /v1/merge/{jobId}` 의 `alignment`)

| 필드 | 정상 | 뜻 |
|---|---|---|
| `mode` | `beep` | `none` 이면 어떤 파일에서도 비프를 못 찾음 |
| `tracks[].fallback` | 전부 `null` | `none` 이면 그 파일만 못 찾아 0초에 놓임 |
| `tracks[].foundBy` | 없음 / `relaxed` / `voice` | 어떻게 찾았는지 |
| `trimmedMs` | 수 초 | 앞에서 잘라낸 길이. **STT 시각 + trimmedMs = 원래 녹음 시각** |
| `drift.ppm` | 폰마다 수십~수백 | 폰별 시계 오차. 종료 비프가 있어야 나옴 |
| `automix` | `true` | 오토믹서 적용 여부 |
| `level` | `dynamic` | 음량 맞추기 설정 |

결과 파일 위치는 서버 로그 `merge_done` 줄의 `output` 에 나온다.

## 7. 주요 설정 (`.env`) — 기본은 전부 켜짐

| 설정 | 기본 | 뜻 |
|---|---|---|
| `BEEP_MIN_TRACKS` | `1` | 비프를 찾은 파일이 이 개수 이상이면 자른다. **2 면 파일 1개 병합이 항상 none** |
| `BEEP_GUIDED` | `1` | 비프 못 찾으면 다시 찾기 (②③) |
| `BEEP_GUIDED_MIN_RISE` | `25` | 느슨한 기준 문턱. 들리는데 못 잡으면 내린다 (10 미만 비권장) |
| `DRIFT_CORRECT` | `1` | 시계 오차 보정 |
| `MERGE_AUTOMIX` | `1` | 오토믹서 |
| `MERGE_LEVEL` | `dynamic` | 음량 맞추기 (`dynamic` 구간별 / `loudnorm` 전체 / `off`) |
| `SWAGGER_USER` / `SWAGGER_PASSWORD` | — | Swagger 화면 로그인 |
| `RUNTIME_DIR` | — | 데이터 폴더. **바꾸면 예전 병합 기록이 안 보인다** |

`.env` 를 고친 뒤에는 `docker compose --env-file .env up -d` 로 다시 띄운다 (`docker restart` 는 반영 안 됨).

## 8. 주소 목록 (API)

| 주소 | 용도 |
|---|---|
| `POST /v1/merge` | 병합 요청 (master-api 용, 서명된 주소로) |
| `POST /v1/merge/upload` | **테스트용** — 파일 직접 올려 병합 |
| `GET /v1/merge/{jobId}` | 작업 상태 조회 |
| `GET /v1/merge/{jobId}/download` | 테스트용 결과 내려받기 |
| `POST /v1/merge/{jobId}/retry` | 재작업 — 시간이 지났으면 **서명된 새 주소**를 넣어야 함 |
| `GET /v1/merge` | 이력 조회 (`roomNo` 로 거름. jobId 검색은 위의 조회 주소로) |
| `GET /docs` | Swagger (오른쪽 위 Authorize 에 토큰 넣으면 Bearer 헤더가 붙음) |

## 9. 문제가 생기면

| 증상 | 먼저 볼 것 |
|---|---|
| 비프가 있는데 안 잘림 | `sync-scan` 진단 명령 → `11_현장점검_20261026.md` 5~6절 |
| 재작업에서 access denied | 주소 만료 → 서명된 새 주소로 재작업 |
| 결과 파일 찾기 | 서버 로그 `merge_done` 의 `output` |
| 예전 jobId 가 안 보임 | `.env` 의 `RUNTIME_DIR` 이 바뀌지 않았는지 |
| 새 기능이 의심스러움 | 7절 설정으로 하나씩 끄기 |
