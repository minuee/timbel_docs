## 1. 출발점 — 사내 테스트에서 나온 문제 4가지

| # | 증상 | 오늘 조치 |
|---|---|---|
| 1 | 방장 비프가 모든 녹음에서 들리는데도 정렬이 `none` 이거나, 방장 트랙만 잘리고 다른 폰은 비프가 남음 | **비프 2차 탐색** + 진단 명령 `sync-scan` |
| 2 | 울림(하울링), 같은 말이 반복되어 들림 ("5초뒤5초뒤5초뒤") | **오토믹서** |
| 3 | 폰마다 녹음 길이가 늘어짐 (시계 오차, 드리프트) | **종료 싱크음으로 드리프트 보정** |
| 4 | 비프음 교체 검토, "음성녹음을 시작합니다" 안내 음성 | **싱크음 3종 선택** (`beep` / `voice` / `jingle`) |

## 2. 0.0.4 에 들어간 것

### 2.1 싱크음 3종 — `options.syncSound`

| 값 | 시작 (안내 음성 → 싱크음) | 종료 (싱크음 → 안내 음성) |
|---|---|---|
| `beep` (기본) | "음성녹음을 시작합니다" → 3연타 비프 | 3연타 비프 → "녹음을 종료합니다" |
| `voice` | "음성녹음을 시작합니다" | "녹음을 종료합니다" |
| `jingle` | "음성녹음을 시작합니다" → 5음 멜로디 | 5음 멜로디 → "녹음을 종료합니다" |

> 서버는 시작은 싱크음 **끝**에서, 종료는 싱크음 **시작**에서 자른다 → 안내 음성은 결과에 남지 않는다.
> 싱크음을 못 찾으면 그 파일 혼자서 느슨한 기준 → 안내 음성 위치로 대신 계산 (2026-10-23).

- 음원: `newDocs/assets/sync_sounds/` (앱은 파일을 그대로 재생, 폰 TTS 금지)
- **서버는 API 가 보낸 값 한 가지만 찾는다** (자동으로 3종을 다 찾지 않음 — 결정 사항)
- 재생 시각: 녹음 시작 후 **약 3초** (서버는 0~10초 안에서 찾으므로 정확할 필요 없음)
- 시작은 **안내 음성 → 싱크음**, 종료는 **싱크음 → 안내 음성** (앱에 10/22 전달한 그대로)
- 검토 후 탈락: 화음·3음 상승·스윕 (듣기 좋지 않음), 음성 밑 숨은 표식 (거슬림)

### 2.2 비프 2차 탐색 (증상 1)

1차 검출은 "두 음 모두 · 세 번 모두 · 배경의 6배" 를 요구한다. 멀리 있는 폰이 한쪽 음을 약하게
받거나, 폰의 노이즈억제가 2·3번째 비프를 깎으면 귀에는 들려도 1차를 못 넘는다.

→ 한 트랙에서라도 비프를 찾으면, 못 찾은 트랙을 그 위치 앞뒤 3초에서 **한쪽 음만, 첫 비프 + 하나 더**
로 다시 찾는다. 말소리를 비프로 잘못 잡지 않도록 순음인지·250ms 유지되는지를 따로 확인한다.

- 시뮬레이션: 1차가 놓친 5가지 경우를 오차 34ms 이내로 회복, 대화만 있는 구간 104개에서 오검출 0
- 응답 `tracks[].guided: true`, 로그 `beep_guided`

### 2.3 오토믹서 (증상 2) — `options.automix`, 기본 켜짐

순간(10ms)마다 각 폰이 담은 에너지 비율만큼 볼륨을 준다. 말하는 사람 앞의 폰은 그대로,
같은 목소리를 멀리서 받은 폰은 최대 -20dB 줄인다.

- 시뮬레이션(3인): 이상적인 결과 대비 잡음비 11.4dB → **20.2dB**
- 비교하려면 `automix=false` 로 같은 파일을 한 번 더 병합해서 들어 본다

### 2.4 드리프트 보정 (증상 3)

시작·종료 싱크음 사이 간격을 트랙마다 재서, 기준 폰과 다른 만큼 미세하게 리샘플한다.
종료 싱크음 지점부터 뒤는 결과에서 잘라낸다.

- **앱 요청 필요**: 종료 버튼 → 바로 종료 싱크음 → 5초 뒤 실제 종료·업로드
- 종료 싱크음이 없으면 보정 없이 지금처럼 병합 (앱 반영 전에도 문제없음)
- 시뮬레이션: 넣은 오차 +500/0/-400ppm → 측정 +499.6/0.0/-401.7ppm
- 응답 `alignment.drift`, 로그 `merge_drift`

### 2.5 진단 명령 `sync-scan`

망분리라 파일을 못 가지고 나오므로, 서버에서 녹음 파일을 넣으면 폰별로 싱크음을 찾았는지,
못 찾았으면 **어느 음·몇 번째 비프가 약한지** 숫자로 보여준다. 읽기 전용.

### 2.6 결과 파일 위치 로그

완료 로그 `merge_done` 에 `output`(업로드한 스토리지 경로, 서명 제거)과 `originalname` 추가.
이제 결과 파일을 찾으러 여기저기 뒤질 필요가 없다.

### 2.7 기본값 변경 — `beepSource`

`leader` → **`all`**. 지금처럼 방장만 울리면 요청에 **`beepSource=leader` 를 명시**할 것
(안 하면 앞부분이 0.3초 더 잘린다. 정렬 자체는 된다).

### 2.8 그 외

- `all` 모드(전원이 각자 울림)에서 다른 폰 비프가 먼저 들어오면 검출에 실패하던 버그 수정.
  지금 현장(방장만 울림)과는 무관하고, 나중에 `all` 로 갈 때 필요
- 결과 파일 위치 외 새 로그: `beep_guided`, `merge_drift`, 경고 `drift_failed` / `automix_failed` / `beep_guided_failed`
  (어느 기능이 실패해도 병합은 계속된다)

### 2.9 (2026-10-23 추가, 0.0.5 예정)

- 파일이 **1개여도** 비프 기준으로 자른다 (`BEEP_MIN_TRACKS` 2→1). 0.0.4 서버는 `.env` 에서 1 로 바꾸면 같은 효과
- 비프를 못 찾은 파일은 **그 파일 혼자서** 느슨한 기준 → 안내 음성 위치로 대신 계산
- 정식 기준으로 찾은 것도 순음인지 확인 (안내 음성의 ㅅ·ㅈ 를 비프로 잘못 잡는 것 방지)
- 종료: 비프 → "녹음을 종료합니다" (10/22 앱 전달 그대로). 종료 비프 **시작**부터 자름. 못 찾으면 안내 음성 위치로 계산
- **결과 음량 맞추기** (`MERGE_LEVEL=dynamic` 기본): 목소리가 작게 들리던 문제. 평균 약 +19 dB

`.env` 는 그대로 둬도 된다 (새 설정은 전부 기본값으로 켜져 있음).

### 3.2 병합 테스트

`POST /v1/merge/upload` (Swagger 또는 Postman):

```
files       [File]  폰별 녹음 (방장 포함)
beepSource  [Text]  leader        ← 꼭 넣기
syncSound   [Text]  beep
format      [Text]  wav           (들어 보기 편하게)
```

완료 응답 `alignment` 에서 볼 것:

| 필드 | 정상 |
|---|---|
| `mode` | `beep` |
| `tracks[].fallback` | 전부 `null` |
| `tracks[].guided` | `true` 가 있으면 2차 탐색으로 찾은 폰 (이번 수정 효과) |
| `automix` | `true` |

**들어 볼 것**: ① 맨 앞에 비프가 남아 있지 않은지 ② 울림·반복이 줄었는지
(같은 파일로 `automix=false` 를 한 번 더 돌려 비교)

### 3.3 안 되면

`07_현장진단가이드_비프정렬.md` 2절대로 `sync-scan` 실행 → 4절의 표만 채워 오면 된다.

```bash
docker cp phone_A.flac mobile-sync-server:/tmp/   # 파일마다
docker exec mobile-sync-server python -m recog sync-scan --sound beep --source leader /tmp/phone_*.flac
```

### 3.4 아직 테스트할 수 없는 것

- **드리프트 보정**: 앱이 종료 싱크음을 울려야 동작한다 (앱 반영 후)
- `voice` / `jingle`: 앱이 해당 음원을 울려야 한다 (앱 반영 후)
