# 병합 기록 조회 가이드

> 병합 작업 이력을 보는 방법. 서버 콘솔 없이도 볼 수 있다.
> 작성 2026-09-19

---

## 1. 기록이 어디에 있나

```
<RUNTIME_DIR>/merge.db          ← SQLite 파일 하나
```

`.env.recog`의 `RUNTIME_DIR` 설정을 따른다. 예시 환경 기준:

```
/data/timblo/recog-runtime/merge.db
```

**서버의 실제 파일**이다. 컨테이너 안이 아니라 호스트 디스크에 있으므로
`ls`로 보이고 복사할 수 있다. 보존 기간은 **90일**(`MERGE_RECORD_TTL_DAYS`).

## 2. 조회 방법 4가지

| 방법 | 서버 접속 필요 | 언제 쓰나 |
|---|:---:|---|
| **A. API** | ❌ | 가장 간단. 브라우저·Postman으로 바로 |
| **B. Swagger UI** | ❌ | 클릭으로 조회 |
| **C. 서버 콘솔** | ✅ | 통계·집계 쿼리 |
| **D. PC로 가져오기** | ✅(복사만) | GUI 도구로 편하게 |

---

## A. API로 조회 (서버 접속 불필요)

가장 간단하다. 브라우저 주소창에 넣어도 된다.

```
GET http://<서버>:28080/v1/merge?limit=50
GET http://<서버>:28080/v1/merge?roomNo=R-20260919-001
```

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `roomNo` | — | 특정 회의룸만 |
| `limit` | 50 | 최대 500 |

```bash
curl "http://127.0.0.1:28080/v1/merge?limit=10"
```

```json
{
  "count": 2,
  "jobs": [
    {
      "job_id": "mrg_a3", "room_no": "R-002", "status": "DONE",
      "retried_from": "mrg_a2", "requeue_count": 0,
      "accepted_at": "...", "finished_at": "...",
      "output": { "durationMs": 1800000, "sizeBytes": 14200000 },
      "timing": { "totalMs": 92000 }
    }
  ]
}
```

보기 좋게 출력:

```bash
curl -s "http://127.0.0.1:28080/v1/merge?limit=10" | python3 -m json.tool
```

특정 작업 하나만 볼 때는 상태 조회를 쓴다 (90일 안이면 조회된다):

```bash
curl "http://127.0.0.1:28080/v1/merge/mrg_a3"
```

## C. 서버 콘솔에서 조회

### ⚠️ 먼저 — `sqlite3` 명령이 없을 수 있다

우분투에는 SQLite CLI가 기본 설치되어 있지 않다. 확인:

```bash
which sqlite3
```

**없으면 두 가지 선택지가 있다.**

**① 설치** (인터넷 되는 서버만)

```bash
sudo apt install sqlite3
```

**② python3로 조회** (설치 불필요, 망분리에서도 됨)

파이썬에는 sqlite 모듈이 내장되어 있어 추가 설치가 필요 없다.

```bash
python3 -c "
import sqlite3
c = sqlite3.connect('/data/timblo/recog-runtime/merge.db')
c.row_factory = sqlite3.Row
for r in c.execute('SELECT job_id, room_no, status FROM merge_jobs ORDER BY accepted_at DESC LIMIT 10'):
    print(dict(r))
"
```

한 줄 요약:

```bash
python3 -c "
import sqlite3
c = sqlite3.connect('/data/timblo/recog-runtime/merge.db')
print('총 %d건 | ' % c.execute('SELECT COUNT(*) FROM merge_jobs').fetchone()[0], end='')
print(' | '.join('%s %d' % r for r in c.execute('SELECT status,COUNT(*) FROM merge_jobs GROUP BY status')))
"
# 총 5건 | DONE 2 | ERROR 3
```

### 기본 사용법 (sqlite3 CLI가 있을 때)

```bash
DB=/data/timblo/recog-runtime/merge.db

sqlite3 "$DB"                       # 대화형 진입 (.quit 으로 종료)
sqlite3 "$DB" "SELECT ..."          # 한 번만 실행
sqlite3 -header -column "$DB" "..." # 표 형태로 예쁘게
```

대화형에서 유용한 명령:

```
.tables              테이블 목록
.schema merge_jobs   컬럼 구조
.headers on          헤더 표시
.mode column         표 정렬
.mode json           JSON 출력
.quit                종료
```

> **읽기만 하는 것이 안전하다.** 서버가 돌아가는 중에 조회해도 문제없지만
> (WAL 모드), `UPDATE`나 `DELETE`는 하지 말 것.

## D. PC로 가져와서 보기

파일 하나라 복사만 하면 된다.

```bash
# 서버에서 안전하게 사본 만들기 (돌아가는 중에도 OK)
sqlite3 /data/timblo/recog-runtime/merge.db ".backup /tmp/merge-$(date +%Y%m%d).db"

# sqlite3 CLI 가 없으면 python3 로
python3 -c "
import sqlite3
src = sqlite3.connect('/data/timblo/recog-runtime/merge.db')
dst = sqlite3.connect('/tmp/merge-backup.db')
src.backup(dst)
"
```

그다음 sftp로 PC에 내려받아 GUI 도구로 연다.

| 도구 | 비고 |
|---|---|
| **DB Browser for SQLite** | 무료, 가장 간편 |
| DBeaver | 다른 DB도 같이 쓸 때 |
| VS Code + SQLite 확장 | 에디터에서 바로 |

> 그냥 `cp`로 복사해도 대부분 잘 되지만, 쓰기 중이면 깨질 수 있다.
> `.backup`을 쓰면 안전하다.

## 3. 자주 쓰는 쿼리

아래 쿼리는 모두 실제로 검증한 것이다.

### 최근 이력

```sql
SELECT job_id, room_no, status, finished_at
  FROM merge_jobs
 ORDER BY accepted_at DESC
 LIMIT 20;
```

```
job_id  room_no  status  finished_at
------  -------  ------  ------------------------
mrg_a3  R-002    DONE    2026-09-19T11:05:00.000Z
mrg_a2  R-002    ERROR   2026-09-19T11:00:00.000Z
mrg_a1  R-001    DONE    2026-09-19T10:00:00.000Z
```

### 상태별 건수

```sql
SELECT status, COUNT(*) AS 건수 FROM merge_jobs GROUP BY status;
```

```
status  건수
------  --
DONE    2
ERROR   3
```

### 실패 원인 분포

`error` 컬럼이 JSON이라 `json_extract`로 꺼낸다.

```sql
SELECT json_extract(error,'$.code') AS 코드, COUNT(*) AS 건수
  FROM merge_jobs
 WHERE status='ERROR'
 GROUP BY 1
 ORDER BY 2 DESC;
```

```
코드     건수
-----  --
E4102  2       ← presigned URL 만료가 가장 많음
E4104  1
```

### 평균 소요시간 / 총 처리량

```sql
SELECT COUNT(*) AS 완료건수,
       ROUND(AVG(json_extract(timing,'$.totalMs'))/1000.0, 1) AS 평균초,
       ROUND(SUM(json_extract(output,'$.sizeBytes'))/1048576.0, 1) AS 총MB
  FROM merge_jobs
 WHERE status='DONE';
```

```
완료건수  평균초    총MB
----  -----  ----
2     130.8  40.7
```

### 재작업 이력 추적

```sql
SELECT job_id, room_no, status, retried_from
  FROM merge_jobs
 WHERE retried_from IS NOT NULL;
```

```
job_id  room_no  status  retried_from
------  -------  ------  ------------
mrg_a3  R-002    DONE    mrg_a2        ← mrg_a2 가 실패해서 재작업한 것
```

### 특정 회의의 전체 시도

```sql
SELECT job_id, status, finished_at
  FROM merge_jobs
 WHERE room_no='R-002'
 ORDER BY accepted_at;
```

### 기간별 집계

```sql
SELECT substr(accepted_at, 1, 10) AS 날짜,
       COUNT(*) AS 건수,
       SUM(status='DONE') AS 성공,
       SUM(status='ERROR') AS 실패
  FROM merge_jobs
 GROUP BY 1
 ORDER BY 1 DESC;
```

### 재시작으로 재큐잉된 작업

`requeue_count`가 계속 오르면 그 입력에서 서버가 반복 실패하고 있다는 신호다.

```sql
SELECT job_id, room_no, status, requeue_count
  FROM merge_jobs
 WHERE requeue_count > 0
 ORDER BY requeue_count DESC;
```

### 오래 걸린 작업 찾기

```sql
SELECT job_id, room_no,
       json_extract(timing,'$.totalMs')/1000 AS 초,
       json_extract(output,'$.durationMs')/60000 AS 녹음분
  FROM merge_jobs
 WHERE status='DONE'
 ORDER BY json_extract(timing,'$.totalMs') DESC
 LIMIT 10;
```

## 4. 테이블 구조

```sql
CREATE TABLE merge_jobs (
    job_id        TEXT PRIMARY KEY,   -- mrg_xxxxx
    room_no       TEXT NOT NULL,      -- 회의룸 번호
    source        TEXT NOT NULL,      -- presigned | upload
    status        TEXT NOT NULL,      -- WAITING | RUNNING | DONE | ERROR
    stage         TEXT,               -- DOWNLOADING | NORMALIZING | MIXING | UPLOADING
    progress      INTEGER,            -- 0~100
    request       TEXT NOT NULL,      -- 원본 요청 (JSON)
    output        TEXT,               -- 결과 정보 (JSON)
    alignment     TEXT,               -- 정렬 결과 (JSON)
    timing        TEXT,               -- 단계별 소요시간 (JSON)
    error         TEXT,               -- 실패 사유 (JSON)
    result_path   TEXT,               -- 업로드 테스트 경로의 결과 파일
    retried_from  TEXT,               -- 재작업이면 원래 job_id
    requeue_count INTEGER,            -- 재시작 재큐잉 횟수
    accepted_at   TEXT NOT NULL,      -- ISO8601
    started_at    TEXT,
    finished_at   TEXT
);
```

JSON 컬럼은 `json_extract(컬럼, '$.키')`로 꺼낸다.

```sql
json_extract(output,  '$.durationMs')    -- 결과 길이(ms)
json_extract(output,  '$.sizeBytes')     -- 결과 크기
json_extract(timing,  '$.totalMs')       -- 전체 소요시간
json_extract(timing,  '$.downloadMs')    -- 다운로드만
json_extract(error,   '$.code')          -- 에러 코드
json_extract(request, '$.roomNo')
```

## 5. 관리

### 백업

```bash
sqlite3 /data/timblo/recog-runtime/merge.db ".backup /backup/merge-$(date +%Y%m%d).db"
```

### 초기화

**지워도 서비스에는 영향이 없다.** 병합된 음성 파일은 이미 오브젝트 스토리지에
올라가 있고, 이 DB는 이력·통계·재작업용이다.

```bash
docker compose down
rm -f /data/timblo/recog-runtime/merge.db
docker compose up -d          # 빈 DB로 새로 시작
```

### 보존 기간 변경

`.env.recog`:

```bash
MERGE_RECORD_TTL_DAYS=90     # 기본 90일. 0 이면 영구 보관
```

서버 기동 시 이 기간이 지난 **완료된** 기록을 자동으로 정리한다.
진행 중인 작업은 대상이 아니다.

### 파일이 너무 커지면

```bash
# 현재 크기
ls -lh /data/timblo/recog-runtime/merge.db

# 삭제된 행이 차지하던 공간 회수 (서버 중지 후)
docker compose down
sqlite3 /data/timblo/recog-runtime/merge.db "VACUUM;"
docker compose up -d
```

한 건당 수 KB 수준이라 90일치가 쌓여도 보통 수 MB를 넘지 않는다.
