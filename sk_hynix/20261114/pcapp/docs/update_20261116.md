## 2. DLL 넣기 (빌드·앱 시험에 필요)

받은 DLL 중 **64비트 2개만** 아래 폴더에 복사한다.
```
src\helpers\windows\amtray\bin\AmInterface_RT_X64.dll      ← 본체 (우리 앱이 부르는 것)
src\helpers\windows\amtray\bin\Rathon-CS_crypt_X64.dll     ← 본체가 안에서 쓰는 것 (꼭 같이)
```
- **32비트**(`AmInterface_RT.dll`, `Rathon-CS_crypt.dll`)와 **C#용**(`RTSessionClient…dll`)은 **넣지 않는다.** 우리 앱은 64비트.
- 이 폴더의 `*.dll` 은 빌드 때 설치본(`설치폴더\helpers\windows\amtray\`)에 자동으로 들어간다. 앱도 여기서 찾는다.
- git 에는 올리지 않는다(반출 불가 파일). 집 소스에는 자리만 있다.

## 3. 확인

모든 명령은 **프로젝트 폴더**에서 `cmd` 로. 시험 창이 말없이 꺼지면 그 창(node)만 꺼진 것 — PC·앱에는 영향 없다.

### ① 평소 동작 (A 반영 확인)
| 확인 | 방법 | 정상이면 |
|---|---|---|
| 지금과 같은가 | `npm start` → 사번 로그인·녹음 평소대로 | 이상 없음 |
| 어느 설정으로 떴나 | 로그 `%APPDATA%\timbloRecApp\logs\combined-날짜.log` 의 `app_started` 줄 | `appEnv: "dev"` |

### ② DLL 시험 (B) — 위에서부터 차례로, 한 줄씩 결과를 적는다

**1단계. 함수 목록 — 실행 안 함, 안전**
```
node scripts\amtray-exports.js src\helpers\windows\amtray\bin
node scripts\amtray-exports.js src\helpers\windows\amtray\bin --all
```
| 볼 것 | 정상이면 |
|---|---|
| 결론 글자 | `A` + 함수 6개 모두 **있음** |
| `--all` 목록 | 11-13 에 적은 15개 + **빠진 1개 이름** ← 이것만 적어 온다 |

**2단계. 가짜 DLL 로 도구 확인 (30초)**
```
node scripts\amtray-koffi-test.js token --dll-dir src\helpers\windows\amtray\test\fake-dll --system-id aimm
```
정상: `"code":"203030"` … `"kind":"인가토큰"`. 안 되면 `fake-dll` 폴더에 `AmInterface_RT_X64.dll`(밑줄)이 있는지 본다.

**3단계. 진짜 DLL** — 내 PC 의 AM-Tray 는 **운영 모드**라 운영 값으로. 시스템 ID 는 신청 중이라 샘플 값 `aimm`. **권한 오류 코드(503032 등)가 나와도 성공**(함수 모양이 맞다는 뜻).
```
set D=--dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO --sid timbloRecApp

node scripts\amtray-koffi-test.js init       %D%
node scripts\amtray-koffi-test.js is-login   %D%
node scripts\amtray-koffi-test.js token      %D% --system-id aimm
node scripts\amtray-koffi-test.js token      %D% --system-id aimm --no-init
node scripts\amtray-koffi-test.js check-user %D% --user-id <내 사번>
node scripts\amtray-koffi-test.js message    %D% --code 504011 --locale ko
```
| 명령 | 정상이면 | 적을 것 |
|---|---|---|
| `init` | `"commOk":true,"code":"201010"` | code. `"version"` 칸에 값이 있으면 그것도 (버전이 **출력값**이라는 뜻) |
| `is-login` | 6자리 code | AM-Tray **로그인 상태일 때** code |
| `token` | `"code":"203030"` + `"kind":"인가토큰"` **또는** 503032 등 6자리 | code (토큰은 앞 6글자만 보이니 옮기지 않아도 됨) |
| `token --no-init` | 위와 같은 code → Init 없이도 됨 | code |
| `check-user` | 6자리 code | 내 사번 code. 가능하면 **남의 사번**으로 한 번 더 |
| `message` | `"result":"통합인증이 필요합니다…"` | 한글이 제대로 나오나 (깨지면 `--utf8` 붙여 다시) |

**안 될 때**
| 나온 것 | 뜻 / 할 일 |
|---|---|
| 아무 출력 없이 끝남 | DLL 안에서 죽음 → **어느 명령에서**인지 적기. `token` 이면 `--no-init` 도 해 보기 |
| `"error":"dll_load_failed"` | `Rathon-CS_crypt_X64.dll` 이 같은 폴더에 있는지, `message` 내용 적기 |
| `"error":"dll_not_found"` | 파일 이름 확인. 다르면 `--dll <파일이름>` 붙이기 |
| `"error":"fn_not_found"` | 1단계 결과와 같이 적기 |
| `"commOk":false` | AM-Tray 와 통신 실패(= 명세의 "공백") — AM-Tray 가 켜져 있는지 |

**4단계. (여유 있으면) AM 로그인 호출** — AM-Tray 에서 **로그아웃한 상태**로:
```
node scripts\amtray-koffi-test.js token   %D% --system-id aimm      ← 504011 이 나와야 함
node scripts\amtray-koffi-test.js show-ui %D%                       ← AM-Tray 로그인이 뜨는지
```
적을 것: 떴나 / 명령이 **바로 끝났나, 로그인할 때까지 기다렸나** / `show-ui` 의 `"code"`

### ③ 로그인 화면 ver2 (C) — 흉내로 화면만
`app.config.json` 에서 `"LOGIN_PAGE_VERSION": 2`, `"AMTRAY_MOCK": "notlogin"` → `npm start`
→ "AM-Tray 통합 SSO 로그인을 진행해 주세요" → [AM-Tray 로그인] → "AM-Tray에서 로그인을 진행해 주세요" → 3초 뒤 "로그인 서버가 아직 준비 중"(백엔드 API 가 없어서 여기서 멈추는 게 정상)
→ **끝나면 `LOGIN_PAGE_VERSION` 1, `AMTRAY_MOCK` `""` 로 되돌린다.**

### ④ (여유 있으면) 운영 빌드
`npm run build:prod` → 설치 → 로그 `app_started` 의 `appEnv` 가 `prod` 인지. 개발판·운영판은 한 PC 에 같이 설치되지 않는다(나중 설치가 덮어씀).

> 빌드 전에는 `AMTRAY_MOCK` 이 `""`, `LOGIN_PAGE_VERSION` 이 원하는 값인지 꼭 확인.

## 4. 매뉴얼에서 옮겨 올 것 — "추측으로 채운 곳" 확정용

DLL 을 부르는 코드는 이미 만들어 두었다. 아래는 **추측으로 채운 곳을 확정**하려는 것이다. 매뉴얼 전체를 옮길 필요 없다. **위에서부터 중요한 순서**, 시간 없으면 **②③만** (①⑤는 11-14 에 받음).

| # | 매뉴얼에서 찾을 곳 | 옮길 것 | 왜 (지금 코드가 추측하는 것) |
|---|---|---|---|
| ~~①~~ | ~~`OnCopyData` 함수 안쪽~~ | ✅ **11-14 받음** (window-message.md 165~173행) | hash 는 `lpData` 를 `cbData` 길이만큼 **문자열**로 읽는다. 샘플은 읽기만 하고 그다음은 "시스템 정책" |
| ② | 샘플 프로그램 **시작 부분과 끝 부분** — 특히 대화상자 시작 함수 **`OnInitDialog`** (같은 `CWindowsFormsApp2Dlg` 안) 와 프로그램 끝날 때 | `Init` · `Close` · `CheckVersion` · `AccessSystem` 을 부르는 줄과 그 앞뒤, **창 핸들(HWND)·`this`·`m_hWnd` 를 어디 넘기는 줄** | 지금은 토큰 전에 `Init` 만 부르고 **`Close` 는 안 부른다** + ③ |
| ③ | 그 밖에 **창·HWND·등록**이 나오는 곳 (예: 창 이름, `FindWindow`, `RegisterWindow`, `SetWindowText`) | 그 문장/줄 | **AM-Tray 가 우리 창을 어떻게 찾는지** — 샘플의 메시지 등록(MESSAGE_MAP)에는 없었다. 가장 큰 미확인 |
| ④ | **`GetSystemToken` 함수원형** (Init 처럼 `char(*x)[크기]` 모양) | 한 줄 | 지금은 샘플 호출 줄로 복원 — sid 크기(256으로 봄)·`strVersion` 위치 확인 |
| ~~⑤~~ | ~~로그아웃 메시지 처리~~ | ✅ **11-14 받음** (182~189행) | `WM_USER + 31001`, wParam 확인 후 처리는 "시스템 정책"(우리가 정함) |
| ⑥ | 응답코드 표에 **`IsLoginIT` / `CheckLoginUserIT` / `ShowSSOLoginUI`** 성공 코드가 있으면 | 코드와 뜻 | 지금은 성공 코드를 몰라 값만 기록 |
| ⑦ | `Init` · `GetSystemToken` 의 **`strVersion` 설명** | 한 줄 | 넣는 값인지 받아 오는 값인지 (지금은 빈 칸으로 넘김) |
| ⑧ | `CheckVersion`, `AccessSystem`, `CheckMenuAuthz` 설명이 있으면 | 함수원형 + 한 줄 설명 | 우리에게 필요한 함수인지 |

> 옮겨 적을 때 `*`, `&`, `[숫자]`, 대소문자는 글자 그대로. 오타는 괜찮다(집에서 바로잡는다).

## 6. 이번에 바뀐 점 (요약)

**A. 설정 개발/운영 분리**
- 값 찾는 순서: **`dev`/`prod` 묶음 → 바깥(공통) → 코드 기본값.** 묶음 값이 `""` 이면 바깥 값 → 지금은 URL 이 모두 `""` 라 **지금과 똑같이 동작**.
- 묶음에 넣은 것: URL 7개 + AM-Tray 4개(`AMTRAY_SSO_KEY`, `AMTRAY_SID`, `AMTRAY_ENV_CODE`, `AMTRAY_SYSTEM_ID`). 운영 URL 은 알게 되면 `prod` 묶음에.
- 설치 파일: `npm run build:prod`(운영) / `npm run build:dev`(개발). 예전 `npm run build` 는 파일의 `APP_ENV` 를 그대로.
- ★ PC 에 깔린 **AM-Tray 모드와 앱 `APP_ENV` 가 같아야** 한다 (운영 AM-Tray = `prod`, 30001). 다르면 로그인 알림을 앱이 무시한다.

**B. AM-Tray DLL**
- 실제 함수(6-1 목록 + C++ 매뉴얼): 모두 **BOOL 반환(통신 성공) + 첫 인자 응답코드**. 정리본 `docs/sso-amtray-java/clean/AmInterface.h`.
- 앱 흐름: `Init`(201010) → `GetSystemToken`(203030 이면 인가토큰). `Init` 은 설정 `AMTRAY_DLL_INIT`(기본 true)로 끌 수 있다.
- `GetSystemTokenIT`·`SSOLogout` 은 DLL 에 없다 → 안 쓴다.
- 집(Mac)에서 가짜 DLL 로 13가지 경우 확인(토큰·504011·통신 실패·503032·Init 실패·문구 한글·DLL 이 죽어도 시험 창만 종료).

**C. 로그인 화면 ver2 + 알림 상시 받기**
- 고르기: `app.config.json` `"LOGIN_PAGE_VERSION"` — `1`(기본, 지금 화면 그대로) / `2`(AM-Tray 전용).
```
화면 열림 → [확인 중…] 바로 AM-Tray 로 토큰 요청 (AM-Tray 로그인은 자동으로 안 띄움)
 ├ 성공 → 백엔드 → 마이크 테스트 화면   (백엔드 API 없으면 "로그인 서버가 아직 준비 중")
 ├ 504011 → "AM-Tray 통합 SSO 로그인을 진행해 주세요" [AM-Tray 로그인]
 │            → ShowSSOLoginUI 호출 → "AM-Tray에서 로그인을 진행해 주세요" [다시 확인] [AM-Tray 로그인 다시 열기]
 │            → AM-Tray 가 로그인 알림을 보내면 자동 로그인
 │            ※ 로그인 방식(지금은 브라우저)은 AM-Tray 몫 — 화면 문구에 방식은 적지 않는다
 ├ 509090/통신 실패 → "AM-Tray가 설치되지 않았습니다" [다시 시도]
 ├ 503031~036 → 명세 문구 + 코드 [다시 시도]
 └ 시스템 ID 없음 → "시스템 로그인 준비 중입니다" [다시 시도]
테스트 로그인(토큰 직접 입력) — 개발 빌드(APP_ENV=dev)에서만 보임
```
- **알림 상시 받기 (ver1·ver2 모두)**: 예전엔 [시스템 로그인]을 누르고 5분 동안만 받았다. 이제 앱이 켜지면 바로 받을 준비를 하고, **로그인 전이면 언제든** 알림이 오면 자동 로그인. 로그인 중에 온 알림은 기록만(다른 사용자인지 hash 비교는 4장 ① 받은 뒤).
- **로그인 알림의 hash 읽기 (11-14 밤)**: 샘플 `OnCopyData` 처럼 `lpData` 를 `cbData` 길이만큼 문자열로 읽어 로그 `amtray_login_hash`(길이·hex·대소문자·**앞 8글자**만, 전체 값은 안 남김). 로그인 중에 알림이 오면 내 사번의 SHA-256 과 비교해 `sameUser: true/false` 기록 — 다른 사람일 때 처리(결정 C)는 아직, 기록만. 대소문자는 무시하고 비교한다.
- **AM-Tray 로그아웃 알림 (결정 D, 11-14 밤)**:
  - 마이크 테스트 화면 + 업로드 없음 → 확인 창 "AM-Tray에서 로그아웃되었습니다. 이 앱에서도 로그아웃할까요?" [로그아웃] / [취소](유지)
  - **녹음 중·업로드 중**(그 밖의 화면) → 로그아웃하지 않고 **미뤄 둔다** → 마이크 테스트 화면으로 돌아오고 업로드가 끝나면 그때 확인 창
  - 미뤄 둔 사이 **같은 사람**이 AM-Tray 에 다시 로그인하면 확인 창 없이 지운다
  - 집(Mac)에서 실제 앱으로 확인: 홈+취소 → 유지 / 다른 화면 → 미룸 / 홈 복귀 → 확인 창 → 로그아웃 → 로그인 화면
- 문구는 고객 요청이 오면 바꾼다(`src/locales/ko.json` `loginV2.*`, `amtray.logout_*`).
- 보류(킵): 화면에 있는 동안 몇 초마다 `IsLoginIT` 로 확인하는 안전장치.
- 집(Mac)에서 실제 앱을 흉내 모드로 띄워 확인: notlogin 전 과정, unavailable, denied(503032), token, 운영 빌드에서 테스트 로그인 숨김, ver1 그대로.

**로그에서 볼 이름** (`%APPDATA%\timbloRecApp\logs\combined-날짜.log`)
| 로그 | 뜻 |
|---|---|
| `amtray_window_hook_installed` | 알림 받을 준비 완료 (`env: 30001/31001`) |
| `amtray_login_message` | **AM-Tray 로그인 알림 받음** |
| `amtray_copydata_ignored` | 알림은 왔는데 값이 다름 (`wParam` 실제 값이 찍힘 → `APP_ENV` 확인) |
| `amtray_login_message_ignored` | 이미 로그인 중 / 설정 없음 / 진행 중 |
| `amtray_token_code` | 응답코드 (`code`, `step: init` 이면 Init 단계, `init`·`version`) |
| `amtray_token_received` | 인가토큰 받음 (길이만) |
| `amtray_login_hash` | 알림의 hash 모양 (`length` 64 · `hex` · `case` · `head` 앞 8글자) |
| `amtray_login_hash_check` | 알림으로 자동 로그인한 뒤 — `sameUser`, `hashHead`, `myHashHead`(내 사번 SHA-256 앞 8글자). 둘이 다르면 집에서 후보(AD 계정 등)와 맞춰 본다 |
| `amtray_login_message_ignored` + `sameUser` | 로그인 중 알림 — **`sameUser: true` 면 hash 대상이 사번이 맞다는 뜻**, `false` 면 사번이 아닌 값(AD 계정 등)으로 hash 한 것 |
| `amtray_logout_message` / `amtray_logout_deferred` | 로그아웃 알림 받음 / 녹음·업로드 중이라 미룸 |
