## 3. DLL 시험

### 11-16 에 왜 막혔나
- ver.18 문서의 명령은 **cmd** 용이었다. **PowerShell** 에서는 `set D=…` 가 `Set-Variable` 로 해석돼 오류가 나고, `%D%` 는 빈칸이 된다.
- 그래서 4단계는 `--dll-dir`·`--sso-key`·`--sid` 가 **모두 빠진 채** 실행 → 시험 도구 기본값(`Dev_CASSO` + 빈 sid)으로 Init → **`501010` = 초기화 실패** (11-16 매뉴얼 6.2). `show-ui` 의 501010 은 **Init 을 안 하고 불러서**(6.1 "Init 필요").
- 이번 반입으로 시험 도구는 `--sso-key` 기본값이 없고, `show-ui`·`is-login`·`check-user` 는 Init 을 먼저 부른다.

### 방법
- **PowerShell** 을 열고 프로젝트 폴더로 이동한 뒤, 아래 줄을 **한 줄씩 그대로** 붙여 넣는다. (변수 안 씀)
- 줄마다 나온 `{ … }` 한 줄을 적는다. 길면 `code`, `commOk`, `step`, `kind` 만.
- 시험 창이 말없이 꺼지면 그 창(node)만 꺼진 것 — PC·앱에는 영향 없다. **어느 줄에서** 꺼졌는지만 적는다.
- **AM-Tray 에 팝업이 뜨면** 그것도 적는다(`_NF` 키는 팝업이 없어야 정상).
- ⚠️ 아래 명령은 **운영판 AM-Tray** 값이다. **개발판 AM-Tray 를 깔았으면** 줄마다 `Prod_CASSO_NF` → **`Dev_CASSO_NF`**, `--sid AIMEETING` → **`--sid AIMEETINGdev`** 로 바꾼다(`--system-id AIMEETING` 은 그대로). 3-3 의 일반 키도 `Dev_CASSO`.

**3-1. AM-Tray 에 로그인한 상태로**
```
node scripts\amtray-koffi-test.js message    --dll-dir src\helpers\windows\amtray\bin --code 501010 --locale ko
node scripts\amtray-koffi-test.js init       --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING
node scripts\amtray-koffi-test.js is-login   --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING
node scripts\amtray-koffi-test.js token      --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING --system-id AIMEETING
node scripts\amtray-koffi-test.js token      --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING --system-id AIMEETING --init-first
node scripts\amtray-koffi-test.js check-user --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING --user-id 내사번
node scripts\amtray-koffi-test.js sm-session --dll-dir src\helpers\windows\amtray\bin --sso-key Prod_CASSO_NF --sid AIMEETING
```
(`내사번` 자리에 실제 사번. 가능하면 **남의 사번**으로 `check-user` 한 번 더)

| 줄 | 정상이면 | 적을 것 |
|---|---|---|
| `message 501010` | `"result":"…"` 에 한글 문구 | 문구 그대로 |
| `init` | `"commOk":true,"code":"201010"` (두 번째부터는 `201011` 일 수 있음 — 정상) | code |
| `is-login` | **`206030`** (로그인 상태) | code, `"reinit":true` 가 붙었는지 |
| `token` | **`"code":"203030"` + `"kind":"인가토큰"`** ★ | code + **`shape`** 칸 그대로 (`length`·`head`·`dots`·`jwtLike`·`special` — 값은 안 보인다) |
| `token --init-first` | 위와 같은 code | code |
| `check-user` | 내 사번 **`206040`** / 남의 사번 **`506040`** | 두 code — **내 사번이 206040 이 아니면** 사번 말고 다른 ID(AD 계정 등)를 쓰는 것 → 꼭 적기 |
| `sm-session` | `"kind":"SMSESSION"` + `shape` | **`shape`** 칸 그대로. 실패면 `code` |

**★ 토큰 모양 비교** — 테스트 로그인 때 넣는 accessToken 과 비교한다. 그 값을 `"` 안에 붙여 넣어 모양만 본다(값은 화면에 안 나온다):
```
node scripts\amtray-koffi-test.js shape "여기에_테스트로그인_accessToken_붙여넣기"
```
| 비교할 칸 | 뜻 |
|---|---|
| `length` | 길이 |
| `head` | 앞 3글자 (JWT 면 `eyJ`) |
| `dots` | 점 개수 (JWT 면 2) |
| `jwtLike` | JWT 모양인가 |
| `special` | `+ / = %` 같은 글자가 섞였나 |

→ 인가토큰·SMSESSION·테스트 accessToken **세 줄의 `shape`** 를 적어 온다. 인가토큰과 accessToken 이 같은 모양이면 "인가토큰 = 우리가 쓰는 토큰" 가능성이 높다.
> PowerShell 은 입력한 줄을 기록(히스토리)에 남긴다. 회사 PC 안이라 괜찮지만, 마음에 걸리면 끝난 뒤 창을 닫고 `Clear-History`.

**안 될 때**
| 나온 것 | 뜻 / 할 일 |

| `"step":"init"` + `502011` 또는 `"commOk":false` | AM-Tray 설정 없음 / 통신 실패 — AM-Tray 가 켜져 있는지 |

### 3-4. ★ 앱으로 자동 로그인 — 인가토큰을 사용자 토큰으로
**이번에 바뀐 것:** AM-Tray 에서 받은 **인가토큰을 그대로 사용자 토큰(accessToken)으로 저장**한다 — 테스트 로그인에 토큰을 넣는 것과 같다.
그다음 그 토큰으로 **`/api/auth/user/me`**(내 정보)를 불러 본다. 되면 마이크 테스트 화면, 안 되면 "AM-Tray 토큰으로 사용자 정보를 가져오지 못했습니다 (코드 ○○○)".
(설정 `AMTRAY_TOKEN_MODE` — 기본 `direct`. 서버 주소는 `DEFAULT_API_BASE_URL`)

**앱의 APP_ENV 와 PC 에 깔린 AM-Tray(개발판/운영판)를 맞춘다.** 값이 다르면 Init 실패·알림 무시가 난다.
| PC 의 AM-Tray | 앱 실행 | 앱이 쓰는 값 |
|---|---|---|
| **개발판** 설치 | `npm start` (그대로 — APP_ENV=dev) | `Dev_CASSO_NF` · sid `AIMEETINGdev` · 31001 · 설치 주소 amdev |
| 운영판 | `$env:APP_ENV="prod"; npm start` | `Prod_CASSO_NF` · sid `AIMEETING` · 30001 · 설치 주소 csam |
> 개발판 AM-Tray 로 하면 ver2 의 **테스트 로그인 칸도 같이 보여서**(APP_ENV=dev 에서만 보임) 4-2 도 같은 창에서 할 수 있다.
> `$env:APP_ENV` 는 그 PowerShell 창에서만 효과가 있다. 로그인 화면 ver2 라면 화면이 열리자마자 자동으로 시도한다.
> 지금 깔린 AM-Tray 가 어느 쪽인지 모르면: 3-1 `init` 을 개발 값으로 해 보고 `201010`/`201011` 이면 개발판.

| 상황 | 해 볼 것 | 정상이면 |
|---|---|---|
| AM-Tray 로그인 상태 | 앱 실행 (ver2 자동) | **마이크 테스트 화면** (= 인가토큰이 우리 토큰) 또는 "AM-Tray 토큰으로 사용자 정보를 가져오지 못했습니다 (코드 401 등)" |
| AM-Tray 로그아웃 상태 | [AM-Tray 로그인] | AM-Tray 로그인 창 → 로그인하면 자동으로 위와 같이 (로그 `amtray_login_message`) |

## 4. 운영 빌드 다시 — `appEnv` 확인

### 11-16 에 무슨 일이 있었나
`npm run build:prod` 로 만들었는데 로그에 `appEnv: "dev"` 만 보였다. 후보는 셋:
1. 빌드가 `Unable to commit changes` 로 **실패** → `dist` 에 **예전 설치 파일이 남아** 그걸 설치함
2. 보인 `dev` 줄이 설치본이 아니라 **`npm start`** 로 띄운 것 (둘 다 같은 로그 파일에 쓴다)
3. PC 에 **Windows 환경변수 `APP_ENV=dev`** 가 있음 (가장 먼저 쓰인다)

→ 이번 반입으로 로그에 **`appEnvSource`**(어디서 정해졌나)와 **`packaged`**(설치본이면 `true`)가 같이 찍혀 한 줄로 가릴 수 있다.

### 순서
1. **`dist` 폴더를 통째로 지운다** (예전 설치 파일을 잘못 쓰지 않도록)
2. **`AMTRAY_MOCK` 이 `""`** 인지 확인 (3-5 를 했다면)
3. PowerShell 에서
   ```
   npm run build:prod
   ```
   - 맨 처음 `[build-env] APP_ENV=prod 로 빌드합니다`
   - 중간에 `[afterSign] … 파일 설명·제품 이름 → SKHynixRecApp` 가 나오면 이름 바꾸기 성공
   - `[afterSign] exe 이름 바꾸기 실패(1/5) — 3초 뒤 다시` 가 나와도 **기다리면 된다**
   - 끝까지 **빨간 `Fatal error` 로 멈추지 않았는지**
4. 설치본에 운영 표시 파일이 들어갔는지
   ```
   npx asar list dist\win-unpacked\resources\app.asar | findstr app.env
   ```
   정상: `\src\config\app.env.json` 한 줄
5. `dist` 의 `SKHynixRecApp-Setup-0.0.14.exe` 로 설치 → **바탕화면/시작 메뉴 아이콘으로** 실행 (npm start 아님)
6. 로그 `%APPDATA%\timbloRecApp\logs\combined-날짜.log` 에서 **가장 아래** `app_started` 줄

| 정상이면 |
|---|
| `appVersion: "0.0.14"`, `appEnv: "prod"`, `appEnvSource: "app.env.json"`, `packaged: true` |

| 다르게 나오면 | 뜻 |
|---|---|
| `appVersion` 이 0.0.14 가 아님 | 예전 설치본 — 1번(dist 지우기)부터 |
| `packaged: false` | npm start 로 띄운 줄을 본 것 — 설치본으로 실행한 줄을 찾기 |
| `appEnvSource: "env"` + `dev` | PC 에 Windows 환경변수 `APP_ENV=dev` 가 있다 → 시스템 속성 > 환경 변수에서 확인 |
| `appEnvSource: "app.config.json"` 또는 `"default"` | 설치본에 `app.env.json` 이 없다 → 4번 결과와 같이 적기 |

### 빌드가 그래도 `Unable to commit changes` 로 멈추면
막 만들어진 exe 를 **사내 보안 프로그램이 검사하느라 잡고 있는** 경우가 대부분이다.
- 한 번 더 `npm run build:prod` (대개 다음엔 된다)
- 계속 멈추면: 멈춘 화면 마지막 20줄쯤 적어 오기

## 5. 이번에 바뀐 점 (요약)

**AM-Tray 연동 통로 두 개 (11-16 담당자 "편한 대로")** — 로그인 방식이 둘이 아니라 **통로가 둘**. 앱은 **둘 다 쓴다**.
- **API(DLL)** — 앱이 물어봄 → **인가토큰**(로그인에 꼭 필요), 로그인 상태·사용자 확인
- **Window Message** — AM-Tray 가 알려 줌 → 사번 hash·로그아웃 신호만. "로그인 끝남/로그아웃/사용자 바뀜"을 바로 따라가는 데 쓴다. AM-Tray 가 어느 창으로 보내는지는 아직 모르지만, 안 와도 [다시 확인]·IsLoginIT 로 버틴다.

**응답코드 처리 (11-16 매뉴얼 표 + 결정)** — 자세히 `docs/sso-amtray-java/analysis.md` 2-5

**인가토큰을 사용자 토큰으로 (11-16 밤)** 🔸 회사 확인 전
- `GetSystemToken` 203030 → 인가토큰을 **accessToken 으로 저장**(테스트 로그인과 같은 방식, refreshToken 없음) → `/api/auth/user/me` → 성공이면 다음 화면(약관·권한 확인은 예전과 같음).
- `/me` 실패면 세션을 지우고 오류 문구 — 로그인 화면이 계속 다시 시도하며 도는 일은 없다.
- 백엔드 교환 방식(예전 제안)은 `AMTRAY_TOKEN_MODE: "backend"` 로 남겨 둠(지우지 않음).
- 인가토큰·SMSESSION 은 **모양만** 로그(`amtray_token_received`·`amtray_smsession_shape`). 값은 남기지 않는다.
- 집에서 확인: `/me` 성공 → 마이크 테스트 화면·이름/사번 받음·`loginMethod: system`, `/me` 401 → 오류·세션 지움·화면 안 바뀜. 가짜 DLL 로 SMSESSION 성공/504011/통신 실패.

**로그인 뒤 AM-Tray 확인** — **시스템 로그인으로 들어온 경우만** (사번·MyAccess·테스트 로그인은 안 함)
- **창이 활성화될 때(30초에 한 번까지) + 녹음 화면으로 넘어가기 전** → `IsLoginIT`. 주기적으로(1분마다 등) 묻지는 않는다.
  - 504011(AM-Tray 로그아웃) → "AM-Tray에서 로그아웃되었습니다" [로그아웃][취소] (녹음·업로드 중이면 미뤘다가 끝나면)
  - [취소] 를 누르면 AM-Tray 가 다시 로그인 상태가 될 때까지 같은 창을 또 띄우지 않는다
  - 509090 · 502011 · 그 밖 → 그대로 둔다(로그만)
- **로그인 중 AM-Tray 로그인 알림** → `CheckLoginUserIT(내 사번)`
  - 206040 같은 사람 → 그대로 / 506040 다른 사람 → "다른 사용자가 사용 중입니다" [로그아웃][취소] / 506041·504011 → 안내 [확인] 후 로그아웃

**DLL 호출**
- version 버퍼 32 → **64** (매뉴얼: 출력 [64]. 작으면 DLL 이 넘쳐 써서 앱이 죽을 수 있었다)
- Init `201011`(이미 됨)도 성공으로 (예전엔 실패로 봐서 토큰을 요청하지 않았다)
- 토큰 앞에는 Init 을 부르지 않는다(매뉴얼: GetSystemToken 이 Init 포함). 로그인 창·상태·사용자 확인 앞에는 부른다.

**집(Mac)에서 확인한 것**
- 가짜 DLL(매뉴얼 코드대로 고침)로: 토큰 203030(version 64바이트 꽉 채워도 이상 없음), Init 전 501010 → Init 후 206030, 로그인 창 203012/506021/502051/502052, 사용자 206040/506040/504011, Init 실패·통신 실패
- 흉내 모드로 앱 로직: 설치 팝업(이동 → 주소 열고 종료 / 닫기 → 유지, 개발·운영 주소 각각), 접근 불가 → 종료, SSO 페이지 실패 [다시 시도] 두 번 → [앱 종료], SSO 불가 → 종료, 506021 → 토큰 한 번 더 → 성공, 503035 → 로그인 창, 녹음 전 IsLoginIT 로그아웃 → [로그아웃] 이면 녹음 화면으로 안 감 / [취소] 면 감, 녹음 중이면 미룸, 다른 사용자 알림 → 확인 창 → 로그아웃
- 화면(ver1·ver2 렌더러)은 문구 연결만 바뀌어 실제 창으로는 띄워 보지 않았다 → 3-5 에서 확인

**그 밖**
- 시작 로그 `app_started` 에 `appEnvSource`(`env` / `app.env.json` / `app.config.json` / `default`), `packaged`
- 빌드: exe 이름 바꾸기(rcedit) — 원래 1초 간격 3번 → 차례마다 3·6·9·12초 기다리며 최대 5차례
- 시험 도구: `--sso-key` 기본값 없음(빠지면 `missing_args`), `--no-init` = 로그인 창·상태·사용자 확인 앞 Init 안 함, `--init-first` = 토큰 앞에 Init
