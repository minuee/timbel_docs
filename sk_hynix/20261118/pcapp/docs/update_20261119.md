## 2. ★ 시험 도구로 GetSystemToken 다시

어제(11-17)는 시험 도구로 무엇을 해도 `502011`, 오늘(11-18)은 앱에서 `504011`·`503032`. **AM 쪽 변경이 없다면 차이는 우리 쪽**이다. 어제와 같은 명령을 그대로 다시 해 본다.

AM-Tray **로그인 상태**에서 (PowerShell, 프로젝트 폴더):
```
node scripts\amtray-koffi-test.js token --dll-dir src\helpers\windows\amtray\bin --sso-key Dev_CASSO_NF --sid AIMEETINGdev --system-id AIMEETING
node scripts\amtray-koffi-test.js token --dll-dir src\helpers\windows\amtray\bin --sso-key Dev_CASSO_NF --sid AIMEETINGdev --system-id AIMEETING --init-first
```

| 결과 | 뜻 |
|---|---|
| 둘 다 `503032` | 오늘 상태와 같다 — 어제 502011 은 그때 AM-Tray(또는 PC) 상태 문제였을 가능성 |
| 첫째 `503032`, 둘째(`--init-first`) `502011` | **Init 을 먼저 부르면 502011** — `.env` INIT 이 원인이었다 |
| 둘 다 `502011` | 시험 도구와 앱이 다르게 부른다 → 명령 그대로 적어 오기 |

## 3. 503032 때 앱이 안 꺼지는지

1. AM-Tray 로그인 상태에서 앱 실행 (개발 빌드든 `npm start` 든)
2. 팝업 "시스템 접근 권한이 없습니다." → [확인]
3. **앱이 열린 채** 로그인 화면에 같은 문구 + `(코드 503032)` + [다시 시도] 가 보이면 끝
4. 로그: `login_failed`(code 503032) 다음에 **`amtray_denied_popup`** (예전 `amtray_denied_quit` 아님)

## 4. 운영 빌드 로그 — 설치하고 실행해야 쌓인다

- `npm run build:prod` 는 **설치 파일만 만든다.** 빌드할 때는 로그가 없다 (정상).
- 로그는 **만든 설치 파일로 설치 → 앱 실행** 해야 생긴다.
  1. `dist` 폴더의 설치 파일 실행 → 설치
  2. 시작 메뉴/바탕화면의 `SKHynixRecApp` 실행 → 로그인 화면까지
  3. 로그 파일: `C:\Users\<사번>\AppData\Roaming\SKHynixRecApp\logs` 의 오늘 날짜 파일 (없으면 `...\Roaming\timbloRecApp\logs`)
  4. 로그 서버: 운영 빌드는 **운영** 로그 서버(`aimeeting.skhynix.com/m/api/pcapp/log`)로 간다 — 개발 서버에서 찾으면 안 보인다
- 운영 빌드라 AM 값도 운영(`Prod_CASSO_NF`, sid `AIMEETING`)으로 간다. 그래서 GetSystemToken 코드가 개발과 다를 수 있다 → 그 코드도 적어 오기

## 6. 앱으로 돌아올 때 자동 로그인 (C)

> 503032(권한 없음)가 풀리기 전에는 끝까지 안 된다. **로그만** 보면 된다.

1. AM-Tray **로그아웃** 상태에서 앱 실행 → [AM-Tray 로그인] → 브라우저 로그인 창
2. 브라우저에서 로그인 → **앱 창을 클릭**해서 돌아오기
3. 로그 `amtray_return_retry` 가 보이면 된다
   - `error: amtray_not_logged_in` → 아직 미로그인으로 봄(화면 그대로 기다림)
   - `error: amtray_denied`, `code: 503032` → 지금 권한 상태 그대로(팝업 뜸, 앱은 열려 있음)
   - `success: true` → 자동 로그인 (권한 풀린 뒤 + 인증서버 API 생긴 뒤)
