# 운영 배포 1.0.2 + 같은 방 "문장 반복" 시험

작성 2026-11-18

## 1.0.2 은 무엇이 바뀌었나

**같은 방에서 녹음하면 문장이 통째로(2~3초) 거의 같은 크기로 한 번 더 들리던 문제**를 고친 버전이다.

### 11/18 까지 알게 된 것

| 들은 것 | 뜻 |
|---|---|
| 다른 장소에서는 정상, **같은 방에서만** 반복 | 두 번째 소리는 다른 폰에 함께 들어간 내 목소리다 |
| 유지시간·전환기준(300~4000ms, 3~15dB)을 바꿔도 그대로, 음량 맞추기를 꺼도 그대로 | 오토믹서 설정 문제가 아니다. 그보다 앞 단계(정렬) 문제 |
| 반복되는 길이가 2~3초, 모든 문장은 아님 | 한 폰이 **초 단위로 밀려서** 합쳐졌다. 폰이 바뀌는 순간에만 되돌아간다 |
| 뒤로 갈수록 심해짐 | 시계 어긋남 보정도 시작 비프로 계산하므로, 시작이 틀리면 같이 틀어진다 |
| 결과 앞에 한 폰의 비프 끝이 들림 | 그 폰의 비프가 다른 폰과 다른 자리에 놓였다는 증거 |

한 폰이 초 단위로 밀리는 원인은 둘 중 하나로 본다. 어느 쪽인지는 현장에서 가리지 않아도 된다(1.0.2 는 둘 다 고친다).

- 세 폰이 다 비프를 울려서, 한 폰이 **남의 비프를 자기 것으로** 짚었다
- 앱이 폰마다 "자기 녹음이 켜진 뒤 몇 초"에 비프를 울려서, **비프가 같은 순간에 울리지 않았다** (폰마다 녹음 켜지는 데 0~2초 넘게 걸린다)

### 바뀐 것

| | 1.0.1 | **1.0.2** |
|---|---|---|
| 목소리 맞추기 범위 (`ALIGN_REFINE_MAX_MS`) | ±0.2초 (200). 초 단위 밀림은 못 잡았고, 현장에서 한 번도 적용되지 않았다 | **±4초 (4000)**, 최대 10초 |
| 재는 방법 | 4초짜리 8곳, 2ms 단위 | 20초짜리 최대 16곳(서로 안 겹치게), 50ms 단위로 넓게 → 10ms → 샘플 단위로 좁혀 감 |
| 시계 어긋남 | 시작·끝 비프로만 | 위 16곳의 값을 **직선으로 이어** 목소리로도 잰다. 남은 만큼 그 폰의 빠르기를 고친다 |
| 믿는 기준 | 3곳 이상이 2ms 안으로 같아야 | 3곳 이상이 한 직선 위(±10ms)에 있어야. 같은 소리가 없는 폰(다른 장소)은 그대로 |
| 남은 비프 | 공통 지점까지 잘라냄 | + **폰마다 앞·뒤 15초 안의 비프를 어디 있든 지움** (`BEEP_SCRUB=1`) |
| 결과에 남는 것 | 고친 양 | + 비프 기준 위치 → 최종 위치, 목소리로 잰 시계 어긋남(ppm), 지운 비프 수 |

**오토믹서(`select`, 유지 1000 / 전환 6), 음량 맞추기(`dynamic`) 는 그대로 둔다.**

### 여기서 미리 확인한 것

같은 방 폰 3대를 흉내 낸 녹음(다른 폰 목소리가 작게 섞임)에서 B폰 말만 2초 늦춰 병합했다.

| 범위 | B폰 | 찾은 값 | 폰 전환 |
|---|---|---|---|
| ±0.2초 (1.0.1) | 못 맞춤 | — | 102번 |
| **±4초 (1.0.2)** | 맞춤 | 1996ms (실제 2000) | 21번 |

1.5초 밀림 + 시계 어긋남 300ppm 을 넣은 8분 녹음에서는 1495ms / 319ppm 을 찾았고, 고친 뒤 남은 어긋남은 대부분 ±2ms 안이었다.
다른 장소처럼 서로 무관한 소리는 한 번도 연결하지 않았다. 다른 폰 목소리가 아주 작으면(약 -26dB) 못 맞추고 **비프 위치를 그대로 쓴다** (엉뚱하게 옮기지 않는다).

## 0-1. 시험 전에 운영 `.env` 를 기준값으로 되돌리기

11/18 에 유지시간·전환기준·음량·목소리 맞추기를 이것저것 바꿔 보았다. 시험 도구는 **목소리 맞추기(`ALIGN_REFINE`, 범위)만** 스스로 바꾸고
나머지는 운영 `.env` 를 그대로 따르므로, **아래 값으로 되돌린 뒤** 돌려야 결과가 의미 있다. 기준 전체는 `deploy/.env.example`.

| 항목 | 값 | 비고 |
|---|---|---|
| `MERGE_AUTOMIX` | 1 | |
| `AUTOMIX_MODE` | select | |
| `AUTOMIX_HOLD_MS` | **1000** | 300~4000 으로 바꿔 봤다면 되돌린다 |
| `AUTOMIX_SWITCH_DB` | **6** | 3~15 로 바꿔 봤다면 되돌린다 |
| `MERGE_TRACK_GAIN` | 0 또는 1 | 반복 문제와 무관. 1 이면 전체 소리가 커진다. 폰 고르는 판단에는 영향 없음 |
| `MERGE_LEVEL` | dynamic | |
| `ALIGN_REFINE` | **1** | 0 으로 두었다면 꼭 되돌린다 |
| `ALIGN_REFINE_MAX_MS` | **4000** | 운영 `.env` 에는 200 이 적혀 있다 (1.0.1 까지의 값) |
| `DRIFT_CORRECT` | 1 | |
| `BEEP_ENABLED` / `BEEP_TRIM` | 1 / 1 | |
| `BEEP_SCRUB` | 1 | 1.0.2 새 항목. 줄이 없어도 기본으로 켜져 있다 |

11/18 에 `ALIGN_REFINE` 을 0 과 1 로 바꿔도 차이가 없었던 것은 당연하다 — 1.0.1 은 범위가 ±0.2초라 실제로는 한 번도 적용되지 않았다.

지금 실제로 어떤 값으로 도는지 확인 (`.env` 에 줄이 없는 항목은 `(기본값)` 으로 나온다):

```bash
docker logs mobile-sync-server 2>&1 | grep server_start | tail -1
```

`.env` 를 고친 뒤에는 `docker restart` 가 아니라 `docker compose --env-file .env up -d`.

### 다른 환경변수는 바꿔 볼 필요가 없다

| 항목 | 판단 |
|---|---|
| `ALIGN_REFINE_MAX_MS` | **핵심.** 시험 도구가 범위별로 바꿔 준다 |
| `DRIFT_CORRECT=0` | 1.0.2 에서도 "뒤로 갈수록 심해짐" 이 남을 때만 비교용으로 |
| `BEEP_SCRUB` | 결과 앞에 비프가 남을 때만 확인용으로 |
| `BEEP_FREQ_*`, `BEEP_DURATION_MS`, `BEEP_REPEAT`, `BEEP_PERIOD_MS` | **건드리지 않는다.** 앱이 울리는 비프와 같아야 한다. 바꾸면 비프를 못 찾는다 |
| `BEEP_MIN_RISE`, `BEEP_GUIDED_*`, `VOICE_*`, `JINGLE_*` | 비프를 못 찾을 때 손대는 값. 지금은 찾고 있으므로 해당 없음 |
| `AUTOMIX_FADE_MS`, `AUTOMIX_SPEECH_DB`, `AUTOMIX_FLOOR_DB`, `AUTOMIX_ATTACK_MS`, `AUTOMIX_RELEASE_MS` | 오토믹서 세부값. 유지시간·전환기준으로 확인했듯 반복과 무관 |
| `MERGE_WORKERS`, `MERGE_MAX_*`, `*_TTL_*`, 포트, 계정 | 운영 설정. 소리와 무관 |

## 1. 먼저 시험 — 운영은 그대로 두고

**운영 서버를 1.0.2 로 바꾸기 전에** 시험부터 할 수 있다. 이미지만 올려 두고, 시험 도구가 그 이미지로 시험용 컨테이너를 띄운다.

```bash
cd /data/timblo/mobile-sync-server                  # 설치 폴더 (아래 2-① 로 확인한 곳)
sha256sum -c mobile-sync-server_1.0.2_amd64.tar.sha256     # "OK"
docker load -i mobile-sync-server_1.0.2_amd64.tar          # 이미지만 올린다. 운영 컨테이너는 그대로
chmod +x howling_test_102.sh
IMAGE=mobile-sync-server:1.0.2 ./howling_test_102.sh /data/timbel/howling_test
```

- `.txt` 로 가져왔으면 `mv howling_test_102.txt howling_test_102.sh`, `$'\r': command not found` 가 나오면 `sed -i 's/\r$//' howling_test_102.sh`
- 설치 폴더가 `/data/timblo/mobile-sync-server` 가 아니면 앞에 `INSTALL_DIR=<설치 폴더>` 를 붙인다
- 운영을 1.0.2 로 바꾼 뒤에는 `IMAGE=...` 없이 돌려도 된다 (`.env` 의 버전을 따른다)
- **1.0.1 이전 이미지로 돌리면** "1.0.2 이전 버전이다" 하고 멈춘다
- 시험 폴더 구조는 101 과 같다 (회의 폴더마다 폰별 원본 flac 2개 이상)

### 기본 범위 (자동으로 전부 돈다)

| 순서 | 범위 | 결과 이름 | 보는 것 |
|---|---|---|---|
| 1 | ±0.2초 | `r200` | 1.0.1 과 같은 범위. **지금 들리는 것과 같아야 한다** (비교 기준) |
| 2 | ±0.5초 | `r500` | |
| 3 | ±1초 | `r1000` | |
| 4 | ±2초 | `r2000` | |
| 5 | ±3초 | `r3000` | |
| 6 | ±4초 | `r4000` | **1.0.2 기본값** |

범위 바꾸기 (`0` = 목소리 맞추기 끔, 최대 `10`):

범위를 넓혀도 병합 시간은 수십 초 정도만 는다. 이미 만든 범위는 건너뛴다 (다시 하려면 `FORCE=1`).

### 숫자 읽는 법

| 값 | 뜻 |
|---|---|
| `연결` | 목소리로 서로 맞춰진 폰. **여기 없는 폰은 비프 위치 그대로** (다른 장소이거나, 다른 폰 목소리가 너무 작아 못 잰 것) |
| `비프기준` → `최종` | 폰별 위치(ms). 둘이 크게 다르면 비프가 그만큼 틀렸던 것 |
| `고친양` | 폰별로 당긴 ms. **1000 이상이 보이면 그 폰이 초 단위로 밀려 있었다** = 반복의 원인 |
| `어긋남ppm` | 목소리로 잰 시계 어긋남. 100ppm = 1시간에 0.36초 벌어짐. 회의 구간이 5분 넘을 때만 잰다 |
| `비프ppm` | 시작·끝 비프로 잰 시계 어긋남 (1.0.1 에도 있던 것) |
| `지운비프` | 폰별로 지운 비프 구간 수. 비프 3번 × 울린 폰 수 정도가 보통 |
| `전환` | 폰이 바뀐 횟수 |
| `주의: 정렬 ...` | 비프로 못 맞췄다는 뜻 → 꼭 사진에 |
| `주의: 실패 기록 있음` | 그 단계는 건너뛰고 병합은 됐다 → 꼭 사진에 |

## 2. 운영 배포

### ① 지금 쓰는 설치 폴더부터 확인

```bash
docker inspect mobile-sync-server \
  --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
```

여기 나온 폴더 = 설치 폴더. 아래 명령은 전부 이 폴더에서 친다.

### ② 파일 올리고 설치

```bash
cd <①에서 나온 폴더>

# 옛 tar 지우기 (안 지우면 설치가 멈춘다) — 1.0.0 이든 1.0.1 이든
rm -f mobile-sync-server_1.0.0_amd64.tar* mobile-sync-server_1.0.1_amd64.tar*

# 새 tar 2개, install.sh, docker-compose.yml, .env.example 을 이 폴더에 복사한 뒤
sha256sum -c mobile-sync-server_1.0.2_amd64.tar.sha256     # "OK"
chmod +x install.sh
./install.sh
```

### ③ `.env` 의 옛값 고치기 — **꼭 할 것**

1.0.1 까지의 `.env` 에는 `ALIGN_REFINE_MAX_MS=200` 이 적혀 있다. **이게 남아 있으면 1.0.2 로 바꿔도 범위가 ±0.2초 그대로라 고친 효과가 없다.**
설치할 때 `ALIGN_REFINE_MAX_MS=200 (1.0.1 까지의 값) 이 .env 에 남아 있다` 경고가 나오면:

```bash
sed -i 's/^ALIGN_REFINE_MAX_MS=200$/ALIGN_REFINE_MAX_MS=4000/' .env
grep -E '^ALIGN_REFINE' .env                                # ALIGN_REFINE=1, ALIGN_REFINE_MAX_MS=4000
docker compose --env-file .env up -d                        # docker restart 로는 반영 안 된다
```

시험(1)에서 4초보다 큰 범위가 나았다면 4000 대신 그 값(ms)을 적는다.

### ④ 확인

```bash
grep IMAGE_VERSION .env                                     # IMAGE_VERSION=1.0.2
curl -s http://127.0.0.1:9995/health                        # {"status": "ok", ...}
docker logs mobile-sync-server 2>&1 | grep server_start     # "version": "1.0.2" + settings
```

`settings` 에서 아래가 나와야 한다:

```
"ALIGN_REFINE": true   "ALIGN_REFINE_MAX_MS": 4000   "BEEP_SCRUB": true
"AUTOMIX_MODE": "select"   "AUTOMIX_HOLD_MS": 1000   "AUTOMIX_SWITCH_DB": 6.0   "MERGE_LEVEL": "dynamic"
```

`ALIGN_REFINE_MAX_MS` 가 200 이면 ③ 을 안 한 것이다. `BEEP_SCRUB` 뒤의 `(기본값)` 은 괜찮다 (`.env` 에 줄이 없어도 켜져 있다).

병합을 한 건 해 본 뒤 로그에서 목소리 맞추기를 본다:

```bash
docker logs mobile-sync-server 2>&1 | grep merge_refine | tail -1
```

### 되돌리기

| 상황 | 할 일 |
|---|---|
| 1.0.2 전체에 문제 | `.env` 의 `IMAGE_VERSION` 을 이전 값(1.0.1 또는 1.0.0)으로 → `docker compose --env-file .env up -d` (옛 이미지는 남아 있다) |
| 목소리 맞추기만 의심 | `.env` 에 `ALIGN_REFINE_MAX_MS=200` (1.0.1 과 같은 범위) 또는 `ALIGN_REFINE=0` (끔) → `docker compose --env-file .env up -d` |
| 비프 지우기만 의심 | `.env` 에 `BEEP_SCRUB=0` → `docker compose --env-file .env up -d` |

## 3. 주의할 점 한눈에

- [ ] tar sha256 이 `2c3f3f0d…` 인지
- [ ] 시험은 `IMAGE=mobile-sync-server:1.0.2` 를 붙여서 (운영을 바꾸기 전이면)
- [ ] 시험은 서비스 안 쓰는 시간에 (운영 서버는 안 건드리지만 CPU 는 같이 쓴다)
- [ ] 요약 화면 사진 + 들은 결과 표 + 반복 났던 구간 시각
- [ ] 배포할 때 **설치 폴더 먼저 확인** (2-①)
- [ ] `install.sh` 를 **새것으로** 교체
- [ ] **`.env` 의 `ALIGN_REFINE_MAX_MS=200` → `4000`** (2-③). 안 하면 고친 효과가 없다
- [ ] 2-④ 에서 `"version": "1.0.2"`, `"ALIGN_REFINE_MAX_MS": 4000`, `"BEEP_SCRUB": true`
- [ ] `.env` 를 고쳤으면 `docker restart` 가 아니라 `docker compose --env-file .env up -d`
