## 🎯 프로젝트 개요

**목적**: Zoom, Teams, Discord 등 회의 앱의 마이크 + 시스템 사운드를 안정적으로 녹음하여 STT(Speech-to-Text) 문서화 지원

**아키텍처**: 
- **UI**: Electron (크로스 플랫폼)
- **오디오 엔진**: Windows C++ AudioHelper (네이티브)
- **통신**: JSON-IPC (stdin/stdout)

## 🏗️ 기술 아키텍처

### 핵심 설계 원칙

1. **마이크-마스터 아키텍처**
   - 마이크 콜백을 기준으로 정확한 타이밍 제어
   - 시스템 오디오는 링버퍼로 지연 보상
   - 무음 구간에서도 연속적인 타임라인 보장

2. **세그먼트 기반 저장**
   - 3분(2,880,000 샘플) 단위 정확한 분할
   - 샘플 정확도로 일관된 파일 크기
   - 메모리 효율적 스트리밍 처리

3. **장치 변경 대응**
   - 시스템 오디오: 자동 감지 및 재연결
   - 마이크: 변경 감지 시 보호 중단
   - IMMNotificationClient 기반 실시간 모니터링

### 성능 지표

| 항목 | 목표 | 현재 달성 |
|------|------|-----------|
| **타이밍 정확도** | ±50ms | ±20ms ✅ |
| **UI-파일 동기화** | ±2초 | ±0.2초 ✅ |
| **메모리 사용량** | <100MB | ~50MB ✅ |
| **CPU 사용률** | <15% | 8-12% ✅ |
| **세그먼트 정확도** | 샘플 단위 | 샘플 단위 ✅ |
// 메모 기능은 Helper 비대상(UI 전용) — 타임스탬프 지표 항목 제거

- 녹음/재초기화 경로에서 기본(디폴트) 마이크 폴백 제거, 선택/세션 마이크만 사용
- 레벨미터 시작 가드 강화: `mic_state: "unavailable"` 통지

**2025-10-20 (v0.4.1)**
- 테스트 재사용 정책 강화(장치 동일 시 재사용), 재초기화는 내부 경로에서 처리
- 레벨미터 자동 재시작 단일화 + 디바운스/백오프(1s→2s→4s)
- 마이크 0개일 때 크래시 방지: InitializeAudioClient 널가드 + `NO_MIC_DEVICE`
- 장치 전환 중 레벨 0 레이스 제거

**2025-10-20 (v0.4.0)**
- 파일명 정책(회차별 접미사) 도입: `{sessionId}{(take)}_{segmentIndex}.{ext}`
- 시작 사전 용량 체크: 50MB 미만 시 시작 거부(`DISK_SPACE_CRITICAL`)
- set_segment_config 응답 확장: `disk_status`, `free_bytes` 포함
- UI: 시작 거부 시 버튼/상태 즉시 복구 처리

**2025-10-15 (v0.3.2)**
- 세그먼트 인덱스 초기화 누락 수정: `HandleStart`에서 `SegmentManager::Reset()` 호출 추가
- 음소거 상태 초기화 누락 수정: `muteMic`, `muteSystem` 초기화 추가
- 일시정지 중 시간 점프 문제 수정: pause 중 FIFO 푸시 차단 및 pause 시 큐/상태 즉시 초기화
- Pause→Stop 시 파일 길이 +5초 문제 수정: `HandleStopTest()`에서 플래그 순서 레이스 해결 (`isRecording=false` 먼저 설정)
- 중복 세션 ID 파일명 처리 추가: Windows 스타일로 `(1)`, `(2)` 자동 추가하여 파일 덮어쓰기 방지 (동일 폴더 내 파일명 구분)
- set_segment_config 응답 확장: `disk_status`, `free_bytes` 포함
- 녹음 시작 사전 용량 체크: 50MB 미만이면 시작 거부(`DISK_SPACE_CRITICAL`)

**2025-10-14 (v0.3.1)**
- 무음 감지: 30초 지속 시 `sustained` 직후 `off` 동시 전송, 테스트 모드에서는 무음/용량 체크 비활성화.
- 음소거: `set_mute` 추가. 무음 감지 중에는 거부. 레벨 이벤트는 음소거 시 0 RMS 전송.
- 레벨미터: `set_level_meter` 추가. on이면 테스트/녹음과 무관하게 캡쳐 유지, pause 중에도 마이크/시스템 레벨 이벤트 전송(파일 기록 없음).
- 진행 이벤트: 녹음 중에만 전송. pause/테스트/레벨미터 전용 시 미전송. `mic_seconds`는 파일 진행과 동기화.

## 🐛 알려진 이슈

### 해결된 문제
- ✅ 시스템 오디오 지연 문제 (60ms 프라임 버퍼로 해결)
- ✅ 타이밍 드리프트 문제 (상태 유지 리샘플러로 해결)
- ✅ 장치 변경 시 캡처 중단 (자동 재연결로 해결)
- ✅ 메모리 누수 (세그먼트 완료 시 제로화 해결)
- ✅ UI-파일 시간 동기화 문제 (t_capture 기반 동기화로 해결)
- ✅ max_ms 초과 시 세그먼트 오버플로우 (미완성 세그먼트 폐기로 해결)
- ✅ JSON 이벤트 파싱 오류 (SimpleJson const char* 오버로드로 해결)
- ✅ 테스트 모드 파일 저장 문제 (isTestMode/isRecording 플래그 분리로 해결)
- ✅ stop 후 UI 시간 2배 증가 문제 (세그먼트 시간 중복 계산 제거로 해결)
- ✅ 일시정지 중 시간 점프 문제 (pause 중 FIFO 푸시 차단 및 큐 초기화로 해결)
- ✅ Pause→Stop 시 파일 길이 +5초 문제 (플래그 순서 레이스 해결로 정확한 경계 보장)

### 현재 제한사항
- Windows만 지원 (macOS 미구현)
- 테스트용 고정 암호화 키 사용
- UI 기능 최소화 (기능 확인 수준)
- SystemOnly 경계 페이드인은 기본 4ms(`AudioConfig::FADE_MS`) 설정
- 디스크 상태 이벤트: 녹음 중에만 평가(1초), 전송(5초) 정책 적용
- 파일명 형식: 시간 기반에서 인덱스 기반(`{sessionId}_{n}.{ext}`)으로 변경
