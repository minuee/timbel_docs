## ① 로그 서버 올리기 (Linux 서버)

```bash
cd <반입 폴더>
chmod +x install.sh
./install.sh /data/timblo/pcapp-log-server
```
- 성공하면 마지막에 `정상 기동` 이 뜬다
- 확인
  ```bash
  curl http://127.0.0.1:9996/health
  curl -X POST http://127.0.0.1:9996/pcapp/log -H 'content-type: application/json' -d '{"msg":"설치 확인"}'
  docker logs --tail 3 pcapp-log-server
  ```
- **nginx 프록시 추가** — 앱은 `https://<서버>/m/api/pcapp/log` 로 보낸다
  ```nginx
  location /m/api/pcapp/ {
      proxy_pass http://127.0.0.1:9996/pcapp/;
      proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
  ```
  `nginx -t && nginx -s reload` 후 외부에서 `curl https://<서버>/m/api/pcapp/health` → 404 가 아니라 JSON 이면 연결됨
  (서버는 끝이 `/health` 인 경로를 받는다)
- Dozzle 에서 컨테이너 `pcapp-log-server` 가 보이는지 확인
- 막히면: 반입 폴더의 `SERVER_INSTALL.md` 맨 아래 "막혔을 때"

## ② 앱 설정 (빌드 전에)

**`src/config/app.config.json`** 을 고친다. `.env` 는 설치본에 안 들어가므로 여기에 넣어야 한다.

| 키 | 넣을 값 | 지금 값 |
|---|---|---|
| `LOG_SERVER_URL` | ①에서 연결한 주소 | `https://aimeeting.mobile.skhynix.com/m/api/pcapp/log` |
| `SSO_LOGIN_URL` | MyAccess 주소 (쿼리 확정값) | 자리표시(`TYPE=XX...`) |
| `MANUAL_LOGIN_ENABLED` | 테스트 기간이면 `true`, 고객 배포면 **`false`** | `true` |
| `EMPNO_LOGIN_ENABLED` | 비밀번호 검증이 없으므로 고객 배포면 **`false`** | `true` |
| `UPDATE_SERVER_URL` | 업데이트 파일 폴더 주소. **아직 없으면 비워 둔다**(업데이트 꺼짐) | 빈 값 |
| `HMP_BASE_URL`, `DEFAULT_API_BASE_URL`, `MOBILE_SERVER_URL` | 모바일 서버와 다르면 수정 | `https://aimeeting.mobile.skhynix.com/m` |

API 경로(내 정보·워크스페이스·부서장 메일·업로드)는 `src/main/services/apiEndpoints.js` — `docs/api-config.md` 참고.

## ③ 앱 빌드·설치 (Windows PC)

```bash
npm run build
```
- 결과: `dist/timbloRecApp Setup <버전>.exe` + `latest.yml` + `.blockmap`
- 설치 파일 실행 → 설치
- 버전은 `package.json` 의 `version` (지금 `0.0.1`). **업데이트를 배포할 때마다 올려야** 자동 업데이트가 인식한다

> ⚠️ 빌드가 인터넷을 찾는 경우: electron-builder 는 Electron·NSIS 파일을 캐시
> (`%LOCALAPPDATA%\electron\Cache`, `%LOCALAPPDATA%\electron-builder\Cache`)에서 쓴다.
> **예전에 회사 PC 에서 빌드해 본 적이 있으면 캐시가 있어 그대로 된다.** 처음이라 다운로드 오류가 나면
> 그 오류 메시지를 가져올 것 — 집에서 캐시 파일을 받아 가면 된다.
> `package.json` 에 `electron-updater` 가 의존성으로 들어 있다(혹시 몰라 추가). 앱은 이 패키지가 아니라
> `src/main/vendor/electron-updater.js` 를 쓴다. 회사에서 `npm install` 이 되면 그대로 두고,
> **설치가 안 돼서 빌드가 `electron-updater` 를 못 찾는다는 오류로 실패하면 `package.json` 에서 그 한 줄만 지우고 다시 빌드**한다.

### 자동 업데이트를 쓸 때 (업데이트 서버가 생긴 뒤)
1. `app.config.json` 의 `UPDATE_SERVER_URL` 을 넣고 빌드·설치 (첫 설치본에 주소가 들어 있어야 한다)
2. 다음 버전: `package.json` 버전 올림 → 빌드 → `exe` · `.blockmap` → `latest.yml` **순서로** 업로드
3. 자세히: `docs/auto-update.md`

## ④ 확인

| # | 할 일 | 기대 결과 |
|---|---|---|
| 1 | 앱 실행 | 로그인 화면 (사번 / MyAccess / 테스트 로그인) |
| 2 | 테스트 로그인: 이름·사번·accessToken | 마이크 테스트 화면, 타이틀에 이름 |
| 3 | 녹음 시작 | 부서장에게 "녹음 시작 안내" 메일 (서버 로그/메일함 확인) |
| 4 | 녹음 종료 → 업로드 | 업로드 성공 |
| 5 | Dozzle `pcapp-log-server` | 위 동작 로그가 사번과 함께 보임 (`hmp_login_*`, `manual_session_started`, `recording_start`, `api_success`, `server_upload_success` …) |
| 6 | MyAccess 로그인 (SSO 협조 후) | 브라우저 로그인 → 앱이 자동으로 메인 화면 |
| 7 | 사번 로그인 | 약관 동의된 사번이면 성공 / 아니면 서버 메시지 표시 |

앱 쪽 로그 파일: `%APPDATA%\timbloRecApp\logs\combined-YYYYMMDD.log`
로그가 서버에 안 들어오면: 앱은 전송 실패를 파일 로그에 남기지 않는다(남기면 그 로그를 또 보내려는 고리가 생김).
PC 브라우저로 `https://<서버>/m/api/pcapp/health` 가 열리는지부터 확인한다. 개발 모드(`npm run dev`)라면 터미널에 `[logShipper] 로그 서버 전송 실패` 가 보인다.
