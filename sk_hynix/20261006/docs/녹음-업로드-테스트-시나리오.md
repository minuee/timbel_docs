# 녹음 → 업로드 테스트 시나리오

녹음 준비부터 업로드 실패 후 재전송까지, 하나의 흐름을 5개 구간으로 나눈 테스트 시나리오와 예상 결과.

- 대상 브랜치: `develop`
- 대상 화면: 홈(서랍 메뉴) → 녹음 화면 → 업로드/변환 팝업 → 녹음 실패 목록
- 관련 코드: `recording_controller.dart`, `audio_recorder_io.dart`, `file_picker_service.dart`, `upload_service.dart`, `upload_progress_widget.dart`, `recording_failure_page.dart`, `FileUploadManager.swift`

---

## 한눈에 보는 시나리오

각 구간을 흐름대로 풀어 쓴 것입니다. 테스터는 이대로 따라가면 되고, 서술된 동작과 다르게 움직이면 결함입니다. 케이스별 상세 확인 항목은 아래 표 형식 문서를 참고하세요.

### 1. 녹음 준비

앱을 켜면 로그인된 상태로 홈 화면이 뜬다. 좌측 상단의 메뉴 아이콘을 누르면 서랍 메뉴가 열리고, 상단에 내 프로필 사진과 닉네임이 보인다. 그 아래로 회의록·캘린더·북마크 바로가기와 알림 메시지, 휴지통, 개인 설정(프로필·비밀번호·알림·녹음 실패·실험실), 로그아웃, 회원탈퇴가 차례로 나온다. 여기서 이름이 비어 있거나 메뉴가 빠져 있으면 로그인 정보가 제대로 내려오지 않은 것이다.

홈으로 돌아와 녹음 버튼을 누르면, 처음이라면 마이크 권한을 묻는 팝업이 뜬다. 허용하면 녹음 화면으로 넘어가고, 거부하면 권한 안내 팝업이 뜨면서 녹음 화면으로 넘어가지 않는다. 안드로이드에서는 (하이닉스 설정이 아닌 경우) 통화 상태 권한도 함께 묻는다.

녹음 화면에 들어오면 상단에 '새 녹음'과 `00:00:00` 타이머가 있고, 가운데는 아직 조용한 웨이브폼 영역, 하단에는 "녹음 중 다른 앱 사용 시 녹음이 정상적으로 진행되지 않을 수 있습니다" 안내 문구와 취소·녹음 시작 버튼이 있다. 이어폰이나 블루투스 헤드셋을 연결한 상태라면, 녹음을 시작해 말했을 때 웨이브폼이 반응하는 것으로 마이크가 살아 있는지 확인한다.

> 참고: 현재 앱에는 녹음 시작 전에 마이크 입력을 미리 테스트하는 기능이 없다. 마이크가 정상인지는 녹음을 시작한 뒤 웨이브폼 반응으로만 알 수 있다. 별도 기능이 필요하다면 개선 항목으로 다뤄야 한다.

### 2. 녹음 시작

녹음 버튼을 누른다. 하이닉스 설정이면 먼저 "녹음을 시작할까요?" 팝업이 뜨고, "녹음 시작시 관리자에게 메일이 발송됩니다. 회의 시작 전, 참석자에게 녹음 동의를 받아주세요."라는 안내가 나온다. 이 시점에는 아직 녹음이 시작되지 않는다. 확인을 누르면 잠깐 로딩이 돌면서 관리자에게 메일이 발송되고, 발송 성공 토스트가 뜬 뒤에야 녹음이 시작된다. 메일 발송에 실패하면 실패 토스트만 뜨고 녹음은 시작되지 않으며, 로딩도 정상적으로 닫힌다. 취소를 누르면 아무 일도 일어나지 않는다. SKT·팀블로 설정에서는 이 팝업 없이 버튼을 누르는 즉시 녹음이 시작된다.

녹음이 시작되면 타이머가 1초씩 올라가고, 화면 정중앙에 레코더처럼 물결 모양의 웨이브폼이 소리에 맞춰 움직인다. 버튼은 일시정지 아이콘으로 바뀌고 그 옆에 '녹음 완료' 버튼이 나타난다. 안드로이드라면 알림 영역에 "녹음이 진행 중입니다" 알림이 뜬다. 통화 중이거나 다른 앱이 마이크를 쓰고 있으면 녹음이 시작되지 않고 안내 팝업이 뜬다.

### 3. 녹음 중

말하는 동안 웨이브폼이 계속 반응하고 타이머는 실제 시간과 어긋나지 않는다. 일시정지를 누르면 "녹음이 일시정지 되었습니다" 토스트와 함께 타이머가 멈추고, 다시 누르면 이어서 올라간다. 나중에 결과 파일을 들어보면 일시정지 앞뒤 음성이 모두 들려야 한다. 실험실에서 그룹녹음을 켠 경우에는 일시정지 중에도 타이머가 계속 가고 그 구간이 묵음으로 채워진다.

녹음은 3분마다 파일 하나씩 조용히 쌓인다. 10분을 녹음하면 파일 4개가 번호 순서대로 빠짐없이 만들어져야 한다. 이 부분이 어긋나면 나중에 업로드가 중간에 멈추는 원인이 된다.

앱을 백그라운드로 보내거나 화면을 꺼도 녹음은 계속된다. 돌아왔을 때 타이머가 그동안의 시간을 포함해 정확히 올라가 있어야 한다. 전화가 오면 녹음이 일시정지되고 안내가 뜨며, 통화가 끝나면 녹음을 이어갈 수 있다. 이어폰을 꽂거나 빼도 녹음이 끊기거나 앱이 죽지 않는다. 3시간에 도달하면 안내 토스트와 함께 더 이상 녹음할 수 없지만, 그때까지의 내용은 남는다.

녹음 도중 앱을 강제 종료하면 그때까지 저장된 폴더가 남고, 나중에 서랍 메뉴의 '녹음 실패' 목록에서 찾을 수 있다. 반대로 취소 버튼으로 녹음을 버리면 폴더까지 삭제되어 실패 목록에도 남지 않는다.

### 4. 녹음 종료 후 업로드

'녹음 완료'를 누르면 녹음이 멈추고 저장 옵션 팝업이 뜬다. 참석자 수(1~2명 / 3~6명 / 7~10명 / 11명 이상)와 언어(한국어 / 영어)를 고르고, 템플릿을 쓰는 서비스라면 템플릿 목록이 세로로 나오며 첫 항목이 미리 선택되어 있다. 취소하면 녹음 화면으로 돌아가고 데이터는 그대로 남아 다시 저장할 수 있다.

확인을 누르면 메인 화면으로 돌아오면서 하단에 "파일 업로드 1건 진행 중" 팝업이 올라온다. 팝업에는 파일명, 진행률 막대와 퍼센트, 전송속도, 남은 시간, 그리고 "업로드 중 화면을 닫거나 앱을 종료하면 업로드가 중단될 수 있습니다"라는 빨간 경고 문구가 있다. 퍼센트는 0%부터 꾸준히 올라가야 하며, **한 자리 숫자에서 30초 이상 멈춰 있으면 안 된다.** 만약 멈춘다면 몇 퍼센트에서 멈췄는지, 녹음이 몇 분짜리였는지를 반드시 기록한다.

100%에 도달하면 업로드 팝업이 사라지고, 이어서 "녹음 파일 변환 N건 진행 중" 팝업이 뜬다. 두 팝업이 동시에 겹쳐 보이면 안 된다. 변환 팝업에서는 '음성 인식 중...' 상태로 퍼센트가 올라가다가, 인식이 끝나면 '요약 진행 중...'으로 바뀌며 90%, 요약까지 끝나면 100%가 된다. 완료되면 팝업이 사라지고 홈과 회의록 목록에 새 회의록이 나타난다. 상세로 들어가면 전사와 요약 내용을 볼 수 있다.

업로드 중에 앱을 백그라운드로 보내도 업로드는 이어져야 하고, 돌아왔을 때 진행률이 뒤로 되돌아가 있으면 안 된다. 비행기 모드로 네트워크를 끊으면 팝업에 "네트워크 연결 끊김"이 표시되고, 다시 연결하면 업로드가 재개된다. 이때 회의록이 두 건 생기지 않는지 목록에서 확인한다. 끝내 실패하면 "파일 업로드 실패" 문구와 함께 '삭제'·'재시도' 버튼이 나타난다. 재시도를 누르면 토스트와 함께 0%부터 다시 올라가고, 삭제를 누르면 확인 팝업을 거쳐 목록에서 사라진다.

업로드가 성공했다면 기기에 있던 녹음 폴더는 삭제된다. 서랍 메뉴의 '녹음 실패' 목록에 방금 올린 회의가 남아 있으면 안 된다. 남아 있다면 사용자가 같은 회의를 두 번 올리게 된다.

### 5. 서랍 메뉴 → 녹음 실패 목록에서 재시도

서랍 메뉴에서 '녹음 실패'를 누르면 업로드되지 못한 녹음 폴더들이 목록으로 나온다. 각 항목에는 폴더명과 "생성일: yyyy-MM-dd HH:mm"이 표시된다. 실패한 녹음이 없으면 빈 상태 안내가 중앙에 뜨고, 내용 없이 껍데기만 남은 폴더는 목록에 나오지 않고 알아서 정리된다. 목록을 아래로 당기면 새로고침된다.

항목 우측의 더보기를 누르면 '재전송'과 '삭제'가 나온다. 재전송을 고르면 참석자 수와 언어를 다시 선택하는 팝업이 뜨고, 확인하면 "재전송을 시작합니다..." 토스트와 함께 이전 화면으로 돌아간다. 곧바로 메인 화면 하단에 업로드 팝업이 나타나 진행률이 올라가며, 그 뒤 과정은 4번 구간과 똑같다. 변환까지 끝난 뒤 실패 목록에 다시 들어가면 그 항목은 사라져 있고, 회의록은 딱 한 건만 생성되어 있어야 한다.

재전송 중에 네트워크가 끊기면 업로드 팝업에 끊김이 표시되고, 복구되면 재개되거나 재시도 버튼이 나타난다. 어느 쪽이든 업로드가 성공하기 전까지 원본 폴더는 지워지지 않는다. 삭제를 고르면 확인 팝업을 거쳐 목록에서 지워지고, 앱을 껐다 켜도 되살아나지 않는다.

한 가지 주의할 점이 있다. 녹음이 진행 중인 상태에서 실패 목록의 재전송을 실행하면, 내부적으로 녹음 종료 로직을 재사용하기 때문에 진행 중이던 녹음에 영향을 줄 수 있다. 이 상황을 반드시 테스트해서 녹음이 임의로 끊기지 않는지 확인해야 한다.

## 상세 테스트 케이스 사용법

### 테스트 환경

| 항목 | 값 |
|------|-----|
| 플랫폼 | Android(정품 단말 2종 이상, 그중 1대는 Android 14+) / iOS 15.6+ |
| 서비스 타입 | `.env`의 `SERVICE_TYPE` = `SKT` / `HYNIX` / `TIMBLO` (구간별로 분기 확인 필요) |
| 네트워크 | Wi-Fi, LTE/5G, 비행기 모드 전환 |
| 언어 | 한국어 기본, 그 외 4개 언어 1회 순회 |
| 테마 | 라이트/다크 각각 1회 순회 |

### 사전 조건 (모든 시나리오 공통)

1. 앱이 설치되어 있고 로그인된 상태
2. 마이크·알림 권한 허용 (권한 자체를 테스트하는 케이스는 예외)
3. 저장공간 500MB 이상 여유
4. 이전 테스트의 녹음 실패 폴더가 남아 있지 않은 상태 (서랍 메뉴 > 녹음 실패에서 정리)

### 알아두어야 할 내부 동작

테스트 결과를 판정할 때 필요한 배경입니다.

| 항목 | 값 | 근거 |
|------|-----|------|
| 녹음 청크 단위 | 3분마다 파일 1개 (`encrypted_audio_N.pcm`, 약 5.76MB) | `audio_recorder_io.dart` `_bufferSize` |
| 녹음 폴더 | `<temp>/save/A.Biz_m_rec_<timestamp>` | `_createRecordingFolder()` |
| 최대 녹음 시간 | 3시간 (10800초) | `recording_controller.dart` `maxSeconds` |
| 업로드 방식 | 폴더 내 전체 PCM을 **1회 multipart POST** | `uploadFolder()` |
| 업로드 재시도 | 최대 3회, 각 2초 간격 | `uploadFolder()` `maxRetries` |
| 타임아웃 | connect 30초 / send 10분 / receive 60초 | `dio.BaseOptions` |
| 업로드 성공 시 | 로컬 녹음 폴더 삭제 | `uploadFolder()` 말미 |
| 녹음 실패 목록 | `<temp>/save` 아래 **남아 있는 폴더** = 업로드되지 않은 녹음 | `recording_failure_page.dart` |
| 변환 진행률 | STT 구간은 서버 퍼센트 × 0.8 (최대 80%), STT 완료 90%, 요약 완료 100% | `main_container_controller.dart` SSE 핸들러 |

### 판정 기준

- **Pass**: 예상 결과와 완전히 일치
- **Fail**: 예상 결과와 다름 (재현 절차·로그·스크린샷 필수)
- **Blocked**: 선행 케이스 실패로 실행 불가

## 1. 녹음 준비 (TC-PRE)

앱의 기본 정보가 UI에 제대로 나오는지 확인하는 구간. 녹음을 시작하기 전 상태.

### TC-PRE-001: 로그인 사용자 정보 표시
| 항목 | 내용 |
|------|------|
| **우선순위** | 높음 |
| **사전 조건** | 로그인 상태, 메인 화면 |
| **테스트 단계** | 1. 좌측 상단 메뉴 아이콘 탭하여 서랍 메뉴 열기 <br> 2. 상단 사용자 영역 확인 |
| **예상 결과** | 프로필 썸네일과 닉네임이 표시된다. 썸네일이 없으면 기본 이미지가 표시되고 레이아웃이 깨지지 않는다. |
| **비고** | 닉네임은 `memberInfo.profile.nickName` |

### TC-PRE-002: 서랍 메뉴 기본 항목 노출
| 항목 | 내용 |
|------|------|
| **우선순위** | 높음 |
| **사전 조건** | 서랍 메뉴 열린 상태 |
| **테스트 단계** | 1. 메뉴 항목 전체를 위에서 아래로 확인 |

## 6. 회귀 확인 체크리스트

릴리즈 전 최소 1회는 아래 흐름을 끊김 없이 통과해야 합니다.

- [ ] 로그인 → 서랍 메뉴에 사용자 정보/메뉴 정상 노출 (TC-PRE-001, 002)
- [ ] 권한 허용 → 녹음 화면 진입 → 기본 UI 확인 (TC-PRE-004, 007)
- [ ] 녹음 시작 (Hynix는 동의 팝업 경유) (TC-STA-001 또는 002~003)
- [ ] 10분 녹음 중 일시정지·재개 1회, 백그라운드 전환 1회 (TC-ING-002, 003, 006)
- [ ] 청크 파일 4개가 순번 누락 없이 생성 (TC-ING-005)
- [ ] 녹음 완료 → 옵션 선택 → 업로드 100% 완료 (TC-UPL-001, 003, 004)
- [ ] 업로드 팝업 → 변환 팝업 전환 시 겹침 없음 (TC-UPL-008)
- [ ] 변환 완료 후 회의록 목록/상세 반영 (TC-UPL-010)

## 7. 결함 리포트 양식

업로드 정체·실패를 리포트할 때는 아래 항목을 반드시 포함해 주세요. 원인 구간을 좁히는 데 직접 쓰입니다.

```
[제목] 업로드가 XX%에서 진행되지 않음

- 플랫폼/OS 버전:
- 서비스 타입(.env SERVICE_TYPE):
- 앱 버전 / 빌드 타입:
- 네트워크: Wi-Fi / LTE / 사내망(프록시 여부)
- 녹음 길이: N분  → 예상 청크 수: ceil(N/3)개
- 정지한 퍼센트: XX%  (청크 경계와 일치하는지: 예/아니오)
- 정지 지속 시간: N분
- 팝업 종류: '파일 업로드' / '녹음 파일 변환'
- 최종 결과: 자동 완료 / 실패 후 재시도 UI / 계속 정지
- 재현율: N/M회
- 첨부: 화면 녹화, 로그(아래 키워드), 서버 액세스 로그 시각
```

**확인할 로그 키워드**

| 키워드 | 위치 | 의미 |
|--------|------|------|
| `저장 완료 대기 타임아웃` | Flutter | 마지막 청크 저장 전에 업로드 시작 |
| `전체 폴더 크기: N bytes, 파일 개수:` | Flutter | 업로드 대상 파일 수 — 예상 청크 수와 대조 |
| `누락된 파일 인덱스(missingFiles)` | Flutter | 서버가 파일 누락을 판정 → 전량 재전송 |
| `파일 업로드 중 오류 발생-재시도(N)` | Flutter | 재시도 횟수와 원인 예외 |
| `업로드 일시 중지` / `Dio 요청 취소됨` | Flutter | 네트워크 전환으로 업로드 취소 |
| `Task N progress:` | Xcode 콘솔 | iOS 실제 전송 진행률 — 0부터 다시 올라가면 재전송 중 |
| `Received Event:` | Flutter | 변환 SSE 수신 — 끊기면 변환 퍼센트 정지 |
