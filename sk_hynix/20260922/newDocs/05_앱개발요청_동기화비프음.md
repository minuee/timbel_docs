# 동기화 비프음 — 앱 개발 요청서

> 2026-09-22 · Timblo Mobile (Flutter) 앱 담당자 전달용
> 요청자: recog 음성병합 서버 팀

---

## 1. 무엇을, 왜

회의 참가자들이 각자 자기 폰으로 녹음한 파일을, 서버가 **하나의 타임라인에 겹쳐서** 합칩니다.
이때 각 파일의 시작점을 맞춰야 하는데, 지금은 이걸 맞출 방법이 없습니다.

**요청: 녹음 시작 후 방장 폰이 스피커로 짧은 비프음을 울려 주세요.**
방 안의 모든 폰이 그 소리를 녹음하게 되고, 서버가 각 파일에서 그 위치를 찾아 시작점을 맞춥니다.

```
방장 폰  ──🔔────────────▶  소리가 방에 퍼짐
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
      폰 A 녹음            폰 B 녹음            폰 C 녹음
      (비프 5.00초 지점)   (비프 4.26초 지점)   (비프 3.07초 지점)
                    → 차이만큼 밀어서 정렬
```

### 왜 시작 시각을 앱에서 받는 걸로는 부족한가

현재 코드 기준으로, **버튼 누른 시각과 실제 녹음 시작 사이에 최대 2.2초 차이**가 납니다.

```
recording_controller.dart:476   startTimestamp = DateTime.now()      ← 시각 기록
                    :494        service.startService()
                    :504        100ms × 최대 20회 대기               ← 최대 2초
                    :520        추가 200ms 대기
audio_recorder_io.dart:70       recorder.startStream(config)         ← 실제 녹음 시작
```

이 지연이 기기마다 제각각이라 시각만으로는 맞출 수 없습니다.
**비프음은 오디오 안에 직접 박히는 기준점이라 이 지연을 건너뜁니다.**

---

## 2. 비프음 규격

**음원 파일을 이미 만들어 드렸습니다: `sync_beep.wav`**
(이 문서와 함께 전달. 48kHz / 16bit / mono / 2.250초 / 216KB)

직접 만들지 않으셔도 됩니다. **asset에 그대로 넣고 재생만 해 주세요.**

| 항목 | 값 |
|---|---|
| 구성 | 3000Hz + 4200Hz 이중음 |
| 길이 | 250ms (앞뒤 5ms 페이드) |
| 반복 | 3회, 1000ms 간격 |
| 전체 길이 | 2.250초 |
| 진폭 | -6dBFS |

> 규격을 바꾸셔야 하면 알려 주세요. 서버 쪽은 환경변수로 되어 있어 맞출 수 있습니다.
> 다만 **8kHz를 넘는 주파수는 불가능합니다** — 녹음이 16kHz라 그 위는 기록되지 않습니다.

---

## 3. 동작 흐름

```
1. 참가자 전원이 각자 녹음 시작
2. 방장 화면에 "동기화 신호 보내기" 버튼 노출 (방장 기기에만)
3. 누르면 sync_beep.wav 를 스피커로 재생
   - 전원 화면에 "동기화 신호 재생 중" 표시
4. 이후 정상 회의 진행
```

### 재생 시점 — 3초가 아니라 **5초**를 권합니다

앱 기동 지연이 최대 2.2초라, 3초 뒤에 울리면 늦게 시작한 폰이 비프를 놓칩니다.

```
방장 폰   : 버튼 ─0.3초─▶ 녹음시작 ──────3초──────▶ 🔔
느린 폰   : 버튼 ────2.2초────▶ 녹음시작 ─0.8초─▶ (아슬아슬)
더 느리면 : 버튼 ──────────────▶ 녹음시작      🔔 놓침 ❌
```

소켓으로 녹음 시작을 전파하실 계획이라면, **전원의 "녹음 시작됨" 확인을 받은 뒤
방장에게 "지금 울려" 신호를 주는 방식**이 가장 안전합니다.

### 중요: 방장 폰도 자기 비프를 녹음해야 합니다

비프를 재생하는 기기가 정렬의 기준이 됩니다.
**재생 중에도 자기 마이크로 그 소리가 들어가야** 합니다. (아래 4번과 직결)

## 4. ⚠️ 반드시 확인해 주실 것 — 이거 놓치면 기능이 통째로 안 먹습니다

현재 `RecordConfig`가 이렇습니다 (`audio_recorder_service.dart:104`):

```dart
const config = RecordConfig(
  sampleRate: 16000,
  encoder: AudioEncoder.pcm16bits,
  numChannels: 1,
);
```

오디오 전처리 옵션이 지정되어 있지 않아 패키지 기본값을 따릅니다.
**아래 세 가지를 명시적으로 꺼 주세요.**

```dart
const config = RecordConfig(
  sampleRate: 16000,
  encoder: AudioEncoder.pcm16bits,
  numChannels: 1,
  echoCancel: false,     // ★★★ 필수
  noiseSuppress: false,  // ★★
  autoGain: false,       // ★★
);
```

| 옵션 | 켜져 있으면 생기는 일 |
|---|---|
| **`echoCancel`** | **스피커로 낸 소리를 마이크에서 빼는 것이 AEC의 목적입니다. 켜져 있으면 비프를 울린 방장 폰에서만 비프가 사라집니다.** 정작 기준이 되어야 할 기기가 정렬에서 빠집니다 |
| `noiseSuppress` | 순음을 정상 잡음으로 보고 감쇠시킵니다 |
| `autoGain` | 비프 순간 게인이 출렁여 파형이 뭉개집니다 |

추가로, 히든 메뉴의 **마이크 증폭(`_kGain`, `dev_mode_service.dart`)**이 켜져 있으면
비프가 클리핑될 수 있으니 확인 부탁드립니다.

## 5. 같이 부탁드리는 것 (비프음 실패 시 폴백용)

비프 검출이 실패했을 때를 대비한 2순위 경로입니다. **작업량은 작습니다.**

### ① `startTimestamp`를 "첫 오디오 샘플 시각"으로

지금은 버튼 누른 시각입니다(`recording_controller.dart:476`).
`audio_recorder_io.dart:74`의 **첫 `data` 도착 시각**으로 옮겨 주세요.

```dart
_streamSubscription = stream.listen(
  (data) async {
    // ← 여기서 최초 1회 DateTime.now() 를 기록
```

### ② `metadata.json` 업로드

이미 만들고 계신데 서버로 가지 않습니다. 업로드가 `.pcm`만 거릅니다:

```dart
// upload_service.dart:250 과 :1664 — 두 군데 동일
if (entity is File && path.extension(entity.path) == '.pcm') {
  pcmFiles.add(entity);
}
```

`metadata.json`은 폴더에 남았다가 삭제와 함께 사라집니다.
`recording_metadata.dart`의 클래스 주석에 **"여러 기기의 시작 타임스탬프를 포함하여
서버에서 딜레이 계산 및 병합에 사용됩니다"**라고 적혀 있는 바로 그 파일입니다.

### ③ 그룹녹음 모드 운영 정책 확인

`dev_mode_service.dart:16` — 히든 메뉴 토글이고 기본값이 `false`입니다.
꺼져 있으면 **일시정지한 시간만큼 묵음을 넣는 보정이 동작하지 않습니다**
(`audio_recorder_io.dart:456`). 그러면 누가 한 번 일시정지하는 순간
그 트랙만 짧아져서 이후 전체가 어긋납니다.

실제 운영에서 이 값이 어떻게 켜지는지 알려 주시면 감사하겠습니다.

## 7. 검증

구현 전에도 **비프음이 실제 환경에서 통하는지 미리 확인**할 수 있습니다.

```
1. 폰 N대를 회의실 테이블에 평소처럼 놓는다
2. 전부 녹음 시작
3. 한 대에서 sync_beep.wav 를 그냥 재생 (앱 기능 없이 파일 재생으로 충분)
4. 몇 마디 대화
5. 녹음 종료 → 파일을 recog 서버로 올린다
6. 서버가 각 파일의 비프 위치를 얼마나 정확히 찾는지 본다
```

**앱 수정 없이 지금 바로 할 수 있습니다.** 해보시면 규격 조정이 필요한지 바로 알 수 있습니다.

### 참고: 서버 쪽 검증 결과

배경 말소리를 깔고 기기 세 대가 서로 다른 시각에 녹음을 시작한 상황을 합성해서 시험했습니다.

| 기기 | 비프 감쇠 | 정렬 편차 |
|---|---|---|
| 방장 (가까움) | -6dB | 0ms |
| 방 건너편 | -20dB | -2ms |
| 가장 멂 | -26dB | -2ms |

검출률 100%, 정렬 오차 최대 2ms (목표는 100ms 이내).
