# 운영 배포 1.0.4 + "같은 사람 유지" 시험

작성 2026-11-26

## 1.0.4 는 무엇이 바뀌었나

1.0.3 현장 시험(11/26)의 결과는 이랬다.

| 1.0.3 에서 | 결과 |
|---|---|
| 폰이 바뀔 때 크기 이어 붙이기 | **기대 이하.** 한 사람이 계속 말해도 유지 시간(`AUTOMIX_HOLD_MS`)이 지나는 순간 폰이 바뀌어 크기가 확 달라졌다. 10초로 늘리면 10초 지점에서 바뀌었다. 1초는 너무 심해서 회사는 3초로 두었다 |
| 잡음 제거 | **좋음.** 말 없는 구간이 깨끗해졌다 (`MERGE_DENOISE=16`) |
| 울림 | 1.0.2 보다 **조금** 더 (처음에 "우우웅" 퍼지는 느낌). 크지 않아 이번엔 다루지 않는다 |

**원인:** 유지 시간은 폰이 바뀌는 순간을 **미룰 뿐**, 같은 사람이 계속 말하는지는 보지 않는다. 시간이 지나 다른 폰이 6dB 더 크게 잡히면 같은 사람이어도 넘어간다.

**1.0.4 — 같은 사람 유지** (`AUTOMIX_SAME_TALKER=1`, 기본 켬)

한 방에서는 모든 폰이 모든 목소리를 녹음한다. 이때 **폰끼리의 크기 차이는 말하는 사람이 앉은 자리로 정해진다.** 예를 들어 A 씨가 말하면 "1번 폰 기준 2번은 -8dB, 3번은 -15dB" 같은 모양이 나오고, A 씨가 앉아 있는 동안 이 모양(**자리 지문**)은 거의 그대로다. B 씨가 말하면 모양이 확 달라진다.

| 상황 | 1.0.3 까지 | 1.0.4 |
|---|---|---|
| 같은 사람이 계속 말함 (자리 지문 그대로) | 유지 시간이 지나면 바뀔 수 있다 | **바꾸지 않는다** (유지 시간과 상관없이) |
| 다른 사람이 말하기 시작함 (자리 지문이 6dB 넘게 바뀜) | 유지 시간이 지나야 바뀐다 | 0.3초 확인한 뒤 **바로 넘긴다** |
| 고개를 크게 돌리거나 자리를 옮김 | — | 자리 지문이 바뀌므로 다른 사람처럼 넘길 수 있다 (그대로 두기로 함) |
| 같은 사람인데 처음에 먼 폰을 골랐음 | — | 몇 초 평균으로 다른 폰이 3dB 넘게 가까우면 **한 번만** 고쳐 잡는다 |

그래서 **유지 시간은 1000(1초)으로 되돌리는 것을 권장한다.** 길면 새 사람이 말을 시작했을 때 그만큼 먼 폰(울리는 소리)으로 들린다. 11/26 울림이 늘어난 것도 유지 3000 의 영향일 수 있다 (추정).

**그대로인 것:** 오토믹서 `select`, 전환 6dB, 크기 이어 붙이기, 처음 구간 다시 재기, 잡음 제거, 목소리 맞추기 ±4초, 비프 지우기. 폰 소리를 더하는 방식은 하나도 늘지 않았다.

### 여기서 미리 확인한 것

| 확인 | 결과 |
|---|---|
| 세 사람이 7번 번갈아 말하는 흉내 녹음 (폰 3대, 방 울림 포함) | 폰 바뀜 **11번 → 6번** (사람이 바뀐 횟수와 같음), 말하는 사람과 먼 폰이 들린 시간 **28% → 0.1%** |
| 흉내 녹음 30가지 (말하는 순서·길이 10가지 × 울림 세기 3가지) | 사람이 바뀐 것은 **모두 찾음**, 새 방식이 기존보다 나빠진 경우 없음 |
| 한 사람이 2분 내내 말하는 녹음 | 폰 바뀜 **0번** |
| 1.0.4 이미지로 `howling_test_104.sh` 를 직접 돌림 | 경우 3개 병합 완료, 요약 정상. 실패 기록이 있으면 이유 문장까지 나오는 것 확인 |

**알고 있는 약점 (원래부터 있던 것):** 어떤 폰 앞에 앉은 사람이 회의 내내 거의 말을 하지 않으면, 그 폰이 실제보다 가깝게 계산되어 다른 사람 목소리를 그 폰으로 들려줄 수 있다. 흉내 녹음 30가지 중 3가지가 이 경우였다 (1.0.3 방식은 같은 경우 더 나빴다).

## 0-1. 시험 전 운영 `.env` 기준값

시험 도구는 **같은 사람 유지·유지 시간·크기 맞추기·잡음 제거와 목소리 맞추기 범위(4000)만** 경우마다 바꾸고, 나머지는 운영 `.env` 를 따른다.

| 항목 | 값 | 비고 |
|---|---|---|
| `AUTOMIX_MODE` | **select** | 같은 사람 유지는 select 에서만 동작한다. 다르면 요약에 주의가 뜬다 |
| `AUTOMIX_SWITCH_DB` | 6 | |
| `MERGE_LEVEL` | dynamic | |
| `ALIGN_REFINE` / `ALIGN_REFINE_MAX_MS` | 1 / **4000** | |
| `ALIGN_HEAD_CHECK` | 1 | 시험 중 바꾸지 않는다 |
| `BEEP_SCRUB` | 1 | |
| `MERGE_TRACK_GAIN` | 아무 값 | 크기 이어 붙이기가 켜져 있으면 쓰이지 않는다 |
| `AUTOMIX_SAME_TALKER` | 1 | **1.0.4 새 항목.** 줄이 없어도 기본으로 켜져 있다 |
| `AUTOMIX_TALKER_DB` | 6 | **1.0.4 새 항목.** 줄이 없어도 기본 6 |

설치할 때 새 항목 둘이 `.env` 에 없다고 경고가 나와도 괜찮다 (기본값으로 돈다).

## 1. 먼저 시험 — 운영은 그대로 두고

```bash
cd /data/timblo/mobile-sync-server                  # 설치 폴더
sha256sum -c mobile-sync-server_1.0.4_amd64.tar.sha256     # "OK"
docker load -i mobile-sync-server_1.0.4_amd64.tar          # 이미지만 올린다. 운영 컨테이너는 그대로
chmod +x howling_test_104.sh
IMAGE=mobile-sync-server:1.0.4 ./howling_test_104.sh /data/timbel/howling_test
```

- `.txt` 로 가져왔으면 `mv howling_test_104.txt howling_test_104.sh`, `$'\r': command not found` 가 나오면 `sed -i 's/\r$//' howling_test_104.sh`
- 설치 폴더가 다르면 앞에 `INSTALL_DIR=<설치 폴더>` 를 붙인다
- **1.0.3 이전 이미지로 돌리면** "1.0.4 이전 버전이다" 하고 멈춘다
- 시험 폴더 구조는 103 과 같다 (회의 폴더마다 폰별 원본 flac 2개 이상). **11/26 의 5명 30분 회의처럼 한 사람이 길게 말하는 구간이 있는 회의**를 넣는다

경우 하나 = `같은사람유지:유지시간ms:크기맞추기:잡음제거dB`

| 순서 | 경우 | 결과 이름 | 보는 것 |
|---|---|---|---|

### 숫자 읽는 법

| 값 | 뜻 |
|---|---|
| `전환` | 폰이 바뀐 횟수. **S1 이 S0 보다 확 줄어야** 한다 |
| `사람바뀜` | 말하는 사람이 바뀌었다고 본 횟수. 실제 회의에서 발언자가 바뀐 횟수와 비슷하면 정상. **전환보다 훨씬 많으면** 고개 돌림 같은 것까지 사람 바뀜으로 본 것 (`AUTOMIX_TALKER_DB` 를 8 로) |
| `들린비율` | 폰별로 결과에서 들린 시간(%). 거의 말 안 한 사람 앞 폰이 높게 나오면 위 "알고 있는 약점" |
| `크기` | 크기 맞추기를 켠 경우, 폰이 바뀐 구간에 준 크기(dB) 최소/중간/최대. 12 에 붙어 있으면 녹음이 아주 작았던 것 |
| `주의: ...` | 사진에 꼭. 11/26 의 `drift_failed` 처럼 실패하면 **이유 문장**이 같이 나온다 |

**한 사람이 길게(20초 넘게) 말한 구간, 발언자가 바뀌는 순간, 처음 1분**을 결과끼리 번갈아 듣고 적는다.

|---|---|

## 2. 운영 배포

### ① 설치 폴더 확인

```bash
docker inspect mobile-sync-server \
  --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
```

### ② 파일 올리고 설치

```bash
cd <①에서 나온 폴더>

# 옛 tar 지우기 (안 지우면 설치가 멈춘다). 1.0.4 tar 는 지우지 않는다
rm -f mobile-sync-server_1.0.[0-3]_amd64.tar*

# 새 tar 2개, install.sh, docker-compose.yml, .env.example 을 이 폴더에 복사한 뒤
sha256sum -c mobile-sync-server_1.0.4_amd64.tar.sha256     # "OK"
chmod +x install.sh
./install.sh
```

시험(1) 때 이미 `docker load` 해 두었어도 그대로 진행하면 된다.

### ③ 시험에서 고른 값 넣기

```bash
set_env() { grep -q "^$1=" .env && sed -i "s/^$1=.*/$1=$2/" .env || echo "$1=$2" >> .env; }
set_env AUTOMIX_HOLD_MS 1000          # 권장. 시험에서 3000 이 낫다면 3000
set_env MERGE_DENOISE 16              # 시험에서 고른 값
# set_env AUTOMIX_LEVEL_MATCH 0       # S1_H1000_L0_N16 이 더 나았으면
docker compose --env-file .env up -d                        # docker restart 로는 반영 안 된다
```

### ④ 확인

```bash
grep IMAGE_VERSION .env                                     # IMAGE_VERSION=1.0.4
curl -s http://127.0.0.1:9995/health                        # {"status": "ok", ...}
docker logs mobile-sync-server 2>&1 | grep server_start     # "version": "1.0.4" + settings
```

`settings` 에서 아래가 나와야 한다 (`(기본값)` 이 붙어도 괜찮다):

```
"AUTOMIX_SAME_TALKER": true   "AUTOMIX_TALKER_DB": 6.0   "AUTOMIX_HOLD_MS": 1000 (또는 고른 값)
"MERGE_DENOISE": 16.0 (또는 고른 값)   "AUTOMIX_MODE": "select"   "ALIGN_REFINE_MAX_MS": 4000
```

병합을 한 건 해 본 뒤:

```bash
docker logs mobile-sync-server 2>&1 | grep merge_automix | tail -1     # "sameTalker": true, "talkerChanges": ...
```

### 되돌리기

| 상황 | 할 일 |
|---|---|
| 1.0.4 전체에 문제 | `.env` 의 `IMAGE_VERSION=1.0.3` → `docker compose --env-file .env up -d` (옛 이미지는 남아 있다) |
| 같은 사람 유지만 의심 | `.env` 에 `AUTOMIX_SAME_TALKER=0` → 같은 방법 (1.0.3 과 똑같이 동작) |
