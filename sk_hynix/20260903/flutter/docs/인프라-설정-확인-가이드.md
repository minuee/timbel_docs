# 인프라 설정 확인 가이드 (도커 VM)

망분리 환경에서 직접 확인하는 방법. 콘솔에서 단계별로 실행하면 됩니다.

---

## 1단계: 도커 컨테이너 접속

> **중요**: 이 단계의 모든 명령어는 **호스트(도커 밖)**에서 실행합니다. 실행 후 프롬프트가 바뀌면 그때부터 **도커 안**에 있는 것입니다.

### 실행 중인 컨테이너 확인 (호스트에서)

```bash
docker ps
```

결과에서 nginx와 API 서버 컨테이너 이름 또는 ID를 찾습니다.
예: `nginx_container`, `api_server_container` 등

### nginx 컨테이너 접속 (호스트에서 실행)

```bash
docker exec -it <nginx-컨테이너-이름> /bin/bash
```

예:
```bash
docker exec -it nginx /bin/bash
```

**실행 후 프롬프트가 이렇게 바뀝니다:**
```
root@a1b2c3d4e5f6:/#
```

이제 **도커 안에 있으므로**, 이후 명령어는 도커 안에서 실행하면 됩니다.

### API 서버(Spring Boot) 컨테이너 접속 (호스트에서 실행)

```bash
docker exec -it <api-컨테이너-이름> /bin/bash
```

마찬가지로 프롬프트가 바뀌면 도커 안에 접속된 것입니다.

### 빠른 참고: 도커 안으로 안 가고 조회하기

파일 내용만 보고 싶으면 도커 밖에서 바로:

```bash
# 방법 1: nginx 전체 설정 + 유효성 검사
docker exec -it nginx nginx -T

# 방법 2: nginx.conf 내용만 출력
docker exec -it nginx cat /etc/nginx/nginx.conf

# 방법 3: 특정 설정만 검색
docker exec -it nginx grep "client_max_body_size" /etc/nginx/nginx.conf
```

## 2단계: nginx 설정 확인

### nginx 설정 파일 위치 확인

nginx 컨테이너 안에서:

```bash
nginx -T
```

이 명령이 **전체 설정을 출력**하고 유효성도 검사합니다.

또는 직접 파일 위치 확인:

```bash
cat /etc/nginx/nginx.conf
```

보통 `/etc/nginx/` 안에 있거나, 외부 설정 파일을 로드하는 경우:

```bash
cat /etc/nginx/conf.d/*.conf
```

### 찾을 설정 (최소 3가지)

**1. `client_max_body_size`**

```bash
grep -r "client_max_body_size" /etc/nginx/
```

출력 예:
```
http {
    client_max_body_size 1M;  # ← 현재값
}
```

**2. `client_body_timeout`**

```bash
grep -r "client_body_timeout" /etc/nginx/
```

출력 예:
```
http {
    client_body_timeout 60s;  # ← 현재값
}
```

**3. `proxy_read_timeout` (WAS로 포워딩하는 경우)**

```bash
grep -r "proxy_read_timeout" /etc/nginx/
```

출력 예:
```
location / {
    proxy_read_timeout 60s;  # ← 현재값
}
```

### 설정값이 나오지 않으면

기본값을 사용 중이라는 뜻입니다. 기본값은:
- `client_max_body_size`: **1M**
- `client_body_timeout`: **60s**
- `proxy_read_timeout`: **60s**

## 3단계: API 서버(Spring Boot) 설정 확인

### 설정 파일 위치

API 서버 컨테이너 안에서, 다음 중 하나:

```bash
# application.properties 찾기
find / -name "application.properties" 2>/dev/null

# application.yml 찾기
find / -name "application.yml" 2>/dev/null

# application-*.properties (프로필별 설정)
find / -name "application-*.properties" 2>/dev/null
```

일반적인 위치:
- `/app/application.properties`
- `/app/config/application.yml`
- `/usr/local/tomcat/webapps/ROOT/WEB-INF/classes/application.properties`

### 찾을 설정 (Spring Boot multipart)

설정 파일을 찾았으면:

```bash
cat <파일경로> | grep -i "multipart\|max"
```

또는 전체 출력:

```bash
cat <파일경로>
```

**찾을 키 (3가지):**

```properties
# 1. 파일 최대 크기
spring.servlet.multipart.max-file-size=1MB

# 2. 요청 최대 크기
spring.servlet.multipart.max-request-size=10MB

# 3. 타임아웃 (application.properties에 없으면 WAS 설정)
server.tomcat.connection-timeout=20000
```

### 설정이 yml 형식이면

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 1MB
      max-request-size: 10MB
```

### 환경 변수로 설정된 경우

컨테이너 실행 시 `-e` 플래그로 넘겨진 경우:

```bash
docker inspect <api-컨테이너-이름> | grep -A 20 "Env"
```

또는 컨테이너 안에서:

```bash
env | grep -i "multipart\|max\|timeout"
```

## 4단계: 부하 로드밸런서(ALB/ELB) 설정 확인

### AWS 사용 중인 경우

도커 VM 안에서는 확인 불가. **AWS 콘솔에서 직접 확인해야 합니다.**

1. AWS Management Console 로그인
2. EC2 > Load Balancers > Application Load Balancer 선택
3. "Actions" > "Edit attributes"
4. "Idle timeout" 값 확인 (기본: 60초)

또는 AWS CLI (VM에 설치되어 있으면):

```bash
aws elbv2 describe-load-balancer-attributes \
  --load-balancer-arn <ALB-ARN> \
  --query 'Attributes[?Key==`idle_timeout.timeout_seconds`]'
```

위에서 찾은 값들을 정리하고 아래와 대조합니다.

| 항목 | 현재값 | 필요값 | 상태 |
|---|---|---|---|
| nginx `client_max_body_size` | ___ | 150M 이상 | ✓ / ✗ |
| nginx `client_body_timeout` | ___ | 300s 이상 | ✓ / ✗ |
| nginx `proxy_read_timeout` | ___ | 300s 이상 | ✓ / ✗ |
| Spring `max-file-size` | ___ | 150M 이상 | ✓ / ✗ |
| Spring `max-request-size` | ___ | 150M 이상 | ✓ / ✗ |
| LB idle timeout | ___ | 300s 이상 | ✓ / ✗ |

## 6단계: 설정 수정 (필요시)

### nginx 설정 수정

#### 방법 1: 파일 직접 수정

nginx 컨테이너 안에서:

```bash
# vi/nano 에디터로 편집
vi /etc/nginx/nginx.conf
```

수정할 부분:

```nginx
http {
    client_max_body_size 150M;        # 1M → 150M
    client_body_timeout 300s;         # 60s → 300s
    
    server {
        location / {
            proxy_read_timeout 300s;  # 60s → 300s
        }
    }
}
```

편집 후 저장 (vi에서 `:wq` + Enter)

#### 방법 2: 한 줄 명령으로 수정 (텍스트 치환)

```bash
# client_max_body_size 수정
sed -i 's/client_max_body_size 1M/client_max_body_size 150M/g' /etc/nginx/nginx.conf

# client_body_timeout 수정
sed -i 's/client_body_timeout 60s/client_body_timeout 300s/g' /etc/nginx/nginx.conf

# proxy_read_timeout 수정
sed -i 's/proxy_read_timeout 60s/proxy_read_timeout 300s/g' /etc/nginx/nginx.conf
```

### Spring Boot 설정 수정

#### application.properties 파일 수정

```bash
vi /app/application.properties
```

수정할 부분:

```properties
# 1M → 150M
spring.servlet.multipart.max-file-size=150M

# 10M → 150M
spring.servlet.multipart.max-request-size=150M

# 새로 추가 (없으면)
server.tomcat.connection-timeout=600000
```

#### sed로 한 줄 수정

```bash
sed -i 's/max-file-size=.*/max-file-size=150M/g' /app/application.properties
sed -i 's/max-request-size=.*/max-request-size=150M/g' /app/application.properties
```

## 7단계: 설정 적용 (재시작)

### nginx 컨테이너 재시작

컨테이너 밖에서:

```bash
docker restart <nginx-컨테이너-이름>
```

또는 컨테이너 안에서:

```bash
nginx -s reload
```

### API 서버 컨테이너 재시작

컨테이너 밖에서:

```bash
docker restart <api-컨테이너-이름>
```

### 재시작 확인

```bash
docker ps
```

UPTIME 컬럼에서 컨테이너가 최근에 시작되었는지 확인

## 8단계: 설정 적용 확인

### nginx 설정이 로드됐는지 확인

nginx 컨테이너 안에서:

```bash
nginx -T
```

또는 특정 항목만:

```bash
grep "client_max_body_size" /etc/nginx/nginx.conf
```

### 설정 파일이 도커 외부에 있는 경우 (마운트)

도커 VM 호스트(도커 밖)에서:

```bash
# 도커 compose 파일 확인
cat docker-compose.yml | grep -A 5 "volumes"

# 마운트된 파일 위치 찾기
# 예: /data/config/nginx.conf:/etc/nginx/nginx.conf
# → VM에서 /data/config/nginx.conf 수정
```

위 1~5단계를 완료한 후 아래를 정리해서 개발팀에 공유하면 됩니다:

## 문제 발생 시

### 설정 파일을 찾을 수 없음

```bash
# 전체 검색
find / -name "nginx.conf" 2>/dev/null
find / -name "application*.properties" 2>/dev/null
find / -name "application*.yml" 2>/dev/null
```

또는 도커 이미지 정보 확인:

```bash
docker inspect <컨테이너-이름> | grep -i "image\|cmd"
```

### vi/nano 에디터가 없음

```bash
# apt 설치 (Debian/Ubuntu 기반 이미지)
apt-get update && apt-get install -y nano

# 또는 sed로 한 줄 수정
sed -i 's/1M/150M/g' /etc/nginx/nginx.conf
```

### 재시작 후에도 설정이 안 적용됨

마운트된 외부 파일을 수정해야 할 수 있습니다:

```bash
# docker-compose.yml에서 volumes 확인
cat docker-compose.yml | grep volumes

# 호스트 경로 수정 (도커 밖에서)
sudo vi /호스트/경로/nginx.conf
```

## 참고

- 모든 숫자값은 **현재 환경에 맞게 조정**하세요
- `150M`은 50분 회의(98MB) + 여유를 본 값입니다
- `300s`는 100MB 업로드 + S3 처리 시간을 고려한 값입니다
- 변경 후 **반드시 업로드 재테스트**를 해서 동작 확인하세요
