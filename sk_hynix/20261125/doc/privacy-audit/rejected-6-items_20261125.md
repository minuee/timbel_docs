## 1. 4.3.2 시스템관리자·개인정보취급자 사용 이력 로깅

**요구:** 필수 항목 ① ID ② 날짜·시간 ③ 접속자 IP ④ 수행업무(조회·수정·삭제·인쇄·입력 등) ⑤ 누구의 개인정보를 처리했는지 ⑥ 다운로드 사유
**증빙:** 개인정보취급자 접속 및 사용 로그 화면

| 요구 | 현황 | 해결안 |
|---|---|---|
| ①②③ | ✅ 로그인 시점은 "사용자 접속 이력"에 있음 | 관리자 **행위마다** 남기기 |
| ④ 수행업무 | 🔸 설정 변경만 남고 **조회는 안 남는 것으로 추정** | 메서드로 판별: GET=조회, POST=입력, PUT/PATCH=수정, DELETE=삭제 |
| ⑤ 정보주체 | 🔸 없음 | 요청 경로·파라미터의 대상 ID(사용자·회의록) 저장. 목록 조회는 "조회 조건 + N건" |
| ⑥ 다운로드 사유 | 관리자 다운로드 기능 없음 | **"해당 없음"** 명시 + 생기면 사유 입력 받는다고 적기 |

**해결안 (🔸)**
1. **게이트웨이**에서 **토큰의 역할이 관리자인 요청**을 모두 기록 (경로가 분리 안 되어 있으므로 "누가 불렀는지"로 거름)
   - 토큰에 역할 정보가 없으면 → 관리자 사이트가 요청에 표시 헤더를 붙이고 게이트웨이가 그걸로 거름
2. 관리자 사이트 **이력/통계 관리 → "관리자 처리 이력"** 메뉴 추가
   - 칸: 일시, 관리자 ID, IP, 수행업무, 대상, 결과
   - 검색: 기간·관리자·업무 종류
   - **조회만 가능** (수정·삭제 없음 → 4.3.4와 연결)
3. **시스템관리자(서버·DB 직접 접속)**
   - 서버: 회사 접근제어 솔루션 로그로 증빙
   - DB: 사람별 계정 사용 + MariaDB 감사 플러그인(`server_audit`)으로 누가·언제·어떤 쿼리를 실행했는지 기록
   - 루트를 여럿이 같이 쓰면 "누가"가 안 남음 → 루트는 비상용·승인 후 사용

**낼 증빙:** 관리자 처리 이력 화면, 게이트웨이 기록 코드 캡처, 관리자 메뉴 목록(다운로드 없음), DB 감사 로그 설정

## 2. 6.1.3 일정시간 미사용 시 접속 차단

**요구:** 일정시간 업무처리가 없으면 자동 차단, 다시 접속 시 재인증. 최대 접속시간은 최소한(통상 10~30분). 장시간 접속이 필요하면 접속시간 기록을 보관
**증빙:** 세션 타임아웃 설정 화면·관리자 설정 화면 또는 소스코드, 시간 경과로 차단되는 화면

**현황**
- ✅ 인증서버 소스 기준 access 토큰 기본 **24시간**, **동작이 없을 때 끊는 기능은 없음** (`auth-api-2-release/src/utils/redis/tokenUtils.js:2`)

**해결안 (🔸)**
1. **관리자 사이트**: **30분** 동안 동작이 없으면 로그아웃 → 재로그인
   - 서버: 요청이 올 때마다 Redis 세션 만료 시간을 연장 (만료 처리 코드 `sessionUtils.js` 의 `expiredSessionHandler` 는 이미 있음)
   - 화면: 만료 시 "세션이 만료되었습니다" 안내 → 로그인 화면
   - 시간은 설정값으로 (설정 화면 또는 환경변수)
2. **일반 사용자 앱(웹·모바일·PC)**: 본인 정보만 보므로 **취급자 시스템 대상 외**로 소명
   - PC앱 녹음 중 끊김 문제도 피할 수 있음
3. **서버·DB 접속**: 회사 접근제어 솔루션의 세션 타임아웃 설정으로 증빙

**낼 증빙:** 타임아웃 설정값(화면 또는 소스), 30분 뒤 차단되는 화면

## 3. 3.1.1 명확한 파기 조건 + 3.1.3 자동 파기 (함께 대응)

**3.1.1 요구:** 현업이 지시한 명확한 파기 조건. 방식은 DB 데이터·백업까지 완전 삭제(복구 불가). 주기는 현업 제시(즉시·월·분기·연 1회 등). 보유기간 경과·목적 달성 시 **5일 이내** 파기
**3.1.1 증빙:** 파기 정책 코드·시스템 로그·PC 파일 점검 보고서 등 캡처, 파기 결과 자료

**3.1.3 요구:** 보유기간 도래·목적 달성 시 자동 삭제(예: 자동 스케줄러). 수동이면 담당자가 수시로 확인해 5일 이내 파기
**3.1.3 증빙:** 배치 정책 코드 등 자동 파기 기능·절차
**파기 대상:** 사번 또는 성명, 접속 IP, 녹음파일, 텍스트 변환 원본

**현황**
- ✅ PC앱: 업로드 성공 시 PC의 녹음파일 즉시 삭제 (`src/main/main.js:723`)
- ✅ 인증서버: 자동 파기 배치 없음 (로그인 이력을 지우는 코드 없음)
- 🔸 "콘텐츠 보존 관리" 메뉴 = 보존 기간 설정으로 추정
- 🔸 회의록 서버·STT·파일 저장소는 소스가 없어 확인 못 함

**해결안 (🔸)**
1. **파기 기준표** (현업에게 받음) ← **유일하게 우리가 정할 수 없는 것**

   | 대상 | 보존 기간 | 파기 주기 | 저장 위치 |
   |---|---|---|---|
   | 녹음 원본 | ? | ? | 파일 저장소 |
   | 텍스트 변환(STT) 원본 | ? | ? | DB |
   | 회의록 | ? | ? | DB |
   | 사번·성명 (퇴사자 등) | ? | ? | DB |
   | 접속 IP (접속기록) | 접속기록 보관 기간 이후 | ? | DB |
   | 백업본 | ? | ? | 백업 저장소 |

2. **매일 도는 파기 배치** (서버)
   - 콘텐츠 보존 관리의 기간 값을 읽어 지난 데이터를 삭제
   - 매일 돌면 "5일 이내"를 항상 만족
   - 실행 로그: 날짜, 대상 종류, 삭제 건수, 결과
3. **백업까지 복구 불가**: 백업 보관 기간이 끝나면 자동으로 사라지게 → "보존 기간 + 백업 보관 기간" 뒤에는 어디에도 없음을 정책서에 명시
4. 접점(PC앱·모바일)의 임시 녹음파일: 업로드 후 즉시 삭제(PC앱 ✅), 업로드 실패로 남은 파일 정리 방법도 적기

**낼 증빙:** 파기 기준표(현업 지시), 콘텐츠 보존 관리 화면, 배치 코드·스케줄 설정, 배치 실행 로그

## 4. 4.3.4 접속기록 백업

**요구:** 접속기록 위변조·도난·분실 방지를 위해 안전하게 백업 보관. 서버·DB·애플리케이션 접속내역·처리내역의 백업정책(대상·주기 등) 수립
**증빙:** 접속기록 백업정책(백업대상·방법·주기·저장장치 형태 등), 접속기록 백업 설정 화면

**해결안 (🔸)** — 정책서 1장

| 항목 | 내용 |
|---|---|
| 백업 대상 | 사용자 접속 이력, 관리자 처리 이력(신규), 설정 변경 이력, DB 감사 로그, 서버 접속 로그(회사 솔루션) |
| 백업 방법 | DB 정기 백업 / 로그 파일 복사 |
| 백업 주기 | 매일 |
| 저장장치 | 운영 서버와 **분리된** 저장소 |
| 보관 기간 | 1년 이상 (🔸 법정 기준 — 회사 기준으로 확인) |
| 위변조 방지 | 이력 테이블은 관리자 화면에서 **조회만** 가능, 백업 저장소는 접근 권한 제한 |

**낼 증빙:** 백업 정책서, 백업 설정 화면(스케줄·저장 위치), 백업 이력

## 5. 4.3.3 접속기록 월 1회 이상 점검

**요구:** 개인정보 오남용·유출 대응을 위해 접속기록 등을 월 1회 이상 점검

- ➡ **체크리스트 초안은 `monthly-checklist_20261125.md`** (점검항목 | 점검내용 | 결과(적합/미적합/대상아님)). 아래 표는 처음 초안이라 참고만
