## 2. 미니 모드 확대 후 파동

**증상**
- 녹음 중 [축소] → 잠시 뒤 [확대] 하면 파동이 빈 화면에서 오른쪽부터 새로 차올랐다.
- 사용자가 보면 "미니 동안 녹음이 안 됐나?" 하고 의심할 수 있다.

**원인 — 녹음은 정상, 화면 표시만 문제**
- 파동은 화면 표시용일 뿐이고 녹음 파일과는 관계없다(헬퍼가 따로 녹음한다).
- 파동 막대를 몇 개 보관할지를 그림 영역의 가로 폭으로 계산한다. 미니 모드에서는 그림 영역이 숨겨져 폭이 0 → 보관 개수가 1개로 줄어, 미니 동안의 파동이 계속 버려졌다.

**수정**
- 마지막으로 잰 보관 개수를 기억해 두고, 숨겨진 동안(폭 0)에는 그 값을 쓴다.
- 숨겨진 동안에는 그리기만 건너뛴다. 막대는 계속 쌓인다.
- 결과: [확대] 하면 미니 동안의 파동이 끊김 없이 이어서 보인다.

**참고 (바꾸지 않음)**
- 미니 모드에 들어가면 항상 위는 **무조건 켜진다**. [확대] 하면 축소 전 설정으로 돌아간다. 지금 그대로 둔다.

## 3. 시스템 로그인(AM-Tray) 연동 뼈대

자세한 내용: `docs/sso-amtray-java/analysis.md`

- 흐름: [시스템 로그인] → `AmHelper.exe` 가 `AmInterface-RT-X64.dll` 의 `GetSystemTokenIT` 호출 → 인가토큰 → **우리 백엔드**(새 API, 아직 없음)가 SSO 서버로 검증 후 토큰 발급.
  - 미로그인(504011): AM 로그인 창을 띄움 → 로그인 알림(윈도우 메시지)이 오면 자동으로 이어감(최대 5분 대기).
  - AM-Tray 사용 불가(509090 등) / SSO 서버 이상 / 그 밖의 코드: 안내 문구를 띄우고 사번·MyAccess 로그인을 쓰게 한다.
- **안전장치**: `AMTRAY_SYSTEM_ID` 가 비어 있으면 예전과 같이 "시스템 로그인은 준비 중입니다." 만 나온다.
- **DLL 함수 형식은 아직 가정**이다(`AmHelper.cpp` "★ 가정"). 아래 확인 2~3번 결과로 맞춘다.
- 백엔드 API 도 아직 없다. 토큰까지 받아도 "시스템 로그인 서버가 준비 중입니다" 가 나온다(정상).
- 할 일: `questions-am.md` 는 AM 담당자에게, `request-backend.md` 는 백엔드에 전달.
- DLL 3개는 **git 에 올리지 말고** 확인할 때만 `src\helpers\windows\amtray\bin\` 에 복사한다(배포 여부는 AM 답변 Q10 뒤에 정함).
