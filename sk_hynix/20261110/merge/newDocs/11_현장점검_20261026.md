## 1. 배포 — `.env` 를 새 파일로 덮어쓰기

1. **기존 `.env` 를 먼저 백업**한다.
   ```bash
   cd <설치경로>
   cp .env .env.backup_20261026
   ```
2. 새 `.env.example` 로 **덮어쓴다.** 새 파일에는 `BEEP_MIN_TRACKS=1` 과 오늘 추가된 설정이 모두 들어 있다.
   ```bash
   cp <반입한 deploy 폴더>/.env.example .env
   ```
3. **아래 세 값이 백업과 같은지 비교**하고, 다르면 백업 값으로 고친다.
   ```bash
   grep -E '^(RUNTIME_DIR|HOST_PORT|SWAGGER_USER|SWAGGER_PASSWORD)=' .env.backup_20261026 .env
   ```
   | 값 | 다르면 생기는 일 |
   |---|---|
   | `RUNTIME_DIR` | 데이터 폴더가 바뀌어 **예전 병합 기록(jobId)이 안 보인다** |
   | `HOST_PORT` | 접속 포트가 바뀐다 (Swagger·master-api 주소) |
   | `SWAGGER_USER` / `SWAGGER_PASSWORD` | Swagger 로그인 계정이 바뀐다 |
4. **설치 스크립트를 실행**한다. 이미지 이름과 실행 계정(uid/gid)은 이 스크립트가 `.env` 에 다시 써 넣는다.
   ```bash
   ./install.sh
   ```
   > `.env` 를 손으로 고친 뒤에는 `docker restart` 가 아니라 `docker compose --env-file .env up -d` 로 다시 띄워야 반영된다.

**[확인]**
```bash
docker exec mobile-sync-server env | grep -E 'BEEP_MIN_TRACKS|MERGE_LEVEL'   # → BEEP_MIN_TRACKS=1, MERGE_LEVEL=dynamic
curl http://127.0.0.1:9995/health                               # → {"status": "ok", ...}
```

### Swagger 에서 Bearer 토큰 넣기 (0.0.5 부터)

Swagger 오른쪽 위 **Authorize** 버튼 → 토큰만 붙여 넣고(앞에 `Bearer` 는 쓰지 않는다) → Authorize.
이후 병합 요청마다 `Authorization: Bearer <토큰>` 헤더가 자동으로 붙는다. 새로고침해도 유지된다.
(10/23 `retry` 에서 난 "access denied" 는 앞단 게이트웨이가 토큰 없는 요청을 막은 것으로 보인다 — 병합 서버에는 그런 응답이 없다.)

## 2. 시험 A — 엊그제 3명이 녹음한 파일 (가장 중요)

Swagger(`/docs`) 의 `POST /v1/merge/upload` 또는 Postman:

```
files       [File]  3명 파일 각각 (같은 key 로 3번)
beepSource  [Text]  leader
syncSound   [Text]  beep
format      [Text]  wav
```

완료 후 `GET /v1/merge/{jobId}` 응답의 `alignment` 를 본다.

| 볼 것 | 좋음 | 기록표에 적을 것 |
|---|---|---|
| `mode` | `beep` | 값 |
| `tracks[].fallback` | 전부 `null` | `none` 이 있으면 어느 파일인지 |
| `tracks[].foundBy` | 없음(정식으로 찾음) / `relaxed` / `voice` | 파일별 값 |
| `trimmedMs` | 3000~8000 정도 | 값 |
| `drift.endFound` | 파일 수와 같으면 좋음 (종료 비프를 찾은 수) | 값 |
| `level` | `dynamic` | — |

`GET /v1/merge/{jobId}/download` 로 받아서 **들어 본다.**

| 들을 것 | 좋음 |
|---|---|
| 맨 앞 | 안내 음성·비프 없이 바로 회의 소리 |
| 맨 끝 | 종료 비프·"녹음을 종료합니다" 없음 |
| 목소리 크기 | 예전보다 확실히 큼 |
| 울림·같은 말 반복 | 예전보다 줄었음 |

**[확인]** `mode=beep` 이고 앞뒤가 잘렸으면 → **3절로**. 아니면 → **5절로**.

## 5. 안 잘렸을 때 — 진단 명령 (새로 빌드할 필요 없음)

같은 3명 파일로 실행한다. 아무것도 저장·업로드하지 않는다.

```bash
docker cp 파일1.flac mobile-sync-server:/tmp/
docker cp 파일2.flac mobile-sync-server:/tmp/
docker cp 파일3.flac mobile-sync-server:/tmp/
docker exec mobile-sync-server python -m recog sync-scan --source leader /tmp/파일1.flac /tmp/파일2.flac /tmp/파일3.flac
```

출력에서 **두 군데만** 기록표에 옮겨 적는다.

1. `== beep` 아래, 파일마다
   - `검출`(O/X), `위치ms`, `비고`
   - 바로 아래 **`└ 음별 1·2·3번째 크기`** 줄의 숫자 6개 (3000Hz 세 개, 4200Hz 세 개)
2. `== voice` 아래, 파일마다 `검출`(O/X) 과 `신뢰도`

추가로 파일 하나만 이것도 (앱이 완전한 무음을 끼워 넣었는지):
```bash
docker exec mobile-sync-server ffmpeg -i /tmp/파일1.flac -t 15 -af silencedetect=noise=-90dB:d=0.1 -f null - 2>&1 | grep silence_
```
→ 나온 줄을 그대로 적는다 (안 나오면 "없음").

## 6. 진단 결과별로 그 자리에서 해 볼 것

| 진단에서 본 것 | 뜻 | 그 자리에서 할 일 (빌드 불필요) |
|---|---|---|
| beep `비고` 가 **기준 근처** | 비프가 있는데 약간 모자람 | `.env` 에 `BEEP_GUIDED_MIN_RISE=15` → 다시 띄우고 시험 A 재시도 |
| `음별` 줄에서 **한 음만 크고** 다른 음이 1 근처 | 한쪽 음이 거의 안 녹음됨 | 위와 같음 |
| `음별` 줄이 **두 음 모두 1 근처** (귀로는 비프가 들림) | 녹음된 비프가 서버가 아는 비프와 다름 | **`syncSound` 를 `voice` 로** 바꿔 시험 A 재시도 (안내 음성 기준으로 자름. 비프 2초가 결과 앞에 남을 수 있음 — STT 영향은 적음) |
| voice `검출` 이 O, 신뢰도 0.5 이상 | 안내 음성은 잡힌다 | 위의 `voice` 재시도가 통할 가능성이 높다 |
| voice 도 X, 신뢰도 0.4 미만 | 안내 음성도 안 잡힘 | 그 자리에서 할 것 없음 → 기록표만 가져옴 |
| `silence_start` 가 3~7초 사이에 나옴 | 앱이 비프 근처에 무음을 끼움 | 기록만. (시험상 무음만으로는 못 잡지 않았음) |

**그래도 안 되거나 이상하면 되돌리기** (`.env` 수정 후 다시 띄우기):
```
BEEP_GUIDED=0        # 비프 다시 찾기 끄기
DRIFT_CORRECT=0      # 시계 오차 보정 끄기
MERGE_AUTOMIX=0      # 오토믹서 끄기
MERGE_LEVEL=off      # 음량 맞추기 끄기
```
또는 0.0.4 이미지로 되돌린다.
