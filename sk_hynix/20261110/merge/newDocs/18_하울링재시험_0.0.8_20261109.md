# 하울링 재시험 — 0.0.8 순간마다 폰 하나만 쓰기

작성 2026-11-09 · 시험: 다음 회사 방문 때

## 왜 방향을 바꿨나

| 지금까지 알게 된 것 | 뜻 |
|---|---|
| 11/05: 설정 12가지 조합 모두 울림 | 음량 맞추기·드리프트·오토믹서 세기는 원인이 아니다 |
| 11/09: 0.0.7 로그 `linked: []`, `used: 0` | 파형 맞추기가 **한 번도 적용되지 않았다**. 결과는 0.0.6 과 같은 조건이었다 |
| 폰 원본 하나는 다른 사람 목소리가 들려도 깨끗하다 | 울림은 **합칠 때** 생긴다 |
| skHynix 예전 소스도 폰 소리를 전부 더했다 | "좋은 것만 잘라 붙이는" 처리는 어느 소스에도 없었다 |

같은 방의 폰 4대는 모두 같은 목소리를 녹음한다. 폰마다 말하는 사람과의 거리가 달라 몇 ms씩 늦게,
각자 다른 방 울림을 담는다. 이것을 더하면 한 목소리 위에 미세하게 어긋난 복사본 3개가 쌓여 울린다.
말하는 사람이 바뀌면 거리 차이도 바뀌므로, 시간을 아무리 맞춰도 더하는 한 울림은 남는다.

**0.0.8 은 더하지 않는다.** 순간마다 말하는 사람에게 가장 가까운 폰 **하나만** 쓰고 나머지는 완전히 끈다.
어느 폰이든 방 안 모든 목소리를 담고 있으므로 폰을 골라도 말이 빠지지 않는다.
시작점 맞추기(비프음)와 드리프트 보정은 그대로 쓴다. 폰을 바꿀 때 말이 끊기거나 반복되지 않게 하기 위해서다.

## 3. 듣고 판단하기

**같은 구간을 번갈아** 듣는다: `single_*` 하나 ↔ `select` ↔ 지난번 `merged_007.flac`(있으면).

| 들리는 것 | 판단 | 다음 |
|---|---|---|
| `select` 가 single 처럼 깨끗하다 | ✅ 해결 | 5절대로 운영 반영 |
| 깨끗한데 목소리가 폰 사이에서 출렁이거나 음색이 자주 바뀐다 | 전환이 잦다 | `select_steady` 가 나으면 그 값으로 운영 반영(5절) |
| 깨끗한데 사람마다 크기가 많이 다르다 | 폰마다 마이크 크기가 다르다 | 기록해서 복귀 (음량 맞추기는 그 다음 단계) |
| `select` 도 울린다, `single` 은 깨끗하다 | 전환이 너무 잦거나 다른 원인 | `select.log` 의 `switches` 값과 함께 복귀 |
| **`single` 부터 울린다** | 원인은 합치기가 아니다 (원본 또는 앞 처리) | 그 `single` 파일 이름 기록하고 복귀 |

**로그 숫자** (`듣기표.md` 아래쪽에 자동으로 적힌다)

```
- f1 = A.Biz_m_~~~1.flac   ← 올린 순서대로 f1, f2 ...
- select: "heardPct": {"f1": 41.2, "f2": 30.5, ...}, "switches": 212
```

| 값 | 뜻 |
|---|---|
| `heardPct` | 결과 파일에서 그 폰이 들린 시간 비율(%). 말을 많이 한 사람의 폰이 높아야 정상 |
| `switches` | 폰이 바뀐 횟수. 1시간 회의에 수백 번 정도는 정상, 수천 번이면 너무 잦다 |

한 폰이 거의 100% 면 그 폰만 쓰인 것이다. 그 폰이 다른 폰보다 녹음 음량이 유난히 크다는 뜻일 수 있으니 기록.

### 원본 샘플레이트 확인 (1분)

서버는 처리 전에 모든 파일을 16kHz 모노로 바꾼다(예전 skHynix 소스는 48kHz).
앱 업로드 규격이 16kHz 라서 이 변환은 아무것도 바꾸지 않을 것으로 본다. 실제 원본으로 확인한다.

```bash
ffprobe -hide_banner /data/timbel/howling_test/meet_20261105/*.flac 2>&1 | grep -E 'Input|Hz'
```

| 결과 | 판단 |
|---|---|
| 전부 `16000 Hz` | 예상대로. 16kHz 변환은 원인이 아니다 |
| `44100 Hz` / `48000 Hz` 가 있다 | 서버가 음질을 낮추고 있다. 울림과는 별개로 고칠 일 → 값 기록하고 복귀 |

- 서버에 `ffprobe` 가 없으면 컨테이너 안의 것을 쓴다:
  `docker exec mobile-sync-server ffprobe -hide_banner <컨테이너 안 경로>` (파일이 컨테이너 안에 없으면 생략)
- 샘플레이트는 울림을 만들지 않는다. 낮으면 소리가 조금 답답해질 뿐이다.
  `single_*.flac` 도 같은 변환을 거치므로 single 이 깨끗하면 이 변환은 원인에서 빠진다.

## 5. 결과가 좋으면 — 운영 반영

시험 스크립트는 **시험하는 동안만** 설정을 바꾸고 끝나면 원래 `.env` 로 되돌린다.
운영 `.env` 를 `deploy/env.example.txt`(최종본) 기준으로 직접 고쳐야 적용된다.

```bash
cd /data/timblo/mobile-sync-server
grep -E '^(MERGE_LEVEL|MERGE_AUTOMIX|AUTOMIX_)' .env       # 지금 값 확인
```

아래 줄이 이 값이 되게 고친다. 없는 줄은 추가한다.

```
MERGE_LEVEL=off
MERGE_AUTOMIX=1
AUTOMIX_MODE=select
AUTOMIX_HOLD_MS=300        # select_steady 가 나았으면 1000
AUTOMIX_SWITCH_DB=3        # select_steady 가 나았으면 6
```

```bash
docker compose --env-file .env up -d
```

- `AUTOMIX_MODE` 줄이 없어도 0.0.8 기본값이 `select` 라 동작은 같다. 명시해 두는 편이 나중에 헷갈리지 않는다.
- 반영 후 실제 앱으로 짧은 회의 하나를 녹음·병합해 한 번 더 들어 본다.
