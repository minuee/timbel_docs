# 운영 배포 1.0.0 + 설정 다듬기 시험

작성 2026-11-10 · 배포 2026-11-11

## 1.0.0 은 무엇이 바뀌었나

11/10 현장 시험 결과를 **기본값**으로 넣고, 폰별 음량 맞추기를 **꺼진 옵션**으로 추가했다.

| 설정 | 0.0.8 | **1.0.0** | 이유 |
|---|---|---|---|
| `AUTOMIX_MODE` | select | select | 그대로 (순간마다 폰 하나만) |
| `AUTOMIX_HOLD_MS` | 300 | **1000** | 300 은 폰 전환 4025번, 말이 끊겼다 |
| `AUTOMIX_SWITCH_DB` | 3 | **6** | 위와 같음 |
| `MERGE_LEVEL` | off | **dynamic** | off 는 소리가 작았다. dynamic 이 확실히 잘 들렸다 |
| `MERGE_TRACK_GAIN` | (없음) | **0 (꺼짐)** | 새 옵션. 아래 설명 |

= 11/10 에 가장 나았던 `select_steady + MERGE_LEVEL=dynamic` 조합. 운영은 이대로 나간다.

### 폰별 음량 맞추기 (`MERGE_TRACK_GAIN`, 기본 0)

폰 하나만 쓰면 그 순간 쓰인 폰의 원본 크기 그대로 나온다. 입 가까이 둔 폰(11/10 의 f3)은 크고
0.5m 떨어진 폰은 작아서, 폰이 바뀔 때마다 소리가 작아지거나 튄다.
`1` 로 켜면 폰마다 말소리 크기를 재서 **고정값 하나로** 키우거나 줄인 뒤 고른다.

- 폰 안의 목소리와 방 울림은 같은 비율로 커진다. 원본보다 더 울리게 만들지는 않는다.
- 다만 멀리 둔 폰은 원래 더 울리므로, 크게 키우면 그 울림도 크게 들린다 → 시험으로 확인.
- 최대 ±12dB (`MERGE_TRACK_GAIN_MAX_DB`), 목표 -20dBFS (`MERGE_TRACK_GAIN_TARGET_DB`).
- 폰 고르기 결과(`heardPct`·`switches`)는 켜도 끄도 같다.

## 시험 결과가 좋으면 1.0.1 이 필요한가 → 필요 없다

위 값은 모두 **`.env` 값**이다. 시험에서 더 나은 조합이 나오면 운영 `.env` 를 고치고 재기동하면 끝.
코드를 고쳐야 하는 결과가 나올 때만 1.0.1 을 만든다.

## 1. 운영 배포 (내일)

```bash
cd /data/timblo/mobile-sync-server

# ① 옛 tar 지우기 (안 지우면 설치가 멈춘다)
rm -f mobile-sync-server_0.0.8_amd64.tar*

# ② 새 tar 2개를 올린 뒤 검사
sha256sum -c mobile-sync-server_1.0.0_amd64.tar.sha256     # "OK"

# ③ 설치 (.env 는 그대로 두고 IMAGE_VERSION 만 1.0.0 으로 바뀐다)
./install.sh /data/timblo/mobile-sync-server
```

### ④ ★ 운영 `.env` 를 직접 고친다 — 꼭 할 것

설치는 기존 `.env` 를 건드리지 않는다. **`.env` 에 옛 값이 적혀 있으면 1.0.0 기본값보다 그 값이 이긴다.**

```bash
grep -E '^(MERGE_LEVEL|MERGE_AUTOMIX|AUTOMIX_MODE|AUTOMIX_HOLD_MS|AUTOMIX_SWITCH_DB|MERGE_TRACK_GAIN)=' .env
```

아래 값이 되게 고친다 (없는 줄은 추가):

```
MERGE_LEVEL=dynamic
MERGE_AUTOMIX=1
AUTOMIX_MODE=select
AUTOMIX_HOLD_MS=1000
AUTOMIX_SWITCH_DB=6
MERGE_TRACK_GAIN=0
```

```bash
docker compose --env-file .env up -d
```

### ⑤ 확인

```bash
grep IMAGE_VERSION .env                                # IMAGE_VERSION=1.0.0
curl -s http://127.0.0.1:9995/health                   # {"status": "ok", ...}
docker exec mobile-sync-server python -c \
  "from recog import automix, merge_job; print(automix.MODE, automix.HOLD_MS, automix.SWITCH_DB, merge_job.LEVEL_MODE, automix.TRACK_GAIN_DEFAULT)"
#   → select 1000 6.0 dynamic False   이 나와야 한다
```

그다음 실제 앱으로 짧은 회의 하나를 녹음·병합해 들어 본다.

## 2. 설정 다듬기 시험 (배포 후, 서비스 안 쓰는 시간에)

**스크립트는 서버를 건드리지 않는다.** `.env` 를 고치고 서버를 다시 띄우는 것은 직접 한다.
스크립트는 지금 떠 있는 서버에 병합 1건을 요청하고, **서버 안에서 실제로 쓰는 설정값**을 읽어 결과 이름에 붙인다.
그래서 `.env` 를 잘못 고쳤거나 재기동을 잊어도 결과 이름을 보면 바로 안다.

### 한 번 하는 일

```bash
cd <howling_test_100.sh 를 둔 곳>
chmod +x howling_test_100.sh
```

- `_txt.txt` 로 가져왔으면 `mv howling_test_100_txt.txt howling_test_100.sh`
- `$'\r': command not found` 가 나오면 `sed -i 's/\r$//' howling_test_100.sh`
- 시험 파일이 커서 `uploaded bytes exceed` 가 나오면 `.env` 에 `MERGE_UPLOAD_MAX_BYTES=4294967296` 을 넣고 다시 띄운다
  (시험이 끝나면 지워도 된다).

### 경우마다 반복 (아래 표 순서대로)

```bash
cd /data/timblo/mobile-sync-server
vi .env                                     # 표의 값으로
docker compose --env-file .env up -d        # 서버 다시 띄우기
<스크립트 위치>/howling_test_100.sh /data/timbel/howling_test
```

| 순서 | `AUTOMIX_HOLD_MS` | `AUTOMIX_SWITCH_DB` | `MERGE_TRACK_GAIN` | 결과 이름 | 보는 것 |
|---|---|---|---|---|---|
| 1 | 1000 | 6 | 0 | `h1000_s6_dynamic_gain0` | **1.0.0 운영 그대로. 비교 기준** |
| 2 | 1000 | 6 | 1 | `h1000_s6_dynamic_gain1` | 폰별 음량 맞추기 효과 (1과 비교) |
| 3 | 700 | 5 | 0 | `h700_s5_dynamic_gain0` | 폰 전환을 조금 더 자주 |
| 4 | 500 | 4 | 0 | `h500_s4_dynamic_gain0` | 그보다 조금 더 자주 |
| 5 | (3·4 중 나은 것) | | 1 | | 나은 전환값 + 음량 맞추기 |

`MERGE_LEVEL=dynamic` 은 모두 그대로 둔다.
**끝나면 1번 값으로 되돌리고 서버를 다시 띄운다** (또는 시험에서 가장 좋았던 값으로).

- 첫 실행 때 **원본 분석**도 한다 (몇 분). 다음부터는 건너뛴다.
- 같은 설정으로 다시 돌리면 그 결과만 덮어쓴다.

### 만들어지는 것

```
/data/timbel/howling_test/results_100/
├── run.log
└── meet_20261105/
    ├── 원본분석.txt                  ← 폰별 샘플레이트, 1분마다 말소리/조용할 때/차이
    ├── h1000_s6_dynamic_gain0.flac   ← 실행할 때마다 하나씩 늘어난다
    ├── h1000_s6_dynamic_gain1.flac
    ├── ... 각각의 .json / .log
```

### 실행할 때마다 화면 끝에 지금까지 결과 전체 요약 → **마지막 실행 화면만 사진으로 찍어 오면 된다**

```
================ 요약 (이 화면을 사진으로 찍어 오면 된다) ================
[meet_20261105]
f1 = A.Biz_m_1111.flac
...
f1 | 16000Hz | 62분 | 처음5분 말 -31.2 조용 -52.0 차이 20.8 | 중간 ... | 마지막5분 ...
...
h1000_s6_dynamic_gain0: "heardPct": {...}, "switches": 1384
h1000_s6_dynamic_gain1: "heardPct": {...}, "switches": 1384
    "gainDb": {"f1": 9.5, "f2": 7.0, "f3": -2.1, "f4": 12.0}
h700_s5_dynamic_gain0:  "heardPct": {...}, "switches": ....
...
```

정렬이 비프음이 아니면 그 줄 아래에 `주의: 정렬 ...` 이 나온다 (없으면 정상).

### 숫자 읽는 법

| 값 | 뜻 |
|---|---|
| 원본 `말` | 큰 소리 쪽 크기(dB). 폰이 입에 가까울수록 크다 (f3 이 가장 커야 정상) |
| 원본 `조용` | 말 사이 조용할 때 크기. 울림·잡음이 많으면 커진다 |
| 원본 **`차이`** | 말 − 조용. **클수록 또렷하다.** 처음 5분이 마지막 5분보다 작으면 "초반에 원본부터 더 울린다"가 숫자로 확인된 것 |
| `gainDb` | 폰별 음량 맞추기로 키운(+) 줄인(-) 양. +12 는 상한에 걸린 것 (그 폰이 아주 작다) |
| `switches` | 폰이 바뀐 횟수. 11/10 은 300/3 이 4025번, 1000/6 이 1384번 |

### 들을 것

같은 구간을 결과끼리 번갈아 듣고 칸마다 적는다.

```
                         울림(없음/약함/심함)  끊김·출렁임(없음/가끔/자주)  목소리 잘 들림(잘/보통/안)
h1000_s6_dynamic_gain0   ____                 ____                        ____
h1000_s6_dynamic_gain1   ____                 ____                        ____
h700_s5_dynamic_gain0    ____                 ____                        ____
h500_s4_dynamic_gain0    ____                 ____                        ____
(5번)                    ____                 ____                        ____
```

| 들리는 것 | 다음 |
|---|---|
| `gain1` 이 `gain0` 보다 잘 들리고 울림이 비슷하다 | 운영 `.env` 에 `MERGE_TRACK_GAIN=1` → 재기동. **이미지 교체 없음** |
| `gain1` 이 잘 들리지만 멀리 둔 폰 차례에서 울림이 커진다 | 기록해서 복귀 (`MERGE_TRACK_GAIN_MAX_DB` 를 6 정도로 낮춰 보는 것도 가능) |
| 700/5 나 500/4 가 1000/6 보다 낫다 | 운영 `.env` 의 두 줄을 그 값으로 → 재기동 |
| 모두 부족하다 | 요약 사진 + 들은 결과 들고 복귀 (설정으로는 한계 → 코드 쪽 검토) |
