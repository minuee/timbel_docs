# 회사 반영 목록 ver.16 — 2026-11-12

> ver.15(`docs/update_20261111.md`)에 **이어서** 적었다.
> 시스템 로그인(AM-Tray)에서 **DLL 을 부르는 방식만** 바꿨다: C++ 로 만든 `AmHelper.exe` → **앱이 직접(koffi) 부름**.
> - C++ 빌드·exe 가 필요 없다. 앱은 Electron(Node.js) 그대로.
> - DLL 은 앱 본체가 아니라 **별도 작업 프로세스**에서 부른다 → DLL 이 죽어도 앱은 안 죽는다(예전 exe 방식과 같음).
> - **회사에서 설치·다운로드할 것 없음.** koffi 는 집에서 받아 `src/main/vendor/koffi/` 에 넣어 왔다(`package.json` 의존성에 넣지 않음, `npm install` 불필요).
> - 기본은 지금과 같다: `AMTRAY_SYSTEM_ID` 가 비어 있으면 [시스템 로그인] 은 "준비 중". 다른 로그인은 바뀌지 않는다.

> `package.json` 은 **통째로 교체하지 말고** 아래 2가지만 직접 고친다.
> 1. `version` → **0.0.11**
> 2. `"build": {` 바로 아래에 추가 (설치본에서 koffi.node 를 asar 밖에 둔다 — 없으면 설치본에서 koffi 를 못 불러온다)
> ```json
> "asarUnpack": [
>   "src/main/vendor/koffi/build/**"
> ],
> ```

**그대로 둔 것**: `src/helpers/windows/amtray/`(AmHelper.exe·가짜 DLL) — 비교용·가짜 DLL 시험용으로 남김. `build.win.extraFiles`(amtray/bin 의 `*.dll` 을 설치 폴더로 복사)도 그대로 — **진짜 DLL 3개는 계속 `src\helpers\windows\amtray\bin\` 에 둔다.**

## 2. 바뀐 점 (요약)

```
예전: amTrayService ─execFile─▶ AmHelper.exe(C++) ─▶ AmInterface-RT-X64.dll
이제: amTrayService ─utilityProcess─▶ amTrayWorker.js ─koffi─▶ AmInterface-RT-X64.dll
```
- 결과 해석·화면·윈도우 메시지 받기(`hookWindowMessage`)는 **그대로**.
- DLL 함수 모양(`AMTRAY_DLL_SIGNATURE`, 기본 `string`):
  - `string` — `const char* GetSystemTokenIT(ssoKey, sid, systemID)` (Java 선언 모양, 지금까지의 가정)
  - `bool_out` — `BOOL GetSystemTokenIT(ssoKey, sid, systemID, char* lpToken, char* lpReturnCode)` (명세 "Bool + lpReturnCode" 기준 **추측**). `203030` 이면 토큰, Bool=false 면 공백(=509090)
  - cpp 헤더(`company-check.md` A-1)를 받으면 `amTrayDll.js` "★ 가정" 블록을 그대로 맞춘다.
- 집(Mac)에서 확인한 것: 가짜 DLL 로 토큰 / 504011 / 한글(CP949) 문구 / `bool_out` / 함수 없음 / DLL 없음 / **DLL 이 죽어도 Electron 앱은 살아 있음**(작업 프로세스만 종료). Windows 실제 실행은 회사에서 처음.
