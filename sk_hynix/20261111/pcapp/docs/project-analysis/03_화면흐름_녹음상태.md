# 03. 화면 흐름 · 녹음 화면 상태

> 기준: 현재 소스 (2026-10-15 작업분까지). 소스 위치는 `파일 · 함수` 로 표기.

## 1. 사용자 관점 전체 흐름

```
앱 실행
 ├─ (남은 녹음이 있으면) "복구되지 않은 녹음 파일 발견" 팝업 → 닫기 / 업로드 리스트 열기
 ├─ (Windows 빌드본, 새 버전이 있으면) 업데이트 화면 → 자동 설치 → 재실행
 ▼
[로그인]  pages/login.html · scripts/login.js
 ├─ 사번(+비밀번호) 로그인
 ├─ MyAccess 로그인 → 브라우저 → 딥링크로 복귀
 └─ 테스트 로그인(이름·사번·토큰 직접 입력, 펼침 메뉴)
 ▼ 로그인 성공 → 메인이 내 정보·워크스페이스 조회 후 화면 전환
[마이크 테스트(홈)]  index.html · index.js
 ├─ 녹음 대상: 마이크+PC소리(기본) / 마이크만 / PC소리만
 ├─ 마이크 선택, (Windows) 출력 장치 선택, 레벨 미터
 └─ "녹음 전 확인해주세요" 동의 체크 → [녹음 시작]
 ▼
[녹음]  pages/recordingWindow.html · scripts/recording.js   (360×320 고정)
 ├─ 들어오자마자 0.3초 뒤 자동으로 녹음 시작
 ├─ 일시정지/재개, 녹음 취소(삭제), 녹음 종료(업로드)
 ├─ 레벨·파형, 경과 시간, 남은 시간(최대 3시간) 바
 ├─ 설정 메뉴: 항상 위, 음소거(마이크/PC소리), 버전 정보(앱/헬퍼), 앱 종료
 └─ 업로드 리스트 열기/닫기
 ▼ 녹음 종료 → "파일을 업로드 할까요?" → [AI 요약 준비하기] 창(제목·언어·참석자 수·템플릿)
 ▼ AI요약 시작 → 업로드 진행 팝업 → 성공 시 녹음 파일 삭제
[녹음 화면 대기 상태로 돌아옴]  ← 같은 화면에서 녹음 버튼을 누르면 새 녹음
```

녹음 화면에서 홈(마이크 테스트)으로 돌아가는 경우는 세 가지뿐이다.
- 녹음 전·후 대기 중에 장치가 바뀌었을 때: 팝업 확인 → 홈
- 녹음 중 마이크가 빠진 뒤 삭제를 골랐을 때: 홈
- 녹음 중 마이크가 빠진 뒤 업로드에 성공했을 때: 홈

## 2. 로그인 화면 (`scripts/login.js`)

- 처음 열리면 `authAPI.getStatus()` 결과에 따라 사번 폼과 테스트 로그인 폼을 보이거나 숨긴다(`EMPNO_LOGIN_ENABLED`, `MANUAL_LOGIN_ENABLED`).
- **로그인에 성공해도 렌더러는 화면을 바꾸지 않는다.** 메인의 `handleAuth.onAuthenticated()` 가 사용자 정보를 받은 뒤 `loadHome()` 으로 바꾼다. 렌더러는 실패 메시지만 보여 준다.
- SSO 는 버튼을 누르면 브라우저만 열리고, 결과는 `auth-exchanged` 이벤트로 받는다.
- 자세한 인증 동작은 `05_인증_API.md`.

## 3. 마이크 테스트 화면 (`index.js`)

| 동작 | 내용 |
|---|---|
| 초기화 | 헬퍼 실행(`startAudioHelper`) → `list_devices` → `devices` 이벤트가 오면 **목록의 첫 마이크로** `start_test` 를 보낸다 |
| 테스트 중 | 헬퍼의 `level` 이벤트로 10칸 레벨 미터를 그린다. 마이크 RMS 0.02 미만은 0칸 |
| 선택 변경 | 마이크, 녹음 대상, 출력 장치를 바꾸면 `stop_test` → 100ms 뒤 `start_test` |
| 장치 변경 | `audio_device_change` 이벤트 → 테스트 정지 → 목록 다시 받기 |
| 시작 조건 | 마이크가 선택돼 있고 안내에 동의해야 함 |
| 녹음 시작 | `stop_test` → 200ms 대기 → 창을 360×320 으로 고정 → `recordingWindow.html` 로 이동 |

화면 사이에 넘기는 값은 `localStorage` 에 둔다: `mic`(마이크 ID), `captureMode`, `render`(출력 장치, 기본 `"default"`).

타이틀에는 `AI 회의록 녹음기(이름)` 이 표시된다. 이름은 로그인 뒤 받은 프로필 값이다.

## 4. 녹음 시작 순서 (`recording.js · startRecording`)

```
1. set_output_dir   { directory: "recordings" }       ← 메인이 절대경로로 바꾸고 응답까지 기다림
2. set_debug_files  { enabled: "false" }              ← 디버그용 원본 WAV 저장 끔
3. set_segment_config { encryption_enabled: "true" }   ← 조각 파일 AES 암호화 켬
4. start {
     mode: MicPlusSystem | MicOnly | SystemOnly,
     out: { sr:16000, ch:1, blockMs:20 },
     mic, render,
     gains: { mic:1.0, sys:0.7 },
     max_ms: 10800000 (3시간),
     segmenting: { duration_ms: 180000 (3분), ... }
   }
```
- `start` 를 보내면 렌더러가 **헬퍼 응답을 기다리지 않고** 곧바로 "녹음 중" 화면으로 바꾼다.
- 헬퍼가 보낸 `recording_started` 는 DB 에 녹음 행을 만드는 데(`dbAPI.insertRecording`)만 쓴다.
- 일부 값(`gains`, `blockMs`, `segmenting` 의 일부)은 헬퍼가 실제로 무시한다. Windows 는 조각 길이 180초, 게인 1.0/0.7 이 코드에 고정돼 있다(`04_오디오헬퍼.md`).

## 5. 녹음 화면 상태

상태 변수 하나로 관리하지 않고 **여러 플래그의 조합**으로 상태가 정해진다.
쓰는 플래그: `isRecording`, `isPaused`, `stopType`(""/"cancel"/"complete"), `isStoppedByError`, `isStoppedByMaxDuration`, `stoppedByDeviceDisconnected`, `isAppClosing`, `isSegmentReadyForUpload`, `isUploadDataReady`.
그래서 상태를 바꿀 때는 이 플래그들이 어디서 바뀌는지를 같이 봐야 한다. 초기화는 `variableInitialize()` 한 곳에서 한다.

```
               ┌──────────── 일시정지 버튼 ───────────┐
               ▼                                      │
 [대기] ─자동시작/녹음버튼─▶ [녹음 중] ◀── 재개 ── [일시정지]
   ▲                          │                    │   │
   │                          │ 취소/종료 버튼     │   │
   │                          ▼ (먼저 일시정지)    │   │
   │               [확인 팝업: 삭제? / 업로드?] ───┘(팝업에서 취소 → 일시정지 유지)
   │                    │삭제            │업로드
   │                    ▼                ▼
   │            stop → 조각 저장    AI 요약 준비 창 → stop + 업로드 요청
   │            → 폴더 삭제          → 조각 저장 + 업로드 작업 등록 → 업로드
   └────────────────────┴────────────────┘
```

| 상태 | 들어가는 계기 | 화면 |
|---|---|---|
| 녹음 중 | 화면 진입 0.3초 뒤 자동 시작, 또는 대기 상태에서 녹음 버튼 | 빨간 점, 타이머, 파란 파형, 취소·종료 활성 |
| 일시정지 | 일시정지 버튼 → `pause` 명령 | 타이머 정지, 회색 파형 |
| 삭제 확인 / 업로드 확인 | 취소·종료 버튼을 누르면 **먼저 일시정지한 뒤** 팝업 | 팝업에서 "취소"를 누르면 일시정지 상태로 남음. 재개해야 stopType 이 지워짐 |
| 삭제 진행 | 팝업 확인 → `stop` → `segment_ready` 에서 폴더 삭제 → `recording_stopped` 에서 초기화 | |
| 업로드 진행 | AI요약 시작 → `stop` + `requestUpload`. **조각 저장 완료(segment_ready)와 업로드 작업 등록(enqueueUpload) 둘 다 끝나야** 업로드 시작(`tryStartUpload`) | 업로드 진행 팝업(메인이 띄움) |
| 오류로 멈춤 | 녹음 중 마이크 제거(`MIC_DEVICE_LOST`), 디스크 부족 정지(`DISK_SPACE_LOW_STOP`) | 재개 불가. 취소(삭제) 또는 종료(업로드)만 가능. 업로드는 조각 저장을 기다리지 않고 바로 시작 |
| 최대 시간 도달 | `recording_stopped` 에서 판정(`recordingStoppedByMaxDuration`) | 삭제/업로드 선택 팝업 |
| 앱 종료 중 | 설정 → 앱 종료. 녹음 중이면 업로드/삭제를 반드시 고르게 함 | 업로드가 성공하면 메인이 앱을 끔. 실패하면 팝업 확인 시 종료 |
| 대기 | 정상 종료·삭제 후 `variableInitialize` | 00:00:00, 남은 시간 03:00:00 |

> ⚠ **최대 시간 판정 의심 버그**: `recording_stopped` 처리에서 `event.totalSamples >= TOTAL_RECORD_MS` 로 비교한다.
> `totalSamples` 는 16kHz 샘플 수이고 `TOTAL_RECORD_MS` 는 3시간을 ms 로 나타낸 값(10,800,000)이다.
> 그래서 약 **11분 15초 이상 녹음하면 정상 종료해도 "최대 시간 도달" 경로로 빠질 가능성**이 크다. → `08_확인필요.md` #1

## 6. 녹음 중 이벤트 처리 (`recording.js · onHelperEvent`)

| 헬퍼 이벤트 | 화면 처리 |
|---|---|
| `level` | 레벨 미터와 파형. 음소거한 쪽은 파형에 반영하지 않음 |
| `progress` | 경과 시간 기준값 갱신. 재개 직후 1.5초는 시간이 튀지 않게 보정 |
| `segment_ready` | 실제 저장 폴더를 확인하고 경로를 고침. DB 의 녹음 경로 갱신(`upsertRecording`). stopType 이 complete 면 업로드, cancel 이면 삭제 |
| `silence` | early: "음성이 감지되지 않습니다", sustained: "30초 이상 음성이 감지되지 않습니다", off: 원래 문구로. 창이 최소화돼 있으면 OS 알림 |
| `disk_status` | low: "500MB 이상 확보" 경고, critical: "약 3분 후 자동 종료" 경고 |
| `audio_device_change` | 녹음 중이면 무시. 대기 중이면 "초기화면으로 이동" 팝업 |
| `error` | 마이크 제거 → 녹음 중일 때만 오류 정지 처리. 디스크 부족 정지 → 오류 정지 처리 |
| `version_info` | 설정 메뉴에 `헬퍼 vX.Y.Z [AEC]` 표시. AEC 가 붙어야 에코 제거가 들어간 빌드다 |

## 7. 업로드 옵션 창 (`scripts/summarizeWindow.js`)

| 항목 | 값 | 서버로 보내는 값 |
|---|---|---|
| 제목 | 선택, 최대 100자 | 비어 있지 않을 때만 `title` |
| 언어 | 한국어(기본) / 영어 | `lang`: ko / en |
| 참석자 수 | 1~2명(기본) / 3~6 / 7~10 / 11명 이상 | `attendeeNum`: 0 / 1 / 2 / 3 |
| 템플릿 | 캐시 목록을 먼저 보여 주고, 서버 목록이 오면 다시 그림. 이전 선택 유지 | `templateId`: 선택한 항목의 code. "기본형"(code 없음)이면 보내지 않음 → 서버 기본값 DEF-BASIC |

제목을 입력하면 업로드 리스트에 보이는 이름도 그 제목으로 바뀐다. 하지만 서버로 가는 `fileName` 은 녹음을 시작할 때 정한 이름 그대로다(`06_저장_DB_업로드.md`).

## 8. 공용 팝업 (`scripts/popupWindow.js`)

하나의 창이 `type` 값에 따라 내용과 버튼을 바꾼다.

| type | 용도 |
|---|---|
| `cancel` / `complete` | 녹음 삭제 확인 / 업로드 확인 |
| `error_cancel` / `error_complete` | 오류로 멈춘 녹음의 삭제 / 업로드 |
| `max_duration_stopped` | 최대 시간 도달 후 선택 |
| `app-close` / `app-close-recording` | 앱 종료 확인 / 녹음 중 종료 시 업로드·삭제 선택 |
| `device_change` | 장치가 바뀌어 홈으로 이동 |
| `upload-progress` | 업로드 진행률(속도·남은 시간). 실패하면 "재시도" |
| `recovery-result` | 앱 시작 시 남은 녹음 안내 |
| `confirm-retry-multi`, `remove-job` | 업로드 리스트의 재시도·삭제 확인 |
| `error-alert`, `error-alert-warning`, `disk-space-low-stop` | 경고 |

- **창이 최소화돼 있거나 숨겨져 있으면 팝업 대신 OS 알림만 뜬다**(`main.js · open-popup-window`). 선택이 필요한 팝업도 마찬가지라서, 이때는 사용자가 고를 방법이 없다. → `08_확인필요.md`
- 팝업 창을 다시 쓸 때 이전 type 이 바꿔 둔 버튼 표시 상태가 남을 수 있다. → `08_확인필요.md`

## 9. 업로드 리스트 (`scripts/uploadList.js`)

- 남아 있는 업로드 작업(jobs)을 모두 보여 준다(업로드 중 / 실패·대기). 성공한 작업은 녹음 행과 함께 지워지므로 목록에 남지 않는다.
- 재시도: 확인 팝업 → `retry-server-uploads` (여러 건을 동시에 백그라운드로 업로드, 끝나면 OS 알림으로 결과 요약)
- 삭제: 확인 팝업 → `remove-job` (작업 + 파일 + DB 행 삭제)
