# 운영 배포 1.0.1 + 같은 사무실 하울링·말 반복 시험

작성 2026-11-11

## 1.0.1 은 무엇이 바뀌었나

**병합 결과(소리)는 1.0.0 과 똑같다.** 설치와 확인을 덜 헷갈리게 고친 버전이다.

| 바뀐 것 | 1.0.0 | **1.0.1** |
|---|---|---|
| 설치 위치 | 명령을 친 폴더. 상위 폴더에서 치면 거기에 `.env` 를 새로 만들었다 | **`install.sh` 가 있는 폴더로 고정.** 다른 곳으로 복사하지 않는다 |
| 기존 `.env` 에 빠진 항목 | 알려주지 않음 | 설치할 때 **경고로 보여줌** (파일은 고치지 않는다) |
| 기동 로그 | 설정 10개 정도만 | **주요 설정 24개의 실제 적용값** (`settings`) |
| 병합 요청 로그 | 설정 없음 | 요청마다 같은 `settings` 를 함께 찍음 |
| 설치 끝 안내 | — | 읽히는 `.env` 경로, 반영 명령 출력 |

`settings` 에서 `.env` 에 적지 않은 항목은 `"3 (기본값)"` 처럼 나온다. 비밀번호는 `****` 로만 나온다.

### 11/11 에 알게 된 것 (1.0.1 을 만든 이유)

- 컨테이너는 **`docker-compose.yml` 이 있는 폴더의 `.env`** 만 읽는다. `deploy/.env` 를 고쳐도 상위 폴더에서 설치했으면 반영되지 않았다.
- `.env` 를 고친 뒤 `docker restart` 로는 반영 안 된다. **`docker compose --env-file .env up -d`** 를 해야 한다.
- `deploy/.env` 로 compose 를 띄우면 "이미지 없음" 이 나왔다 → `IMAGE_VERSION=latest` 가 그대로였기 때문.

## 1. 운영 배포

### ① 지금 쓰는 설치 폴더부터 확인 — 꼭 할 것

11/11 에는 상위 폴더의 `.env` 가 실제로 쓰였다. **그 폴더**에 설치해야 운영 설정이 이어진다.

```bash
docker inspect mobile-sync-server \
  --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
```

여기 나온 폴더 = 설치 폴더. 아래 명령은 전부 이 폴더에서 친다.

### ② 파일 올리고 설치

```bash
cd <①에서 나온 폴더>

# 옛 tar 지우기 (안 지우면 설치가 멈춘다)
rm -f mobile-sync-server_1.0.0_amd64.tar*

# 새 tar 2개, install.sh, docker-compose.yml, .env.example 을 이 폴더에 복사한 뒤
sha256sum -c mobile-sync-server_1.0.1_amd64.tar.sha256     # "OK"
chmod +x install.sh
./install.sh
```

- `install.sh` 를 `_txt.txt` 로 가져왔으면 `mv install_txt.txt install.sh`
- `$'\r': command not found` 가 나오면 `sed -i 's/\r$//' install.sh`
- 설치 중 `[install] 설치 위치:` 줄이 **①의 폴더**인지 본다.
- `.env.example 에는 있는데 .env 에 없는 항목` 경고가 나오면 → 그 항목은 기본값으로 돈다. 필요하면 `.env.example` 에서 그 줄을 옮겨 적는다.

### ③ 확인

```bash
grep IMAGE_VERSION .env                                     # IMAGE_VERSION=1.0.1
curl -s http://127.0.0.1:9995/health                        # {"status": "ok", ...}
docker logs mobile-sync-server 2>&1 | grep server_start     # "version": "1.0.1" + settings
```

`settings` 에서 아래가 나와야 한다 (1.0.0 운영값):

```
"AUTOMIX_MODE": "select"   "AUTOMIX_HOLD_MS": 1000   "AUTOMIX_SWITCH_DB": 6.0
"MERGE_LEVEL": "dynamic"   "MERGE_TRACK_GAIN": false  "MERGE_AUTOMIX": true
```

뒤에 `(기본값)` 이 붙어 있으면 `.env` 에 그 줄이 없는 것이다. 값이 맞으면 상관없다.

### 되돌리기

| 상황 | 할 일 |
|---|---|
| 1.0.1 에 문제 | `.env` 의 `IMAGE_VERSION=1.0.0` → `docker compose --env-file .env up -d` (옛 이미지는 남아 있다) |

## 2. 같은 사무실 하울링·말 반복 시험

### 왜 하나

| 장소 | 결과 |
|---|---|
| 폰 4대가 각자 다른 곳 | 하울링 없음, 말 반복 없음 |
| 폰 4대가 같은 사무실 | **하울링 심함, 같은 말이 연달아 들림** |

같은 사무실에서는 한 사람의 목소리가 4대에 **조금씩 다른 시간에** 다 들어간다.
오토믹서(select)는 순간마다 폰 하나를 고르는데, **폰이 바뀌는 순간** 두 폰이 조금 어긋나 있으면 방금 들은 말이 한 번 더 들린다.
→ **전환을 줄이면** 말 반복이 줄어드는지 본다.

| 설정 | 뜻 | 올리면 |
|---|---|---|
| `AUTOMIX_HOLD_MS` | 폰을 고르면 최소 이 시간 유지 | 전환 ↓, 말하는 사람이 바뀌어도 늦게 따라감 |
| `AUTOMIX_SWITCH_DB` | 다른 폰이 이만큼 더 커야 넘어감 (6 ≈ 2배, 9 ≈ 2.8배, 12 ≈ 4배) | 전환 ↓, 너무 높으면 먼 폰에 머물러 소리가 멀어짐 |

### 100 과 다른 점 — 운영 서버를 건드리지 않는다

| | 100 (11/10) | **101 (이번)** |
|---|---|---|
| 설정 바꾸기 | `.env` 고치고 서버 재기동 | **안 한다.** 조합마다 시험용 컨테이너(`automix-test`, 포트 19995)를 잠깐 띄웠다 지운다 |
| 한 번 실행에 | 1개 설정 | **여러 조합 차례로** |
| 업로드 한도 | `.env` 에 `MERGE_UPLOAD_MAX_BYTES` 추가 필요 | 시험 컨테이너에만 4GB 자동 |
| 나머지 설정 | — | 운영 `.env` 그대로 (`MERGE_LEVEL`, `MERGE_TRACK_GAIN` 등) |
| 이미 한 조합 | 덮어씀 | 건너뜀 (다시 하려면 `FORCE=1`) |

시험 폴더 구조, 원본 분석, 결과 이름, 요약 화면은 100 과 같다.

### 실행

```bash
cd /data/timblo/mobile-sync-server        # 설치 폴더 (1-① 에서 확인한 곳)
chmod +x howling_test_101.sh
./howling_test_101.sh /data/timbel/howling_test
```

- 설치 폴더가 `/data/timblo/mobile-sync-server` 가 아니면 앞에 `INSTALL_DIR=<설치 폴더>` 를 붙인다.
- 싱크음이 비프가 아니면 `SYNC_SOUND=voice` 를 붙인다 (100 과 같다).
- 조합은 한 개씩 차례로 돈다. **1시간 회의 × 6조합이면 오래 걸린다** → 서비스 안 쓰는 시간에.
  급하면 `COMBOS="1000:6 2000:9"` 처럼 줄여서 먼저.

### 기본 조합 (자동으로 전부 돈다)

| 순서 | `AUTOMIX_HOLD_MS` | `AUTOMIX_SWITCH_DB` | 결과 이름 | 보는 것 |
|---|---|---|---|---|
| 1 | 300 | 3 | `h300_s3_dynamic_gain0` | 0.0.8 값. 참고용 (11/10 에 4025번 전환) |
| 2 | 1000 | 6 | `h1000_s6_dynamic_gain0` | **지금 운영값. 비교 기준** |
| 3 | 2000 | 6 | `h2000_s6_dynamic_gain0` | 유지시간만 올림 |
| 4 | 1000 | 9 | `h1000_s9_dynamic_gain0` | 전환 기준만 올림 |
| 5 | 2000 | 9 | `h2000_s9_dynamic_gain0` | **둘 다 올림 (추천 후보)** |
| 6 | 3000 | 12 | `h3000_s12_dynamic_gain0` | 아주 강하게. 비교용 끝값 |

3·4 를 2 와 비교하면 **시간과 dB 중 무엇이 효과 있는지** 갈린다.
결과 이름 끝 `dynamic_gain0` 은 운영 `.env` 값을 따른 것이다.

조합 바꾸기 (예: 5번 근처를 더 보고 싶을 때):

```bash
COMBOS="1500:8 2000:9 2500:10" ./howling_test_101.sh /data/timbel/howling_test
```

### 끝나면 화면에 요약 → **사진으로 찍어 오면 된다**

```
================ 요약 (이 화면을 사진으로 찍어 오면 된다) ================
[meet_20261111]
f1 = A.Biz_m_1111.flac
...
h1000_s6_dynamic_gain0:  "heardPct": {...}, "switches": 1384
h2000_s9_dynamic_gain0:  "heardPct": {...}, "switches": ....
...
```

### 숫자 읽는 법

| 값 | 뜻 |
|---|---|
| `switches` | 폰이 바뀐 횟수. **줄어든 만큼 말 반복 기회가 줄어든다** |
| `heardPct` | 폰별로 쓰인 비율(%). 한 폰이 90% 넘으면 거의 그 폰 하나로만 나온 것 |
| 원본 `차이` | 말 − 조용. 클수록 또렷. 같은 사무실이면 다른 장소보다 작게 나올 것 |
| `주의: 정렬 ...` | 비프음으로 못 맞췄다는 뜻. **이게 나오면 말 반복의 원인이 정렬일 수 있다** → 꼭 사진에 |

**말 반복이 났던 구간**을 결과끼리 번갈아 듣고 칸마다 적는다.

                      말 반복(없음/가끔/자주)  울림(없음/약함/심함)  화자 바뀔 때 늦음(없음/가끔/자주)
h300_s3               ____                    ____                 ____
h1000_s6 (지금)       ____                    ____                 ____
h2000_s6              ____                    ____                 ____
h1000_s9              ____                    ____                 ____
h2000_s9              ____                    ____                 ____

| 들리는 것 | 다음 |
|---|---|
| 2000/9 (또는 다른 조합)이 지금보다 낫고 늦음이 거슬리지 않는다 | 운영 `.env` 의 `AUTOMIX_HOLD_MS`, `AUTOMIX_SWITCH_DB` 를 그 값으로 → `docker compose --env-file .env up -d`. **이미지 교체 없음** |
| 3000/12 까지 올려도 말 반복이 남는다 | 전환 때문이 아니다 → 정렬 문제. 요약 사진 + 그 회의 원본 들고 복귀 |
| 전환이 줄면 말 반복은 줄지만 울림이 남는다 | 원본부터 울리는 것(같은 공간 반사음). 원본 `차이` 숫자와 함께 복귀 |
| 모두 부족하다 | 요약 사진 + 들은 결과 들고 복귀 (설정으로는 한계 → 코드 쪽 검토) |
