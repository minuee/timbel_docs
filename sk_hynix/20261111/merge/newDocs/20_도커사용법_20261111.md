# 도커 사용법 — mobile-sync-server 운영용

> 헷갈릴 때 이 문서만 보면 되도록 정리했다. (1.0.1 기준, 2026-11-11)

---

## 0. 딱 세 가지만 기억

1. **명령은 항상 설치 폴더 안에서 친다.** (`install.sh`, `docker-compose.yml`, `.env` 가 같이 있는 폴더)
2. **설정은 그 폴더의 `.env` 하나뿐이다.** `.env.example` 은 견본일 뿐 읽히지 않는다.
3. **`.env` 를 고쳤으면 `docker compose --env-file .env up -d`.** `docker restart` 로는 반영 안 된다.

---

## 1. 용어 정리

| 말 | 뜻 | 비유 |
|---|---|---|
| 이미지 | 프로그램 + 실행환경을 묶은 판. `mobile-sync-server:1.0.1` | 설치 CD |
| 컨테이너 | 이미지를 실제로 띄운 것. 이름은 `mobile-sync-server` | 설치해서 켜 놓은 프로그램 |
| `tar` 파일 | 이미지를 파일 하나로 저장한 것 (반입용) | CD 를 이미지 파일로 뜬 것 |
| `docker-compose.yml` | 컨테이너를 어떻게 띄울지 적은 정의서 (포트, 폴더, 네트워크) | 설치 옵션 |
| `.env` | 설정값 (비프음, 작업자 수, 비밀번호 …) | 프로그램 설정 파일 |

**이미지 이름 = 이름:버전.** `.env` 의 `IMAGE_NAME`, `IMAGE_VERSION` 이 실제 적재된 이미지와 같아야 뜬다.
(`install.sh` 가 자동으로 맞춰준다)

## 2. 설치 폴더 모습

```
/data/timblo/mobile-sync-server/        ← 여기서 모든 명령을 친다
 ├─ install.sh
 ├─ docker-compose.yml
 ├─ .env                                ← ★ 실제로 읽히는 설정
 ├─ .env.example                        ← 견본 (읽히지 않음)
 ├─ mobile-sync-server_1.0.1_amd64.tar
 └─ mobile-sync-server_1.0.1_amd64.tar.sha256
```

지금 떠 있는 컨테이너가 **어느 폴더의 `.env` 로 떴는지** 모르겠으면:

```bash
docker inspect mobile-sync-server \
  --format '{{ index .Config.Labels "com.docker.compose.project.working_dir" }}'
```

여기 나온 폴더가 진짜 설치 폴더다.

## 3. 상황별 명령

### 3-1. 처음 설치 / 새 버전 올리기

```bash
cd /data/timblo/mobile-sync-server
rm -f mobile-sync-server_*_amd64.tar*          # 옛 tar 지우기 (여러 개면 설치가 멈춘다)
# 새 tar, .sha256, install.sh, docker-compose.yml, .env.example 복사
sha256sum -c mobile-sync-server_1.0.1_amd64.tar.sha256   # "OK" 확인
./install.sh
```

- `.env` 가 **없으면** `.env.example` 을 복사해서 만든다.
- `.env` 가 **있으면** 그대로 쓴다 (이미지 버전·실행 계정만 갱신).
  새 버전에 생긴 항목이 빠져 있으면 경고로 알려준다 → 필요하면 `.env.example` 에서 그 줄을 옮겨 적는다.

### 3-2. 설정 바꾸기

```bash
cd /data/timblo/mobile-sync-server
vi .env
docker compose --env-file .env up -d       # 바뀐 걸 감지해서 컨테이너를 새로 만든다
docker logs mobile-sync-server 2>&1 | grep server_start    # 적용값 확인
```

`server_start` 로그의 `settings` 에서
- `"BEEP_TRIM": false` → `.env` 에 적은 값이 먹은 것
- `"MERGE_WORKERS": "3 (기본값)"` → `.env` 에 없어서 기본값으로 도는 것

### 3-2-1. `.env` 에 변수가 등록돼 있는지 확인

```bash
cd /data/timblo/mobile-sync-server

# ① .env 에 적힌 변수 전체 (주석·빈 줄 제외)
grep -vE '^\s*(#|$)' .env

# ② 특정 변수가 있는지 (예: BEEP_TRIM) — 안 나오면 등록 안 된 것
grep -E '^BEEP_TRIM=' .env

# ③ .env.example 에는 있는데 .env 에 빠진 변수 목록
comm -13 <(grep -oE '^[A-Z_][A-Z0-9_]*' .env | sort -u) \
         <(grep -oE '^[A-Z_][A-Z0-9_]*' .env.example | sort -u)

# ④ 실제로 떠 있는 컨테이너 안에 들어간 값 (예: BEEP 로 시작하는 것)
docker exec mobile-sync-server env | grep -E '^BEEP_' | sort
```

④ 가 `.env` 와 다르면 고친 뒤 `docker compose --env-file .env up -d` 를 안 한 것이다.

### 3-3. 상태 보기

```bash
docker ps                                   # 떠 있는지, STATUS 가 (healthy) 인지
curl http://127.0.0.1:9995/health           # 응답 오면 정상
docker images mobile-sync-server            # 서버에 있는 이미지 버전들
```

### 3-4. 로그 보기

```bash
docker logs -f mobile-sync-server                      # 실시간 (Ctrl+C 로 빠져나옴)
docker logs --tail 100 mobile-sync-server              # 최근 100줄
docker logs mobile-sync-server 2>&1 | grep mrg_xxxx    # 특정 병합 작업만
docker logs mobile-sync-server 2>&1 | grep '"level":"ERROR"'   # 오류만
```

### 3-5. 끄기 / 켜기

```bash
cd /data/timblo/mobile-sync-server
docker compose --env-file .env down        # 끄고 컨테이너 삭제 (데이터는 남는다)
docker compose --env-file .env up -d       # 다시 켜기
```

데이터(`merge.db`, 작업 파일)는 `.env` 의 `RUNTIME_DIR` 폴더에 있어서 `down` 해도 지워지지 않는다.

### 3-6. 옛 이미지 정리 (디스크 확보)

```bash
docker images mobile-sync-server           # 목록 확인
docker rmi mobile-sync-server:0.0.8        # 안 쓰는 버전 지우기 (지금 쓰는 건 지워지지 않는다)
```

### 3-7. 이전 버전으로 되돌리기

```bash
cd /data/timblo/mobile-sync-server
vi .env                                     # IMAGE_VERSION=1.0.0 으로 고침
docker compose --env-file .env up -d
```

서버에 그 버전 이미지가 남아 있어야 한다 (`docker images` 로 확인).

## 4. 하면 안 되는 것 / 자주 하는 실수

| 실수 | 결과 | 올바른 방법 |
|---|---|---|
| `.env.example` 을 고침 | 아무 변화 없음 | `.env` 를 고친다 |
| 다른 폴더에서 `docker compose` 실행 | 엉뚱한 `.env` 를 읽거나 "파일 없음" | 설치 폴더로 `cd` 먼저 |
| `.env` 고치고 `docker restart` | 옛 설정 그대로 | `docker compose --env-file .env up -d` |
| 폴더에 tar 가 2개 | `install.sh` 가 멈춤 | 옛 tar 삭제 |
| `.env` 를 `.env.example` 로 덮어씀 | 운영 설정·비밀번호가 기본값으로 돌아감 | 빠진 줄만 옮겨 적기 |

## 5. 오류 메시지별 해결

| 메시지 | 원인 | 해결 |
|---|---|---|
| `pull access denied` / `image ... not found` / `No such image` | `.env` 의 `IMAGE_VERSION` 과 적재된 이미지가 다름 | `docker images mobile-sync-server` 로 버전 확인 → `.env` 의 `IMAGE_VERSION` 을 맞춤 (또는 `./install.sh` 다시) |
| `network timblo-net not found` | MinIO·master-api 와 같이 쓰는 네트워크가 없음 | `docker network create timblo-net` |
| `port is already allocated` | 9995 포트를 다른 게 쓰는 중 | `docker ps` 로 확인 후 끄거나 `.env` 의 `HOST_PORT` 변경 |
| 컨테이너가 계속 `Restarting` | 대부분 데이터 폴더 권한 | `docker logs --tail 50 mobile-sync-server` 에 `PermissionError` → `sudo chown -R <RUN_UID>:<RUN_GID> <RUNTIME_DIR>` |
| `no configuration file provided` | 설치 폴더가 아닌 곳에서 실행 | 설치 폴더로 `cd` |

```bash
cd /data/timblo/mobile-sync-server               # 항상 여기서

./install.sh                                     # 설치·업데이트
vi .env && docker compose --env-file .env up -d  # 설정 변경
docker ps                                        # 상태
docker logs -f mobile-sync-server                # 로그
docker logs mobile-sync-server 2>&1 | grep server_start   # 적용된 설정
docker compose --env-file .env down              # 끄기
```
