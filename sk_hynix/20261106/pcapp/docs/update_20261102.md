## 3. `x-device-timezone` 헤더

- 목적: 서버가 미국·중국 등 접속 환경을 구분.
- 값: PC(Windows)에 설정된 시간대 이름. 예: `Asia/Seoul`, `America/Los_Angeles`, `Asia/Shanghai`.
- `apiService.js` 의 공통 헤더(`timblo-App-OS` 등과 같은 곳)에 넣었다. 그래서 **토큰 교환·로그인·업로드 포함 모든 API 요청**에 붙는다.
- 요청할 때마다 다시 읽는다(사용자가 시간대를 바꿔도 바로 반영). 시간대를 못 읽는 경우는 헤더를 붙이지 않는다.
- 로그 서버 전송도 같은 경로라 헤더가 붙는다. 자동 업데이트 확인(`latest.yml`·exe 다운로드)에만 안 붙는다.
- **로그에도 남긴다:** 로그 서버로 가는 모든 로그 줄에 `"timezone":"Asia/Seoul"` 필드를 붙였다(사번·deviceId·appOs 와 같은 공통 값). `app_started` 로그에도 넣었다. 로그 서버는 받은 필드를 그대로 저장하므로 **서버 수정은 필요 없다.**
- 추가 설치·설정은 필요 없다.

## 4. 웹 → PC앱 연동 안내 (`docs/web-integration/`)

- 회의록 웹 [녹음] → 선택창 [웹에서 녹음] | [PC앱으로 녹음] 으로 바뀔 때 웹 개발자에게 줄 문서.
- 결론: **브라우저는 설치 여부를 직접 확인할 수 없다.** 앱 주소 `timbloRecApp://connect?code=…&host=…` 를 열어 보고, 페이지가 포커스를 잃으면 설치됨 / 2초간 반응 없으면 미설치로 판단한다. 미설치 안내창에 [다시 열기]를 같이 둔다.
- 앱 주소는 지금 웹 "앱 연결"과 **같다.** 앱 소스는 바꾸지 않았다(앱은 열리면 로그인된 상태로 첫 화면).
- 설치 파일 주소(`INSTALLER_URL`) = 업데이트 서버 폴더의 **`SKHynixRecApp-Setup-latest.exe`**. 빌드하면 `dist/` 에 버전 붙은 exe 와 이 고정 이름 exe 가 같이 생긴다. **업데이트 서버에 올릴 때 둘 다 올린다**(순서: exe·blockmap·latest exe → 마지막에 `latest.yml`).

## 5. 업로드 응답 처리 (`main.js`)

**고치기 전 문제:** 앱이 HTTP 상태만 보고 응답 본문은 보지 않았다. 서버는 HTTP 200 안에 실패(`errorCode`)나 누락(`data.missingFiles`)을 담아 보내는데, 앱은 이것도 **성공으로 보고 로컬 녹음 파일을 지웠다** → 누락분을 다시 보낼 수 없었다.

**바꾼 것**
- 업로드 응답 본문을 확인한다.
  - `errorCode` 가 있거나 `httpCode` 가 400 이상 → **실패** (파일 보존, 업로드 목록에 "실패", 서버 메시지를 팝업에 표시)
  - `data.missingFiles` (조각 순서 번호, 예: `[0,1,2,3]`) → 그 번호의 조각 파일(`{세션ID}_{번호}.확장자`)만 골라 **자동으로 다시 보낸다.** 최대 3번 (첫 요청 + 3 = 4번, 서버 그룹녹음 정책과 같음)
  - 서버가 말한 번호 중 PC 에 있는 것만 보낸다. **PC 에 하나도 없으면(유실)** 재업로드를 포기하고 안내한다(아래)
  - 3번 다시 보내도 누락이 남으면 → **실패** (파일 보존)
  - 둘 다 없으면 → 성공 (지금처럼 파일 삭제)
- 다시 보낼 때 `fileName`·`deviceId` 는 처음과 같고, `totalNum` 은 **이번 요청에 담은 조각 수**다(서버가 jobId 기준으로 누적 관리 — 서버 담당 확인).
- **유실 안내** (팝업, 창이 가려져 있거나 다건 재업로드면 Windows 알림):
  > 업로드에 실패했습니다.
  > 유실된 파일이 있어 웹사이트의 [미완성 회의록]에서 "A.Biz_p_rec_…" 파일을 재업로드해 주십시오. 단, 유실된 파일을 제외한 파일만 가능합니다.
  - 버튼은 [확인] 하나(눌러도 다시 올리지 않고 닫힘). 앱 업로드 목록에는 "실패"로 남고 녹음 파일도 남는다.
  - 4개 언어 모두 넣었다. 웹 메뉴 이름 `[미완성 회의록]` 의 영어·일본어·중국어 표기는 웹과 맞춰 볼 것.
- 업로드 목록에서 **여러 건을 한꺼번에** 재업로드할 때 제목·템플릿이 빠지던 것 수정.
- HTTP 4xx/5xx·네트워크 오류 처리는 그대로(실패, 파일 보존).
- 로그: `server_upload_missing_files`(누락 번호), `server_upload_resend_missing`(재전송), 실패 시 `server_upload_failed` kind `lost`(유실) / `missing`(재전송 한도) / `rejected`(서버 거절).

**집에서 확인한 것:** 가짜 서버로 6가지 — 정상 / 누락 1회 후 성공(누락 조각 2개만, totalNum=2) / 계속 누락(3번 재전송 후 실패, 파일 보존) / 유실(바로 유실 안내) / 일부 유실([1,9] → 1번만 재전송 → 9번 유실 안내) / 본문 errorCode(실패, 파일 보존). 유실 팝업 4개 언어 화면 확인. 실제 서버로는 미확인.

그대로 둔 내부 이름(일반 사용자가 볼 일 거의 없음): 실행 파일 `timbloRecApp.exe`, 설치 폴더 `...\Programs\timbloRecApp`, 앱 데이터 `AppData\Roaming\timbloRecApp`, 앱 주소 `timbloRecApp://`.

### 설치 파일 이름

- 바꾼 것: **설치 파일 이름만** (`package.json` `build.nsis.artifactName`). 고정 이름 복사본도 `SKHynixRecApp-Setup-latest.exe`.
- 그대로 둔 것: `productName`(`timbloRecApp`). 이걸 바꾸면 **앱 데이터 폴더**(`AppData\Roaming\timbloRecApp` — DB·로그인 유지·기기 ID·언어 설정)가 바뀌어 기존 사용자의 업로드 목록·기기 ID 가 사라진다. 바로가기·제어판(프로그램 제거) 이름은 이미 `SKHynixRecApp`.
- 자동 업데이트: 앱은 `latest.yml` 에 적힌 파일 이름을 받으므로, 옛 이름으로 설치된 PC 도 새 이름 파일로 정상 업데이트된다.
- 이름에 빈칸을 없앴다(`-`). 주소에 빈칸이 들어가 생기는 문제를 피하려는 것.

## ⚠️ 주의 — 업데이트 서버 주소

- 강제 업데이트와 웹 [설치 파일 받기] 링크는 **같은 업데이트 서버 폴더**(`UPDATE_SERVER_URL`)를 쓴다.
- 집 소스의 `src/config/app.config.json` 은 `"UPDATE_SERVER_URL": ""` (비어 있음 = 자동 업데이트 꺼짐)이다. 회사 소스에 실제 주소가 들어가 있는지 확인하고, **이 파일은 교체하지 않는다.**
- 주소가 정해지면 웹 개발자에게 `INSTALLER_URL = {UPDATE_SERVER_URL}/SKHynixRecApp-Setup-latest.exe` 로 알려준다.
