sLLM 사용 가이드 및 주의사항
==============================
AICC 워크플로우 적용 시 고려할 점


1. 핵심 의존 체인
------------------

Answer를 뽑으려면 아래 체인이 반드시 성립해야 합니다.

  Answer 생성
      ↑ 필수 선행
  Intent / Entity 추출
      ↑ 학습 필요
  sLLM Fine-tuning
      ↑ 데이터셋 필요
  학습 데이터셋 (수천~수만 건)

GPT-4.1 같은 대형 모델은 프롬프트에 인텐트 목록을
명시하면 zero-shot으로 추출이 가능했습니다.

sLLM은 모델 크기의 한계로 동일한 방식이 통하지 않으며,
Intent/Entity 추출을 위한 별도의 fine-tuning이 필수입니다.


2. sLLM 학습의 전제 조건
-------------------------

  (1) 인텐트 목록 별도 관리
      - 워크플로우에서 사용하는 모든 인텐트를
        별도 체계로 정의하고 관리해야 합니다.
      - 기존에는 프롬프트 내에 인텐트를 텍스트로
        나열하는 것만으로 충분했지만,
        sLLM에서는 이 목록이 학습 데이터의 기준이 됩니다.

  (2) 인텐트 변경 시 재학습
      - 인텐트가 추가·수정·삭제되면
        fine-tuning을 다시 수행해야 합니다.
      - 즉, 운영 중에도 인텐트 변경이 있을 때마다
        학습 파이프라인을 재실행해야 합니다.


3. 학습 데이터셋 생성의 딜레마
-------------------------------

fine-tuning에는 인텐트당 수백 건 이상의 발화 예시가 필요합니다.
인텐트가 50개라면 최소 수만 건의 데이터셋이 필요한데,
이를 확보하는 방법이 두 가지뿐이고 둘 다 문제가 있습니다.

  방법 A: 외부 LLM으로 데이터셋 생성
  ------------------------------------
  - GPT-4 등 대형 모델로 발화 예시를 자동 생성
  - 품질은 우수하나, 학습 과정에서 고객 데이터
    (인텐트 정의, 도메인 용어, 상담 시나리오)가
    외부 API로 전송됨
  - 금융권 폐쇄망 환경에서는 보안 정책상 불가

  방법 B: 수작업 생성
  --------------------
  - 보안 문제는 없음
  - 그러나 수천~수만 건의 발화 예시를
    사람이 직접 작성해야 함
  - 현실적으로 감당하기 어려운 공수


4. 요약
-------

  구분              | GPT-4.1 (SaaS)       | sLLM (온프레미스)
  ------------------|----------------------|-------------------------
  Intent 추출 방식   | 프롬프트 명시 (zero-shot) | fine-tuning 필수
  학습 데이터 필요   | 불필요               | 수천~수만 건 필요
  인텐트 변경 대응   | 프롬프트 수정만       | 재학습 필요
  데이터셋 생성      | 해당 없음            | 외부 LLM or 수작업
  폐쇄망 호환       | 불가 (외부 API)       | 가능 (단, 데이터셋 병목)

핵심 병목은 "폐쇄망에서 학습 데이터셋을 어떻게 확보할 것인가"이며,
이 문제가 해결되지 않으면 sLLM 기반 Intent 추출 자체가 불가합니다.
