### 🔵 [참고] AICC 내 KMS(AICM) 연동으로 교체 예정 (전략 방향)

위 rag-parser-engine 직접 연동은 **장기적으로 AICC 프로젝트 내 KMS(AICM) 연동으로 교체될 예정**입니다. KMS(AICM)는 AICC 시스템 구성요소(지식 관리 시스템, 담당: 김현철 수석님)로, advisor는 `/proxy/knowledge/*` 위임 형태로 KMS에 **클라이언트로 붙는 구조**로 전환됩니다.

**현재 코드상 이미 공존 중** — `SEARCH_HOST`(rag-parser)와 `AICM_HOST`(KMS)가 [validation.config.ts](../asst-service/src/config/validation.config.ts) (L77·L79)에 **둘 다 선언**되어 있습니다:

| 연동 | 환경변수 | 호출처 | 인증 헤더 | 상태 |
|------|----------|--------|-----------|------|
| rag-parser-engine (RAG 스트리밍) | `SEARCH_HOST` | search / assist-stream / document 서비스 | `X-Tenant-Id` (하드코딩) | 현행 사용 중 (위 P0 대상) |
| KMS(AICM) 프록시 | `AICM_HOST` | [knowledge-proxy.controller.ts](../asst-service/src/common/proxy/knowledge-proxy.controller.ts) | `X-Auth-token` | 신규 추가됨, 재검토 필요 |

> ⚠️ 아키텍처 문서([architecture/aicc-system-context.md](architecture/aicc-system-context.md))는 RAG(Search Service)와 KMS(AICM)를 **별개 외부 시스템**으로 기술하며, KMS env 명칭이 코드(`AICM_HOST`)와 문서(`KNOWLEDGE_API_URL`)가 불일치하므로 정합화 필요.

**KMS 전환 시 연동 범위**:
- ✅ **검색**: 인텐트 추출 → KMS 검색 API 호출 → 결과 수신 (현재의 RAG 스트리밍 방식 아님)
- ✅ **즐겨찾기**: KMS API로 조회/등록/삭제 위임 (advisor 내부 즐겨찾기 5종과는 분리)
- ❌ **문서/첨부 다운로드 제외**: 현재 [document.service.ts](../asst-service/src/advisor/document/services/document.service.ts)는 "특수 상황"으로 들어간 기능으로, KMS 전환 시 **빠지는 기능 → 제거 대상**

**영향받는 코드(전환 시)**: `advisor/search/`, `advisor/assist-stream/`, `advisor/document/`(제거 후보), `advisor/bookmark/`(KMS 위임), `common/proxy/knowledge-proxy.controller.ts`(재검토)

> KMS(AICM) 측 인터페이스 명세에 advisor를 맞추는 **클라이언트 입장**이므로, 전환 착수 전 KMS 측 API 스펙 확정이 선행 조건입니다. (KMS는 현재 담당 공석 상태이므로 스펙 협의 채널 확인 필요)
