# MeCab 파이프라인 입력 데이터 가이드

> **대상**: `POST /api/finetune/mecab`
> **목적**: MeCab 사용자 사전 자동 생성
> **작성일**: 2026-02-23

---

## 한 줄 요약

> **"이런 종류의 단어가 필요하다"고 카테고리와 예시만 알려주면, LLM이 관련 단어를 대량 생성하고 MeCab 사전 파일(CSV + dic)로 만들어준다.**

---

## 1. 전체 흐름

```
사용자가 준비하는 것              신 엔진이 자동으로 하는 것
─────────────────────          ──────────────────────────────

┌───────────────────┐          ┌─────────────────────────────┐
│ 어휘 정의 (JSON)   │          │ LLM이 단어 대량 생성         │
│                   │    →     │ "갤럭시S24", "아이폰15프로"  │
│ • 카테고리 이름    │          │ "맥북에어", "LG그램" ...     │
│ • 품사 태그       │          │                             │
│ • 예시 단어들     │          │ 읽기/의미 자동 부여           │
└───────────────────┘          │ "갤럭시에스이십사", "삼성_폰" │
                               └─────────────────────────────┘
                                          │
                                          ▼
                               ┌─────────────────────────────┐
                               │ MeCab CSV 사전 빌드          │
                               │ → mecab-dict-index 컴파일    │
                               │ → zip 압축 후 MinIO 업로드   │
                               └─────────────────────────────┘
```

---

## 2. MeCab 사전이 왜 필요한가

MeCab은 한국어 형태소 분석기인데, 기본 사전에 없는 단어는 제대로 분석하지 못한다.

```
기본 사전만 사용했을 때:
  "갤럭시S24울트라 환불해주세요"
  → ["갤", "럭", "시", "S", "24", "울트라", "환불", "해", "주세요"]
  → "갤럭시S24울트라"가 쪼개져버림

사용자 사전 추가 후:
  "갤럭시S24울트라 환불해주세요"
  → ["갤럭시S24울트라", "환불", "해", "주세요"]
  → 상품명이 하나의 단어로 인식됨
```

도메인 특화 용어(상품명, 브랜드명, 서비스명 등)를 사전에 등록해야 형태소 분석 품질이 올라간다. 이걸 수동으로 하면 너무 오래 걸리니, LLM이 자동으로 해주는 것이 이 파이프라인이다.

## 3. 어휘 정의 파일 형식 (JSON)

### 기본 구조

```json
{
  "type": "common",
  "domain": "",
  "categories": [
    {
      "name": "product_name",
      "name_ko": "상품명",
      "pos": "NNP",
      "description": "전자제품, 패션, 식품 등 상품명",
      "examples": ["갤럭시S24", "아이폰15프로", "맥북에어"]
    }
  ]
}
```

### 필드 설명

#### 최상위 필드

| 필드 | 필수 | 타입 | 설명 |
|------|------|------|------|
| `type` | 필수 | string | `"common"` (범용) 또는 `"domain"` (도메인 특화) |
| `domain` | 선택 | string | type이 "domain"일 때 도메인명 (예: "ecommerce") |
| `categories` | 필수 | array | 카테고리 배열 (최소 1개) |

#### 카테고리 필드

| 필드 | 필수 | 타입 | 설명 |
|------|------|------|------|
| `name` | 필수 | string | 카테고리 영문 식별자 (예: "product_name") |
| `name_ko` | 필수 | string | 카테고리 한글명 (LLM 프롬프트에 사용) |
| `pos` | 필수 | string | 품사 태그 (아래 표 참조) |
| `description` | 선택 | string | 카테고리 설명 (LLM이 참고) |
| `examples` | 선택 | string[] | 예시 단어 목록 (LLM이 참고) |

#### 사용 가능한 품사 태그

| 태그 | 의미 | 용도 | 예시 |
|------|------|------|------|
| `NNP` | 고유명사 | 브랜드, 상품명, 인명 등 | 갤럭시S24, 삼성, 홍길동 |
| `NNG` | 일반명사 | 서비스명, 일반 용어 | 새벽배송, 당일배송 |
| `NNB` | 의존명사 | 단위, 의존 표현 | 개, 건, 종 |
| `VV` | 동사 | 도메인 동사 | 환불하다, 교환하다 |
| `VA` | 형용사 | 도메인 형용사 | 불량이다 |
| `MAG` | 일반부사 | 도메인 부사 | 빠르게, 즉시 |

## 5. LLM이 생성하는 데이터

### LLM 프롬프트 예시

```
카테고리: 상품명 (product_name)
설명: 전자제품, 패션, 식품 등 구체적인 상품명. 모델번호 포함
품사: NNP (고유명사)
예시: 갤럭시S24울트라, 아이폰15프로맥스, 맥북에어M3

요청: 위 카테고리에 해당하는 한국어 단어를 20개 생성해주세요.
- 실제로 사용되는 단어
- 예시와 유사하지만 다른 단어
- 띄어쓰기 없이 붙여서 (예: "갤럭시S24")
```

### LLM 응답 형식

```json
{
  "words": [
    {"word": "갤럭시Z플립5", "reading": "갤럭시지플립오", "semantic": "삼성_폴더블폰"},
    {"word": "아이패드프로12", "reading": "아이패드프로십이", "semantic": "애플_태블릿"},
    {"word": "LG그램17", "reading": "엘지그램십칠", "semantic": "LG_노트북"}
  ]
}
```

### 생성된 엔트리 구조

```json
{
  "word": "갤럭시Z플립5",
  "reading": "갤럭시지플립오",
  "pos": "NNP",
  "category": "product_name",
  "semantic": "삼성_폴더블폰"
}
```

| 필드 | 설명 |
|------|------|
| `word` | 사전에 등록될 단어 |
| `reading` | 읽기 (발음). 없으면 word와 동일 |
| `pos` | 품사 태그 (카테고리에서 가져옴) |
| `category` | 어떤 카테고리에서 생성되었는지 |
| `semantic` | 의미 분류. 언더스코어로 연결 (예: "삼성_폴더블폰") |

## 6. 최종 출력 - MeCab CSV 사전

### CSV 형식

생성된 단어들은 MeCab이 이해하는 CSV 형식으로 변환된다.

```csv
갤럭시Z플립5,1785,1785,0,NNP,삼성_폴더블폰,T,갤럭시지플립오,*,*,*,*
아이패드프로12,1785,1785,0,NNP,애플_태블릿,F,아이패드프로십이,*,*,*,*
LG그램17,1785,1785,0,NNP,LG_노트북,T,엘지그램십칠,*,*,*,*
로켓배송,1781,1781,0,NNG,즉시_배송서비스,F,로켓배송,*,*,*,*
```

### CSV 각 컬럼의 의미

```
표층형, 좌문맥ID, 우문맥ID, 비용, 품사, 의미분류, 종성유무, 읽기, *, *, *, *
```

| 위치 | 이름 | 설명 |
|------|------|------|
| 1 | 표층형 | 단어 그 자체 |
| 2-3 | 문맥 ID | 품사별 고정값 (NNP=1785, NNG=1781 등) |
| 4 | 비용 | 0 (사용자 사전은 항상 0) |
| 5 | 품사 | NNP, NNG 등 |
| 6 | 의미분류 | semantic 값 |
| 7 | 종성유무 | T(받침 있음) / F(받침 없음) |
| 8 | 읽기 | reading 값 |
| 9-12 | 기타 | * (사용 안 함) |

### 최종 산출물

파이프라인이 완료되면 다음 파일들이 생성되어 MinIO에 업로드된다:

```
nlp/{workspace_id}/models/mecab/{task_id}/{timestamp}/
├── mecab_dict.zip        ← 이 파일을 추론 서비스가 다운로드
│   ├── vocab.csv         ← 원본 CSV
│   ├── vocab.dic         ← 컴파일된 바이너리 사전
│   └── meta.json         ← 메타데이터
└── generated_vocab.json  ← 생성 데이터 (재사용 가능)
```

## 7. API 파라미터 가이드

### 최소한의 요청

```json
{
  "workspace_id": "ws_001",
  "task_id": "ecommerce_vocab",
  "vocab_definition_path": "data/mecab/vocab_config.json"
}
```

### 전체 파라미터

| 파라미터 | 기본값 | 설명 |
|---------|--------|------|
| `workspace_id` | (필수) | 워크스페이스 ID |
| `task_id` | (필수) | 태스크 ID (사전 구분용) |
| **데이터 소스 (택 1)** | | |
| `vocab_definition_path` | null | 어휘 정의 파일 상대 경로 (새로 생성) |
| `generated_data_path` | null | 기존 생성 데이터 경로 (재사용) |
| **LLM 생성** | | |
| `generation_platform` | `"hybrid"` | LLM 플랫폼 (`openai` / `google` / `hybrid`) |
| `generation_per_category` | `100` | 카테고리당 생성 단어 수 (최소 10) |

### 경로 규칙

```
vocab_definition_path에는 상대 경로만 입력:
  ✅ "data/mecab/vocab_config.json"
  ❌ "ce/ws_001/data/mecab/vocab_config.json"  ← 400 에러!
```

## 8. 세 파이프라인 비교 요약

| 항목 | Intent | NER | MeCab |
|------|--------|-----|-------|
| **입력 파일** | NDJSON (인텐트+발화) | JSON (엔티티 정의) | JSON (어휘 카테고리 정의) |
| **LLM이 생성하는 것** | 발화 텍스트 | 엔티티 포함 문장 | 단어 + 읽기 + 의미 |
| **최종 산출물** | 학습된 모델 (.bin) | 학습된 모델 (.bin) | MeCab 사전 (.dic + .csv) |
| **학습 여부** | KoBERT 파인튜닝 | KoELECTRA 파인튜닝 | 학습 없음 (사전 빌드만) |
| **생성 단위** | Intent당 100개 | 엔티티당 200개 | 카테고리당 100개 |
| **기본 LLM 플랫폼** | hybrid | hybrid | hybrid |
| **재사용 지원** | generated_data_path | generated_data_path | generated_data_path |
